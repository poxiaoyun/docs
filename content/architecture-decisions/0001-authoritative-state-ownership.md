# ADR-0001：按领域划分权威状态

- 状态：accepted
- 日期：2026-07-16

## 背景

平台包含 IAM、Moha、Apps、Rune、AIRouter、KMS、Installer、Kubernetes 和观测后端。它们的数据生命周期、访问频率和一致性要求不同，跨组件不存在统一事务。

## 决策

每类业务状态只设一个权威来源：IAM 持有身份与组织，Moha 持有 AI 资产，Apps 持有产品目录与面向用户的实例视图，Rune 持有集群和算力治理期望，Installer Instance 持有新路径的安装期望与状态，AIRouter 持有模型访问策略与用量，Kubernetes 持有运行资源，观测后端持有原始指标和日志。KMS 不保存业务密钥对象，业务密文与加密数据密钥由调用方持有。其他组件只能保存可重建投影、引用或缓存。

组件通过 API、事件或声明式调谐协作，不直接读写其他组件数据库。

## 后果

- 故障归因和写入责任清晰，组件可独立部署。
- 跨组件业务采用最终一致性，需要明确 status、重试和补偿。
- 查询可能需要聚合多个来源，不能假设单库事务快照。
- Rune 旧 Product/Instance Controller 与 Apps/Installer 新路径并存期间，同一逻辑实例只能选择一个权威安装 Controller。

## 验证

领域模型和数据表评审必须指出权威来源；删除缓存后系统能够重建；任何跨组件双写都必须通过新的 ADR 评审。
