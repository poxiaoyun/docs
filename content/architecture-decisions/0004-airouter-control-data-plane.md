# ADR-0004：AIRouter 分离控制面与数据面

- 状态：accepted
- 日期：2026-07-16

## 背景

模型渠道和策略管理属于低频业务操作，模型推理属于高并发、低延迟且可能长期流式的请求。两类负载共享进程和数据库访问路径会扩大故障范围。

## 决策

AIRouter Control Plane 管理渠道、Token、用户、策略和账务配置；Data Plane 执行认证、限流、审核、路由、转发和计量。数据面优先读取 Redis，缓存未命中时通过 gRPC 查询控制面，不直接访问业务数据库；配置变化通过 Redis Pub/Sub 广播。

Rune 将显式 `InferenceServiceRegistration` 同步到控制面，模型调用直接进入数据面。

## 后果

- 控制面和数据面可独立扩缩容和隔离故障。
- 缓存一致性、失效和控制面不可用时的行为必须明确。
- 渠道注册成功不代表上游模型在所有时刻可调用。

## 验证

测试覆盖缓存命中与未命中、配置广播、控制面故障、数据面故障、流式中断、限流、审核、上游重试和 usage 记录。
