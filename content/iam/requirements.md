# IAM 需求

本文描述平台级 IAM 的稳定需求和验收边界。它关注其他平台组件可以依赖的能力，不复述 IAM 仓库中的全部页面和字段。

## 背景

Console、BOSS、IAM、Moha、Apps、Rune、AIRouter 和自动化客户端需要共享一致的用户、组织和权限语义。若每个产品独立维护账号或成员关系，用户停用、成员移除和权限收回无法在全平台一致生效，也无法形成可信审计链路。

IAM 因此需要同时服务交互式用户、API 客户端和内部服务，并把身份认证、资源授权、组织治理与审计接收组织成可独立部署的公共能力。

## 用户与集成方问题

### 用户需要安全登录

- 支持用户名密码、Session、Bearer Token、API Key 以及配置启用的 OIDC/OAuth 和 MFA 流程。
- 登录结果必须能够形成后续请求可验证的身份，不在业务服务间传递明文凭据。
- Session Cookie 的 Secure、Domain、有效期等属性必须可按部署环境配置。
- 用户被禁用、Token 过期或验证失败时返回明确的未认证结果。

### 管理员需要治理组织和成员

- 组织具有稳定标识，展示名称变化不能产生新的租户边界。
- 支持组织、成员、用户组、角色和资源权限的管理。
- 支持平台级系统管理员与组织范围角色。
- 成员移除和角色变更应由 IAM 首先生效，下游缓存只能作为有界、可失效的投影。

### 平台服务需要统一鉴权

- 提供认证、授权和审计 Webhook，供统一入口及其他受信任组件复用。
- 提供受支持的 HTTP Client/内部 API，查询组织、成员和 RBAC 信息。
- 每次授权判断包含主体、动作、资源、组织或作用域，不能只依据前端页面角色。
- 服务身份与最终用户身份必须可区分，不能共用不可追踪的共享管理员凭据。

### 安全与运营人员需要审计证据

- 受保护写操作产生用户、动作、资源、范围、结果、时间和关联标识。
- 外部服务可以通过审计 Webhook 提交平台入口记录。
- 审计数据与业务状态分开保存，并支持查询、保留和归档策略。
- 日志和审计不得记录密码、Session、完整 Token 或下游凭据。

## 平台集成契约

| 集成方 | 使用 IAM 的能力 | IAM 不替其负责 |
| ------ | --------------- | -------------- |
| Rune API Server | 请求认证、资源授权、审计提交 | Cluster、Quota、Instance 和 Kubernetes 权限投影 |
| Rune Cloud | 组织、成员与租户上下文查询 | Tenant Enablement、Workspace 和资源配额 |
| Moha | 组织、成员、仓库访问判断所需身份 | Git revision、LFS 对象、镜像内容和仓库协作状态 |
| Apps | Product、ProductVersion 和 Instance 的认证、授权与租户范围 | 产品目录、artifact 和 Installer status |
| AIRouter | 外部或混合身份来源、租户成员上下文 | Channel、网关 Token、RPM/TPM、usage 和 billing |
| Console / BOSS | 登录与身份治理流程 | 其他领域业务状态 |

## 质量需求

- 默认拒绝匿名访问；公开路由逐项声明并接受绕过测试。
- 认证与授权结果可以缓存，但必须设置有效期并支持变更后的失效策略。
- Bootstrap 重复执行不得重复创建系统租户、角色或管理员关系。
- 依赖超时使用稳定错误分类，不把不可用降格为空列表、非成员或 404。
- etcd、MongoDB 或 Casdoor 任一不可用时，健康状态和受影响能力必须可诊断。
- 认证、授权和审计链路携带 request/trace ID，并暴露必要的耗时和错误指标。
- 内部 API、Webhook 凭据和可信请求头只能在受控网络与服务身份下使用。

## 非目标

- IAM 不管理 Rune 的资源配额、工作负载或 Kubernetes 对象。
- IAM 不管理 Moha 的资产内容与版本。
- IAM 不管理 Apps 的产品版本、artifact 或应用安装状态。
- IAM 不管理 AIRouter 的模型渠道、调用 Token 或用量。
- IAM 不作为通用 Secret/KMS，也不保存其他组件的业务凭据。
- 下游组件不通过复制 IAM 表来获得离线可写的用户和组织主数据。

## 验收标准

- 登录后可建立 Session 或 Token，并能通过认证接口还原主体。
- 同一资源请求在系统管理员、组织管理员、普通成员和非成员下得到符合策略的结果。
- 组织或成员关系变更后，下游在约定缓存窗口内观察到新结果。
- IAM 不可用时，入口返回依赖错误而不是伪装成权限拒绝或资源不存在。
- 对受保护写操作可按 request ID 关联入口日志、授权结果和审计记录。
- 直接访问 internal 路由、伪造可信身份头和跨组织对象路径会被部署边界或服务端校验拒绝。
