# 租户需求

本文描述 `rune` 中租户能力的产品需求。租户是面向组织、团队或客户的资源和访问边界，用来管理某个团队能看到哪些集群、能创建哪些工作空间、能使用多少资源，以及应用实例如何归属。

## 背景

`rune` 面向多团队共享集群。集群、节点、资源池、Flavor、应用模板和底层 Kubernetes 资源都不能直接无差别暴露给所有用户。租户层需要提供一个稳定边界：

- 用户先进入租户。
- 租户选择或启用集群。
- 租户在集群下创建工作空间。
- 工作空间内创建应用实例。
- 租户配额限制可用资源规格。

租户主要通过路由、标签、enablement 和配额体现，而不是一个复杂的独立控制器对象。

## 用户问题

### 租户需要知道哪些集群可用

平台可能管理多个集群，但不同租户不一定都能使用。

需求：

- 租户可以查看已发布的集群元数据。
- 租户可以检查某个集群是否已启用。
- 租户可以发起集群启用请求。
- 集群启用后需要初始化基础资源配额。

### 租户需要隔离工作空间

同一集群中，不同租户可以创建多个工作空间。租户 A 不能访问租户 B 的工作空间。

需求：

- 工作空间必须记录所属租户。
- 租户 API 列表只能返回当前租户的工作空间。
- 获取、更新、删除工作空间时必须校验租户归属。
- 工作空间对应 namespace 需要带租户标签。

### 租户需要资源配额

租户不能无限使用集群资源。租户配额是后续工作空间配额、Flavor 过滤和调度队列容量的来源。

需求：

- 租户在集群维度有 `ClusterResourceQuota`。
- 配额按资源名、型号、厂商和资源池表达。
- 租户可以查询自己的配额、可用资源和筛选器。
- 没有租户配额时，不允许创建工作空间。
- 租户启用集群时可以初始化默认 CPU/Memory 配额。

### 租户需要影响应用归属

应用实例创建在工作空间内，但资源也需要能回溯到租户。

需求：

- 通过租户路由创建 Instance 时，自动注入租户 label。
- Instance 渲染出的 Kubernetes 资源继承租户 label。
- 资源树、监控、日志、追踪和成本统计可以按租户过滤。

### 租户需要看到可用规格

Flavor 是集群级规格，但租户只能选择配额覆盖的规格。

需求：

- 租户只能看到自己配额允许的 Flavor。
- 配额用尽时 Flavor 标记售罄。
- 过滤维度包括类型、型号、厂商和资源池。

## 产品能力需求

### 集群可用性

租户集群可用性需要支持：

- 查询可用状态。
- 发起启用请求。
- 记录请求原因。
- 展示是否已请求。
- 展示启用结果和原因。

### 租户工作空间

租户工作空间能力需要支持：

- 列表。
- 创建。
- 获取详情。
- 更新名称、描述、标签和注解。
- 删除。
- 保留租户归属校验。

### 租户配额

租户配额能力需要支持：

- 查询 `ClusterResourceQuota`。
- 查询租户可用 quota resources。
- 查询 quota selector。
- 按 type、model、vendor 过滤。
- 后续作为调度队列容量来源。

### 租户应用

租户应用能力需要支持：

- 在租户/集群/工作空间路径下管理 Instance。
- 自动注入租户标签。
- 应用实例资源必须落到目标工作空间 namespace。
- 实例端点、资源树和事件只展示目标工作空间范围。

## 非目标

第一阶段不要求：

- 不在 `rune` 中实现完整 IAM 租户模型。
- 不把租户对象本身设计成复杂 CRD。
- 不允许租户绕过工作空间直接安装普通应用。
- 不在租户 enablement 中完成所有资源审批流程。
- 不自动给租户分配 GPU/NPU 等高级资源；默认初始化只覆盖基础 CPU/Memory。
- 不把租户配额和工作空间配额合并成同一层。

## 验收标准

- 租户可以查询已发布集群元数据。
- 租户可以检查和请求启用集群。
- 创建工作空间前必须存在租户配额。
- 租户工作空间列表只包含本租户工作空间。
- Instance 创建时注入租户 label。
- 租户可用 Flavor 受租户配额限制。
- 租户可查询 ClusterResourceQuota、quota resources 和 quota selector。
