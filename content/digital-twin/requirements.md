# 数字孪生需求

> 状态：**提案，已确认、未实施**（2026-10-16）。设计与决策见[设计](design.md)。

本文描述数字孪生接入平台的需求。数字孪生回答"机房里哪台机器、哪张卡现在不对"，不负责纳管集群、调度工作负载或产出指标。

## 背景

`rune-digital-twin` 目前是独立前端：数据来自构建期配置的自定义 HTTP 接口，只支持一个机房，没有用户登录和授权控制。
平台已经由 cloud 纳管多个集群，节点、GPU 指标和告警都有权威来源。数字孪生需要改为消费这些来源，并纳入平台的身份、
权限和 License 体系。

## 用户问题

### 运维人员需要按机房查看真实运行状态

- 一个 cloud 集群呈现为一个机房，可在多个机房之间切换。
- 节点、GPU 与节点级指标来自平台，按机房隔离与汇总。
- 平台没有采集来源的部件明确显示"无数据"，不显示演示数值。

### 管理员需要编排机房而不维护平台事实

- 管理员选择哪些集群启用为机房，可调整显示名和顺序。
- 节点自动从平台同步，管理员只负责上架位置和资产字段（整机型号、序列号、BMC IP、部件模板）。
- 集群或节点在平台消失时保留台账，由管理员决定清理。
- 后台不提供接口地址配置，平台地址由部署配置决定。

### 平台需要控制谁能使用数字孪生

- 使用平台账号登录，复用平台登录页与会话。
- 查看与管理分为两级角色，由 IAM 判定。
- 平台 License 未开通 `DigitalTwin` 时拒绝进入，并给出明确原因。

## 数据来源要求

- 节点与监控数据只经 apiserver 获取；监控只经 cloud 的 Prometheus 透传接口查询。
- 数字孪生不直连 Prometheus、Kubernetes 或 cloud，不使用厂商原始指标。
- 监控查询集合以指标清单表维护，每项写明指标名、时间范围、频率和聚合方式。

## 安全要求

- 平台访问凭据只在数字孪生服务端持有，不下发浏览器，不写日志或错误响应。
- 权限与 License 由服务端执行；前端隐藏入口不算授权。
- License 校验失败关闭，会话期间定期重新校验。

## 验收标准

| 场景 | 预期 |
| ---- | ---- |
| 未登录访问 `/twin/` | 跳转平台登录，登录后回到数字孪生 |
| 有 viewer 角色、License 有效 | 可查看已启用机房，看不到管理后台 |
| 有 admin 角色、License 有效 | 可启用机房、同步节点、编排机柜 |
| License 未开通 `DigitalTwin` | 拒绝进入，提示联系管理员开通 |
| apiserver 不可达 | 拒绝进入，提示授权状态暂时无法确认 |
| 集群无 GPU 指标 | GPU 灯显示无数据，页面不报错 |
| 集群在 cloud 被删除 | 机房标记已失联，台账保留 |
| 浏览器网络请求 | 只访问 `/twin/` 与 `/api/digital-twin/`，看不到 PromQL 与平台凭据 |
