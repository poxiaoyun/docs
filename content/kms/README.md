# KMS

KMS 是晓石 AI 平台的轻量数据密钥能力，为需要信封加密的内部调用方生成随机数据密钥，并在调用方持有加密数据密钥的前提下执行解密。它是独立部署的内部服务，不是通用 Secret 管理、证书管理或硬件密钥管理产品。

## 核心功能

| 功能 | 说明 |
| ---- | ---- |
| 生成数据密钥 | 生成 AES-256 或 SM4 数据密钥，同时返回明文数据密钥与加密数据密钥 |
| 解密数据密钥 | 使用相同算法和口令解密调用方保存的加密数据密钥 |
| 信封加密支撑 | 业务数据由调用方使用明文数据密钥加密，KMS 不接收或保存业务数据 |
| 服务接口 | 提供 REST、OpenAPI、版本与健康检查接口，可通过 Helm 部署 |

## 产品边界

- KMS 不持久化业务密钥对象、明文数据密钥或调用方密文。
- 加密数据密钥由调用方与业务密文共同保存。
- KMS 不替代 Kubernetes Secret、Vault、云厂商 KMS 或 HSM。
- Rune API Server 可以暴露受保护的统一路由，但不因此成为 KMS 状态所有者。

## 当前状态

当前实现基线为 `62db853`，提供 `generate-data-key` 和 `decrypt-data-key` 两个核心接口，支持 AES-GCM 与 SM4-GCM。当前实现仍使用口令派生包装密钥，认证、密钥版本、轮换、独立审计和外部主密钥托管尚未形成完整产品闭环，因此应将其描述为轻量内部能力。
