# Authentication and Token Management

Authentication is how the Moha platform knows **who you are**. Once you authenticate, the token is stored on your computer and every later command uses it automatically, so you never retype it.

You can authenticate in two ways: an **access token** (recommended, more secure) or a **username and password** (easiest; the platform exchanges them for a token when you log in).

## Before you start

- You have a Moha platform account (username and password).
- You know the platform address, in the form `https://<platform-url>`.

## How to get an access token

Method 1: copy it from the website (works as soon as you have a platform account)

1. Log in to the platform and go to **Moha Hub**.
2. In the left sidebar of the home page click **Access Tokens** (below **My Favorites**).
3. The page shows your current access token; click the copy button next to it.
4. Use the copied value wherever `<access-token>` appears.

Method 2: skip the manual step and log in with your username and password (recommended for beginners)

When you run `moha login` and enter your username and password, the platform issues a token automatically and saves it to your machine. You never see the token itself.

:::warning A token is as powerful as your password
An access token can access platform resources on your behalf. Do **not** paste it into chat groups, public code repositories, or screenshots. If it leaks, log in again immediately to replace it.
:::

## How to log in from the command line

The easiest way is interactive login, which only needs the platform address:

```bash
moha login https://<platform-url>
```

The terminal then asks, in order:

1. `Token (leave empty to log in with username/password):` — press Enter.
2. `Username:` — type your username and press Enter.
3. `Password:` — type your password and press Enter (no characters are shown, which is normal).
4. If several organizations are listed, type the number or name you want and press Enter.

On success the terminal shows `Login succeeded` and prints the current organization and the configuration file path.

If you already have an access token, you can do it in one step:

```bash
moha login https://<platform-url> --token <access-token>
```

Option reference:

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `https://<platform-url>` | Yes | None | The platform address; it **must include `https://`**, a bare domain is not enough |
| `--token <access-token>` | No | None | Log in with an existing token; if omitted, the command prompts for a username and password |
| `--username` / `-u` | No | None | Pass the username directly and skip the prompt |
| `--password` / `-p` | No | None | Pass the password directly and skip the prompt |
| `--token-dir` | No | `~/.moha` | Store login information in a different directory |

Logging in does not mean you must remember your account. Run `moha whoami` at any time to see the current login status:

```bash
moha whoami
```

## Where the token is stored

Login information is saved in your user directory:

| Item | Location / behaviour |
| --- | --- |
| Configuration file | `~/.moha/config.json` |
| What it contains | Access token, platform address, username, current organization |
| File permissions | Readable and writable only by you (other users on the machine cannot read it) |
| Custom location | Add `--token-dir <directory>` when logging in |

:::info Switching machines or directories
Other machines do not have this file, so you need to run `moha login` again, or provide a token temporarily with the `MOHA_TOKEN` environment variable.
:::

## How to replace a token or switch accounts

You do not need to delete the old token first; logging in again overwrites it:

```bash
moha login https://<platform-url> --token <new-access-token>
```

To log out completely so the machine keeps no login information:

```bash
moha logout
```

If you only want to use a different token for one command (without changing what is saved locally), pass it on the spot:

```bash
moha download <organization>/<model-name> --token <temporary-access-token>
```

Or set it for the current terminal session:

```bash
export MOHA_TOKEN=<temporary-access-token>
```

Authentication information is used in this priority order, highest first: **specified in the command** > **environment variable** > **saved on this machine**.

## What to do when a token expires or is revoked

When a token expires, an administrator revokes it, or you change your password, later commands report an authentication failure. The fix is always the same: **log in again**.

```bash
moha login https://<platform-url>
```

Reference table:

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| A command reports an authentication failure or 401 unauthorized | The token expired or was revoked | Run `moha login` again |
| Everything worked before, then all commands suddenly fail | The account was disabled or the password was changed | First confirm you can log in on the website, then run `moha login` again |
| `moha whoami` says you are not logged in | No login information is saved on this machine | Run `moha login` |
| The username or password is always reported as wrong | A typo, or the account does not exist | Check your credentials, or log in with an access token instead |

## Public versus private repositories

| Repository type | Usable without logging in | Description |
| --- | --- | --- |
| Public | Yes, you can download and list | No token needed; anyone who knows the repository name can pull it |
| Private / internal | No | You must log in with an account that has access to download, upload, or view |

So before you start, **log in once**; that is the least surprising path. You can only skip login if you are certain you will download public repositories only.

## Using it from Python

If you call the SDK from code, you can omit the token after logging in once, because the library reads the saved information automatically:

```python
from xiaoshiai_hub import HubClient

client = HubClient()  # Reuses the token saved on this machine
```

You can also pass the token explicitly, which is convenient when a script reads it from an environment variable:

```python
import os

from xiaoshiai_hub import HubClient

client = HubClient(token=os.environ["MOHA_TOKEN"])
```

Common authentication functions:

| Function | Purpose |
| --- | --- |
| `login(username, password, base_url)` | Log in with a username and password and save the token on this machine |
| `save_token(token, base_url, username)` | Save a token on this machine manually |
| `load_token()` | Read the saved token, platform address, and username |
| `delete_token()` | Delete the saved token (equivalent to `moha logout`) |
