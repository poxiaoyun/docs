# Model training and export workflow

This page solves one thing: **how to make a trained model show up in a Moha model repository**.
It goes from "pull the base model and dataset from the platform" to "the model is visible on the website", with every step spelled out. The training part uses a generic recipe; the important part is the last two steps, exporting and pushing back.

## Before you start

- The SDK is installed, `pip install moha-hub`, and you are logged in or hold an access token.
- To train, also install `pip install transformers datasets torch` (and `pip install peft` for LoRA).
- **Create the target repository first.** Uploading never creates a repository; a missing repository fails immediately.
- The training environment (GPU, VRAM) comes from your own machine or a platform development environment; this page does not cover it.

## Minimal working example

Assume the model is already trained and saved in `./output`. Uploading it and confirming the result takes three steps:

```bash
# 1. Create the repository first (replace the organization with your own)
moha create model ai-lab/my-finetuned-model --description "Fine-tuned model"

# 2. Upload the model directory
moha upload ai-lab/my-finetuned-model ./output --message "Upload the fine-tuned model"

# 3. Confirm the repository is visible
moha info model ai-lab/my-finetuned-model
```

:::tip Decide what to upload before you start
A training output directory often holds intermediate files such as `checkpoint-100` and `optimizer.pt`. They do not help anyone use the model and only slow the upload down. Upload only the final model files, or use the filter options to skip the large ones.
:::

## Step 1: pull the base model and dataset from the platform

```python
from xiaoshiai_hub import snapshot_download

base_dir = snapshot_download(
    repo_id="ai-lab/qwen2-7b",
    local_dir="./base/qwen2-7b",
    token="<access-token>",
)

data_dir = snapshot_download(
    repo_id="ai-lab/training-data",
    repo_type="datasets",
    local_dir="./data/training-data",
    token="<access-token>",
)
print(base_dir, data_dir)
```

After that, `transformers` and `datasets` only see these two local directories and need no further network access.

## Step 2: train and save

### Simplest full fine-tuning

```python
from datasets import load_dataset
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    Trainer,
    TrainingArguments,
)

base_dir = "./base/qwen2-7b"
out_dir = "./output"

tokenizer = AutoTokenizer.from_pretrained(base_dir)
model = AutoModelForCausalLM.from_pretrained(base_dir)

dataset = load_dataset("json", data_files="./data/training-data/*.jsonl", split="train")

def preprocess(examples):
    result = tokenizer(examples["text"], truncation=True, max_length=512)
    result["labels"] = result["input_ids"].copy()   # Causal LM: labels are the inputs themselves
    return result

dataset = dataset.map(preprocess, batched=True, remove_columns=["text"])

trainer = Trainer(
    model=model,
    args=TrainingArguments(
        output_dir=out_dir,
        num_train_epochs=1,
        per_device_train_batch_size=1,
    ),
    train_dataset=dataset,
)
trainer.train()

# Save the final model (Safetensors, the platform-recommended format)
model.save_pretrained(out_dir, safe_serialization=True)
tokenizer.save_pretrained(out_dir)
```

- When VRAM is short, reduce `per_device_train_batch_size` first, or switch to LoRA below.
- `safe_serialization=True` writes `.safetensors`, the most widely supported and fastest-loading format on the platform.

### Save VRAM with LoRA

LoRA trains only a small set of extra parameters, so the adapter directory it produces is small and uploads very quickly.

```python
from peft import LoraConfig, get_peft_model, TaskType

peft_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=8,
    lora_alpha=32,
    lora_dropout=0.1,
    target_modules=["q_proj", "v_proj"],
)
model = get_peft_model(model, peft_config)

# ... trainer.train() as usual ...

model.save_pretrained("./lora-adapter")   # Only the adapter, very small
tokenizer.save_pretrained("./lora-adapter")
```

Whether to merge the adapter into the full model depends on how you will use it:

| Your situation | What to upload |
| --- | --- |
| You only want to keep the fine-tuning result and stack it on demand | Upload the adapter directory directly |
| You want a complete model that loads on its own | Merge first, then upload (see below) |

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

base = AutoModelForCausalLM.from_pretrained("./base/qwen2-7b")
merged = PeftModel.from_pretrained(base, "./lora-adapter").merge_and_unload()
merged.save_pretrained("./merged-model", safe_serialization=True)
```

## Step 3: export to a format the platform recognises

A Moha repository is essentially "a file store with version control": whatever format you upload is what it stores. The difference is whether **others can load it directly with `transformers`**.

| Format | How to produce it | Description |
| --- | --- | --- |
| Safetensors | `save_pretrained(..., safe_serialization=True)` | Recommended. `transformers` loads it directly, and almost every model on the platform uses it |
| PyTorch bin | `save_pretrained(..., safe_serialization=False)` | Loadable, but slower and less safe than Safetensors |
| ONNX | Convert with your own toolchain | For other inference engines; `transformers.from_pretrained` does not read it |
| TorchScript | Convert with your own toolchain | Same as above |
| GGUF | Use the converter from the corresponding ecosystem | For CPU-side inference tools |
| TensorRT | Use the matching conversion tool | For high-performance inference on NVIDIA GPUs |

:::warning You do the format conversion yourself
The platform only stores and distributes files; it does not convert formats online. ONNX, GGUF, TensorRT, and the like must be converted locally with their own tools, and the result uploaded as ordinary files. Also, if a converted directory lacks the `config.json` structure, `from_pretrained` may not load it, so verify locally before uploading.
:::

## Step 4: push the result back to Moha

### Create the repository first

```bash
moha create model ai-lab/my-finetuned-model --description "Fine-tuned from qwen2-7b"
```

You can also create it from Python (see [HubClient API detailed explanation](./hub-api)):

```python
from xiaoshiai_hub import HubClient

client = HubClient(base_url="<platform-url>", token="<access-token>")
client.create_repository(
    organization="ai-lab",
    repo_type="models",
    repo_name="my-finetuned-model",
    description="Fine-tuned from qwen2-7b",
    visibility="internal",
    base_model=["ai-lab/qwen2-7b"],
    relationship="finetune",
)
```

### Then upload the directory

```python
from xiaoshiai_hub import upload_folder

upload_folder(
    folder_path="./output",
    repo_id="ai-lab/my-finetuned-model",
    commit_message="Upload the fine-tuned model",
    ignore_patterns=[
        "checkpoint-*",      # Intermediate checkpoints
        "optimizer.pt",      # Optimizer state, not needed
        "scheduler.pt",
        "rng_state.pth",
        "training_args.bin",
        "__pycache__/*",
        "*.pyc",
    ],
)
print("Upload finished")
```

- `repo_type` already defaults to `models`, so you rarely need to change it.
- Files 5 MB or larger automatically use the large-file channel and show progress; model weights almost always take this path.
- To put the files into a repository subdirectory, add `path_in_repo="v1.0"`.

The command line equivalent:

```bash
moha upload ai-lab/my-finetuned-model ./output \
  --exclude "checkpoint-*" \
  --exclude "optimizer.pt" \
  --message "Upload the fine-tuned model"
```

## Step 5: confirm the model is on the platform

```python
from xiaoshiai_hub import HubClient

client = HubClient(base_url="<platform-url>", token="<access-token>")

info = client.get_repository_info("ai-lab", "models", "my-finetuned-model")
print(info.organization, info.name, info.visibility)

# Check that all the files are there
content = client.get_repository_content(
    "ai-lab", "models", "my-finetuned-model", branch="main"
)
for item in content.entries or []:
    print(item.type, item.path, item.size)
```

On the command line: `moha info model ai-lab/my-finetuned-model`.

If the weight files, `config.json`, and the tokenizer files are all present, the model is on the platform and others can download it or load it as described in [Integrate with Transformers & Datasets](./transformers-datasets).

## Complete end-to-end example

```python
from datasets import load_dataset
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    Trainer,
    TrainingArguments,
)

from xiaoshiai_hub import HubClient, snapshot_download, upload_folder

BASE_REPO = "ai-lab/qwen2-7b"
DATA_REPO = "ai-lab/training-data"
TARGET_REPO = "ai-lab/my-finetuned-model"
ORG, NAME = TARGET_REPO.split("/")

# 1. Pull the base model and data from the platform
base_dir = snapshot_download(repo_id=BASE_REPO, local_dir="./base/qwen2-7b")
data_dir = snapshot_download(
    repo_id=DATA_REPO, repo_type="datasets", local_dir="./data/training-data"
)

# 2. Train
tokenizer = AutoTokenizer.from_pretrained(base_dir)
model = AutoModelForCausalLM.from_pretrained(base_dir)
dataset = load_dataset("json", data_files=f"{data_dir}/*.jsonl", split="train")

def preprocess(examples):
    result = tokenizer(examples["text"], truncation=True, max_length=512)
    result["labels"] = result["input_ids"].copy()
    return result

dataset = dataset.map(preprocess, batched=True, remove_columns=["text"])

trainer = Trainer(
    model=model,
    args=TrainingArguments(
        output_dir="./output", num_train_epochs=1, per_device_train_batch_size=1
    ),
    train_dataset=dataset,
)
trainer.train()
model.save_pretrained("./output", safe_serialization=True)
tokenizer.save_pretrained("./output")

# 3. Create the repository on the platform (skip this step if it already exists)
client = HubClient(base_url="<platform-url>", token="<access-token>")
client.create_repository(
    organization=ORG,
    repo_type="models",
    repo_name=NAME,
    description="Fine-tuned from qwen2-7b",
    base_model=[BASE_REPO],
    relationship="finetune",
)

# 4. Upload the result
upload_folder(
    folder_path="./output",
    repo_id=TARGET_REPO,
    commit_message="Upload the fine-tuned model",
    ignore_patterns=["checkpoint-*", "optimizer.pt", "scheduler.pt", "training_args.bin"],
)

# 5. Confirm
info = client.get_repository_info(ORG, "models", NAME)
print(f"Model is on the platform: {info.organization}/{info.name}")
```

## Common errors

| Error | Meaning | What to do |
| --- | --- | --- |
| `RepositoryNotFoundError: Repository not found: ... Please create the repository first.` | You uploaded before creating the repository | Run `moha create model organization/repository` first |
| `FileNotFoundError: File not found: ...` | The directory to upload has the wrong path | Confirm `folder_path` points at the training output directory |
| `ValueError: Path is not a directory: ...` | A file path was passed to `upload_folder()` | Use `upload_file()` for files |
| The weights you just uploaded are not visible on the website | They went into a subdirectory, or onto another branch | List the directory with `get_repository_content()`; check that the `revision` branch is right |
| The upload is very slow | Intermediate checkpoints and optimizer state were uploaded too | Use `ignore_patterns` to skip `checkpoint-*` and `optimizer.pt` |
| Others cannot load it with `from_pretrained` | The directory lacks `config.json`, or the weights are not named in the standard way | Save with `save_pretrained()`, do not copy loose files by hand |
| `UploadError: Upload failed: ...` | The server rejected the upload | Usually permissions or quota; read the specific reason that follows |
