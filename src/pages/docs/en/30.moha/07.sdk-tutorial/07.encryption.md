# Data encryption and secure transmission

If you do not want model weights or datasets to sit on the platform as plaintext, you can encrypt them during upload: the file is encrypted **on your own machine** and the platform stores ciphertext.
This page explains which algorithms are available, where the password comes from, which files actually get encrypted, and how to restore plaintext after downloading.

:::tip What envelope encryption is
Think of each file as a safe. The SDK first generates a random "data key" to lock the file, then locks that data key with your password and stores it at the very front of the file.
So you only have to remember one password, and a fresh data key is generated for every file.
:::

## Before you start

- The SDK is installed (`pip install moha-hub`) and you are either logged in on the command line or hold an access token.
- Decide on an **encryption password** and remember it: lose the password and the file cannot be restored.
- Confirm that the files you want encrypted actually meet the conditions below (size and extension); otherwise encryption does not happen.

## Core concepts

| Term | Plain-language explanation |
| --- | --- |
| Envelope encryption | Lock the file with a random data key, then lock that data key with your password; the file stores the locked key |
| Data key | The random key that actually encrypts the file: 32 bytes for AES mode and 16 bytes for SM4 mode. You never generate it yourself |
| KMS | The platform key service, which issues a data key based on your password and algorithm |
| CTR mode | A streaming encryption mode that encrypts as it reads, so a large file need not be loaded into memory |
| Encryption flag | A marker on the repository: once any encrypted file has been uploaded, the platform sets it and the website can no longer write to the repository |

## Which algorithms are available

| Value | Actual algorithm | Key length | Description |
| --- | --- | --- | --- |
| `AES` | AES-256-CTR | 32 bytes | The default; good performance, usually the right choice |
| `SM4` | SM4-CTR | 16 bytes | A Chinese national standard algorithm, for compliance requirements |

The command line also accepts `AES-256-CTR` and `SM4-CTR`, which behave exactly like `AES` and `SM4`. Python accepts only `AES` or `SM4`.

Encryption uses Python's `cryptography` library, which is installed with the SDK, so nothing extra is needed.

## Where encryption happens

The whole process finishes before the upload, so the platform only ever receives ciphertext:

1. You call an upload function and provide the password. The SDK sends the password to the platform KMS and receives a pair of keys: a **plaintext data key** and an **encrypted data key**.
2. The SDK generates a random 16-byte initialisation vector (IV) for each file locally and encrypts the file content with the data key.
3. The result is written to a new file with this structure: a 4-byte metadata length, then the metadata (containing the encrypted data key and the algorithm name), then the 16-byte IV, then the ciphertext body.
4. The SDK uploads the ciphertext file. The file name in the repository is unchanged, the content is now ciphertext, and the file is slightly larger.
5. If any file in this run was encrypted, the SDK sets the **encryption flag** on the repository.

Once the flag is set, the website can no longer add files to that repository (it reports that browser writes are unavailable for encrypted repositories), so further writes must go through the SDK or the command line.

## Minimal working example

Command line:

```bash
# Upload a folder with encryption; the environment variable is the safer way to pass the password
export MOHA_ENCRYPTION_PASSWORD="<encryption-password>"

moha upload ai-lab/my-model ./model \
  --encrypt \
  --algorithm AES \
  --message "Encrypted upload"
```

Python:

```python
from xiaoshiai_hub import upload_file

upload_file(
    path_file="./model.safetensors",
    path_in_repo="model.safetensors",
    repo_id="ai-lab/my-model",
    encryption_password="<encryption-password>",
    algorithm="AES",
    commit_message="Upload encrypted weights",
)
print("Encrypted upload finished")
```

## Options

| Option | Command line | Default | Description |
| --- | --- | --- | --- |
| Whether to encrypt | `--encrypt` / `-e` | Off | Must be turned on explicitly; nothing is encrypted automatically |
| Encryption password | `--encryption-password` or the `MOHA_ENCRYPTION_PASSWORD` environment variable | None | If neither is present the command fails immediately rather than quietly uploading plaintext |
| Algorithm | `--algorithm` / `-a` | `AES` | `AES`, `SM4`, `AES-256-CTR`, or `SM4-CTR` |
| Temporary directory | `--temp-dir` | Created automatically | Only affects where ciphertext temporary files are stored during upload; they are cleaned up automatically |

On the Python side the matching parameters are `encryption_password` and `algorithm`, and both `upload_file()` and `upload_folder()` accept them.

:::warning A lost password cannot be recovered
The platform only keeps the data key **encrypted with your password**; without your password the plaintext cannot be restored. Before an encrypted upload, store the password in a password manager or a CI secret.
:::

## Which files get encrypted

Encryption applies only to files that meet both conditions:

1. The file size is **5 MB or larger**;
2. The extension is on the list below.

| Category | Extensions |
| --- | --- |
| Model weights | `.safetensors`, `.bin`, `.pt`, `.pth`, `.ckpt`, `.h5`, `.onnx`, `.mlmodel`, `.model` |
| Data and arrays | `.arrow`, `.npy`, `.npz`, `.msgpack` |
| Archives | `.zip`, `.tar`, `.tgz`, `.gz`, `.bz2`, `.xz`, `.7z`, `.rar`, `.ftz` |
| Other | `.wasm` |

:::warning Small files and text files are not encrypted
Files under 5 MB, and files whose extension is not on the list such as `.json`, `.md`, `.txt`, and `.yaml`, are **uploaded as plaintext** even when you supply a password. This keeps configuration files and documentation viewable on the website. So do not put sensitive content in those files.
:::

## Download and decryption

**The SDK download functions do not decrypt**: `moha_hub_download()`, `snapshot_download()`, and the command line `moha download` all save the ciphertext as-is.
The SDK's own documentation describes the workflow as decrypting afterwards with a separate `xpai-enc` command line tool (refer to that tool's documentation for the exact commands).

To restore one file you need three things together:

| What you need | Where it comes from |
| --- | --- |
| The password used at upload time | Something you saved yourself |
| The algorithm (`AES` or `SM4`) | What you specified when uploading, or read from the file header |
| The file's encrypted data key | Queryable on the platform, see below |

The platform can return the encrypted data key and algorithm of every encrypted file in a repository for a given revision:

```python
from xiaoshiai_hub import HubClient

client = HubClient(base_url="<platform-url>", token="<access-token>")

info = client.get_repository_encryption(
    organization="ai-lab",
    repo_type="models",
    repo_name="my-model",
    reference="main",
)
for item in info.get("files", []):
    print(item["path"], item["algorithm"], item["encryptedKey"][:16])
```

With these in hand the restore path is: decrypt the encrypted data key with your password to get the plaintext data key, then decrypt the body with that key and the IV from the file header using the matching algorithm.
The one thing you truly must not lose is the **password**; everything else can be recovered from the file itself or from the platform.

## Security recommendations

- Do not hardcode the password in repository code; prefer an environment variable or a CI secret.
- Use a different password for each project to limit the impact of any single leak.
- Encryption only covers large files whose extension is on the list, so handle sensitive small text files before uploading.
- When team members need to decrypt, distribute the password through a separate secure channel, not alongside the repository.

## Common errors

| Error | Meaning | What to do |
| --- | --- | --- |
| `Error: --encrypt requires an encryption password. Set MOHA_ENCRYPTION_PASSWORD or use --encryption-password.` | Encryption was switched on without a password | Add `--encryption-password`, or set the `MOHA_ENCRYPTION_PASSWORD` environment variable |
| `Unsupported encryption algorithm: XXX. Choices: AES, SM4, AES-256-CTR, SM4-CTR` | The algorithm name is misspelled | Use one of the accepted values |
| `ValueError: AES requires 32-byte key, got N bytes` | The data key length does not match the algorithm (usually the algorithm and key are mismatched) | Confirm whether the algorithm is `AES` or `SM4`, and request a new data key |
| `ValueError: SM4 requires 16-byte key, got N bytes` | Same as above; an SM4 key was used as an AES key | Same as above |
| `FileNotFoundError: Source file not found: ...` | The local file to encrypt does not exist | Check the file path |
| The upload succeeds but the file is still plaintext | The file is under 5 MB, or its extension is not on the list | See "Which files get encrypted" above; this is expected behaviour |
| The downloaded file will not open or looks garbled | You downloaded ciphertext without decrypting it | Restore it with the upload password as described above |
