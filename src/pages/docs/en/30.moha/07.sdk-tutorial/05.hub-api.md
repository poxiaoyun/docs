# HubClient API detailed explanation

`HubClient` is the Python entry point of the Moha SDK. It lets you do in code everything the website can do for repository management: list repositories, create repositories, inspect branches, change visibility, read and write files, and publish Spaces.
It suits situations where you do not want to click by hand, such as "create dozens of repositories at once", "upload from inside a training script", or "check versions in CI".

## Before you start

- The SDK is installed: `pip install moha-hub`.
- You have an access token (created on the **Access Tokens** page of the website), or your username and password.
- Pass the platform address and token through environment variables rather than hardcoding them.

## Minimal working example

```python
from xiaoshiai_hub import HubClient

# The platform address can also come from MOHA_ENDPOINT; passing it here is clearer
client = HubClient(
    base_url="<platform-url>",
    token="<access-token>",
)

# List the model repositories you can see
for repo in client.list_repositories(repo_type="models"):
    print(f"{repo.organization}/{repo.name} - {repo.description}")
```

:::tip The token is not checked at construction time
`HubClient(...)` only attaches the credentials; it does not go online immediately. A wrong token fails on the first request, not here.
:::

## Client initialization

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `base_url` | `str` | The value of the `MOHA_ENDPOINT` environment variable | Platform address; include `https://` |
| `token` | `str` | None | Access token, recommended |
| `username` | `str` | None | Username, must be passed together with `password` |
| `password` | `str` | None | Password, must be passed together with `username` |

If you pass `token`, the token is used; if you pass only a username and password, Basic authentication is used. Passing neither does not fail immediately, but the first request fails authentication.

### What the return values look like

The API returns data class objects. The most common ones:

`Repository` (a repository)

| Field | Meaning |
| --- | --- |
| `name` / `organization` | Repository name / owning organization |
| `owner` / `creator` | Owner / creator |
| `type` | `models`, `datasets`, or `spaces` |
| `visibility` | `public`, `internal`, or `private` |
| `description` | Repository description |
| `metadata` | Metadata such as license, tasks, tags, and frameworks |
| `defaultBranchSize` / `repositoryStorageSize` | Default branch size / bytes used by the repository; may be empty |

`Ref` (a branch or tag): `name`, `ref`, `type` (`branch` or `tag`), `hash`, `is_default`.

`GitContent` (a file or directory): `name`, `path`, `type` (`file`, `dir`, `symlink`, `submodule`), `size`, `hash`, `content`, and `entries` (directories only).

## Repository management API at a glance

| Function | Purpose | Main parameters | Return value |
| --- | --- | --- | --- |
| `list_repositories()` | List repositories | `repo_type`, `scope`, `organization`, `mycreated` | `List[Repository]` |
| `get_repository_info()` | Inspect one repository | `organization`, `repo_type`, `repo_name` | `Repository` |
| `create_repository()` | Create a repository | `repo_name`, `description`, `visibility`, `metadata`, `base_model`, `relationship` | None |
| `update_repository()` | Change description, visibility, metadata | The fields above, plus `annotations` | None |
| `delete_repository()` | Delete a repository | `organization`, `repo_type`, `repo_name` | None |
| `list_organizations()` | List organizations | `organization_type`, `username` | `List[Organization]` |
| `get_organization()` | Inspect an organization | `organization` | `Organization` |
| `list_images()` | List images | `scope`, `organization`, `mycreated` | `List[Image]` |
| `create_image()` / `update_image()` / `get_image()` / `delete_image()` | Image create, read, update, delete | `organization`, `image_name`, `visibility`, `repo`, and more | `Image` or None |
| `list_repository_stats()` / `get_repository_stats()` | Repository statistics | Repository locator parameters | `List[Dict]` / `Dict` |

:::info Create, update, and delete return nothing
Except for query functions such as `list_*` and `get_*`, the create, update, and delete functions **have no return value**. Success is signalled by the absence of an exception; confirm the result with a query function.
:::

### Listing repositories: `scope` decides what you see

`scope` defaults to `all`.

| `scope` | What is listed |
| --- | --- |
| `all` | If `organization` is passed, the repositories visible to that organization; otherwise public repositories globally |
| `public` | Public repositories |
| `create` | Repositories you created |
| `favorite` | Repositories you favorited |
| `organization` | Repositories inside the given organization; `organization` is required |

```python
# Models I created
mine = client.list_repositories(repo_type="models", scope="create")

# Models inside an organization; with mycreated=True only your own
org_models = client.list_repositories(
    repo_type="models",
    scope="organization",
    organization="my-org",
    mycreated=True,
)
```

`repo_type` is `models`, `datasets`, or `spaces`.

### Create a repository and record where it came from

```python
client.create_repository(
    organization="my-org",
    repo_type="models",
    repo_name="my-new-model",
    description="A model fine-tuned from qwen2-7b",
    visibility="internal",
    metadata={
        "license": ["apache-2.0"],
        "tasks": ["text-generation"],
        "frameworks": ["pytorch"],
    },
    base_model=["ai-lab/qwen2-7b"],   # Source model, optional
    relationship="finetune",           # Relationship to the source model
)
```

| Parameter | Default | Description |
| --- | --- | --- |
| `visibility` | `internal` | One of `public`, `internal`, `private` |
| `metadata` | None | Keys and values are lists, for example `{"license": ["apache-2.0"]}` |
| `base_model` | None | List of source models, for example `["ai-lab/qwen2-7b"]` |
| `relationship` | None | `adapter`, `finetune`, `quantized`, `merge`, `repackage` |

`relationship` only has meaning when `base_model` is set. Creating a repository returns no object, so confirm it with `get_repository_info()`.

### Change description and visibility

```python
client.update_repository(
    organization="my-org",
    repo_type="models",
    repo_name="my-model",
    description="Updated description",
    visibility="public",
    metadata={"tags": ["llm", "fine-tuned"]},   # Merged with the old value
)
```

Fields you do not pass keep their old value; `metadata` and `annotations` are **merged**, not replaced wholesale.

:::warning Deleting a repository cannot be undone
`delete_repository()` removes all files and versions inside it, and they cannot be recovered. Before deleting, confirm that no other service is still pulling from it.
:::

## Branches and versions

| Function | Purpose | Parameters | Return value |
| --- | --- | --- | --- |
| `get_repository_refs()` | List branches and tags | `organization`, `repo_type`, `repo_name` | `List[Ref]` |
| `get_default_branch()` | Get the default branch name | Same as above | `str` (returns `main` when not found) |
| `create_branch()` | Create a branch | Same as above, plus `branch_name`, `from_branch` | None |
| `delete_branch()` | Delete a branch | Same as above, plus `branch_name` | None |

```python
refs = client.get_repository_refs("ai-lab", "models", "qwen2-7b")
for ref in refs:
    kind = "branch" if ref.type == "branch" else "tag"
    mark = " (default)" if ref.is_default else ""
    print(f"[{kind}] {ref.name}{mark} -> {ref.hash[:8]}")

# Create a development branch from main
client.create_branch(
    organization="my-org",
    repo_type="models",
    repo_name="my-model",
    branch_name="dev",
    from_branch="main",
)
```

`create_branch()` returns quietly when the branch already exists, and `delete_branch()` does the same when the branch does not exist. Both calls are safe to put in a script that runs repeatedly.

## Reading and writing files in a repository

| Function | Purpose | Parameters |
| --- | --- | --- |
| `get_repository_content()` | See what is inside a directory | `branch`, `path` (empty means the root) |
| `create_file()` | Write a small text file (README, config) | `branch`, `file_path`, `content`, `message` |
| `delete_file()` | Delete a file | `branch`, `file_path`, `message` |
| `download_file()` | Download a single file | `branch`, `file_path`, `local_path`, `show_progress` |

```python
# See what is in the root directory
content = client.get_repository_content("ai-lab", "models", "qwen2-7b", branch="main")
for item in content.entries or []:
    print(item.type, item.path, item.size)

# Write a README
client.create_file(
    organization="my-org",
    repo_type="models",
    repo_name="my-model",
    branch="main",
    file_path="README.md",
    content="# My Model\n\nThis is the fine-tuned model.",
    message="Add README",
)

# Download a file to the local machine
client.download_file(
    organization="ai-lab",
    repo_type="models",
    repo_name="qwen2-7b",
    branch="main",
    file_path="config.json",
    local_path="./downloaded_config.json",
)
```

:::tip Do not use create_file for large files
`create_file()` encodes the file content into the request body, so it only suits small text files. For model weights and datasets, use `upload_file()` and `moha_hub_download()` from [Upload, download and synchronization](./transfer).
:::

## Spaces

| Function | Purpose | Parameters |
| --- | --- | --- |
| `list_clusters()` | List available clusters | `organization` |
| `list_cluster_workspaces()` | List workspaces in a cluster | `organization`, `cluster_id` |
| `list_workspace_flavors()` | List workspace flavors | `organization`, `cluster_id`, `workspace_id` |
| `list_products()` / `get_product()` | List / inspect app templates | `organization`, `product_id` |
| `create_space_repository()` | Create a Space repository | `repo_name`, `cluster`, `namespace`, `product_id`, `product_version`, `visibility`, `flavor`, `env`, `description` |
| `deploy_space()` / `redeploy_space()` / `stop_space()` | Start / restart / stop | `organization`, `repo_name` |
| `get_space_status()` | Check status | `organization`, `repo_name` |
| `list_space_pods()` / `stream_space_logs()` | List running instances / stream logs | `organization`, `repo_name`, `pod`, and more |

```python
clusters = client.list_clusters("my-org")
workspaces = client.list_cluster_workspaces("my-org", clusters[0].id)
flavors = client.list_workspace_flavors("my-org", clusters[0].id, workspaces[0].id)
products = client.list_products("my-org")

client.create_space_repository(
    organization="my-org",
    repo_name="my-gradio-app",
    cluster=clusters[0].id,
    namespace=workspaces[0].id,
    product_id="gradio",
    product_version="latest",
    visibility="internal",
    flavor=flavors[0].id if flavors else None,
    env=[{"name": "MODEL_NAME", "value": "llama-7b"}],
    description="My Gradio app",
)

client.deploy_space("my-org", "my-gradio-app")
status = client.get_space_status("my-org", "my-gradio-app")
print(status.phase, status.healthy)
```

- Both `cluster` and `namespace` must be the `id` returned by the list functions above, not a name.
- `product_version` must match a version that really exists in the template, otherwise the request fails with "product version not found".
- `stream_space_logs()` depends on `websocket-client`, which is installed with the SDK. Pass `pod` the name returned by `list_space_pods()`; when a Space has several containers you also have to name the container.

## Encryption related functions

| Function | Purpose |
| --- | --- |
| `generate_data_key()` | Ask the KMS for a data key used for envelope encryption |
| `set_repository_encrypted()` / `cancel_repository_encrypted()` | Set / clear the "encrypted" flag on a repository |
| `get_repository_encryption()` | Look up the key and algorithm information of encrypted files under a revision |

```python
data_key = client.generate_data_key(algorithm="AES", password="<encryption-password>")
print(len(data_key.plaintext_key), data_key.encrypted_key[:16])
```

`generate_data_key(algorithm="AES", password=...)` defaults to `AES` and also accepts `SM4`. For the full upload encryption flow see [Data encryption](./encryption).

## Full example: create a repository, write a README, branch, then confirm

```python
from xiaoshiai_hub import HubClient

client = HubClient(base_url="<platform-url>", token="<access-token>")

client.create_repository(
    organization="my-org",
    repo_type="models",
    repo_name="finetuned-model",
    description="Fine-tuned model",
    visibility="internal",
)

client.create_file(
    organization="my-org",
    repo_type="models",
    repo_name="finetuned-model",
    branch="main",
    file_path="README.md",
    content="# Finetuned Model\n\nFine-tuned on custom data.",
    message="Add README",
)

client.create_branch(
    organization="my-org",
    repo_type="models",
    repo_name="finetuned-model",
    branch_name="dev",
    from_branch="main",
)

info = client.get_repository_info("my-org", "models", "finetuned-model")
print(info.organization, info.name, info.visibility)
```

## Common errors

| Error | Meaning | What to do |
| --- | --- | --- |
| `AuthenticationError: Authentication failed` | The token is invalid or expired, or no credentials were passed at all | Regenerate the token; check that `token` or `username`/`password` is passed correctly |
| `RepositoryNotFoundError: Resource not found` | The server returned 404: the repository does not exist, you have no access, or the path is wrong | Check the organization and repository names with `list_repositories()`; for a private repository confirm you have access |
| `ValueError: Invalid repo_id format: ... Expected 'organization/repo_name'` | The repository ID is not two segments | Check whether the organization name is missing or there is an extra slash |
| `ValueError: organization is required when scope is 'organization'` | An organization query was requested without an organization name | Always pass `organization=` together with `scope="organization"` |
| `HTTPError: Product version '...' not found for product '...'.` | The template version given when creating a Space does not exist | Confirm the available versions with `get_product()` or `list_products()` |
| `HTTPError: HTTP <status>: <reason>` | The server returned 4xx / 5xx (401 and 404 become the two errors above) | 4xx usually means a parameter problem; retry 5xx later |
| `HTTPError: Request failed: ...` | The network layer failed: cannot connect, timed out, or DNS resolution failed | Check the platform address, the network, and proxy settings |

:::info Where each exception is imported from
The exceptions you can import directly from `xiaoshiai_hub` are `HubException`, `RepositoryNotFoundError`, `FileNotFoundError`, `AuthenticationError`, and `UploadError`; `HTTPError` must be imported from `xiaoshiai_hub.exceptions`. See [Error handling and FAQ](./error-handling) for details.
:::
