# Complete reference for CLI tools

`moha` is a command line tool installed together with the SDK. It lets you log in, create repositories, upload and download, and publish Spaces without writing code.
This page lists the **purpose, usage, options, and examples** of every subcommand, so you can look things up as needed.

## Before you start

- The tool is installed (running `moha --version` prints a version number).
- It is best to log in once with `moha login https://<platform-url>`; every later command then uses the saved token.

## General rules

A few rules apply to all commands below. Reading them once saves time.

1. **Global options come before the subcommand**, for example `moha -vvv download <organization>/<model-name>`.
2. **Authentication options** (`--token`, `--username`, `--password`) work with almost every command; if you do not pass them, the tool reads what login saved or the environment variables.
3. **Write a repository ID as `organization/repository`**. If you have already selected a current organization with `moha organization use <organization>`, you can write just the repository name.
4. **Resource type aliases**: the forms in the table below are equivalent, pick any.

| Resource | Accepted forms |
| --- | --- |
| Model | `model`, `models`, `m` |
| Dataset | `dataset`, `datasets`, `ds` |
| Image | `image`, `images`, `img` |
| Space | `space`, `spaces`, `s` |

**Command aliases**: `list` can be `ls`, `create` can be `c`, `info` can be `i`, `update` can be `u`, `delete` can be `del`, `upload` can be `ul`, `download` can be `dl`, `branch-create` can be `bc`, `branch-delete` can be `bd`, and `branch-list` can be `bl`.

:::warning Delete operations need a second confirmation
`delete` and `branch-delete` are **irreversible**. The terminal asks you to type `--yes-i-really-mean-that` exactly before it proceeds;
adding `--force` skips that step (common in scripts, but you must be sure the target is correct).
:::

For debugging you can put `-v` before the command: `-v` shows basic information and `-vvv` shows detailed request logs (passwords and tokens are masked automatically):

```bash
moha -vvv download <organization>/<model-name>
```

## Authentication and organizations

### `moha login`

**Purpose**: log in to the platform and save the token and address on this machine.

**Usage**:

```bash
moha login <endpoint> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<endpoint>` | Yes | None | Must include `https://`, for example `https://<platform-url>` |
| `--token` | No | None | Log in with an existing access token |
| `--username` / `-u` | No | None | Specify the username |
| `--password` / `-p` | No | None | Specify the password |
| `--token-dir` | No | `~/.moha` | Directory in which to store login information |

**Examples**:

```bash
# Interactive login (prompts for token, username, and password)
moha login https://<platform-url>

# Log in directly with an access token
moha login https://<platform-url> --token <access-token>
```

### `moha logout`

**Purpose**: log out and delete the token saved on this machine.

**Usage**:

```bash
moha logout
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `--token-dir` | No | `~/.moha` | The configuration directory to clean up |

**Example**:

```bash
moha logout
```

### `moha whoami`

**Purpose**: show the current login status, username, platform address, and configuration file path.

**Usage**:

```bash
moha whoami
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `--token-dir` | No | `~/.moha` | The configuration directory |

**Example**:

```bash
moha whoami
```

### `moha organization list`

**Purpose**: list the organizations you can access; the current one is marked with `*`.

**Usage**:

```bash
moha organization list [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `--type` | No | None | Filter by type: `organization` or `user` |
| `--member` | No | None | Only list organizations joined by a given username |
| `--mine` | No | None | Only list organizations joined by the current user |

**Examples**:

```bash
moha organization list
moha org list --mine
```

### `moha organization use`

**Purpose**: set the current organization; afterwards repository commands can omit the organization prefix.

**Usage**:

```bash
moha organization use <organization> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<organization>` | Yes | None | The name of the organization to use |
| `--no-verify` | No | None | Skip the server-side check (rarely needed) |

**Examples**:

```bash
moha organization use <organization>
moha org use <organization>
```

## Repository management

### `moha list`

**Purpose**: list one kind of resource (models, datasets, images, or Spaces).

**Usage**:

```bash
moha list <resource> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<resource>` | Yes | None | `model` / `dataset` / `image` / `space` (aliases accepted) |
| `--all` / `-a` | No | None | Resources in the current organization plus public resources from all organizations |
| `--mine` / `-m` | No | None | Only resources you created |
| `--favorite` / `-f` | No | None | Only resources you favorited |

:::info The three filters are mutually exclusive
You can use only one of `--all`, `--mine`, and `--favorite`. When you use none of them, the command lists the resources of the **current organization**, so run `moha organization use <organization>` first.
:::

**Examples**:

```bash
# List the models of the current organization
moha list model

# List the images you favorited
moha list image --favorite

# List the Spaces of another organization
moha organization use <organization>
moha list space
```

### `moha create`

**Purpose**: create a model, dataset, image, or Space repository.

**Usage**:

```bash
moha create <resource> <repository> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<resource>` | Yes | None | `model` / `dataset` / `image` / `space` |
| `<repository>` | Yes | None | Repository ID, written as `organization/repository` or just the repository name |
| `--description` / `-d` | No | None | Repository description |
| `--visibility` / `-v` | No | `internal` | Visibility: `public`, `internal`, or `private` |
| `--license` | No | None | License, can be repeated |
| `--tasks` | No | None | Task type, can be repeated |
| `--languages` | No | None | Language, can be repeated |
| `--tags` | No | None | Tag, can be repeated |
| `--frameworks` | No | None | Framework, can be repeated |
| `--base-model` | No | None | Base model, can be repeated, in the form `organization/model-name` |
| `--relationship` | No | None | Relationship to the base model: `adapter`, `finetune`, `quantized`, `merge`, or `repackage` |

When you create an **image**, the last two rows are replaced by the image-specific options:

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `--repo` | No | None | Address of the upstream image repository |
| `--readme` | No | None | Image description content |
| `--alias` | No | None | Display alias |
| `--media-type` | No | None | Image media type |

**Examples**:

```bash
# Create a model repository
moha create model <organization>/my-model --description "My model"

# Create a dataset repository
moha create dataset <organization>/my-dataset --description "My dataset"

# Create an image repository
moha create image <organization>/my-runtime --repo <image-repository-url> --visibility internal

# Create a Space repository
moha create space <organization>/my-space --description "My app"
```

### `moha update`

**Purpose**: change a repository description, visibility, or metadata.

**Usage**:

```bash
moha update <resource> <repository> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<resource>` | Yes | None | `model` / `dataset` / `image` / `space` |
| `<repository>` | Yes | None | Repository ID |
| `--description` / `-d` | No | Unchanged | New description |
| `--visibility` / `-v` | No | Unchanged | `public`, `internal`, or `private` |
| `--license` / `--tasks` / `--languages` / `--tags` / `--frameworks` | No | Unchanged | Metadata, can be repeated |

**Example**:

```bash

```

### `moha delete`

**Purpose**: delete a repository (irreversible).

**Usage**:

```bash
moha delete <resource> <repository> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<resource>` | Yes | None | `model` / `dataset` / `image` / `space` |
| `<repository>` | Yes | None | Repository ID |
| `--force` | No | None | Skip the second confirmation and delete immediately |

**Examples**:

```bash
moha delete model <organization>/my-model
moha del img <organization>/my-runtime --force
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<repository>` | Yes | None | Repository ID |
| `--repo-type` / `-t` | No | `model` | Repository type |


### `moha branch-create`

**Purpose**: create a new branch from an existing one.

**Usage**:

```bash

```

| Option | Required | Default | Description |
| --- | --- | --- | --- |

| `--repo-type` / `-t` | No | `model` | Repository type |

**Examples**:

**Usage**:


| Option | Required | Default | Description |
| --- | --- | --- | --- |

**Examples**:

## Upload and download

### `moha upload`

**Purpose**: upload one local file or a whole folder to a repository.

**Usage**:

```bash
moha upload <repository> <local-path> [path-in-repo] [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<repository>` | Yes | None | Target repository ID, **written first** |
| `<local-path>` | Yes | None | The file or folder to upload |
| `[path-in-repo]` | No | The local file name | Which subdirectory or file name to use inside the repository |
| `--revision` / `-r` | No | `main` | Which branch to upload to |
| `--repo-type` / `-t` | No | `model` | Repository type |
| `--commit-message` / `--message` / `-m` | No | None | Commit message |
| `--commit-description` | No | None | Extra commit description |
| `--include` | No | None | Upload only matching files, can be repeated |
| `--exclude` | No | None | Exclude matching files, can be repeated |
| `--ignore` / `-i` | No | None | Ignore matching files, can be repeated |
| `--temp-dir` | No | Created automatically | Temporary directory used during encryption |
| `--disable-tqdm` | No | Off | Turn off the progress bar |
| `--quiet` / `-q` | No | Off | Reduce output and turn off the progress bar |
| `--encrypt` / `-e` | No | Off | Encrypt large model files before uploading |
| `--encryption-password` | No | None | Encryption password; the `MOHA_ENCRYPTION_PASSWORD` environment variable also works |
| `--algorithm` / `-a` | No | `AES` | Encryption algorithm: `AES`, `SM4`, `AES-256-CTR`, or `SM4-CTR` |

**Examples**:

```bash
# Upload a whole folder
moha upload <organization>/my-model ./my_model

# Upload a single file into a specific subdirectory
moha upload <organization>/my-model ./config.yaml configs/config.yaml

# Skip temporary files while uploading
moha upload <organization>/my-model ./my_model --ignore "*.log" --exclude ".git*"

# Encrypt a large model file before uploading
moha upload <organization>/my-model ./model.safetensors \
  --encrypt \
  --encryption-password <encryption-password>
```

### `moha upload-file`

**Purpose**: upload a single file (the arguments differ slightly from `upload`).

**Usage**:

```bash
moha upload-file <local-file> <repository> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<local-file>` | Yes | None | Path of the file to upload |
| `<repository>` | Yes | None | Target repository ID |
| `--path-in-repo` / `-p` | No | The file name | Path of the file inside the repository |
| `--repo-type` / `-t` | No | `model` | Repository type |
| `--revision` / `-r` | No | `main` | Target branch |
| `--commit-message` / `--message` / `-m` | No | None | Commit message |
| `--encryption-password` | No | None | Encryption password |
| `--encrypt` / `-e`, `--algorithm` / `-a` | No | Off / `AES` | Same as `upload` |

**Examples**:

```bash
moha upload-file ./config.json <organization>/my-model
moha upload-file ./model.bin <organization>/my-model --path-in-repo weights/model.bin
```

### `moha download`

**Purpose**: download a whole repository, or only a few selected files.

**Usage**:

```bash
moha download <repository> [files...] [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<repository>` | Yes | None | Repository ID to download |
| `[files...]` | No | None | Download only these files; omit to download the whole repository |
| `--local-dir` / `-o` | No | `./downloads/<organization>_<type>_<repository>/` for a whole repository, the current directory for selected files | Where to save the download |
| `--repo-type` / `-t` | No | `model` | Repository type |
| `--revision` / `-r` | No | The repository default branch | Which branch, tag, or commit to download |
| `--include` | No | None | Download only matching files, can be repeated |
| `--exclude` / `--ignore` / `-i` | No | None | Exclude matching files, can be repeated |
| `--disable-tqdm` / `--quiet` / `-q` | No | Off | Turn off the progress bar |

**Examples**:

```bash
# Download the whole repository (into ./downloads/... by default)
moha download <organization>/my-model

# Choose the download directory
moha download <organization>/my-model --local-dir ./models

# Download only YAML files
moha download <organization>/my-model --include "*.yaml"

# Download two specific files
moha download <organization>/my-model config.yaml tokenizer.json
```

### `moha download-file`

**Purpose**: download a single file from a repository, saved to the current directory by default.

**Usage**:

```bash
moha download-file <repository> <file-path> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `<repository>` | Yes | None | Repository ID |
| `<file-path>` | Yes | None | Path of the file inside the repository |
| `--local-dir` / `-o` | No | The current directory | Where to save the file |
| `--repo-type` / `-t` | No | `model` | Repository type |
| `--revision` / `-r` | No | The repository default branch | Branch, tag, or commit |
| `--disable-tqdm` / `--quiet` / `-q` | No | Off | Turn off the progress bar |

**Example**:

```bash
moha download-file <organization>/my-model config.json --local-dir ./configs
```

### `moha logs`

**Purpose**: show the runtime logs of a Space.

**Usage**:

```bash
moha logs <repository> [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |

## AI assistant

### `moha ai`

**Purpose**: use natural language to have the AI assistant look up repositories, inspect files, publish Spaces, and more (delete operations are never performed by the assistant).

**Usage**:

```bash
moha ai [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `--prompt` / `-p` | No | None | Run one instruction and exit without entering interactive mode |
| `--api-base` | No | None | Large model API address; `MOHA_AI_API_BASE` also works |
| `--api-key` | No | None | Large model key; `MOHA_AI_API_KEY` also works |
| `--model` / `-m` | No | None | Model name; `MOHA_AI_MODEL` also works |
| `--no-stream` | No | Off | Turn off streaming output and show the answer once it is complete |

**Examples**:

```bash
moha ai
moha ai --prompt "List the models I created"
```

### `moha ai-config`

**Purpose**: configure the large model API used by the AI assistant.

**Usage**:

```bash
moha ai-config [options]
```

| Option | Required | Default | Description |
| --- | --- | --- | --- |
| `--api-base` | No | Unchanged | Large model API address |
| `--api-key` | No | Unchanged | Large model key |
| `--model` / `-m` | No | Unchanged | Model name |
| `--show` / `-s` | No | Off | Show the current configuration only |

**Examples**:

```bash
moha ai-config --api-base <api-url> --api-key <api-key> --model <model-name>
moha ai-config --show
```

## Common errors

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `unknown command` | A subcommand is misspelled | Use the command the hint suggests, or run `moha --help` to see every command |
| An authentication failure or unauthorized error | You are not logged in, or the token expired | Run `moha login https://<platform-url>` to log in again |
| The command asks you to select a current organization first | No current organization is set and the organization prefix was omitted | Run `moha organization use <organization>`, or write the full `organization/repository` in the command |
| `Invalid repository ID` | The repository name format is wrong | Use `organization/repository`, or set the current organization first and write just the repository name |
| The delete command seems to do nothing | It is waiting for the confirmation phrase | Type `--yes-i-really-mean-that` exactly and press Enter, or use `--force` |
| `--encrypt requires an encryption password` | Encryption is on but no password was given | Add `--encryption-password <password>`, or set `MOHA_ENCRYPTION_PASSWORD` |
| File filters do not take effect | The shell expanded the wildcard before the command ran | Quote the pattern, for example `--include "*.yaml"` |
