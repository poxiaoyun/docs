# Upload and download synchronized with files

This page covers advanced upload and download usage: when a repository is too large to fetch in full, when you only want one branch, when you want to skip caches and logs during upload, and what to do when a download is interrupted.
If you have not completed an upload or download yet, start with [Quick start in 5 minutes](./quick-start).

## Before you start

- The SDK is installed and you are logged in (`moha whoami` on the command line shows your login status).
- The target repository must **already exist**. Neither upload nor download creates a repository; a missing repository fails immediately.
- Leave enough local disk space: a whole-repository download fetches every file completely, and skips nothing that was not filtered out.

## Minimal working example

```python
from xiaoshiai_hub import moha_hub_download, upload_file

# Download one file: repo_id is "organization/repository"
path = moha_hub_download(
    repo_id="ai-lab/qwen2-7b",
    filename="config.json",
    local_dir="./models",
    token="<access-token>",
    base_url="<platform-url>",
)
print("Downloaded to:", path)

# Upload one file: the first two arguments are the local path and the path in the repository
upload_file(
    path_file="./README.md",
    path_in_repo="README.md",
    repo_id="my-org/my-model",
    token="<access-token>",
    base_url="<platform-url>",
)
```

:::tip The two functions take their arguments in different orders
`moha_hub_download(repo_id, filename)` is "repository first, file second"; `upload_file(path_file, path_in_repo, repo_id)` is "local file, then path in the repository, then the repository". Mixing up the order is the most common source of errors.
:::

## Download

| Function | When to use it | Cost |
| --- | --- | --- |
| `moha_hub_download()` | You need only one or two files (a config, a tokenizer) | One request per file, so many files need a loop |
| `snapshot_download()` | You need the whole repository, or a filtered batch | It walks the repository tree first to count files, an extra round of requests for a large repository |

Neither function **decrypts**: an encrypted file stays encrypted after download and needs separate handling, see [Data encryption](./encryption).

### Download one file: `moha_hub_download()`

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `repo_id` | `str` | — | Must be the two-segment `organization/repository` |
| `filename` | `str` | — | Path of the file inside the repository |
| `repo_type` | `str` | `models` | `models`, `datasets`, or `spaces` |
| `revision` | `str` | None | Branch name or commit SHA; omit to use the default branch |
| `local_dir` | `str` | None | Directory to save into |
| `show_progress` | `bool` | `True` | Whether to show a progress bar |
| `base_url` / `token` / `username` / `password` | `str` | None | Credentials; when omitted, environment variables and local login state are used |

Where the file goes:

- With `local_dir` → `local_dir/filename`, for example `./models/config.json`.
- Without `local_dir` → saved under its relative path in the current directory, so `filename="data/config.yaml"` becomes `./data/config.yaml`.

```python
# Download only the weights and process them later
weights = moha_hub_download(
    repo_id="ai-lab/qwen2-7b",
    filename="model.safetensors",
    local_dir="./models",
)
```

### Download a whole repository: `snapshot_download()`

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `repo_id` | `str` | — | `organization/repository` |
| `repo_type` | `str` | `models` | `models`, `datasets`, or `spaces` |
| `revision` | `str` | None | Branch name or commit SHA |
| `local_dir` | `str` | None | Download directory; when omitted it becomes `./downloads/organization_type_repository` |
| `allow_patterns` | `str` or list | None | Download only matching files |
| `ignore_patterns` | `str` or list | None | Skip matching files |
| `show_progress` | `bool` | `True` | Whether to show a progress bar |

```python
from xiaoshiai_hub import snapshot_download

repo_path = snapshot_download(
    repo_id="ai-lab/qwen2-7b",
    local_dir="./models/qwen2-7b",
)
print("Downloaded to:", repo_path)
```

:::info Download counters
A whole-repository download also adds one to the repository download count at the end. If that report fails it does not fail the download, it only logs a warning. A single-file download does not add to the count.
:::

### Download only the files you need

`allow_patterns` is a whitelist and `ignore_patterns` is a blacklist. A file matches when either its **file name** or its **full path inside the repository** matches.

| What you want | How to write it |
| --- | --- |
| Only safetensors weights | `allow_patterns="*.safetensors"` |
| Only configs and weights | `allow_patterns=["*.safetensors", "*.json"]` |
| Only one directory | `allow_patterns="weights/*"` |
| Everything except old bin weights | `ignore_patterns="*.bin"` |
| Skip caches and temporary files | `ignore_patterns=["*.pyc", "__pycache__", "*.tmp"]` |

```python
# The whitelist and blacklist can be used together
repo_path = snapshot_download(
    repo_id="ai-lab/qwen2-7b",
    allow_patterns=["*.safetensors", "*.json"],
    ignore_patterns=["*.tmp"],
    local_dir="./models/qwen2-7b",
)
```

:::warning The blacklist wins
`ignore_patterns` takes priority over `allow_patterns`: a file that matches the blacklist is never downloaded, even if it also matches the whitelist. So to fetch "everything except one file", write only the blacklist.
:::

Cost: filtering happens **after the server lists the directory and before the download**, so it does not reduce the requests spent counting files; it only transfers fewer files, saving bandwidth and disk.

### Download by version

`revision` accepts a branch name or a commit SHA. If you omit it, the repository default branch is used.

```python
# Pull the development branch
snapshot_download(repo_id="ai-lab/qwen2-7b", revision="dev", local_dir="./dev")

# Pull one commit to reproduce exactly what was there
snapshot_download(repo_id="ai-lab/qwen2-7b", revision="abc123def456", local_dir="./pinned")
```

To see which branches and commits a repository has, use `get_repository_refs()` from [HubClient API](./hub-api), or run `moha refs <organization>/<repository>` on the command line.

### Command line equivalents

```bash
# Download the whole repository into ./downloads
moha download ai-lab/qwen2-7b -o ./downloads

# Download only a few files
moha download ai-lab/qwen2-7b config.json tokenizer.json -o ./downloads

# Filter by pattern and pick a branch
moha download ai-lab/qwen2-7b \
  --include "*.json" --exclude "*.log" \
  --revision dev -o ./downloads

# Download a single file
moha download-file ai-lab/qwen2-7b config.json -o ./downloads
```

When `moha download` is followed by file names, it calls the single-file download for each; only when there are no file names does it download the whole repository.

## Upload

| Function | When to use it | Cost |
| --- | --- | --- |
| `upload_file()` | Update one file, add one config | One file per call; many files need your own loop |
| `upload_folder()` | Upload a whole model or dataset directory | Files are processed one after another, so many files are slow |

Both functions pick a channel based on file size: files **under 5 MB** have their content encoded and sent in one request; files **5 MB or larger** use the large-file channel, which first requests an upload address and then transfers directly, with a progress bar.

### Upload one file: `upload_file()`

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `path_file` | `str` | — | Local file path |
| `path_in_repo` | `str` | — | Path of the file inside the repository |
| `repo_id` | `str` | — | `organization/repository` |
| `repo_type` | `str` | `models` | `models`, `datasets`, or `spaces` |
| `revision` | `str` | `main` | Which branch to upload to |
| `commit_message` | `str` | Generated automatically | Commit message; when omitted it becomes "Upload <file name>" |
| `commit_description` | `str` | None | Commit description, appended after the commit message |
| `encryption_password` | `str` | None | Encryption password, see [Data encryption](./encryption) |
| `algorithm` | `str` | None | Encryption algorithm, `AES` or `SM4` |
| `base_url` / `token` / `username` / `password` | `str` | None | Credentials |

```python
# Upload into a subdirectory of the repository
upload_file(
    path_file="./weights/model.safetensors",
    path_in_repo="weights/v1.0/model.safetensors",
    repo_id="my-org/my-model",
    commit_message="Upload v1.0 weights",
)

# Upload into a dataset repository
upload_file(
    path_file="./train.json",
    path_in_repo="data/train.json",
    repo_id="my-org/my-dataset",
    repo_type="datasets",
)
```

### Upload a whole directory: `upload_folder()`

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `folder_path` | `str` | — | Local directory |
| `repo_id` | `str` | — | `organization/repository` |
| `repo_type` | `str` | `models` | `models`, `datasets`, or `spaces` |
| `revision` | `str` | `main` | Which branch to upload to |
| `allow_patterns` | list | None | Upload only matching files |
| `ignore_patterns` | list | None | Skip matching files |
| `path_in_repo` | `str` | None | Which subdirectory of the repository to put these files into |
| `commit_message` / `commit_description` | `str` | Generated automatically | Commit message / description |
| `temp_dir` | `str` | Created automatically | Temporary directory used during encryption |
| `encryption_password` / `algorithm` | `str` | None | Encryption password / algorithm |

```python
from xiaoshiai_hub import upload_folder

# Upload a PyTorch project, skipping environments and caches
upload_folder(
    folder_path="./my_model",
    repo_id="my-org/my-model",
    ignore_patterns=[
        ".*",              # Hidden files
        "venv/*",          # Virtual environment
        "__pycache__/*",   # Python cache
        "*.pyc",
        "build/*",
        "dist/*",
    ],
    commit_message="Upload the fine-tuned model",
)

# Upload only weights and index files, all into a weights subdirectory
upload_folder(
    folder_path="./output",
    repo_id="my-org/my-model",
    path_in_repo="weights",
    allow_patterns=["*.safetensors", "*.index.json"],
)
```

:::info Automatic skips
When uploading a directory, `.git` and `.gitattributes` are skipped automatically; you do not need to list them in `ignore_patterns`.
:::

Cost:

- Files under 5 MB are **read into memory in full** and sent with the request, so a very large number of files makes the request body large.
- Large files use the 5 MB threshold to pick the direct-upload channel, but there is **no resume support**: if it breaks midway, the whole file is sent again.

### Command line equivalents

```bash
# Upload a directory
moha upload my-org/my-model ./my_model

# Upload a directory with filtering
moha upload my-org/my-model ./my_model \
  --ignore "*.log" --exclude ".git*"

# Upload a single file to a chosen path
moha upload-file ./config.yaml my-org/my-model --path-in-repo configs/config.yaml
```

`moha upload` decides by itself: a directory goes through the directory upload, a file through the single-file upload. The historical "local path first, repository second" order still works.

## Interruptions, retries, and concurrency

The SDK **does not build in** any of these three; you have to add a layer yourself:

| Need | What the SDK provides | What to do |
| --- | --- | --- |
| Resume after interruption | Not supported. Downloads overwrite; after an interruption a rerun starts from the beginning | Try to finish large files in one go; after an interruption, rerun or use an external tool that supports resuming |
| Automatic retries | Not supported. A network blip raises an exception | Wrap the call in your own loop that catches the exception and retries |
| Concurrent downloads | Not supported. A whole-repository download is serial, one file at a time | Use a thread pool to call `moha_hub_download()` concurrently |

Here is how to add retries and concurrency yourself (this is logic you write, not a built-in SDK feature):

```python
import time
from concurrent.futures import ThreadPoolExecutor

from xiaoshiai_hub import HubException, moha_hub_download

FILES = ["config.json", "tokenizer.json", "vocab.json"]

def fetch(name, max_retries=3):
    for attempt in range(max_retries):
        try:
            return moha_hub_download(
                repo_id="ai-lab/qwen2-7b",
                filename=name,
                local_dir="./models",
                show_progress=False,
            )
        except HubException:
            if attempt == max_retries - 1:
                raise
            time.sleep(2 ** attempt)   # 2, then 4 seconds, and so on

# Download several files concurrently; keep the thread count low so the server is not overloaded
with ThreadPoolExecutor(max_workers=4) as pool:
    for path in pool.map(fetch, FILES):
        print("Downloaded:", path)
```

The cost of concurrency: each task opens its own connection and checks once that the repository exists, while the token is shared; too many threads get rate limited or slow down others. When there are only a few files, serial is simpler.

## Which function to choose

| Situation | Use |
| --- | --- |
| One or two files | `moha_hub_download()` |
| The whole repository | `snapshot_download()` |
| Part of a repository | `snapshot_download()` with `allow_patterns` / `ignore_patterns` |
| Update one file | `upload_file()` |
| Upload a directory | `upload_folder()` with `ignore_patterns` |

## Common errors

| Error | Meaning | What to do |
| --- | --- | --- |
| `ValueError: Invalid repo_id format: ... Expected 'organization/repo_name'` | The repository ID is not two segments | Write `organization/repository`, with neither an extra nor a missing slash |
| `RepositoryNotFoundError: Repository not found: ... Please create the repository first.` | The target repository does not exist, or you have no access | Create the repository on the website first, or check the organization and repository names |
| `FileNotFoundError: File not found: ...` | The local file or directory to upload does not exist | Check the local path and whether the file is still there |
| `ValueError: Path is not a file: ...` | A directory was passed to `upload_file()` | Use `upload_folder()` for directories |
| `ValueError: Path is not a directory: ...` | A file was passed to `upload_folder()` | Use `upload_file()` for files |
| `UploadError: Upload failed: ...` | The server rejected the upload request | Read the reason that follows: usually permissions, quota, or an oversized file |
| `HTTPError: Request failed: ...` | The network layer failed | Check the network, proxy, and platform address |
