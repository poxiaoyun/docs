# Error handling and FAQ

When a script breaks, do not rush into changing the code. The SDK throws only a handful of exception types, and every message names the repository and file involved.
This page gives you a "message to meaning to fix" lookup table plus a few patterns you can copy directly.

## How to read an error

1. Look at the **exception class name** to sort it into a broad category: authentication, not-found, network, upload, or a bad parameter.
2. Look at the **objects in the message**: which organization, repository, file, and branch.
3. Find the same message in the tables below and follow the "what to do" column.

## Exception types at a glance

```
HubException (base class of every SDK exception)
├── RepositoryNotFoundError   repository not found, or no permission
├── AuthenticationError       authentication failed
├── HTTPError                 the server returned an error status, or the request failed
├── FileNotFoundError         file not found in the repository (the SDK's own class; a missing local file raises the built-in exception of the same name)
└── UploadError               an upload operation failed
```

| Exception | When it appears |
| --- | --- |
| `HubException` | The base class; catching it covers every SDK exception |
| `RepositoryNotFoundError` | The server returned 404: the repository does not exist, you have no permission, or the path is wrong |
| `AuthenticationError` | The server returned 401: the token is invalid or expired, or no credentials were provided |
| `HTTPError` | The server returned another 4xx/5xx, or the request never went out (network, timeout) |
| `UploadError` | The upload request was rejected or interrupted |
| `FileNotFoundError` | The local file or directory to upload does not exist (Python's built-in exception of the same name) |

:::warning Two easy traps

1. `HTTPError` **cannot** be imported from the top-level `xiaoshiai_hub`; write `from xiaoshiai_hub.exceptions import HTTPError`. The other exceptions can all be imported from the top level.
2. `FileNotFoundError` has a name clash: the SDK also exports an exception of that name at the top level, but a missing local file raises the **built-in Python** `FileNotFoundError`. So do not use `from xiaoshiai_hub import FileNotFoundError`, which would shadow the built-in name and make your `except` miss it.

:::

## Error message lookup

### Authentication

| Message | Meaning | What to do |
| --- | --- | --- |
| `AuthenticationError: Authentication failed` | The server returned 401: the token is invalid or expired, or nothing was passed at all | Regenerate the access token; check that `token` (or `username`/`password`) was passed |
| `AuthenticationError: Authentication failed: ...` | The server returned 401 during an upload | Same as above; focus on the `token` parameter |
| `AuthenticationError: Invalid username or password` | Wrong account or password at login | Check the credentials; logging in with an access token avoids the password entirely |
| `AuthenticationError: Server did not return a token` | Login succeeded but the server returned no token | Confirm the platform address points at the Moha platform and not some other service |
| `AuthenticationError: Login request failed: ...` | The login request itself failed (network, timeout) | Check the network and the platform address |
| `ValueError: Endpoint must be an HTTP(S) URL including the scheme, for example https://hub.example.com` | The platform address has no `https://` | Add the scheme; do not write a bare domain |

### Repositories and files

| Message | Meaning | What to do |
| --- | --- | --- |
| `RepositoryNotFoundError: Resource not found` | The server returned 404. The repository may not exist, you may lack permission, or the file/branch path may be wrong | Check the organization and repository names with `list_repositories()` or `moha list model`; confirm you have access to a private repository |
| `RepositoryNotFoundError: Repository not found: <organization>/<type>/<repository>. Please create the repository first.` | The pre-flight check before an upload or download found no repository | Create it first: `moha create model organization/repository` |
| `RepositoryNotFoundError: Repository not found: ...` (during upload) | The server returned 404 for the upload request | Same as above |
| `ValueError: Invalid repo_id format: <...>. Expected 'organization/repo_name'` | The repository ID is not the two-segment form | Write `organization/repository`, with neither an extra nor a missing slash |
| `ValueError: organization is required when scope is 'organization'` | An organization query was requested without an organization name | Always pass `organization=` together with `scope="organization"` |
| `ValueError: Invalid scope: <...>. Must be one of: all, public, create, favorite, organization` | The `scope` value is outside the allowed set | Use one of the five allowed values |
| `ValueError: Path is not a file: <...>` | A directory was passed to an API that accepts only files | Use `upload_folder()` instead |
| `ValueError: Path is not a directory: <...>` | A file was passed to an API that accepts only directories | Use `upload_file()` instead |
| `HTTPError: Product version '<v>' not found for product '<id>'.` | The template version given when creating a Space does not exist | Confirm the available versions with `get_product()` / `list_products()` |

### Upload and download

| Message | Meaning | What to do |
| --- | --- | --- |
| `FileNotFoundError: File not found: <path>` | The local file to upload does not exist | Check the path and whether the file was moved |
| `FileNotFoundError: Folder not found: <path>` | The local directory to upload does not exist | Same as above |
| `UploadError: Upload failed: <reason>` | The server rejected the upload request | Work from the reason that follows: usually permissions, quota, or an oversized file |
| `UploadError: Request failed: <reason>` | The upload request failed at the network layer | Check the network and proxy; retry large files |
| `HTTPError: Request failed: <reason>` | The request never went out: cannot connect, timed out, or DNS resolution failed | Check the platform address, network, and proxy settings |

### Encryption

| Message | Meaning | What to do |
| --- | --- | --- |
| `Error: --encrypt requires an encryption password. Set MOHA_ENCRYPTION_PASSWORD or use --encryption-password.` | Encryption was switched on at the command line without a password | Add `--encryption-password`, or set the `MOHA_ENCRYPTION_PASSWORD` environment variable |
| `Unsupported encryption algorithm: <...>. Choices: AES, SM4, AES-256-CTR, SM4-CTR` | The algorithm name is misspelled | Use one of the four accepted values |
| `ValueError: 'XXX' is not a valid Algorithm` | Python received an `algorithm` other than `AES` or `SM4` | Pass only `AES` or `SM4` |
| `ValueError: AES requires 32-byte key, got N bytes` | The data key length does not match the algorithm | Confirm the algorithm matches the one used when the key was requested |
| `ValueError: SM4 requires 16-byte key, got N bytes` | Same as above | Same as above |
| `ValueError: Unsupported algorithm: <...>` | The low-level cipher received an unknown algorithm | Use `AES` or `SM4` |
| `FileNotFoundError: Source file not found: <path>` | The file to encrypt does not exist | Check the path |

### Command line and server

| Message | Meaning | What to do |
| --- | --- | --- |
| `Error: invalid choice '<...>'.` / `Error: unknown command '<...>'.` | A subcommand or resource name is misspelled | Run `moha -h` to see the available commands |
| `Error: no current organization selected. Run 'moha organization use <organization>' first.` | No current organization is set and the repository name had no organization prefix | Run `moha organization use organization-name` first |
| `Error: username and password cannot be empty` | The username or password was empty at login | Provide them, or log in with `--token` |
| `Error: --mine requires a saved username or --username.` | `--mine` was used but the tool does not know who you are | Log in first, or add `--username` |
| `Error: upload requires: <repo_id> <local_path> [path_in_repo]` | `moha upload` got the wrong number of arguments | Write them in the order "repository, local path" |
| `Not logged in` / `Run 'moha login' to log in.` | No login information on this machine | Run `moha login <platform-url>` |
| `Multiple pods are available. Use --pod <name> to select one.` | The Space has several running instances and the log command cannot tell which to show | Add `--pod <instance-name>` |
| `Multiple containers are available. Use --container (-c) <name> to select one.` | One instance has several containers | Add `--container <container-name>` |
| `No pods found for this Space` | The Space has no running instance | Run `moha status` first to confirm the Space is online |
| `Pod not found: <name>` | The instance name given to `--pod` is wrong | Use `moha status` to find the real instance names |
| `RevisionNotFound` | The mirror endpoint cannot find this branch or tag | Run `moha refs organization/repository` to see the available references |
| `EntryNotFound` | The mirror endpoint cannot find this file or path | Check the file name, or list the directory first |
| `Error: AI API URL is not configured.` | The AI assistant was called before `moha ai-config` was ever run | Run `moha ai-config` first to set the API address and key |

## Patterns you can copy directly

### Pattern 1: layered catching with a different message per error

```python
from xiaoshiai_hub import (
    AuthenticationError,
    HubException,
    RepositoryNotFoundError,
    moha_hub_download,
)
from xiaoshiai_hub.exceptions import HTTPError

try:
    path = moha_hub_download(repo_id="ai-lab/qwen2-7b", filename="config.json")
except RepositoryNotFoundError:
    print("Repository missing or no permission; check the organization and repository names")
except AuthenticationError:
    print("Authentication failed; check the access token")
except HTTPError as e:
    print(f"Request failed (status {e.status_code}): {e}")
except HubException as e:
    print(f"Other SDK error: {e}")
```

### Pattern 2: retry on network blips

```python
import time

from xiaoshiai_hub import HubException, moha_hub_download

def download_with_retry(repo_id, filename, max_retries=3):
    for attempt in range(max_retries):
        try:
            return moha_hub_download(repo_id=repo_id, filename=filename)
        except HubException:
            if attempt == max_retries - 1:
                raise
            wait = 2 ** attempt          # 2, 4, ... seconds
            print(f"Attempt {attempt + 1} failed, retrying in {wait} seconds")
            time.sleep(wait)
```

:::warning Sort out the error type before retrying
Retrying authentication failures or missing repositories a hundred times will not help. Only retry network errors (an `HTTPError` whose message contains `Request failed`); for parameter or permission problems, fix the configuration instead.
:::

### Pattern 3: turn on detailed logs to locate a problem

```python
import logging

logging.basicConfig(level=logging.INFO)
logging.getLogger("xiaoshiai_hub").setLevel(logging.DEBUG)
```

On the command line, add `-v` for basic diagnostics and `-vvv` for more detail (including redacted request information). `-v` goes before the subcommand, for example `moha -vvv download ai-lab/qwen2-7b`. Passwords, tokens, and file content are redacted in the logs.

## FAQ

### Where is the login information stored?

After a command line login, the token, platform address, username, and current organization are stored in `~/.moha/config.json`. Older versions may leave a `~/.moha/token.json` behind, which is cleaned up after a successful login.

### How do I log out and clear the local token?

```bash
moha logout
```

This deletes the saved token but leaves other configuration alone. To clear everything, delete `~/.moha/config.json` by hand.

### How do I confirm who I am logged in as and which platform I am connected to?

```bash
moha whoami
```

### How do I use a proxy?

The `HTTP_PROXY` / `HTTPS_PROXY` environment variables work for both the SDK and the command line:

```bash
export HTTPS_PROXY="http://proxy.example.com:8080"
```

### What if a large download is interrupted?

The SDK does not support resuming, so a rerun starts from the beginning. For genuinely large files, use `snapshot_download(..., allow_patterns=[...])` to fetch only what you need, or split the work into single-file downloads. See [Upload, download and synchronization](./transfer).

### How do I download several files concurrently?

The SDK has no built-in concurrency; use a thread pool to call `moha_hub_download()` yourself. See [Upload, download and synchronization](./transfer) for an example.
