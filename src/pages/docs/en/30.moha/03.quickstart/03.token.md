# Access Tokens

An **access token** is a long string of characters whose job is to **replace your password** and prove who you are. The command line, Git and the SDK cannot use the signed-in state of a browser, so they use the token instead.

:::tip What a token is like

Think of it as an **access card**: you in person (the browser session) can already walk in, but a machine (the command line) has no hands and can only swipe a card. If the card is lost, report it immediately — whoever picks it up can walk into your repositories.

:::

## Before you start

- You are signed in and can enter Moha.

![Where the access token actually is: click **Access token** in the left column of the home page, then the copy icon in the box](/assets/screenshots/moha/token-01.png)

The page has a fixed address, so bookmarking it beats hunting through the home page every time. One click on the copy icon puts the whole string on the clipboard with no confirmation toast, so paste it once to check before moving on.

## Find and copy the token

1. Click **Home** in the top navigation.
2. Click **Access Tokens** in the left menu.
3. The page shows the current token; click the copy icon to its right to copy it.
4. Paste it somewhere safe, such as a password manager.

Moha only shows **the token for the current session**. There is no interface to create several tokens or to divide permissions by purpose — what you copy is the token you are using right now.

## Why the command line must use a token to download private repositories

- A **public** repository can be pulled by anyone; no identity is needed.
- An **internal** or **private** repository can only be pulled by you or your organization's members, so the command line must present a token to prove it is allowed.

If you try to pull a private repository without a token, the command line reports "no permission" or asks for a password — in that case **enter the token as the password**.

## What the token is allowed to do

The token has no permission scopes to tick. It **fully inherits your account's permissions**:

| The token can | Description |
| --- | --- |
| Download repositories you can reach | Public, internal or private, depending on what your account can see |
| Upload to repositories you can write to | The same scope as manually uploading after signing in |
| Call Moha-related APIs | Used by the command line and the SDK |

| The token cannot | Description |
| --- | --- |
| Go beyond your rights | A private repository your account cannot see stays invisible to the token |
| Last forever | After you sign out or the session expires, the old token is void immediately |

:::warning There is no "read-only" option for a token

Because it matches your account permissions exactly, you cannot lower the risk by narrowing its scope. The only way is to **keep it safe**: do not commit it to a code repository, do not post it in chat groups, and do not leave it in screenshots.

:::

## Use the token from the command line

Install the command-line tool and sign in once; the token is saved in a local config file and is not asked for again:

```bash
pip install moha-hub
moha login https://<platform-address> --token <your-access-token>
```

After a successful sign-in, run `moha whoami` to see the login status. You can also skip the config file and pass it in temporarily with an environment variable:

```bash
export MOHA_TOKEN="<your-access-token>"
```

## Use the token with Git

When you download a private repository, Git asks for a username and password — enter the token as the password. You can also put it straight into the URL:

```bash
git clone https://<username>:<access-token>@<platform-address>/moha/<organization>/models/<repository>.git
```

To avoid typing it repeatedly, cache the credential temporarily:

```bash
git config --global credential.helper 'cache --timeout=3600'
```

:::warning Do not use store

`credential.helper store` writes the token to a file on disk in plain text, which is very dangerous on a shared computer or server. Prefer `cache`, or simply type it in each time.

:::

## Use the token with the SDK

```python
from xiaoshiai_hub import snapshot_download

repo_path = snapshot_download(
    repo_id="ai-lab/qwen2-7b",
    repo_type="models",
    token="<your-access-token>",
)
print(repo_path)
```

## If the token is lost or leaked

1. **Sign out immediately**: click the avatar in the top-right corner and click **Sign out** at the bottom of the panel. The old token becomes invalid at once.
2. **Sign in again**: sign in with your username and password, then copy a fresh token from the Access Tokens page.
3. **Check for activity**: if you pasted the token somewhere public, confirm that your repositories have not been changed by looking at their commit history.
4. **Change your password**: if you are not sure how the token leaked, change your password in Settings as well, see [Account Settings](/moha/quickstart/account).
