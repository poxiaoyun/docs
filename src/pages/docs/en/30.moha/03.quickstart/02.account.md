# Account Settings

Moha has no separate "account settings" page. Your account, password, email and phone are all managed in **Personal settings**, which you open from the avatar in the top-right corner. This page explains what each of its four tabs is for, and how Moha's **access token** differs from the platform's **API Key** — those two are the easiest to mix up.

## Concepts

| Term | Plain explanation |
| --- | --- |
| Personal settings | Everything about you as a person: avatar, nickname, email, phone, password, keys and interface preferences |
| Access token | The pass the command line and Git use to prove who you are; copied from the Moha home page |
| API Key | The key used to call model inference APIs; generated under **Access keys** in Personal settings |
| SSH key | A public/private key pair that lets Git pull and push without a password; the public half is stored under **Access keys** |

:::tip Personal settings and the organization are two layers
Personal settings are about **you** and apply across the whole platform. The tenant (organization) in the left column or the avatar panel is about the **team**: switching organizations changes which data you see, not which account you are.
:::

## Before you start

- You are signed in to the platform and can see the avatar in the top-right corner.
- To change your password, have the current one at hand; to enable MFA, install an authenticator app on your phone first.

## Opening Personal settings

1. Click the **avatar** in the top-right corner.
2. In the panel that slides out on the right, click **Personal settings**.
3. The page title reads **Personal settings**, with a row of tabs below it — click a tab to switch.

![Opening Personal settings: click the avatar at the top right and choose Personal settings from the panel](/assets/screenshots/moha/avatar-menu-01.png)

The avatar panel also has two handy buttons: **Switch tenant** (move to another organization) and **Sign out** (leave the current account). **Home** in the same panel only returns to the home page — do not confuse it with **Personal settings**.

## What the four tabs do

| Tab | What you can do |
| --- | --- |
| **General** | Change your avatar; view the username (read-only); change the nickname; add or change your email and mobile number |
| **Security** | Change the password (old password plus the new one twice); turn on multi-factor authentication |
| **Access keys** | Generate and manage the API Key; add, view and delete SSH public keys |
| **Preferences** | Switch **Appearance mode** (light / dark and so on), **Color** and **Language preference** |

![Personal settings page: title Personal settings, four tabs General / Security / Access keys / Preferences, currently on General, showing avatar, username, nickname, email and mobile rows](/assets/screenshots/moha/account-settings-01.png)

## Changing your avatar, nickname, email and mobile number

1. Open **General**.
2. Avatar: click the avatar area and upload an image from your machine (up to 3 MB).
3. Nickname: click **Change** on the **Nickname** row, enter the new one and click **Save**.
4. Email or mobile: click **Change** on the matching row (the button reads **Add** before anything is bound) and complete the verification.
5. The username cannot be changed; an unbound email or mobile number shows **Not added**.

## Changing your password and enabling MFA

### Changing the password

1. Open **Security** and find the **Password** row under **Password and authentication**.
2. Click **Change password** on its right (an account with no password yet shows **Set password**) to open the dialog.
3. Fill in **Old password** (only needed when you already have one), **New password** and **Confirm password**.
4. Click **Save**.

The password rules are configured by the platform — **follow the hints under the password field** (typically a minimum length, upper and lower case plus digits, and a special character). If the two entries differ, the form reports a password mismatch.

### Enabling MFA

1. Under **Password and authentication** in **Security**, find **Multi-factor authentication**; its status chip reads **Not enabled**.
2. Click **Set up authenticator** and enter the code the authenticator app on your phone generates to finish binding.
3. On success the dialog switches to the **Recovery Code** screen and lists **several** recovery codes, each with a copy button.
4. Copy and store every code, then click **I saved my recovery codes; continue** — only then is this step finished.
5. The status chip then reads **Enabled** and the button becomes **Change authenticator**. From then on, signing in needs both the password and the code the app generates.

:::warning Recovery codes appear only on this screen
If you lose your phone or cannot use the authenticator app, **the recovery codes are the only way in**. Closing this dialog does not show the same codes again, so copy them somewhere safe while it is open.
:::

:::warning Rebind the authenticator before changing phones
The authenticator app lives on your phone. Before changing phones or uninstalling the app, click **Change authenticator** under **Security** and scan the new QR code on the new phone, then enter the code it generates; otherwise losing the old phone may lock you out.
:::

## Managing access keys

The **Access keys** tab holds two blocks: **API Key** and **SSH key**.

### API Key

An account keeps only **one** API Key.

1. Open **Access keys** and find the **API Key** block (described as "Access services through the API").
2. Click **Generate**, confirm, and you get an Access Key and a Secret Key.
3. Once a key exists the button becomes **Regenerate**: it **immediately replaces** the current key and the old one stops working.

:::warning The Secret Key is shown only once
The Secret Key you get at generation time **appears only this one time**. Copy and save it immediately; once you close the dialog it is gone and you can only regenerate.
:::

### SSH key

1. In the **SSH key** block click **Add SSH key**.
2. Enter a **name** that identifies this machine.
3. Paste the public key: pick an existing key, or paste one complete single-line OpenSSH public key.
4. Click **Add**. The list shows the name and creation time; use delete to remove one.

:::tip How to find your SSH public key
The public key usually lives at `~/.ssh/id_rsa.pub` or `~/.ssh/id_ed25519.pub`. Open it in a text editor and copy the whole line — **do not paste the private key** (the file without the `.pub` suffix).
:::

## Switching to another organization

1. Click the **avatar** in the top-right corner.
2. Click **Switch tenant**.
3. On the **Select your tenant** page, select the target organization and click **Enter Platform**.
4. If the organization is not listed, click **Create Tenant** to make one yourself.

## An access token is not an API Key

Both are called "keys", but they are used for completely different things — do not mix them up:

| Name | Where it lives | What it is for |
| --- | --- | --- |
| Access token | Moha **Home → left column → Access Tokens** | Command-line uploads and downloads, Git pull/push, SDK authentication |
| API Key | Personal settings → **Access keys** | Calling model inference APIs (the AI capabilities) |

For downloading and uploading models and datasets in Moha you use the **access token**, see [Access Tokens](/moha/quickstart/token).

## Confirming the result

- After changing the nickname, email or mobile number, **General** shows the new value immediately; anything never bound shows **Not added**. Saving shows **no** "Updated" toast — the dialog closing and the value changing is the confirmation.
- If you see "Changes saved, but refreshing the current session failed: …", the data really was saved and only the page is stale; use the retry offered in that message and **do not submit again**.
- After saving a new password, the next sign-in must use it.
- After enabling MFA, the status chip on that row in **Security** switches to **Enabled**.
- After adding an SSH key it appears in the list with its name and creation time.
