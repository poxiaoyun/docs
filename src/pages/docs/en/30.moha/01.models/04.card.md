# Model Cards

The model card is the **introduction page** of a model detail page — the one you see by default when you open a repository (the tab is called **Model card**). The body is on the left, and an overview column sits on the right.

Whether other people download and trust your model is mostly decided on this page. Writing a good body is the most worthwhile step after uploading.

## Where the body comes from

The body is the `README.md` at the repository root. Change that file and the card changes with it.

1. Open the model repository and click the **File** tab.
2. Find `README.md` in the list and click the edit icon at the end of its row.
3. Write the content in Markdown, fill in the **Commit Message**, and commit.
4. Go back to the **Model card** tab to see the updated card.

If there is no `README.md` yet, click **Add files** on the **File** page, choose **Create file**, and use `README.md` as the file name.

:::info
Online editing supports text files up to 2 MiB only. If the README is large, or you prefer your own editor, push `README.md` with Git or the SDK, see [Upload Models](/moha/models/upload).
:::

:::tip The README can reference images in the repository
Use a relative path to a file in the same repository, for example `![result](images/demo.png)`, and the platform rewrites it into a reachable URL for you.
:::

## What is in the right-hand column

The right-hand blocks are **generated automatically from the repository information**. A block only appears when the matching information exists, so you never configure it by hand.

| Block | Appears when | What is inside |
| --- | --- | --- |
| User Rating / Download Count | Always | Average score, number of participants, total downloads |
| Safetensors | Model statistics were detected | Model size and tensor types; also a chat template when `chat_template.jinja` exists at the repository root |
| Recommendation | The platform marked a recommendation | Recommendation index and reason |
| Genealogy | A base model or derivative relationship is declared | Upstream base models and downstream derivatives, which you can expand |
| Datasets used to train / Spaces using this model | Always | The datasets this model used and the Spaces that reference it |
| Hardware requirements | Model resources | The accelerators, VRAM and other requirements to run it |

## About rating

- Rating is one to five stars; one click is enough.
- Once someone has rated, the stars become read-only and cannot be changed.
- Hover over the rating count to see how many people took part.

## Tips for a good model card

Cover these parts in the README and readers will understand it immediately:

- **What the model does**: task type and suitable scenarios.
- **How to use it**: a minimal working loading example.
- **Training data and method**: what data was used and how it was trained.
- **Evaluation results**: what score on which dataset.
- **Limitations and caveats**: what it is not good at and what risks exist.
- **License**: how others are allowed to use it.

:::tip Fill in the metadata too
The right-hand blocks and the model hub filters both depend on the license, category, framework and tags you set when creating the repository.
You can complete them on the **Settings** tab.
:::
