# Model Cards

The repository detail page opens on the **Model Card** (`content`) tab. It is composed of a README area and a right-hand info column whose blocks appear based on resource type and metadata.

## Page structure

| Area | Block | Condition |
| --- | --- | --- |
| Left | README rendering | Always |
| Right | Rating and download stats | Non-image resources |
| Right | Safetensors info | Safetensors stats exist |
| Right | Recommendation | `RECOMMEND_COMMENT` annotation exists |
| Right | Genealogy (model family) | Model, with `genealogy.parents` or `genealogy.children` |
| Right | Training relations / Used by Spaces | Model or dataset |
| Right | Hardware requirements | Model |

## README

The root `README.md` is rendered as the card body. Relative image/video/attachment links are rewritten to the repository `resolve` API, so the README can reference files inside the repository. Images without a README show an empty state.

## Rating and download stats

| Field | Annotation key | Description |
| --- | --- | --- |
| User rating | `RECOMMEND_RATE_COUNT` | Average score; read-only once rated |
| Downloads | `RECOMMEND_DOWNLOAD_COUNT` | Formatted with `fNumber` |

## Safetensors info

- `model_size`: model size
- `tensor_type`: tensor types
- `chat_template`: appears when `chat_template.jinja` exists at the repository root; opens a read-only drawer (handlebars).

A `partial` Safetensors status is flagged.

## Recommendation

Shown when `RECOMMEND_COMMENT` exists, together with the recommendation score (`RECOMMEND_SCORE`).

## Genealogy

Model only. Renders parents/children from `genealogy` as a tree.

## Training relations and Used by Spaces

| Component | Description |
| --- | --- |
| TrainingRelations | Models see datasets and vice versa |
| UsedBySpaces | Spaces that reference the resource |

Clicking opens a right drawer with `datasets` / `models` / `spaces` tabs.

## Hardware requirements

Model only; rendered from model metadata.

## Authoring tips

- Write the README in Markdown with a clear structure.
- Include intro, training data and method, usage examples, evaluation, limitations and license.
- Fill in metadata (license, task, framework, tags) — the right column and filters depend on it.

> 💡 Tip: All right-hand blocks are metadata driven; they only appear when the corresponding fields exist.
