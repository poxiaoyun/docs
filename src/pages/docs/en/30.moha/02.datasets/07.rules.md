# Dataset File Rules

This page is the **pre-flight checklist** for uploading. The platform's limits are hard limits, and anything over them is rejected outright; the advice below saves you from common mistakes.

## Naming rules

| Item | Rule | Example |
| --- | --- | --- |
| Repository name | Must start with a letter or digit, and may contain letters, digits, `.`, `_` and `-` | `chinese-qa-v2` |
| Repository ID | Must start with a lowercase letter and may contain only lowercase letters, digits and hyphens; **cannot be changed after creation** | `chinese-qa-v2` |
| File / folder name | Cannot be empty or only spaces, cannot contain control characters, and is at most 255 bytes | `train-2026-01.parquet` |
| File path | A relative path from the repository root, at most 1024 bytes in total | `train/part-0001.parquet` |
| Reserved names | You cannot create a `.git` directory, and you cannot commit `.gitattributes` or `.gitmodules` | — |

:::info
Avoid non-ASCII characters, spaces and slashes in names, or the commit reports a format error.
:::

## Size and count limits

| Limit | Value | What happens if you exceed it |
| --- | --- | --- |
| Files per web upload | 100 | You are told the file count exceeds 100 and to use the Moha SDK |
| Total size per web upload | 100 MiB | You are told the total size exceeds 100 MB and to use the Moha SDK |
| Single file through plain Git (not LFS) | 5 MB | The push is rejected with a message to use Git LFS or the Moha SDK |
| Online create / edit text file | 2 MiB | You must upload the file or use the SDK instead |
| Commit message | Required, first line at most 200 characters | You cannot submit |

:::warning Large files must go through Git LFS
Committing a new file larger than 5 MB with plain Git is rejected by the server. This is not a network problem, it is a hard platform limit.
Run something like `git lfs track "*.parquet"` to register the files first, then `git add`; or simply use the SDK to upload.
:::

:::tip Page messages win
A platform administrator can configure a stricter upload limit for a particular repository. If the limit shown on the page differs from this page, follow the page.
:::

## Suggested directory layout

Split directories by purpose so anyone can understand it at a glance:

```text
chinese-qa/
├── README.md            # Dataset description, rendered as the introduction page
├── train/
│   └── part-0001.parquet
├── validation/
│   └── part-0001.parquet
└── test/
    └── part-0001.parquet
```

- Use lowercase English for directory names, joined with `-` or `_`.
- Include a version or date in file names, for example `train-2026-01.parquet`.
- Split large files into several smaller parts so others can download what they need.

## Content compliance

The platform checks file size, path and naming. **Whether the content itself is compliant is up to you**:

- Do not upload content that breaks the law, infringes someone's copyright, or contains malicious code.
- Do not upload other people's personal information without processing it.
- Before uploading, confirm that you have the right to distribute this data.

## Privacy and security advice

- **Anonymize personal information** before uploading: names, phone numbers, ID numbers, addresses and so on.
- Note the data source and usage restrictions in the README.
- Set sensitive data to **Private** or **Internal** visibility, never **Public**.

## Choosing a license

Fill in the license in the repository metadata to tell others how they may use this data:

| License | Meaning |
| --- | --- |
| CC BY 4.0 | Free use is allowed, as long as the source is credited |
| CC BY-SA 4.0 | Use is allowed, and derivative works must keep the same license |
| CC BY-NC 4.0 | Non-commercial use only |
| Apache 2.0 | A permissive license, suitable for code-oriented data |

## Pre-submit self-check

- [ ] The name uses only letters, digits, `-`, `_` and `.`
- [ ] Large files are registered with Git LFS, or you switched to the SDK
- [ ] The web upload stays under 100 files / 100 MiB
- [ ] Directories are split by purpose and file names carry a date or version
- [ ] Personal information is anonymized and the license is filled in
