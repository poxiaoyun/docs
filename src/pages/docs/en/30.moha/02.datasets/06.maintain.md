# Dataset Maintenance

A dataset is not done once it is uploaded. Data gets appended, mistakes get fixed, formats get adjusted. This page covers how to make those changes safely.

![A dataset's Snapshots tab: title, branch, commit message, creator and creation time, with diff / roll back / delete per row](/assets/screenshots/moha/repo-dataset-freezes-01.png)

Branches and snapshots are different things: a **branch** is a line that keeps moving, whereas a **snapshot** freezes one moment and is untouched by later commits. Rolling back lands as a new commit, so the history stays intact.

## Version management: branches plus snapshots

| Term | What it means |
| --- | --- |
| Branch | One timeline of the data. `main` is the official version; use a new branch for cleaning or experiments |
| Snapshot | A saved photo of the current state that you can return to at any time |
| Rollback | Reset a branch to the state of a snapshot |

The **Branch: xxx** button at the top left of the **File** tab switches both branches and snapshots, see [Model Versions](/moha/models/version) — datasets work the same way.

:::tip Take a snapshot before sharing
Take a snapshot before sharing the dataset with colleagues. Then they reference a fixed version, and your later changes do not affect them.
:::

## Append data

Cloning locally and pushing is recommended, because the change record is clear:

```bash
cd my-dataset
cp /path/to/new-data/*.parquet .

git add .
git commit -m "Append 2026-01 training data"
git push origin main
```

To add just one small file, you can also work in the browser: open the **File** tab, click **Add files** then **Upload files**, fill in the **Commit Message** and submit.

## Edit and delete files

On the **File** tab, hover over a row and action icons appear at the end of it:

| Icon | What it does | Note |
| --- | --- | --- |
| Edit | Change the content of a text file online | Only text files up to 2 MiB are supported |
| Delete | Remove the file from the current branch | You must type the file name to confirm |

:::warning Deleting affects the whole branch
After you delete a file, everyone viewing this branch stops seeing it. The change stays in the history, but **the file really is gone from the current branch**.
Make sure nobody else still depends on it before deleting.
:::

## Roll back a change

If newly committed data turns out to be wrong, you can undo it:

```bash
# Undo the changes of the most recent commit and create a new undo record
git revert HEAD
git push origin main
```

If you simply want to return to an earlier fixed state, the snapshot rollback on the page is more direct, see [Model Versions](/moha/models/version).

:::warning Rollback cannot be undone
A rollback resets the target branch to the snapshot's commit, and **the commit history may be rewritten**. Before rolling back, make sure nobody else is working on that branch.
:::

## Cleaning and archiving advice

- **Remove expired files**: delete them locally, then commit and push, so the repository does not fill up with data nobody uses.
- **Archive old versions**: keep data you really need on a separate branch, or pin it with a snapshot.
- **Prefer snapshots over keeping many branches**: too many branches makes switching versions confusing.

:::warning The history of large files keeps taking space
Git keeps the history of every commit, and committing large files again and again makes the repository bigger and bigger. Use a suitable format such as Parquet from the start, and periodically clean up historical large files you no longer need.
:::
