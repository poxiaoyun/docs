# Dataset card

The dataset card is the **introduction page** of a dataset detail page — the one you see by default when you open a repository (the tab is called **Dataset card**). The body is on the left, and an overview column sits on the right.

When people do not know your data, this page is what they use to decide whether to use it. Ten minutes of writing saves a lot of back-and-forth questions.

## Where the body comes from

The body is the `README.md` at the repository root. Change that file and the card changes with it.

1. Open the dataset repository and click the **File** tab.
2. Find `README.md` in the list and click the edit icon at the end of its row.
3. Write the content in Markdown, fill in the **Commit Message**, and commit.
4. Go back to the **Dataset card** tab to see the updated card.

If there is no `README.md` yet, click **Add files** on the **File** page, choose **Create file**, and use `README.md` as the file name.

:::info
Online editing supports text files up to 2 MiB only. If the README is large, push it with Git or the SDK, see [Upload Datasets](/moha/datasets/upload).
:::

:::tip The README can reference images in the repository
Use a relative path to a file in the same repository, for example `![field sample](images/sample.png)`, and the platform rewrites it into a reachable URL.
When you switch branch or snapshot, these references follow the same version.
:::

## What is in the right-hand column

The right-hand blocks are **generated automatically from the repository information**. A block only appears when the matching information exists, so you never configure it by hand.

| Block | Appears when | What is inside |
| --- | --- | --- |
| User Rating / Download Count | Always | Average score, number of participants, total downloads |
| Recommendation | The platform marked a recommendation | Recommendation index and reason |
| Datasets used to train / Spaces using this dataset | Always | The models trained on this dataset and the Spaces that reference it |

Datasets never show a Genealogy or Hardware requirements block; those appear only in model repositories.

## About rating

- Rating is one to five stars; one click is enough.
- Once someone has rated, the stars become read-only and cannot be changed.

## Tips for a good dataset card

It is best to structure the README like this:

```markdown
# Dataset name

## Overview
What this data is for and where it came from.

## Contents
- Size: 100,000 rows
- Format: JSONL
- Language: Chinese
- Quality level: Silver

## Fields
| Field | Type | Description |
| --- | --- | --- |
| text | string | Raw text |
| label | int | Class label |

## Usage
A one-line loading example, or the recommended processing flow.

## Limitations and caveats
What it is not suitable for, and whether it contains sensitive content.

## License
How others are allowed to use this data.
```

:::tip Fill in the metadata too
The right-hand blocks and the dataset hub filters both depend on the category, industry, language and quality level you set when creating the repository.
You can complete them on the **Settings** tab.
:::
