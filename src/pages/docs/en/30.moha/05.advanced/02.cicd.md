# CI/CD Workflows

Put actions like "upload artefacts to Moha the moment code is pushed" or "pull a given model before deploying" into your pipeline, so Moha works together with your code repository. This page gives configurations you can copy directly — just replace the placeholders with your own values.

## Before you start

- An **access token dedicated to the pipeline**, created on the [Access Tokens](/moha/quickstart/token) page. Use a dedicated account and keep its permissions as small as possible.
- Know your **console address**, **organization name** and the **repository names** you will work with.
- The pipeline environment must be able to install Python 3.10 or later.

## Step 1: Put the token into the pipeline's secret store

1. Create the access token.
2. Save it as a secret in your CI platform (GitHub Actions, GitLab CI, and so on), for example `MOHA_TOKEN`.
3. Reference it as a variable in your configuration. **Do not** write the token in plain text into the YAML.

:::warning A leaked token means a hijacked account

Once a token is written into a config file, committed to a repository or printed into build logs, anyone who can see it can operate your repositories. Keep it only in a secret, and regenerate it immediately if it leaks.

:::

## Option 1: Use the `moha` command line

### Sign in and select an organization

Run a login once at the start of each pipeline, and later commands no longer need the token:

```bash
pip install "moha-hub[upload]"
moha login "https://<your-console-address>" --token "$MOHA_TOKEN"
moha org use "<your-organization>"
```

Expected result: `moha whoami` shows the signed-in user, and in `moha org list` the current organization is marked with a `*`.

### Upload artefacts

```bash
moha upload <organization>/<repository> ./dist \
  --revision main \
  --message "publish ${GITHUB_SHA}" \
  --exclude ".git*" \
  --exclude "*.log"
```

Expected result: the command finishes with one commit record, and the new files appear on the repository's **File** tab.

Common options:

| Option | Effect |
| --- | --- |
| `--revision` / `-r` | Which branch to upload to; defaults to `main` |
| `--message` / `-m` | The commit message |
| `--include` / `--exclude` | Upload only, or exclude, matching files; can be repeated |
| `--encrypt` | Encrypt model files before uploading (used together with `--encryption-password`) |

### Pull resources

```bash
# Fetch only the files you need — much faster
moha download <organization>/<repository> \
  --include "*.json" \
  --include "*.safetensors" \
  --local-dir ./artifacts
```

Expected result: the files appear in the `./artifacts` directory. To download a single file, use `moha download-file <organization>/<repository> <file-path>`.

### Trigger a Space restart

```bash
moha redeploy <organization>/<space-name>   # restart
moha status   <organization>/<space-name>   # check the running state
moha logs     <organization>/<space-name> -n 100   # see the last 100 log lines
```

`moha logs` also supports `--follow` / `-f` for live tracking, and `--container` / `-c` to pick a container (useful when a Space has several). To take it offline, use `moha stop`.

## Option 2: Use Git directly

Model, dataset and Space repositories are all Git repositories, so you can push files just like code:

```bash
git lfs install
git clone https://<username>:<access-token>@<your-console-address>/moha/<organization>/<type>/<repository>.git
cd <repository>
cp -r ../dist/* .
git add .
git commit -m "publish ${GITHUB_SHA}"
git push origin main
```

Here `<type>` is `models`, `datasets` or `spaces`.

:::tip Skip downloads when you do not need large files

When you only want to validate a build and do not want to pull the large LFS files, prefix the clone with `GIT_LFS_SKIP_SMUDGE=1` — it is much faster.

:::

## Full example: GitHub Actions

```yaml
name: Publish to Moha

on:
  push:
    branches: [main]

jobs:
  publish:
    runs-on: ubuntu-latest
    env:
      # All three values come from secrets / repository variables; never hard-code them
      MOHA_TOKEN: ${{ secrets.MOHA_TOKEN }}
      MOHA_ENDPOINT: https://<your-console-address>
      MOHA_ORGANIZATION: <your-organization>
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install the SDK
        run: pip install "moha-hub[upload]"

      - name: Log in to Moha
        run: moha login "$MOHA_ENDPOINT" --token "$MOHA_TOKEN"

      - name: Select the organization
        run: moha org use "$MOHA_ORGANIZATION"

      - name: Upload artefacts
        run: |
          moha upload "$MOHA_ORGANIZATION/my-model" ./dist \
            --revision main \
            --message "publish ${GITHUB_SHA}" \
            --exclude ".git*" --exclude "*.log"

      - name: Restart the Space
        run: moha redeploy "$MOHA_ORGANIZATION/my-space"
```

## Common problems

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `moha: command not found` | The SDK is not installed, or its bin directory is not on PATH | Run `pip install "moha-hub[upload]"` first, and make sure the current Python environment's bin directory is on PATH |
| Login complains about the address format | The console address is missing `https://` | The address passed to `moha login` must include the scheme |
| Upload reports a permission error | The token's account has no write access to this repository | Add that account as read/write or admin in the repository's **Settings** |
| `404` repository not found | The organization name or repository name is wrong | Confirm the repository exists first with `moha info model <organization>/<repository>` |
