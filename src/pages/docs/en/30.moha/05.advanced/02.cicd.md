# CI/CD Workflows

Moha resources are Git repositories, so pipeline integration is based on **Git push/clone** and the **SDK**. There is no dedicated CLI named `moha-cli upload`.

## Prerequisites

1. Create an API Key / SSH Key for CI in IAM (see [Account Settings](/moha/quickstart/account)).
2. Inject it as a secret (e.g. `MOHA_TOKEN`).

## Push artefacts

```yaml
name: Publish to Moha

on:
  push:
    branches: [main]

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install Git LFS
        run: git lfs install

      - name: Clone and push artifacts
        env:
          MOHA_TOKEN: ${{ secrets.MOHA_TOKEN }}
        run: |
          git clone https://ci-user:${MOHA_TOKEN}@moha.your-domain/moha/models/my-org/my-model.git target
          cd target
          cp -r ../dist/* .
          git add .
          git commit -m "publish ${GITHUB_SHA}"
          git push origin main
```

> 💡 Tip: Set `GIT_LFS_SKIP_SMUDGE=1` when cloning for validation only.

## Fetch resources

```yaml
- name: Install Moha SDK
  run: pip install moha-hub

- name: Download model
  run: moha download --repo-type models my-org/my-model
```

## Trigger a Space restart

```bash
curl -X POST -H "Authorization: Bearer ${MOHA_TOKEN}" \
  https://moha.your-domain/api/moha/organizations/my-org/spaces/my-space:restart
```

Related lifecycle endpoints: `:online`, `:restart`, `:delete`. Status and logs are available via `.../spaces/{repository}:status`, `.../pods`, `.../pods/{pod}/logs`.

## Use the HuggingFace-compatible endpoint

```bash
export HF_ENDPOINT=https://moha.your-domain/moha/huggingface
export HF_TOKEN=${MOHA_TOKEN}
```

> ⚠️ Note: Replace the host and token with your own; the permissions in CI are those of the token's account.
