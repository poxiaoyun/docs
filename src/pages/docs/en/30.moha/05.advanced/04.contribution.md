# Community Contribution

Moha has no community features such as points, badges or forums. "Contributing" comes down to something concrete: **publishing valuable content, describing it clearly, and collaborating with others inside a repository**. Do these and your model, dataset or Space can be found and used by others.

## Before you start

You need an account that can create resources. As long as you can create a model, dataset, image or Space, you can contribute following the steps below.

![The visibility block on the Settings tab: personal / tenant-only / public radio buttons, applied with Update](/assets/screenshots/moha/repo-model-setting-01.png)

You must press **Update** in this block — nothing saves automatically. Before switching to **Public**, make sure the repository holds nothing that should stay internal: once public, anyone on the internet can download it.

## 1. Make your content public

1. Open the resource you want to publish and go to the **Settings** tab.
2. In the **Visibility** card, choose **Public**.
3. Click **Update**.

Expected result: the resource appears in public lists and search results, and other accounts can browse, download and cite it without any authorization.

:::warning Check three things before going public

- Does the README explain the purpose, usage and dependencies?
- Does it contain data, keys or internal information that should not be public?
- Is a license filled in, so others can legally use it?

:::

## 2. Describe it clearly

Publishing is only half the job — being **found and understood** matters more:

| What to do | How |
| --- | --- |
| Write a README | Maintain a README at the repository root; it becomes the body of the introduction page |
| Complete the metadata | In the **Metadata** card under **Settings**, fill in the license, category, framework, tags, language and so on — these decide whether you can be found |
| Upload a cover | A Space can upload a landscape image in the **Cover** card under **Settings** to stand out in lists |

## 3. Collaborate with others

| Method | How |
| --- | --- |
| Add members | **Settings** → **Members** → **Add Member**, with the **Admin**, **Read/Write** or **Read Only** role |
| Discuss | Start topics and reply in **Discussion & Feedback** to keep questions on record |
| Pull requests | After changing files, **Create Pull Request** to have someone review and merge |
| Take a snapshot | Take a **Freeze** before releasing a stable version, so you can return to that state at any time |
| Roll back history | In the commit history, use **Revert (Preserve History)** to undo a commit, or **Reset (No History)** to discard the commits after it |

## 4. Favourites, ratings and statistics

These are the platform's "feedback signals": the more they are used, the more good content floats to the top:

| Capability | How to use it |
| --- | --- |
| Favourite | The heart button at the top right of a resource page; starred items are collected in [Liked by Me](/moha/home/liked-by-me) |
| Rating | You can rate models and datasets on their introduction page; the page shows the average and the number of participants |
| Download count | Counted automatically by the system; lists can be sorted by it |
| Featured recommendation | Whether a resource enters the Featured section is set by platform operators; there is no self-service entry on the tenant side |

:::tip Want to be recommended? Get the basics solid first

A clear README, complete metadata, standard formats and ongoing maintenance beat any trick.

:::

## Permissions at a glance

| What you want to do | What you need |
| --- | --- |
| Browse public resources | Just be signed in |
| Browse internal resources | Be a member of the same organization |
| Browse private resources | Be a repository member |
| Change settings or delete a repository | System admin, repository owner, organization admin, or a repository admin/read-write member |
| Start a discussion or open a pull request | Any signed-in user |

## Confirm it worked

- After going public, another account — or even a signed-out visitor — can open the resource.
- After the metadata is saved, filtering lists by the matching tag surfaces your resource.
