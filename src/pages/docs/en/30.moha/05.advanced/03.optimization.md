# Performance Optimization

Large models are often tens of GB, and slow downloads are usually not a network problem but a matter of **downloading far too many files you will never use** — the same model often ships `.safetensors`, `.bin` and several precision variants, so a full download is naturally slow and wastes disk. This page gives several things you can apply immediately, each with its command and the result to expect.

## Before you start

Install the SDK and sign in:

```bash
pip install moha-hub
moha login https://<your-console-address> --token <your-access-token>
moha org use <your-organization>
```

:::warning One thing to be clear about first

`moha` downloads files **one at a time, in order**, and currently offers no option to download in parallel. It also has no resume for an interrupted download, and no automatic retry. So the truly effective way to speed things up is to **download less**, not to tune a concurrency setting.

:::

## Method 1: Download only the files you need (most effective)

### List the file names explicitly

```bash
moha download <organization>/<repository> config.json tokenizer.json --local-dir ./model
```

Expected result: only those two files are downloaded into `./model`; nothing else is pulled.

### Pick files with wildcards

```bash
moha download <organization>/<repository> \
  --include "*.safetensors" \
  --include "*.json" \
  --exclude "*.bin" \
  --local-dir ./model
```

Expected result: only the weights and config files are downloaded, skipping duplicate weights such as `.bin`. Many models provide weights in two formats, and skipping one can save close to half the size.

| Option | Effect |
| --- | --- |
| `--include` | Download only matching files; can be repeated |
| `--exclude` / `--ignore` | Skip matching files; can be repeated |
| `--local-dir` / `-o` | Choose which directory to download into |

## Method 2: Download a single file

When you are just missing one file, there is no need to re-download the whole repository:

```bash
moha download-file <organization>/<repository> model.safetensors --local-dir ./model
```

Expected result: only this one file is downloaded, almost instantly.

## Method 3: Skip the large LFS files when cloning with Git

Moha repositories store large files with Git LFS. Skip them at clone time and you get a lightweight copy with only the directory structure:

```bash
GIT_LFS_SKIP_SMUDGE=1 git clone https://<your-console-address>/moha/<organization>/models/<repository>.git
cd <repository>
git lfs pull --include="*.safetensors"
```

Expected result: the clone finishes in seconds; the second command pulls only the kind of large file you actually need, leaving the rest as pointers.

:::tip When to use this

It saves the most time in a pipeline that only validates the directory structure or runs static checks, or when you need only one class of weights.

:::

## Method 4: Do not download — let the framework read on demand

If all you need is to run inference or load a dataset, you can skip landing the whole file set and let the framework fetch the shards it needs:

```bash
export HF_ENDPOINT=https://<your-console-address>/moha/huggingface
export HF_TOKEN=<your-access-token>
```

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

# The framework pulls the files it needs through HF_ENDPOINT above, not from huggingface.co
tokenizer = AutoTokenizer.from_pretrained("demo/my-model", trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained("demo/my-model", device_map="auto")
```

Expected result: files are read on demand, skipping anything irrelevant to this run (for example GPU-only weights when you infer on CPU).

## Method 5: Upload large files with the SDK

A browser upload handles at most 100 files totalling 100 MB at a time; beyond that you must switch to the command line, or wait and send it in many batches:

```bash
moha upload <organization>/<repository> ./my_model --message "upload model" --exclude "*.log"
```

Expected result: no browser limit, and a large directory goes up in one go.

## While you are at it: pick the right file formats

- Prefer `.safetensors` for weights: they load faster, and the model page can show the model size and tensor statistics directly.
- Prefer columnar or streaming formats such as Parquet and JSONL for datasets, stored with Git LFS.

These two do not affect download speed, but they affect how fast you load and read the data afterwards.

## Effect comparison

| Approach | Fits when | Roughly how much it saves |
| --- | --- | --- |
| `--include` to pull only what you need | You know which files you need | Depends, often more than half |
| `moha download-file` | You are missing only one or two files | Almost all of the time |
| `GIT_LFS_SKIP_SMUDGE=1` + on-demand `git lfs pull` | Validation only, or only some weights | The clone stage is almost instant |
| `HF_ENDPOINT` on-demand reads | Running inference or loading a dataset directly | No need to land the whole repository |
