# Performance Optimization

Moha does not ship training-side tooling such as quantization or pruning. This page covers optimizations tied to Moha capabilities: transfer, storage format and inference access.

## File transfer

| Scenario | Recommendation |
| --- | --- |
| Large uploads | Use Git LFS (`git lfs track "*.safetensors"`, ...) |
| Validation-only builds | `GIT_LFS_SKIP_SMUDGE=1 git clone <url>` |
| On-demand pull | `git lfs pull --include="*.safetensors"` |
| Bulk folder upload | Use the upload session (`uploadFolder`) |

> ⚠️ Note: Per-upload size/count limits come from the server `capabilities.limits` (`maxFiles` / `maxTotalBytes` / `maxManifestBytes` / `maxPathBytes` / `maxEditableBytes`); the frontend hardcodes no threshold.

## Storage format

- Prefer `.safetensors` for weights; the detail page shows Safetensors stats (model size, tensor types).
- Prefer Parquet / JSONL for datasets, together with Git LFS.
- When `chat_template.jinja` exists at the repository root, the model card offers a read-only viewer.

## Inference access

| Method | Description |
| --- | --- |
| Transformers | Load via `HF_ENDPOINT=https://<host>/moha/huggingface` |
| vLLM | `pip install vllm` + `vllm serve`, OpenAI-compatible API |
| SGLang | `pip install "sglang[all]"` + `python -m sglang.launch_server` |

These snippets are available in the **How to use** dialog on the model detail page.

## Space runtime

- `flavorID` selects the CPU/memory/GPU flavor.
- Saving deploy settings restarts the Space automatically.
- Use Pod logs (`.../pods/{pod}/logs`) to diagnose runtime failures.

> ⚠️ Note: Quantization, pruning and distillation are training-side techniques unrelated to Moha; refer to the framework docs.
