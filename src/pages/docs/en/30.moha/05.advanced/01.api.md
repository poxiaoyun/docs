# API Integration

Use HTTP to read and write models, datasets, Spaces and images in Moha directly. It suits writing scripts, syncing data, or wiring Moha into your own systems.

:::tip If you can use the SDK, do not hand-write HTTP

The official SDK (`moha-hub`) already wraps authentication, paging and uploads, so fewer things go wrong. Only call HTTP directly when you cannot use Python. For the SDK, see the [SDK tutorial](/moha/sdk-tutorial/quick-start).

:::

## Before you start

- An **access token**: create one on the [Access Tokens](/moha/quickstart/token) page.
- Your **console address**, the one in the browser address bar when you normally open the Moha web page.
- A tool that can send HTTP requests: `curl`, Postman, or any programming language.

## Authentication: carry the access token

Every request needs this header:

```text
Authorization: Bearer <your-access-token>
```

:::warning A token is a password

Do not put the token into a code repository, post it in chat, or print it into public logs. In CI/CD, inject it with the platform's secret feature.

:::

## Minimal runnable example

Replace the three placeholders with your own values and run this in a terminal:

```bash
# Look up the basic information of a model repository
curl -s -H "Authorization: Bearer <your-access-token>" \
  "https://<your-console-address>/moha/v1/organizations/demo/models/my-model"
```

If it returns some JSON with the repository name, visibility and metadata, both the address and the token are correct.

## How the API is organized

Every endpoint lives under `/moha/v1` and locates a repository by "organization / resource type / repository name". The resource type is `models`, `datasets`, `spaces` or `images` (plural).

| What you want to do | Method and path |
| --- | --- |
| List public resources | `GET /moha/v1/{type}` |
| List resources in an organization | `GET /moha/v1/organizations/{organization}/{type}` |
| Look up repository information | `GET /moha/v1/organizations/{organization}/{type}/{repository}` |
| List branches and tags | `GET /moha/v1/organizations/{organization}/{type}/{repository}/refs` |
| Browse a directory | `GET .../{repository}/contents/{branch}` |
| Read the contents of a file | `GET .../{repository}/contents/{branch}/{file-path}` |
| Download a file | `GET .../{repository}/resolve/{branch}/{file-path}` |

Change the resource type or repository name and the same set of paths still works.

## Upload files

Uploading over HTTP is more involved than downloading and takes three steps: first create an "upload session" declaring which files you will send, then transfer the files one by one to the addresses the session returns, and finally tell the session to finish so the server creates a single commit.

This is easy to get wrong, so **use the SDK** — its `upload_file()` / `upload_folder()` — instead, see [Upload, download and file sync](/moha/sdk-tutorial/transfer).

## Load directly with Transformers / Datasets

Point the Hugging Face address at Moha to load in code without downloading the whole repository:

```bash
export HF_ENDPOINT=https://<your-console-address>/moha/huggingface
export HF_TOKEN=<your-access-token>
```

```python
from datasets import load_dataset

# Pulls from Moha through HF_ENDPOINT above, not from huggingface.co
dataset = load_dataset("demo/my-dataset")
print(dataset)
```

## Common errors

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `401` | The token is missing or no longer valid | Check the `Authorization` header; if the token expired, create a new one |
| `403` | The token is valid but has no rights to this repository | A private repository requires you to be a member; confirm which organization your account belongs to |
| `404` | The path is wrong | Check the organization name, the resource type (must be plural) and the repository name segment by segment |
| An upload fails halfway | The file is too large or the network dropped | Use the SDK to upload instead: it streams the file in chunks and creates the commit for you, so you can simply run it again |
