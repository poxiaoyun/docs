# API Integration

Moha frontend calls live under the `/api/moha` prefix. Most resource endpoints are addressed by `organization` + `type` + `repository`.

## Authentication

Requests carry the access token via `Authorization: Bearer <token>` (see [Access Tokens](/moha/quickstart/token)).

```bash
curl -H "Authorization: Bearer <token>" \
  https://moha.your-domain/api/moha/organizations/my-org/models/my-model
```

## Endpoint groups

| Area | Typical paths |
| --- | --- |
| Lists and recommendation | `/api/moha/{type}`, `/api/moha/{type}/recommendation` |
| Personal data | `/api/moha/my-create/{type}`, `/api/moha/my-favorite/{type}`, `/api/moha/my-favorite/summary` |
| Organizations | `/api/moha/organizations`, `/api/moha/organizations/{organization}/summary` |
| Repository basics | `/api/moha/organizations/{organization}/{type}/{repository}` |
| README / files | `.../readme`, `.../raw/{ref}`, `.../resolve/{ref}`, `.../contents/{ref}` |
| Refs and commits | `.../refs`, `.../commits/{ref}`, `.../commit/{ref}/diff`, `.../refs/{ref}:reset`, `.../refs/{ref}:revert` |
| Freezes | `.../freezes`, `.../freezes/{id}`, `.../freezes/{id}/diff`, `.../freezes/{id}:rollback` |
| Discussion / PR | `.../discussion`, `.../discussion/{name}`, `.../{name}:close|:open|:merge`, `.../discussion/{name}/diff` |
| Favourite | `.../favorite` (GET status / POST update) |
| Members | `/api/moha/organizations/{organization}/members`, `.../{type}/{repository}/members` |
| Upload sessions | `/moha/{organization}/{type}/{repository}/api/upload-sessions[/capabilities|/{id}|/{id}:finalize]` |
| Space lifecycle | `.../spaces/{repository}:online|:restart|:delete`, `.../{repository}/pods`, `.../pods/{pod}/logs` |
| Space deploy options | `/api/moha/organizations/{organization}/clusters`, `.../clusters/{cluster}/workspaces`, `.../flavors`, `.../products` |

> ⚠️ Note: The table reflects paths used by the frontend (`src/services/moha.ts`). Request/response schemas follow the backend contract and are not confirmed here.

## Create and update

- Create: `POST /api/moha/organizations/{organization}/{type}`.
- Update: `PUT /api/moha/organizations/{organization}/{type}/{name}`.
- Delete: `DELETE /api/moha/organizations/{organization}/{type}/{name}`.

The create body includes `name`, `alias`, `description`, `organization`, `visibility`, `metadata`, `members`; models may also include `requestgenealogy` (`baseModel` + `relationship`).

## Upload sessions

1. `GET .../api/upload-sessions/capabilities` for capabilities and limits.
2. `POST .../api/upload-sessions` to initialise (with `Idempotency-Key`).
3. Upload files, then `POST .../api/upload-sessions/{sessionId}:finalize`.

## SDK and compatible endpoint

The SDK package is `moha-hub` (Python module `xiaoshiai_hub`):

```bash
pip install moha-hub
moha download --repo-type models my-org/my-model
```

```python
from xiaoshiai_hub import snapshot_download

snapshot_download(
    repo_id="my-org/my-model",
    repo_type="models",
    username="your-username",
    password="<token>",
)
```

For Transformers / Datasets, configure the compatible endpoint:

```bash
export HF_ENDPOINT=https://moha.your-domain/moha/huggingface
export HF_TOKEN=<token>
```

> ⚠️ Note: SDK options such as `HubClient`, `MOHA_ENDPOINT` and `base_url` are not part of this frontend repo; their semantics are unconfirmed here.
