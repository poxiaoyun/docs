# Repository Settings & Publishing

The settings page maintains repository attributes and collaboration permissions. Cards differ by resource type and follow the implementation order.

## Who can see the settings tab

At least one of:

- System administrator
- Repository owner (`data.owner === user.name`)
- Organization admin (org member `role === 'admin'`)
- Repository member with role `admin` or `readwrite`

## Settings cards

| Order | Card | Applies to | Description |
| --- | --- | --- | --- |
| 1 | Visibility | All | Switch between `public` / `internal` / `private` |
| 2 | Alias | All | Update the display name |
| 3 | Members | All | Manage repository members and roles |
| 4a | Metadata (data) | Models / datasets | License, tasks, frameworks, tags, language |
| 4b | Metadata (image) | Images | Image metadata |
| 4c | Metadata (code) | Spaces | `license` / `domain` / `scene` |
| 4d | Cover | Spaces / images | Upload or change the cover image |
| 4e | README | Images | Edit the image README |
| 5 | Deploy | Spaces | Deployment parameters |
| 6 | Delete | All | Delete the repository |

## About "publishing"

Moha has no separate "publish / submit for review" button: making a resource public means **setting its visibility to `public`**. Whether a manual review is required is managed on the BOSS side; the tenant settings page offers no review entry.

> 💡 Tip: BOSS provides a review page at `/boss/moha/audit` (`src/pages/boss/moha/audit`), plus `/boss/moha/:type` to create/edit data managers and `/boss/moha/mirrors` for mirror sources. The tenant side only sets visibility.

## Space deployment

- Saving deploy parameters calls `updateDataManager` and then automatically restarts the Space (`restartSpace`).
- You therefore do not need to click restart manually after changing deploy settings.

> ⚠️ Note: Settings directly affect visibility and collaboration permissions; keep them with the repository owner or an administrator.
