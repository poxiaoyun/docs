# Repository Settings & Publishing

The **Settings** tab is the repository's admin console: it controls who can see it, which colleagues can change it, and the extra information that makes it searchable; for Spaces it also carries the cover, deploy settings and schedule, and at the very bottom there is delete. Different resource types show slightly different cards, and the card order is fixed.

## Before you start

Only people who meet at least one of these conditions can see the **Settings** tab:

- a system administrator;
- the owner of this repository;
- an administrator of the organization that owns this repository;
- someone added to this repository with the **Admin** role (models, datasets and images also accept **Read/Write**).

## Card overview

From top to bottom the page shows these cards:

| Card | Shown for | What you can do |
| --- | --- | --- |
| **Visibility** | All | Click **Change visibility** to switch between Public / Internal / Private |
| **Basic Info** | All | Change the alias and description |
| **Members** | All | Add people, change roles, remove people |
| **Metadata** | All (different content) | Fill in license, classification, tags and other searchable information |
| **Readme** | Images | Edit the image's description text |
| **Cover** | Spaces | Upload or replace the cover image |
| **Deploy Config** | Spaces | Change the runtime flavor and environment variables |
| **Scheduled running** | Spaces | Run the Space only within a chosen time window |
| **Delete …** | All | Delete the whole repository |

![Visibility card on Settings: Visibility / Current fields plus a Change visibility button, and the dialog with Public / Internal / Private and Confirm change](/assets/screenshots/moha/repo-setting-01.png)

The visibility card does not show a radio group — it only shows **Visibility**, the **Current** value and a **Change visibility** button. Every change goes through a confirmation dialog.

## Changing visibility

1. Click **Change visibility** in the **Visibility** card.
2. The dialog title reads "Set the visibility of XXX to YYY". Pick the target level.

| Option | Who can see it | What the dialog says |
| --- | --- | --- |
| **Public** | Anyone, including signed-out visitors | Anyone can view this resource; write access still follows the repository permission rules |
| **Internal** | Members of the organization that owns it | Access is limited to the owning organization and still follows the repository permission rules |
| **Private** | Repository members and individually authorized people | The resource is no longer public or open to the whole organization; access follows repository members and permission rules |

3. Click **Confirm change** to submit.

All three levels can be switched back and forth; nothing is locked once chosen. After the resource becomes **Public**, anyone — including signed-out visitors — can view its visible content.

:::tip There is no separate publish button
The platform has no separate "publish" or "submit for review" button — setting visibility to **Public** is how you publish. Whether manual review is needed is handled by the platform administrators; this page offers no review entry.
:::

## Changing the alias and description

1. Fill in **Alias** in the **Basic Info** card; this is the name shown on the page.
2. Fill in **Description** with a short explanation of what the resource is for.
3. Click **Update**.

## Managing members

1. Click **Add Member** in the **Members** card.
2. Type or pick a member of the organization in **Username**.
3. Choose a **Role**:

| Role | Permission |
| --- | --- |
| **Admin** | Can manage members and has read/write access |
| **Read/Write** | Has read/write access |
| **Read Only** | Has read-only access |

4. Click **Confirm**.

Members you have already added appear in the list together with their **join time**. Click the pencil icon to change a role and the trash icon to remove someone. You cannot change or remove yourself.

## Filling in metadata

Metadata decides whether your resource can be found and recommended, so it is worth filling in carefully. Different resource types ask for different things:

| Resource | Main fields |
| --- | --- |
| Models | License, Classification, Industry / business domain, Use cases, Frameworks, Languages, Hardware backends, Minimum VRAM (GiB), Custom tags |
| Datasets | Industry / business domain, Project stage, Languages, Text types, Data quality level, Acquisition methods, Tags |
| Images | Classification, Accelerator framework |
| Spaces | License, Domain, Scene |

Limits: each dimension supports up to 30 values, a single tag must be 32 characters or fewer, and a single value must be 128 characters or fewer. Click **Update** when you are done.

## Editing an image's readme

The **Readme** card of an image maps to the Markdown body shown on the image detail page. Edit it directly in the card and click **Update**.

![An image repository's Settings tab: visibility, basic info, members, metadata and readme](/assets/screenshots/moha/repo-image-setting-01.png)

## Changing a Space's cover

1. Click **Upload Cover** in the **Cover** card and choose a local image.
2. Static images are cropped to a 20:9 landscape image; GIF, APNG, animated WebP/AVIF and animated SVG keep their animation.
3. Click **Update**.

The supported formats are jpg, png, apng, webp, gif, avif and svg, and the image may be at most 5 MB.

![A Space repository's Settings tab: visibility, basic info, members, metadata and cover, with role and join time in the member list](/assets/screenshots/moha/repo-space-setting-01.png)

## Changing a Space's deploy config

A Space's **Deploy Config** card lives right here on the Settings tab; you do not need to go back through the creation flow.

1. In the **Deploy Config** card, set **Flavor** (how much CPU / memory / accelerator the Space gets) and **Environment Variables** (a key plus a value; you can add as many pairs as you need).
2. Click **Update**.

**Product SDK** and **Deploy Workspace** are decided when the Space is created and are read-only afterwards. After you save the deploy config the system **automatically republishes** the Space, so you do not have to click **Republish** yourself.

:::info Saving the config is a republish
Saving the deploy config triggers a republish, so the Space is briefly unavailable. If the Space is in active use, warn its users before changing it during peak hours.
:::

## Scheduled running (Spaces only)

The **Scheduled running** card keeps a Space running only within a chosen window and scales replicas to zero outside it, saving idle compute.

1. Turn on **Enable scheduled running**.
2. Choose a **Schedule mode**:

| Mode | What else you fill in |
| --- | --- |
| **Every day** | Start time, end time |
| **Selected weekdays** | **Run on** (multiple weekdays allowed, for example Monday and Wednesday), start time, end time |
| **Run once** | Start date, end date, start time, end time |

3. Fill in the **Time zone** using an IANA name such as `Asia/Shanghai` or `UTC`.
4. Save to apply. A Space that has not been deployed yet applies the schedule on its next deployment.

:::tip Overnight windows
When the end time is earlier than the start time, the Space runs until that time on the following day. `22:00` to `02:00`, for example, means it runs from 10 pm to 2 am the next morning.
:::

## Deleting a repository

1. Scroll to the very bottom and, in the **Delete Models / Delete Datasets / Delete Images / Delete Spaces** card, type the repository name **exactly as it is** into the box.
2. Once the name matches exactly, the **Confirm** button becomes clickable.
3. Click **Confirm** to finish.

:::warning Deletion cannot be undone
Deleting **permanently removes the resource and all of its associated files and resources** and cannot be recovered. Before deleting, make sure the data is backed up or create a snapshot for the record.
:::

## Confirming the result

- After every **Update**, an **Updated successfully** message appears above the card.
- After changing visibility, the **Current** value on the card switches to the new level immediately; go back to the list page to confirm the resource appears in the expected scope.
- After saving the deploy config, the Space's status label briefly shows a deploying state before returning to running.
- After saving the schedule, reopen Settings and the switch and window still hold the values you entered.
