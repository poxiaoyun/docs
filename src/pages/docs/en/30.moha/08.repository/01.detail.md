# Repository detail page structure

The resource type and repository name are shown at the top of the detail page, and different tabs are rendered below based on the resource type and permissions.

## Entry points

Open a repository by clicking its card on the model, dataset, image or Space list page.

Typical path examples:

- `/moha/models/:organization/:id/content`
- `/moha/datasets/:organization/:id/file`
- `/moha/images/:organization/:id/tags`
- `/moha/spaces/:organization/:id/setting`

## Tab composition

Tabs are not a fixed list; they are assembled dynamically from the resource type and permissions:

| Tab | value | Shown when |
| --- | --- | --- |
| Model card / Dataset card / Image card / Overview | `content` | Always (the label varies by resource type) |
| Files | `file` | Non-image resources |
| Freezes | `freezes` | Non-image resources |
| Tags | `tags` | Image resources only |
| Discussion | `discussion` | Resources that support discussion |
| Settings | `setting` | When one of the permission conditions below is met |

## Permission control

The settings page is not available to all users. The current front-end decides whether to display the "Settings" tab based on the following conditions:

- System administrator
- Repository owner
- Organization administrator (org member with `role === 'admin'`)
- Repository administrator (`role === 'admin'`) or a member with read-write access (`role === 'readwrite'`)

## Why it matters

- A unified operating model lowers the learning cost across resource types.
- Quick switching between resource details, files, freezes, discussion and settings.
- A fixed working entry for team collaboration, review and publishing.
