# File browsing and version viewing

The **File** tab is the repository's folder view: you can open directories level by level, preview file contents, switch to a branch or snapshot to see what it looked like at the time, and upload or change files here too. Models and datasets have their download button in the top bar; Spaces have the download entry in the top right of the file page.

## Before you start

- Sign in to Moha and make sure you can open this repository.
- To upload, change or delete files: your account must be added as a member on the **Settings** tab (admin or read-write role), and the repository must not be encrypted.

:::tip Image repositories have no file page
Images manage versions through the **Tags** tab and have no file tree. This page only applies to models, datasets and Spaces.
:::

## Page layout

| Where | What it does |
| --- | --- |
| **Branch: xxx** at the top left | Switch branch or snapshot; decides which version you see |
| Path text | Shows the current directory; click any segment to jump back up a level |
| **Commit** | View the commit history; the button shows the number of commits, such as `3 commits` |
| **Add files** | Upload files, upload a folder, create a file, create a folder (models and datasets) |
| **Download** | Spaces have it in the top right and offer both Git and SDK methods |

## Switching branch or snapshot

1. Click **Branch: xxx** at the top left.
2. In the menu that opens, choose:
   - The **Branch** group: switch to a branch's current state.
   - The **Snapshot** group: switch to a historical archive. This group only appears once the repository has snapshots.
3. The page refreshes to that version immediately. While you are on a snapshot the page is **read-only**; switch back to a branch before you change anything.

![The file list: file icon and name on the left, size and last commit message in the middle, commit time and the edit / download icons on the right](/assets/screenshots/moha/repo-model-file-01.png)

The top row is an upstream metadata commit; the repository's own files start below it. The two icons on the right are edit and download — edit only works on text files, while binary weights can only be downloaded.

## Browsing and previewing files

1. Click a folder to go one level deeper; click an earlier path segment to go back.
2. Click a file name to preview it:
   - text, code and JSON show their content directly;
   - images are displayed inline;
   - Markdown is rendered with its formatting.
3. A file that is too large (over 5 MB) is not displayed; the page shows **File size exceeds preview range** and asks you to download it instead.
4. Large files stored with Git LFS show the same kind of notice: **This file is stored with Git LFS. It is too large to display, but you can still download it.**

The file preview page has three buttons at the top:

| Button | What it does |
| --- | --- |
| **Raw** | Opens the file's raw content in a new tab |
| **Commit** | Shows this file's commit history |
| **Create Pull Request** | Only appears for text files; sends a change through review |

## Viewing the commit history and diffs

1. Click **Commit** in the top right of the file page (or **Commit** after opening a file).
2. The list shows the time, author and message of each commit.
3. To see what a commit changed, open the diff view: added and removed lines are coloured separately for comparison.

## Downloading files

### Models and datasets

Use the download button in the top info bar (**Download Models** / **Download Datasets**). The dialog has **Git** and **SDK** tabs and the commands can be copied directly:

| Tab | Commands provided |
| --- | --- |
| **Git** | `git lfs install`, `git clone <repository-url>`, `GIT_LFS_SKIP_SMUDGE=1 git clone <repository-url>` (clone without large files) |
| **SDK** | `pip install moha-hub`, `moha download --repo-type models <organization>/<repository>`, and a Python `snapshot_download` example |

![A Space's Files tab: Download Space at the top right rather than per-file download, with folders and files listed together](/assets/screenshots/moha/repo-space-file-01.png)

Downloads work at a different granularity for Spaces: **Download Space** grabs the whole Space at once, and the list may hold both folders and files. Branch switching and the commit log still work the same way.

### Spaces

The Space file page has a download button in the top right, offering the same Git and SDK methods.

## Uploading, creating, editing and deleting files (models / datasets)

1. Click **Add files** and choose the operation: **Upload files**, **Upload folder**, **Create folder** or **Create file**.
2. For an upload, drag the files into the dialog or click to pick them; for a new item, enter a name.
3. Fill in the **Commit Message** (required).
4. Click **Commit changes**.

If a file with the same name already exists at the target path, the dialog shows **Files already exist**, and you can choose **Overwrite and commit**.

### Editing a single file online

Click **Edit file** on the right of a file row, make your change, enter a commit message and submit. You cannot edit online when:

- it is a folder;
- it is a large file stored with Git LFS;
- the file is in an encrypted repository;
- the file exceeds the online editing limit;
- it is a binary file such as an image or model weights (only text is supported).

:::warning Deletion cannot be undone
When you delete a file or folder you must type the name to confirm. A folder is deleted together with everything inside it and cannot be recovered. You can bring it back afterwards with the rollback actions in the commit history, but check carefully before you act.
:::

### Browser upload limits

| Item | Limit |
| --- | --- |
| Number of files in one upload | At most 100 |
| Total size of one upload | At most 100 MB |
| A single file created online | At most 2 MiB |

Above these limits, upload with the Moha SDK instead — see the [SDK tutorial](/moha/sdk-tutorial/transfer).

## Confirming the result

- After a successful commit a **Committed successfully (<commit>)** message appears in the top right, and the file list refreshes.
- After switching branch or snapshot, the path and the list contents change together.

## Common questions

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| **Add files** is missing | You have no write permission, or the repository is encrypted | Ask an administrator to grant you read-write access in **Settings**; for an encrypted repository, upload with Git |
| A button says the file exceeds the online editing limit | It is not a text file, is an LFS file, or is too large | Overwrite it with **Upload files**, or change it with Git/SDK |
| The list does not change after a commit | Page cache | Refresh, or reopen the tab |
