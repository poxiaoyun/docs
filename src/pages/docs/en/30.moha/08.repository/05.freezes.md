# Snapshots

A **snapshot** is an archived picture of the repository's current state: once it is taken, you can return to exactly that state no matter what changes afterwards. Models, datasets and Spaces all have this tab, so take a snapshot before publishing an important version and later changes stop being scary.

:::tip A snapshot is not a copy of the repository
A snapshot only records which files and which commit existed at that moment. It does not duplicate your files, so it is fast to create and does not take up a second copy of storage.
:::

## Before you start

Sign in to Moha and make sure you can open this repository. Image repositories have no snapshot tab.

## Opening the Snapshots page

Open any model, dataset or Space repository and click the **Snapshot** tab.

![The six snapshot columns: title, branch, commit message, creator, created at and actions (diff / roll back / delete snapshot)](/assets/screenshots/moha/repo-model-freezes-01.png)

The **commit message** column shows the short hash the snapshot points at (`13448952dbda` here) — match it against the commit list on the Files tab.

## Reading the list

Each row in the list is one snapshot:

| Column | Meaning |
| --- | --- |
| Title | The name of this snapshot; if you left the title empty when creating it, the snapshot's identifier is shown, and the reason appears underneath the title |
| Branch | Which branch the snapshot was taken from |
| Commit Message | The commit the snapshot was taken at |
| Creator | Who took it |
| Created At | When it was taken |
| Actions | **Diff**, **Rollback**, **Delete Snapshot** |

## Creating a snapshot

1. On the **Snapshot** tab, click the **Freeze** button in the top right.
2. In the window that opens, fill in:
   - **Title**: a name you will recognise later, at most 32 characters;
   - **Reason**: why you are taking this snapshot; it can span several lines, and you may leave it empty.
3. Click **Confirm**.

:::tip When to take a snapshot
Before a big change to the files, before publishing to others, or right after you get a working version running — those are all good moments to take a snapshot.
:::

## Comparing differences

1. Find the snapshot in the list and click **Diff**.
2. The dialog shows **this snapshot** against **the current state** in a side-by-side split view, listing only the files that changed.
3. If the change is too large (more than 4 MiB of data), the page does not render the content and instead warns that **The snapshot diff is too large to render safely in the browser. Narrow the comparison range or view specific file diffs.**

## Rolling back to a snapshot

1. Click **Rollback** in the list.
2. The dialog shows the branch and commit it is about to roll back to — check that it is the right one.
3. Click **Confirm** and the repository is reset to the commit that this snapshot points at.

:::warning Rollback rewrites the commit history
Rollback resets the target branch to the snapshot's commit, and **records after that commit may be discarded**. This step cannot be undone, so make sure the target snapshot is the right one, and take a snapshot of the current state first if you need to.
:::

## Deleting a snapshot

Click **Delete Snapshot** in the list; after you confirm, that archive record is removed.

:::warning Deleting a snapshot does not affect the current files
Deleting a snapshot only removes the archive record — **the repository's current file contents do not change** — but you will no longer be able to roll back to that snapshot afterwards.
:::

## Seeing snapshot contents on the File page

Snapshots also appear in the branch selector at the top left of the **File** tab: click **Branch: xxx**, pick one from the **Snapshot** group, and the file view switches to how things looked at that moment, exactly like switching branches, which makes it easy to look at historical files.

## Confirming the result

- After a successful creation a new snapshot row appears in the list immediately, with a **Snapshot created** message.
- After a successful rollback a **Rollback finished** message appears, and the page refreshes to the rolled-back content.
