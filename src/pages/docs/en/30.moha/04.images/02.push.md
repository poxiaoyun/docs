# Pushing Images and Managing Tags

An image is not uploaded as files — it is pushed with Docker's `push`. This page gives the complete command sequence from login to push, then explains how to manage versions and run vulnerability scans on the **Tags** tab.

## Concepts

| Term | Plain explanation |
| --- | --- |
| Image repository | Where images live; every image in Moha has its own repository address |
| Tag | A version name for an image, for example `v1.0` or `latest`; one image can carry several tags |
| Digest | A unique fingerprint of the image content; it changes only when the content changes |
| Architecture | The CPU architecture the image targets, for example `linux/amd64` or `linux/arm64` |
| Image scan | A check for known vulnerabilities in the software installed in the image |

:::tip Tag versus digest
A tag is like a book title — you can reissue the same book under a new name. A digest is a fingerprint of the content: change one byte and it changes. For a real release, record both.
:::

## Before you start

- The image is already built locally and `docker images` can see it.
- You can write to this image repository in the target organization, or you own it.
- Docker is installed and can reach the platform address.

## Step 1: Log in to the registry

1. Open the image's detail page and click **Push image** in the top right.
2. The first block in the dialog is **Login to Registry**, with a command shaped like this:

```bash
docker login <registry address> -u <username> -p <access token>
```

3. Click the copy icon on the right of the command and paste it into your terminal. `Login Succeeded` means it worked.

:::warning This command carries your token
The dialog masks it for safety, but what you copy is the real token. Do not paste this command onto a shared screen, into a recording, or into a chat group.
:::

## Step 2: Tag the local image

Before pushing, the local image name has to match the platform address format. Use the **Tag Image** command:

```bash
docker tag <local image> <registry address>/<organization>/<image name>:<tag>
```

For example, to push a local `my-app:dev` as `v1.0` into an image called `chatbot` under the `ai-lab` organization:

```bash
docker tag my-app:dev <registry address>/ai-lab/chatbot:v1.0
```

The `<tag>` the dialog shows defaults to the image's first existing tag; replace it.

## Step 3: Push

```bash
docker push <registry address>/<organization>/<image name>:<tag>
```

A large image can take several minutes; the terminal shows progress per layer. When every layer says `Pushed` and a digest is printed at the end, the push is complete.

Go back to the **Tags** tab and refresh to see the new tag.

## What is on the Tags tab

The **Tags** tab lists every version of the image:

| Column | Meaning |
| --- | --- |
| **Tags** | The version name, for example `main` or `v1.0` |
| **Pull Image** | The `docker pull` command for this tag, with one-click copy |
| **Architecture** | Which architectures this tag contains; one tag can carry both amd64 and arm64 |
| **More actions** | Expands to **Image Scan** and **Delete tag** |

Expanding a tag reveals the **Image Scan** block, which lists one row per architecture:

| Column | Meaning |
| --- | --- |
| **Digest** | The digest of that architecture's image |
| **Architecture** | `operating system/CPU architecture`, for example `linux/amd64` |
| **Scan Status** | Not scanned, Queued, Scanning, Scan complete, or Scan error |
| **Size** | The size of that image |

## Pulling an image

1. On the **Tags** tab, find the tag you need.
2. Click copy in the **Pull Image** column to get `docker pull <registry address>/<organization>/<image name>:<tag>`.
3. Paste it into your terminal. For a private image, log in once following Step 1 above.
4. Docker automatically picks the layer that matches your machine's architecture.

## Scanning for vulnerabilities

1. On the **Tags** tab, expand a tag.
2. Click **Image Scan** on the row of an architecture.
3. While the scan runs the button becomes **Stop Scan**; click it to interrupt.
4. When the scan finishes, the row shows counts in four severities: **Critical**, **High**, **Medium** and **Low**; when nothing is found it shows **No vulnerabilities found**.
5. Click a count to open the **CVE Report** and read each vulnerability's ID, package, severity, version and fixed version.

:::info Scans are per architecture
The amd64 and arm64 images under one tag are different content and must be scanned separately. After pushing new content you need to scan again; old reports are not updated automatically.
:::

## Deleting a tag

In **More actions** click **Delete tag**. The dialog warns that the tag can no longer be used to pull the image, and that every scan job, status and vulnerability report for all architectures under that tag is deleted too; other tags and the image content are unaffected.

:::warning Check for dependents before deleting a tag
If CI or another service pins this tag, it will fail to pull immediately. After pushing a tag with the same name again, you also have to scan again.
:::

## Editing an image's metadata

| What you want to change | Where to go |
| --- | --- |
| Classification, accelerator framework | **Settings** → **Metadata** |
| Readme body (the Markdown on the detail page) | **Settings** → **Readme** |
| Visibility | **Settings** → **Visibility** → **Change visibility** |
| Alias, description | **Settings** → **Basic Info** |

Images have no file tab and no snapshot tab: content versions are managed by tags, and history is kept by the image repository itself.

## Confirming the result

- `docker push` prints `digest: sha256:...` as its last line when it succeeds.
- The new tag appears on the **Tags** tab, with at least one entry in the **Architecture** column.
- Copying the **Pull Image** command and running it on another machine pulls the image, which confirms both the address and your permissions.
- After a scan the row shows vulnerability counts, or **No vulnerabilities found**.

## Troubleshooting

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `denied: requested access to the resource is denied` | Not logged in, or the account has no write access to this repository | Run the **Login to Registry** command again; confirm the role is Admin or Read/Write |
| `unauthorized` | The token expired (it dies as soon as you sign out) | Copy it again from **Access Tokens** and log in |
| The push succeeded but the tag is missing | The page has not refreshed | Click the refresh icon on the Tags tab |
| The pulled image will not start | Architecture mismatch | Check the **Architecture** column, or pass `--platform` explicitly |
| The scan stays queued | The scan queue is busy | Refresh later; contact a platform administrator if it never moves |
