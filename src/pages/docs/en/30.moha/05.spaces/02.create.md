# Creating a Space

Creating a Space happens in two steps: first you decide what runs, where it runs and who can see it, then you push the application code. This page explains every field in the form and which choices are locked once you submit.

## Concepts

| Term | Plain explanation |
| --- | --- |
| Space | An online AI app built with code and published to the web, usable from a link |
| Product SDK | The app's scaffold; it decides how the platform builds and starts your code |
| Deploy Workspace | Where the app actually runs, defined by a **Region** plus a **Workspace** |
| Flavor | How much CPU, memory and accelerator the Space gets; leave it unselected to use the default instance |
| Scheduled running | Run only within a window, scaling replicas to zero outside it |

:::tip How the three deploy choices fit together
Think of opening a shop: the Product SDK is the kind of shop (a café or a bookshop), the Deploy Workspace is the address, and the Flavor is the floor area. The kind and the address are fixed once chosen; the floor area can change later.
:::

## Before you start

- You are signed in to Moha and belong to an organization — a Space must live under one.
- You have application code that can run, for example a Gradio or Streamlit app, or a Docker image.
- If your organization already has shared deploy workspaces, ask an organization administrator which one to use.

## Opening the creation form

1. Click **Space** in the top navigation.
2. Click **Create space** at the top of the page. You can also start from the quick-create entries on the home page, or from **Create space** in the top right of the **Created by Me** tab.

![Create Space form: the Space block (name, ID, organization, description), the Metadata block, Deploy Config and Scheduled running](/assets/screenshots/moha/create-space-01.png)

## Filling in the basics

| Field | How to fill it | Notes |
| --- | --- | --- |
| Name | For example `My Q&A bot` | Required; this is the display name others see and it can be changed later |
| ID | Generated automatically | Shown as `ID: xxx` under the name; click the pencil icon to set it yourself |
| Organization | Pick from the dropdown | Required and decides who owns the Space; fixed when you start from an organization page |
| Description | For example `Knowledge-base customer support bot` | Optional, but one sentence about the problem it solves helps |

The ID is generated from the name: Chinese characters become pinyin, invalid characters become dashes, and the result must start with a letter or digit and contain only letters, digits and `.` `_` `-`, up to 63 characters. **The ID cannot be changed after creation**, so double-check it before submitting.

## Filling in metadata

| Field | How to fill it |
| --- | --- |
| License | Single choice from the dropdown, describing how others may use the Space |
| Domain | Multiple choice, for example multimodal, computer vision or natural language processing |
| Scene | Multiple choice, describing where the app is used |

All three can be left empty, but filling them in makes the Space easier to find through the list filters. You can add them later under **Settings** → **Metadata**.

## Choosing the Product SDK and Deploy Workspace

In the **Deploy Config** block:

1. **Product SDK**: pick the app template. This choice decides how the platform builds and starts your app.
2. **Deploy Workspace**: pick a **Region** first, then a **Workspace**. The workspace list only appears once a region is selected.
3. Once both are set, the page fills in the matching Git address, which you use when pushing code.

:::warning These two cannot be changed later
**Product SDK** and **Deploy Workspace** are fixed once submitted; the Settings tab shows them read-only. If you pick the wrong one, you have to create another Space. Confirm the region and workspace with your colleagues before submitting.
:::

## Choosing a flavor and environment variables

**Flavor** decides how much CPU, memory and accelerator the Space gets. Leave every flavor unselected and the platform runs the default instance — the easiest start; get it working first and tune later.

When the app needs configuration passed in, add it one row at a time under **Environment Variables**:

| Field | Notes |
| --- | --- |
| Variable name | The key your code reads, for example `MODEL_NAME`; names cannot repeat within one configuration |
| Variable value | The value for that key |

Click **Add Environment Variable** to add a row and the trash icon to remove one. An empty name or value cannot be submitted.

## Scheduled running (optional)

If the Space is only used during certain hours — business hours only, for instance — turn the switch on in the **Scheduled running** block and choose a **Schedule mode**:

| Mode | What else you fill in |
| --- | --- |
| **Every day** | Start time, end time |
| **Selected weekdays** | **Run on** (multiple weekdays), start time, end time |
| **Run once** | Start date, end date, start time, end time |

Then fill in the **Time zone** (IANA form, for example `Asia/Shanghai`). If you leave it off, the Space runs continuously at a fixed replica count. This can be changed later under **Settings**.

## Adding members and setting visibility

1. In the **Members** block click **Add Member**, enter the **Username** and choose a **Role**:

| Role | Permission |
| --- | --- |
| **Admin** | Can manage members, change settings, and publish or stop the Space |
| **Read/Write** | Can push code and edit files |
| **Read Only** | View only |

2. In the **Visibility** block pick a level:

| Option | Who can see it |
| --- | --- |
| **Public** | Anyone, including signed-out visitors |
| **Internal** | Members of the organization |
| **Private** | Repository members only |

The default depends on where you started: **Private** from **Created by Me**, **Internal** from an organization page.

3. Click **Confirm** to submit, or **Cancel** to give up.

## Confirming the result

- After submitting, the page opens the Space's **Overview**; with no code yet it shows a getting-started guide (`git lfs install` → `git clone` → write `app.py` → commit).
- The status label at the top shows **Deploying**, meaning the platform has started preparing instances.
- The **File** tab shows the repository structure, which confirms the repository was created.
- Next, push your code following that guide, then go back to Overview and click **Operations** → **Publish**; see [Publishing, stopping and republishing](/moha/spaces/operations).

## Troubleshooting

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| The workspace list stays empty after picking a region | That region has no workspace available to your organization | Pick another region, or ask an organization administrator to provision one |
| The form rejects the name | The name contains spaces or Chinese punctuation | Use letters, digits and `.` `_` `-` |
| The status stays at **Deploying** | The instance is still being scheduled, or the configuration is wrong | Open **Operations** → **Log** to see where it stops |
| You want a different Product SDK or workspace | Both are fixed after submission | Create a new Space and push the code there |
