# Create Workloads

Everything you create in Rune is called an **instance**, also known as a "workload".
An inference service, a training and fine-tuning job, a development service, an app instance, a metrics service, and an evaluation service are all instances; only the template you choose differs.
The good news: **they share one creation flow** — pick a template → fill in basic info → fill in parameters → click **Confirm**.

:::tip An analogy
A template is like a standard work instruction, and an instance is a production line you start by following it.
Different instructions produce different things, but "open the instruction, fill it in, press start" is always the same action.
:::

## Core concepts

| Term | Plain explanation |
| --- | --- |
| Instance | A "machine" you created; it can be an inference service, a fine-tuning job, a development environment, and so on |
| Template | A configuration sheet written in advance; it decides what the instance looks like and which parameters you fill in |
| Version | Different versions of the same template; parameters may differ, so choose clearly before creating |
| Flavor | How much CPU, memory, and accelerator this machine is given |
| Replicas | How many identical machines run at the same time |
| Parameters | The detailed configuration the template asks you to fill in, such as which model to use or which storage volume to mount |

## What I want to do → which feature to use

| What I want to do | Which menu | The create button on screen |
| --- | --- | --- |
| Turn a model into an API that others can call | **Workbench → Inference** | **Create Inference** |
| Retrain a model with my own data | **Workbench → Traning&Fine tuning** | **Create Jobs** |
| Have an online environment with accelerators for writing and debugging code | **Workbench → Runebox** | **Create Runebox** |
| Deploy my own web app or another service | **Workbench → Apps** | **Create Apps** |
| Record and compare training experiment data | **Observability → Metrics** | **Create Metrics** |
| Evaluate and score models | **Observability → Evaluations** | **Create Evaluations** |
| Not sure which to pick | **Marketplace** | Browse all templates and search by category |

:::info How the workload types differ
- **Inference**: once the model is deployed it provides a callable address; the key question is "can it be reached".
- **Training & Fine-tuning**: runs a training job; the key question is "how the run and its result look".
- **Runebox**: a development machine you can sign in to (SSH, VSCode, remote desktop supported); the key question is "can I connect and write code".
- **Apps**: deploys general applications — the fallback option for anything outside the others.
- **Metrics / Evaluations**: companion services used to track experiments and score models.
:::

## Creation steps

The entry point differs by feature, but the flow is identical.

1. First confirm the **Region** and **Workspace** at the top are selected (see [Prerequisites](/rune/guide/prerequisites)).
2. In the left sidebar click the type you want to create, for example **Inference**.
3. Click the create button in the top-right of the page, for example **Create Inference**. The same applies to other types: **Create Jobs** for training and fine-tuning, **Create Runebox** for development, **Create Apps** for apps.
4. On the template list, find the card you want and click **Deploy** on it.
5. Confirm the **Version**: there is a **Version** button in the top-right that you can open to switch; if you do not switch, the latest version is used.
6. Fill in the **Basic Info**:

   | Field | What to fill | Notes |
   | --- | --- | --- |
   | Name | For example `my-first-service` | Required; this is what the list will show later |
   | ID | No need to fill it in manually | Generated automatically from the name and shown below the name field; click the pencil icon next to it if you really want to change it |
   | Description | For example `test inference service` | Optional, for people to read |

7. Fill in the **Parameters**: the form is generated from the template, so fields differ between templates. The code icon in the top-right switches back and forth between form mode and JSON mode; use JSON mode only when you deliberately want to write the parameters by hand.
8. Click **Confirm**.

:::warning A JSON mistake blocks submission
After switching to JSON mode, if the content is not valid JSON the page marks it in red and blocks submission.
Before editing, it is worth switching back to form mode for a look, or keeping a copy of the original parameters.
:::

## Confirming the result

After a successful submit, the page returns to the instance list for that type:

1. The instance you just created appears in the list, with the name you filled in.
2. The **Status** column first shows **Installing** or **Syncing status**, meaning it is being created; when it becomes **Healthy** or **Running**, it has succeeded.
3. Click the name to open the detail page, where you can use the **Overview / Monitoring / Logging / Events** tabs.

Common statuses and what they mean:

| Status | Meaning |
| --- | --- |
| Installing / Syncing status | Being created or updated; just wait |
| Pending | Queued, waiting for resources |
| Healthy / Running | Working normally |
| Paused | You stopped it manually; it can be started again |
| Processing failed | Creation failed; open the detail page and check **Events** for the cause |
| Deleting | Being deleted |

## Common operations

| Operation | Where to click |
| --- | --- |
| Start / Stop | The **⋮** icon at the far right of the row in the list, or the **Actions** button in the top-right of the detail page |
| Edit | **Edit** in the **⋮** menu; you can change parameters and click **Confirm** to finish |
| Scale | **Scale** in the **Actions** button in the top-right of the detail page; adjusts the replica count |
| Delete | **Delete** in the **⋮** menu; a second confirmation is required |

:::warning Deletion cannot be undone
Deleting an instance removes the instance itself and releases the resources it used; it **cannot be undone**.
Temporary data inside the instance that was not stored on a storage volume disappears with it, so make sure important files are already on a storage volume.
:::
