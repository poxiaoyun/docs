# Prerequisites

Before you create anything in Rune, you only need to confirm three things: **which account you sign in with, what role you hold in the tenant, and which resources an administrator has prepared for you**.
Rune requires no software installed on your computer and has no command-line tool — everything is done in the browser.

:::tip Why do this first
It is like joining a gym: you need a membership card, a locker, and the right clothes, or you are stopped at the door.
The most common "why does this button not work" in Rune comes from a region or workspace not being ready.
:::

## Self-check list

| What to confirm | How to check it |
| --- | --- |
| I can sign in | You reach the console normally, with no wrong account or password message |
| I have a tenant | Open the avatar menu in the top-right and confirm the **Tenant xxx** entry is the one you intend to use |
| I have picked a region | A usable region (data center) is selected in the **Region** selector at the top left |
| I have picked a workspace | An office is selected in the **Workspace** selector at the top left |
| This tenant has access to the cluster | The content area does not show the full-page "tenant has not enabled this cluster" notice |
| Quota is still available | If creating something reports not enough resource, the quota is the cause and an administrator must adjust it |
| Templates and flavors are available | You can see templates in the Marketplace and pick a usable flavor when creating |

![Console after the self-check: region and workspace selected, all three sidebar groups visible](/assets/screenshots/rune/prerequisites-01.png)

## What is my role

Rune has three tenant roles: **Administrator**, **Developer**, and **Member**.

| Role | Which features you can use |
| --- | --- |
| Administrator | Every feature, plus member, quota, and workspace management |
| Developer | Every business feature (creating instances, reading metrics and logs); the tenant **Members** tab is admin-only |
| Member | Can only see **Home** and **Marketplace**; cannot see **Workbench** or **Observability** |

:::info How to tell whether you are an Administrator or Developer
Look at the left sidebar for the **Workbench** and **Observability** groups.
If they are there, you are an Administrator or Developer; if not, you are a Member — that is not a fault, it is a permission setting.
:::

## What you see when the cluster is not enabled

Even with the right role, the **tenant must first enable the region (cluster)** before anything can be created there.
While it is not enabled the sidebar still shows up, but the content area is replaced by a full-page status notice and no create button appears.

| Message on the page | Meaning | What you can do |
| --- | --- | --- |
| The tenant has not enabled this cluster yet | No application has been submitted | An administrator fills in the **Application reason** and clicks **Apply** |
| The activation request is under review | Submitted, waiting for the platform administrator | Wait, then click **Refresh status** |
| The activation request was rejected | Rejected; the reason is shown on the page | An administrator adjusts the **Application reason** and clicks **Resubmit** |
| The cluster is being activated | Approved, resources are being prepared | Wait a few minutes and click **Refresh status** |
| Cluster activation failed | The system could not finish the activation | Click **Refresh status** to retry, otherwise contact the platform administrator |
| Cluster access for this tenant is disabled | The platform disabled this tenant's access to the cluster | Contact the platform administrator |
| This cluster is temporarily unavailable | Enabled, but cluster resources are unavailable | Click **Refresh status** later, or contact an administrator |
| Unable to read cluster activation status | The status request failed | Check your network and retry from the page |

:::warning Only administrators can submit the request
The **Application reason** field and the **Apply / Resubmit** buttons appear only for a **tenant administrator**.
Developers and members see the status text and a **Refresh status** button only; ask an administrator to start the request.
:::

## What an administrator needs to prepare for you

The resources below cannot be created by you; a tenant administrator or platform administrator must set them up in advance:

| Resource | Who prepares it | What happens without it |
| --- | --- | --- |
| Tenant and membership | Platform administrator | After signing in you see no business content at all |
| Region (cluster) access | Applied for by the tenant administrator, approved by the platform administrator | The content area is replaced by the activation notice and nothing can be created |
| Workspace | Tenant administrator | The workspace selector is empty and you cannot create instances |
| Quota | Tenant administrator | Creating something reports not enough resource |
| Usable flavors | Platform administrator | No usable compute flavor is selectable when creating |

**Flavors** decide how much CPU, memory and accelerator an instance can ask for. They are defined per cluster by platform administrators and cannot be created by users — if the dropdown has nothing you want, this is the layer that is incomplete.

## Where to look these settings up

Quota, flavors, and workspaces are not top-level items in the console sidebar. They live under **Tenant Clusters**:

1. Click the avatar in the top-right and click **Tenant <your tenant name>**.
2. Click **Tenant Clusters** in the left navigation.
3. Click a cluster name; the page then shows the **Overview / Quota / Flavor / Workspace** tabs.

For the full walk-through see [Tenant Clusters](/rune/console/tenant-clusters).

:::info Not seeing those four tabs is normal
The four tabs on a cluster are visible only to **Administrators** and **Developers**. Members entering the tenant area only see the tenant's basic information.
:::

## Confirming the result

Your environment is ready when the left sidebar shows all three groups — **Home / Workbench / Observability** — both the **Region** and **Workspace** selectors show a specific name, and no activation notice replaces the content area.
