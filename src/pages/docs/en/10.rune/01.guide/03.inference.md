# Inference Hosting

This page takes you through **running one inference from zero to finish**: pick a template, deploy the model as an inference service, then publish it to the gateway so others can call it too.
Everything is done by clicking in the page; no coding and no command line.

:::tip What an inference service is
Think of a model as an expert. The model file is him staying at home; an inference service gives him an office and hangs a sign outside —
anyone with the address can come and ask questions. Publishing to the gateway is like putting that sign in the company lobby so people outside can find him too.
:::

## Core concepts

| Term | Plain explanation |
| --- | --- |
| Inference service | The deployed model service, which provides a callable address |
| Template | A ready-made deployment plan; decides which inference framework is used and which parameters you fill in |
| Endpoint | The access address the service exposes; others call it through this |
| Publish Service | Registers that address with the platform gateway so other users or systems can call it too |
| Visibility | Who can reach it: Public (everyone) / Tenant / Workspace (this tenant) / Private (only you) |

## Before you start

- Your tenant role must be **Administrator** or **Developer**, otherwise **Workbench → Inference** is hidden from the left sidebar.
- The **Region** and **Workspace** at the top are selected (see [Prerequisites](/rune/guide/prerequisites)).
- The current workspace still has accelerator quota available.
- You can see templates in the **Inference** category in the Marketplace.

## Step 1: create the inference service

1. In the left sidebar click **Workbench → Inference**.
2. Click **Create Inference** in the top-right to open the template list.
3. Find the template card you want and click **Deploy** on it.
4. On the deploy page, first check the **Version** in the top-right — it defaults to the latest and can be changed by opening it. New users can keep the default.
5. Fill in the **Basic Info**:

   | Field | What to fill | Notes |
   | --- | --- | --- |
   | Name | For example `qwen-demo` | Required; this is also the name shown in the list |
   | ID | No need to fill it in | Generated automatically from the name and shown below it; click the pencil icon next to it to change it |
   | Description | For example `inference service for testing` | Optional |

6. In the **Parameters** area, fill in what the template asks for; the common ones are:

   | Parameter | Notes |
   | --- | --- |
   | Model | The model to deploy, usually chosen from the platform model hub or a storage volume |
   | Flavor | How much CPU, memory, and accelerator this service gets; choose from the available flavors |
   | Replicas | How many copies run at once; more copies allow higher concurrency but use more resources |

7. Click **Confirm**.

:::warning The page is the final word on parameters
Different templates have different parameter fields; the ones above are only the common ones. If a field does not appear on the page, this template does not need it.
:::

## Step 2: confirm the service is up

1. Back in **Workbench → Inference** in the left sidebar, you can see the service you just created.
2. Look at the **Runtime Status** column: it is first **Syncing status**, and once it becomes **Healthy** the service is up.
3. If it stays at **Pending**, it is most likely queued for resources; if it shows **Processing failed**, click the service name to open the detail page and check the **Events** tab for the cause.
4. The **Access** column shows the service address; click the name to open the detail page, where the **Overview** tab shows more complete endpoint information.

:::info It must be healthy before publishing
Only when the status is **Healthy** is the **Publish Service** menu clickable; otherwise the menu is greyed out and says "Instance must be in Running state to publish service".
:::

## Step 3: publish to the gateway

1. In the inference service list, find the service you just created and click the **⋮** icon in its **Actions** column.
2. Click **Publish Service**.
3. In the dialog, fill in:

   | Field | What to fill | Notes |
   | --- | --- | --- |
   | Endpoint | The first endpoint is already filled in by default | Must be a valid address; the dropdown offers the service's other endpoints and you can also type one |
   | Visibility | Defaults to **Private** | Options are **Public** (anyone can call it), **Tenant / Workspace** (available inside this tenant), and **Private** (only you) |
   | Inference Engine | Defaults to `openai` | Choose `vllm` when you need LoRA adapters |
   | Adapters | Usually left empty | Each adapter needs an **Adapter Name** and an **Adapter Path**; click **Create Adapter** if you need more than one |

4. Click **Confirm**.

## Confirming the result

After publishing, go back to the inference service list:

1. In the **Access** column, the gateway status changes from **Gateway not registered** to **Active**, with the visibility you chose shown next to it.
2. Click the **⋮** icon on that row again — the original **Publish Service** has become **Gateway Configuration**, meaning registration succeeded and you can come back to change the configuration at any time.
3. Callers can use the address in the **Access** column to reach this model.

## Unpublishing

In the **Actions** column click the **⋮** icon, then click **Unpublish** to remove the service from the gateway.

:::warning After unpublishing, others cannot call it
When you confirm, the dialog warns "After unpublishing, users will not be able to access the model through the model gateway!".
The service instance itself still exists, but external calls will fail; publish it again when you need to.
:::

## FAQ

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| No template to choose in the template list | No usable template in this category right now | Check the **Inference** category in the **Marketplace**, or contact an administrator |
| Status stays **Pending** | Not enough resource, or queued | Check the workspace quota, or contact an administrator to expand it |
| Status is **Processing failed** | Wrong parameter or an image problem | Open the detail page and check **Events** and **Logging** |
| **Publish Service** is greyed out | The instance has not reached **Healthy** | Wait until the service is healthy and try again |
| Publishing says the endpoint is required | The service has not produced a usable endpoint yet | Confirm the service is healthy; the endpoint is normally filled in automatically, and you can also type it |
