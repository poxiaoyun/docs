# Presets

**Presets** stores a **reusable instance configuration**.
Once you save a tuned inference service or fine-tuning job with **Save as Instance Preset**, the next time you need a similar instance you can deploy from that preset instead of filling in every parameter from scratch.

:::tip What a preset saves you from filling in
Without a preset, every new instance means picking an application and filling in a pile of parameters again.
With a preset, the application, version, category, and all parameters are already remembered — deploying only asks you for an ID.
Saving your usual configuration as a preset turns "fill it in every time" into "fill it in once, use it many times".
:::

## Core concepts

| Term | Plain explanation | Think of it as |
| --- | --- | --- |
| Preset | A saved snapshot of an instance configuration: source application, version, and every parameter | A fixed recipe for a dish |
| Application | Which application and version the preset was saved from | Which cookbook edition the recipe comes from |
| Category | What the preset is: an inference service or a fine-tuning task | Whether it is a main course or a dessert |
| Deploy | Create a new instance from this preset | Follow the recipe to make another portion |

## Before you start

- Your tenant role must be **Administrator** or **Developer**, otherwise **Workbench → Presets** is hidden from the left sidebar.
- The **Region** and **Workspace** at the top are selected. Presets are **isolated per workspace**, so only members of the same workspace can see them.
- You already have an instance whose configuration you are happy with (an inference service or a fine-tuning job); otherwise there is nothing to save.

## Save an existing instance as a preset

1. In the left sidebar click **Workbench → Inference** (for fine-tuning jobs, click **Training & Fine-tuning** instead).
2. Find the instance you want to save and click the **⋮** icon at the far right of its row.
3. Click **Save as Instance Preset**.
4. In the dialog, fill in:

   | Field | What to fill | Notes |
   | --- | --- | --- |
   | Name | For example `Qwen inference standard config` | Required; an ID is generated below it, click the pencil icon to change it |
   | Preset Description | For example `8B model + 1 card, team standard` | Optional; state the purpose and prerequisites |

5. Click **Confirm**; when the message "Saved as instance preset successfully" appears, you are done.

:::info Training & Fine-tuning has a second entry
Besides the row menu, the **Actions** menu in the top-right of a fine-tuning instance detail page also offers **Save as Instance Preset**.
:::

:::info What exactly a preset stores
When saving, Rune records the tenant, region, and workspace the instance belongs to, plus its application, version, and all parameters.
That is why a preset can only be used to create new instances **inside the same workspace** — and also why it can be shared by the team.
:::

## Deploy a new instance from a preset

1. In the left sidebar click **Workbench → Presets**.
2. Find the preset you want and click the **⋮** icon at the far right of its row.
3. Click **Deploy**.
4. In the "Deploy from Instance Preset" dialog, fill in:

   | Field | What to fill | Notes |
   | --- | --- | --- |
   | ID | Generated automatically | The new instance's system identifier; it cannot be changed after creation |
   | Instance Description | For example `for the test team` | Optional, to make it easier to recognise later |

5. Click **Confirm**.
6. Rune creates the instance with the application and parameters from the preset, then jumps to the instance list for that type.

:::tip No name needed at deploy time
The preset already carries the configuration, so the dialog only asks for an ID — usually you keep the generated one.
:::

## About the preset list

The **Presets** list looks like this:

![Presets list: application, preset name, preset description, category and created-at, with a deploy action per row](/assets/screenshots/rune/presets-01.png)

The `lla-template` row was saved from the `llamaFactory 0.152` application and is categorised as a **fine-tuning task**, so you can use it later to spin up the same kind of fine-tuning instance.

The list has these columns:

| Column | What to look at |
| --- | --- |
| Application | Which application it comes from; the small line below is the version |
| Preset Name | The preset's name |
| Preset Description | The purpose note you wrote |
| Category | Inference Service or Fine-tuning Task |
| Created At | When it was created; the small text below is the creator |

The list supports search, multi-select, refresh, and delete; the **⋮** menu at the far right of each row also has **Deploy** and **Edit**.

## Edit a preset

1. In the preset list, click the **⋮** icon at the far right of a row and click **Edit**.
2. In **Basic Info** you can change the **Name** and **Description**.
3. In **Parameters** you can change the parameter values. The icon in the top-right switches between form mode and JSON mode:
   - Form mode: a form generated from the template, good for changing a few values day to day.
   - JSON mode: edit the parameter text directly, good for bulk replacement.
4. Click **Confirm** to save.

:::warning Think before you edit
A preset is shared by the team, so changing parameters affects every new instance deployed from it afterwards (instances already deployed are unaffected).
If you only want to try a new set of parameters, keep the original preset and save another one under a new name.
:::

:::info The parameter form may fail to load
If this application version is no longer available, the page says "Application … is unavailable. Only basic configuration and JSON parameters can be edited."
In that case you can only change the basic info and the JSON parameters, and you can no longer switch back to form mode.
:::

## Delete a preset

Select one or more presets and click **Delete**, or use **Delete** in the row's **⋮** menu; Rune asks you to **type the preset name** as a second confirmation and deletes it only after that.

:::warning Deletion cannot be undone
After deletion the preset **cannot be recovered**.
Deleting a preset **does not** affect instances already deployed from it; those keep running as usual.
:::
