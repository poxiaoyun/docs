# Product Overview

This page maps four shipped products: Rune, Moha, AIRouter and BOSS. On the Rune side you claim compute and run training, fine-tuning, inference and application instances. On the Moha side you keep models, datasets and images.

As a user you normally do three things: **get compute**, **get a model running**, and **keep your models and data organised**. This page is not about individual operations. It shows what each part is called, who uses it, and which page to read first.

If this is your first visit, read this page and then go straight to [Quick Start](/guide/quick-start): it walks you through five stages, from signing in to running your first inference service.

:::tip One analogy for how these parts fit

Think of the parts below as rooms in the same factory:

- **BOSS** is the platform-operations back office, the plant manager's office: it plans the production lines, allocates capacity and sets safety rules.
- **Rune** is the workshop (the interface often calls it the AI Platform): training, fine-tuning, inference and debugging happen here.
- **Moha** is the asset repository (the docs nav says Moha; the interface often says Moha Hub): models, datasets, images and demo Spaces are stored here.

:::

## What the platform is made of

The four parts below are shipped, and this version of the docs has procedures for them. This version has no XCMP operator guide. Rune Harness is still planned, not a shipped feature.

| Part | Who uses it | What it does for you | How to get in |
| --- | --- | --- | --- |
| **Rune** (tenant portal; the interface often says AI Platform) | Tenant admins, developers, members | Your daily home: deploy inference services, submit fine-tuning jobs, open dev environments, create storage volumes, read logs and evaluations, and chat with models directly | You land here after signing in; the URL ends with `/console` |
| **BOSS** (platform operations / admin portal) | Platform admins | Platform-wide management: onboard clusters, divide resource pools, define flavors, allocate quota to tenants, maintain the model gateway and content moderation | Separate entry; the URL ends with `/boss` |
| **Moha** (docs nav: Moha; the interface often says Moha Hub) | Teams that manage models, datasets, images or Spaces | A hosting repository for models, datasets, images and Spaces: uploads, version management, branches and pull requests, and sync from external sources such as HuggingFace | Switch to Moha Hub from **Products** in the top-left corner |
| **AIRouter** (aggregation gateway) | Members who try models or issue call keys for a program | Chat with a model, compare two models, manage API keys and review usage. The default on-screen name may be Chat, and an administrator can change it | **Products** in the top-left corner |
| **Account & personal settings** | Every signed-in user | Sign-in, registration, password-recovery guidance, avatar and display name, password and multi-factor authentication, access keys, interface preferences | The sign-in page URL ends with `/iam`; once inside, click your avatar → **Personal settings** |

### How they fit together

1. **BOSS lays the road first**: a platform admin onboards clusters, defines flavors and allocates quota to tenants in BOSS, so that there is compute to use at all.
2. **The AI Platform does the work**: a tenant admin splits the tenant quota among workspaces, and members deploy services and run jobs in the AI Platform.
3. **Moha Hub supplies the goods**: models and data live in Moha Hub. The AI Platform can deploy a model from the Hub directly as an inference service; once it is running you can try it in a chat window and hand the endpoint address to a program.

:::warning The entry points do not connect

The AI Platform and BOSS are two separate interfaces. Regular users only ever see the AI Platform; only platform admins can enter BOSS. It is normal that you cannot find BOSS menus inside the AI Platform.

:::

## Menus inside the AI Platform

After signing in, the left menu has three groups. **Workbench** and **Observability** are shown only to tenant admins and developers; members do not see them.

| Group | Menu | What it is for |
| --- | --- | --- |
| **Home** | Home | Resource, quota and workload overview of the current workspace |
| | Marketplace | Deploy an application from a ready-made template in one click |
| **Workbench** | Inference | Deploy a model as an online endpoint |
| | Traning&Fine tuning | Keep training a model with your own data |
| | Runebox | Open a development machine with a graphical interface (JupyterLab, VS Code) |
| | Apps | Deploy your own AI applications |
| | Templates | Manage the application templates you published |
| | Storage | Create network disks that hold model files and datasets |
| **Observability** | Metrics | View experiment curves and compare runs |
| | Logs | Search instance runtime logs |
| | Evaluations | Score models in batches and compare versions |

The product name of the aggregation gateway is **AIRouter**. The steps are on [AIRouter](/airouter/). The default on-screen name may be Chat, and an administrator can change it, so trust the label in your menu. Some older English pages still spell it AIrouter; that is the same product, and it is not a reason to rename API paths or fields.

## Menus inside BOSS

| Group | What it is for |
| --- | --- |
| **Overview** | Platform-wide dashboard |
| **Model Gateway / Model Services / User Management / Security Services / Platform Settings** | Configure model channels, model metadata, gateway tokens and call logs, content moderation policies and sensitive words, gateway and currency settings |
| **Asset Management / Data Sync / Security Audit / System Settings** | Manage platform-level models, datasets, images and Spaces; configure image mirroring, audit logs, announcements and banners |

| **Account Center** | Account, Tenant |
| **System Settings** | System Member, Platform Settings, AI Platform Settings, Moha Hub Settings, Gateway Settings, AI Assistant Settings, License |

## What lives in Moha Hub

| Item | What it is for |
| --- | --- |
| **Models** | Store model files, with versions, branches and pull requests |
| **Datasets** | Store training and evaluation data, also versioned |
| **Images** | Store container images |
| **Spaces** | Host small Gradio or Streamlit apps as an online demo page for a model |
| **Organization** | Manage repository ownership and members by team |
| **Mirror** | Sync public models and datasets in from HuggingFace or ModelScope |
