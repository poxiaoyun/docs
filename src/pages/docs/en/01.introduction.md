# Product Overview

XiaoShi AI is an **enterprise AI platform**. It turns the GPU machines in your data centre into compute you can claim on demand and release when you are done, turns a large model into an online service that web pages and programs can call at any time, and keeps your model files, datasets and container images in one place.

As a user, you normally do three things here: **get compute**, **get a model running**, and **keep your models and data organised**. This page is not about individual operations — it gives you the whole map first: what each part is called, who owns it, and which page you should read now.

If this is your first visit, read this page and then go straight to [Quick Start](/guide/quick-start): it walks you through five stages, from signing in to running your first inference service.

:::tip One analogy for the whole platform

Think of XiaoShi AI as an "AI factory":

- **BOSS Platform** is the plant manager's office: it plans the production lines, allocates capacity and sets safety rules.
- The **AI Platform** is the workshop: the place where the work actually happens, where models are deployed, trained and debugged.
- **Moha Hub** is the warehouse: models, datasets and images are stored here, ready to be taken out.

:::

## The platform has three parts

| Part | Who uses it | What it does for you | How to get in |
| --- | --- | --- | --- |
| **AI Platform** (tenant portal) | Tenant admins, developers, members | Your daily home: deploy inference services, submit fine-tuning jobs, open dev environments, create storage volumes, read logs and evaluations, and chat with models directly | You land here after signing in; the URL ends with `/console` |
| **BOSS Platform** (admin portal) | Platform admins | Platform-wide management: onboard clusters, divide resource pools, define flavors, allocate quota to tenants, maintain the model gateway and content moderation | Separate entry; the URL ends with `/boss` |
| **Moha Hub** | Teams that manage models and datasets | A hosting repository for models and datasets: uploads, version management, branches and pull requests, an image registry and online Spaces — it can also sync from external sources such as HuggingFace | Switch to Moha Hub from **Products** in the top-left corner |

### How the three fit together

1. **BOSS lays the road first**: a platform admin onboards clusters, defines flavors and allocates quota to tenants in BOSS, so that there is compute to use at all.
2. **The AI Platform does the work**: a tenant admin splits the tenant quota among workspaces, and members deploy services and run jobs in the AI Platform.
3. **Moha Hub supplies the goods**: models and data live in Moha Hub. The AI Platform can deploy a model from the Hub directly as an inference service; once it is running you can try it in a chat window and hand the endpoint address to a program.

:::warning The two entry points do not connect

The AI Platform and BOSS are two separate interfaces. Regular users only ever see the AI Platform; only platform admins can enter BOSS. It is normal that you cannot find BOSS menus inside the AI Platform.

:::

## Menus inside the AI Platform

After signing in, the left menu has three groups. **Workbench** and **Observability** are shown only to tenant admins and developers; members do not see them.

| Group | Menu | What it is for |
| --- | --- | --- |
| **Home** | Home | Resource, quota and workload overview of the current workspace |
| | Marketplace | Deploy an application from a ready-made template in one click |
| **Workbench** | Inference | Deploy a model as an online endpoint |
| | Traning&Fine tuning | Keep training a model with your own data |
| | Runebox | Open a development machine with a graphical interface (JupyterLab, VS Code) |
| | Apps | Deploy your own AI applications |
| | Templates | Manage the application templates you published |
| | Storage | Create network disks that hold model files and datasets |
| **Observability** | Metrics | View experiment curves and compare runs |
| | Logs | Search instance runtime logs |
| | Evaluations | Score models in batches and compare versions |

The **Products** switcher in the top-left corner also contains **Chat App**: chat with a model without writing code, send the same question to two models side by side, manage API keys, and review call volume and cost.

## Menus inside BOSS

| Group | What it is for |
| --- | --- |
| **Overview** | Platform-wide dashboard |
| **Model Gateway / Model Services / User Management / Security Services / Platform Settings** | Configure model channels, model metadata, gateway tokens and call logs, content moderation policies and sensitive words, gateway and currency settings |
| **Asset Management / Data Sync / Security Audit / System Settings** | Manage platform-level models, datasets, images and Spaces; configure image mirroring, audit logs, announcements and banners |
| **AI Platform** | Cluster, Tenant Resource, App Template |
| **Account Center** | Account, Tenant |
| **System Settings** | System Member, Platform Settings, AI Platform Settings, Moha Hub Settings, Gateway Settings, AI Assistant Settings, License |

## What lives in Moha Hub

| Item | What it is for |
| --- | --- |
| **Models** | Store model files, with versions, branches and pull requests |
| **Datasets** | Store training and evaluation data, also versioned |
| **Images** | Store container images |
| **Spaces** | Host small Gradio or Streamlit apps as an online demo page for a model |
| **Organization** | Manage repository ownership and members by team |
| **Mirror** | Sync public models and datasets in from HuggingFace or ModelScope |
