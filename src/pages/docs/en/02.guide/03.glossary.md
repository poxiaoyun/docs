# Glossary

This is the page people come back to most. Every term is written as three things: **a plain-English explanation, a real-life analogy, and where you first run into it**. Whenever a page does not make sense, press `Ctrl+F` (or `Cmd+F` on macOS) and search here.

## Platform and roles

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **XiaoShi AI** | The brand name for the whole enterprise AI platform, wrapping compute, models, chat and management together | The brand name in the top-left corner when you open the platform |
| **AI Platform** | Your day-to-day working interface. Analogy: the workshop | You land here after signing in |
| **BOSS** | The back office for platform admins. Analogy: the plant manager's office | Only platform admins can enter; regular users never see it |
| **Moha Hub** | The repository that holds models, datasets, images and demo apps. Analogy: a shelf, or a warehouse | Switch to Moha Hub from the top-left corner |
| **Chat App** | An interface for chatting with models and comparing them without writing code | Switch to Chat App from the top-left corner |
| **Tenant** | One company's own space, with members, assets and quota isolated from everyone else. Analogy: a detached office building with its own gate | If you belong to several tenants, you are asked to pick one after signing in |
| **Admin (admin)** | The most powerful role inside a tenant; can manage members, workspaces and quota | You see the most menu items; also when assigning roles |
| **Developer (developer)** | A role that can deploy services and run jobs — the people who do the work | When adding workspace members; when deploying a service |
| **Member (member)** | A look-but-do-not-touch role, suited to people who only need to follow progress | When adding workspace members; when the **Workbench** menu is missing |
| **Platform admin** | The person who runs the whole platform; can onboard clusters and allocate quota to tenants | When entering BOSS |
| **Role** | The label that decides which menus you see and which buttons you can press | When a button goes missing, think about your role first |

## Compute and resources

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Cluster** | One data-centre building full of real machines. All compute comes from some cluster | The cluster selector at the top of the left menu |
| **Node** | One server inside the building. Analogy: one computer on a floor | Instance details, where you can see which machine a container runs on |
| **Accelerator** | A specialised card for running AI models; GPU is the most common, and there are domestic options such as NPU. Analogy: a graphics card added to a computer | The "Accelerator" entry in Home's resource quota; when picking a flavor |
| **GPU** | Graphics Processing Unit, the accelerator most often used for AI training and inference | Home quota, flavor tables, instance monitoring |
| **NPU** | Neural Processing Unit, a domestic accelerator such as Huawei Ascend | Appears in flavor tables when a domestic cluster is available |
| **Shared GPU (vGPU)** | Slicing one physical card into several shares for multiple instances. Analogy: splitting one flat into single rooms and renting them out | The "Shared GPU" type in the flavor table |
| **VRAM** | The memory built into the accelerator; the bigger the model, the more it uses. Analogy: the graphics card's memory stick | "Accelerator Memory" in instance monitoring |
| **Resource Pool** | Grouping the machines in a cluster to isolate them by purpose or team. Analogy: splitting a whole building into department zones | Configured by platform admins in BOSS; regular users do not operate it directly |
| **Flavor** | The spec sheet for one instance: how many CPU cores, how much memory, how many accelerators. Analogy: the configuration you choose when buying a computer | The **Flavor** card when deploying a service; also when no flavor can be selected |
| **Quota** | The upper limit of how much you may use. Analogy: this month's budget | "Resource Quota" and "Quota warnings" on Home; when a flavor is not selectable |
| **Namespace** | The way Kubernetes isolates resources. A workspace normally maps to one namespace underneath, and you never operate it directly | Possibly when viewing an instance's YAML or resource details |

## Workspaces and instances

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Workspace** | One office inside the building, shared by colleagues; the smallest unit of resource isolation. Every action happens inside some workspace | The workspace selector at the top of the left menu |
| **Workspace selector** | The pair of dropdowns at the top of the left menu; pick the cluster first, then the workspace | Your first task after every sign-in |
| **Instance** | The collective name for the running "machines" in a workspace: inference services, fine-tuning jobs, dev environments, applications, experiments, evaluations | Every row in the feature list pages |
| **Inference** | Deploy a model as an online endpoint others can call. Analogy: opening the model for business | The **Inference** item in the left menu |
| **Traning&Fine tuning** | Use your own data to "top up" an existing model so it understands your business better. Analogy: sending an employee on specialist training | The **Traning&Fine tuning** item in the left menu |
| **Runebox** | An online development environment with a graphical interface, running JupyterLab or VS Code. Analogy: a remote computer that is always ready | The **Runebox** item in the left menu |
| **Apps** | Deploy AI applications built by you or provided by the platform | The **Apps** item in the left menu |
| **Metrics** | View experiment records and compare curves across experiments. Analogy: a lab notebook | The **Metrics** item in the left menu |
| **Evaluations** | Score models in a standardised way and compare versions. Analogy: a final exam | The **Evaluations** item in the left menu |
| **Status** | Which step an instance is currently on; the common ones are **Installed** (starting), **Healthy** (usable), **Needs attention**, **Paused** and **Processing failed** | The "Runtime Status" column in an instance list |
| **Installed / Healthy** | "Installed" means the containers are still starting; "Healthy" means the service can already be reached | A freshly deployed inference service |
| **Replicas** | How many copies of the same service run at once. Analogy: how many checkout counters are open | In deployment parameters; when scaling |
| **Scale** | Adjust the number of replicas — add when busy, reduce when quiet | The **Scale** action in instance details |
| **Start / Stop** | Stop pauses an instance to release compute while keeping the configuration; Start takes compute again and runs it | The action buttons in an instance list |
| **Access URL** | The external entry point of a service; a program uses this address to call your service | **Overview** in instance details |

## Templates and deployment

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Template** | A recipe for one-click deployment: which image to use and which parameters are needed. Analogy: a cookbook recipe | The template list after you click **Create Inference** |
| **Marketplace** | Where you browse and pick templates | The **Marketplace** item in the left menu |
| **Version** | A published version of a template; prefer the one marked **Latest Version** | Choosing a version at the top of the deploy page |
| **Parameters** | The area of the deploy form where you fill in the actual values; different templates have different fields | The deploy page |
| **Form mode / JSON editor** | Parameters can be filled in through a visual form or edited directly as JSON; the icon in the top-right corner switches between them | The Parameters card on the deploy page |
| **Image** | A "disk template" with the operating system and software already installed, from which an instance is created. Analogy: the system disk you install an OS from | The **Images** page in Moha Hub; template configuration |
| **Container** | One isolated environment running from an image. Analogy: a virtual machine installed from a system disk | The "Containers" section in instance details |
| **Pod** | The smallest scheduling unit in Kubernetes; one instance normally maps to one or more Pods | The "Pod List" in instance details |
| **Namespace** | See "Compute and resources" above | Resource details |
| **Ports / Expose Service** | Opening a service port inside the container to the outside world | The "Ports Configuration" section in deployment parameters |

## Storage and files

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Storage** | The left-menu section where you manage storage volumes | The **Storage** item in the left menu |
| **Storage Volume** | A network disk you can plug in and out repeatedly, holding models and data; files survive even if the instance is deleted. Analogy: a USB drive | When mounting data for an inference service; the File Manager |
| **Storage Cluster** | The real storage infrastructure behind a storage volume, maintained by platform admins | Choosing a "Storage Cluster" when creating a storage volume |
| **Storage Class** | The grade of a storage volume, which determines performance and similar characteristics | Choosing a "Storage Class" when creating a storage volume |
| **Capacity** | The size of a storage volume, for example `20Gi`; leave headroom for the model's size | Creating a storage volume |
| **Access Mode** | Who may read and write the volume: `ReadWriteOnce` (one instance reads and writes), `ReadOnlyMany` (many read-only), `ReadWriteMany` (many read and write) | Creating a storage volume |
| **File Manager** | The web file manager inside a storage volume: upload, download, preview, create folders | Opening a storage volume |
| **Storage Job** | A background task that moves files into a storage volume for you | **Create Storage Job** inside a storage volume |
| **HuggingFace** | A well-known public site for models and datasets outside China; you can pull models from it | Choosing a kind when creating a storage job |
| **ModelScope** | A public model and dataset community in China; you can pull models from it | Choosing a kind when creating a storage job |
| **Git LFS** | The technology that lets a Git repository hold large files, which is how model weights get into a repository | Uploading a large model file in Moha Hub |
| **Branch / Tag / Commit** | Git's version-management ideas: a commit is one recorded change, a branch is a parallel line of work, and a tag is a version name given to a commit | The repository page of a model or dataset in Moha Hub |
| **Pull Request** | A request to merge your changes into the main version; someone reviews it before it is merged | A repository page in Moha Hub |
| **Organization** | How Moha Hub groups repository ownership by team. Analogy: a department | **Organization** in Moha Hub |
| **Space** | Where Moha Hub hosts demo apps, such as a small Gradio page. Analogy: a model's shop window | **Spaces** at the top of Moha Hub |

## Model assets

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Models** | The place in Moha Hub where model files are stored, with version history | **Models** at the top of Moha Hub |
| **Datasets** | Collections of data files used for training and evaluation | **Datasets** at the top of Moha Hub |
| **Model card** | A model's description page, saying what it is for, when to use it and how to use it | Opening a model in Moha Hub |
| **Visibility** | Who can see an asset: **Public** (everyone), **Internal** (this tenant), **Private** (only you) | Creating a model or dataset |
| **Fine-tuning** | Keep training an existing model with your own data so it understands your business better. Analogy: pre-job specialist training for an employee | The **Traning&Fine tuning** item in the left menu |
| **Experiment** | One recorded training configuration and result, making it easier to compare which settings were better | The **Metrics** item in the left menu |
| **Evaluation** | Score a model against standard questions to quantify how good it is | The **Evaluations** item in the left menu |
| **Base Model** | The model you start from when fine-tuning; fine-tuning keeps training on top of it | In fine-tuning parameters |

## Chat and model calling

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Model Gateway** | The middle layer that handles model-call traffic: picking a model, applying rate limits, moderating content and recording usage. Analogy: a switchboard | Chat App and Marketplace; **Model Gateway** in BOSS |
| **Channel** | One specific route a model can take (for example a particular provider, or one inference service inside the platform) | "Available channels" in model details |
| **Models** | Browse which models can be called and see context length, price and more | **Models** at the top of Chat App |
| **Playground** | The page where you actually chat with a model | **Playground** at the top of Chat App |
| **Comparison** | Two models answer the same question side by side. Analogy: asking two people at once | **Comparison** at the top of Chat App |
| **API Keys** | The "key" a program uses to call models, as opposed to your sign-in password | **API Keys** at the top of Chat App |
| **Token Management** | The place where platform admins manage every key centrally | BOSS |
| **Deep Thinking** | A mode where the model reasons before answering; on by default | The switch on the Playground page |
| **Token** | The smallest unit of text a model processes; roughly "the unit you count text in" | "Token consumption" in Usage analysis |
| **Usage analysis** | The page showing request count, token usage, cost and success rate | **Usage analysis** at the top of Chat App |
| **Rate limits (RPM / TPM)** | Limits on how often you may call: RPM is requests per minute, TPM is tokens per minute | When creating or editing an API key |
| **Content Moderation** | The safety check on requests and replies; anything hitting a policy is blocked | **Content Moderation** in BOSS; when a conversation is blocked |
| **Sensitive Word Management / Policy Management / Hit Records** | Sensitive words are the word lists, policies are the rules that use them, and hit records are the log of what was blocked | The **Security Services** group in BOSS |
| **Call Logs / Audit Logs** | Detailed records of every call, used for troubleshooting and compliance checks | **User Management** and **Security Audit** in BOSS |

## Account and security

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Multi-factor Authentication (MFA)** | Asking for a second, time-based code on top of your password at sign-in. Analogy: an access card plus a fingerprint | The second code box that appears when you sign in |
| **Verification Code** | A slider puzzle or an image of characters, used to prove you are a person | After several failed sign-in attempts |
| **API Key (Access Key / Secret Key)** | A credential you generate yourself in the User Center, for command-line tools and scripts | User Center → API Key |
| **SSH Keys** | A key pair that lets you push to Git repositories without typing a password | User Center → SSH Keys |
| **User Center** | Where you edit your profile, change your password, manage keys and switch tenants | The avatar in the top-right corner |
| **Theme / Dark mode** | The colour scheme of the interface; switch between light and dark | The theme icon in the top navigation bar |

## Monitoring and troubleshooting

| Term | Plain-English explanation and analogy | Where you first meet it |
| --- | --- | --- |
| **Home (Workspace Overview)** | An overview of the current workspace: workloads, quota, storage, and anything needing attention | The first thing you see after signing in |
| **Needs Attention** | Home gathers abnormal workloads, quotas over their warning threshold and near-full storage into one panel | "Needs Attention" on Home |
| **Logs** | The text an instance prints while running; your first source when something breaks | The **Log** page in instance details |
| **Events** | What the platform recorded — scheduling, image pulls, health checks; the first thing to read when a deployment fails | The **Events** page in instance details |
| **Monitoring** | Charts showing CPU, memory, accelerator utilisation, network traffic and more | The **Monitoring** page in instance details |
| **AI Assistant** | An assistant docked on the right edge of the page; describe your problem in natural language and it builds a troubleshooting path from the current workspace's resource state | The floating entry on the right edge of AI Platform pages |
| **Service Register** | Registering an inference service inside the platform with the Model Gateway, so it can then be called with a shared key | The gateway status of an inference service |
