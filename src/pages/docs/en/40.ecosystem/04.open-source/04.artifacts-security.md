# Products and safety

This page covers **where models, datasets and images are stored, and how they are read, written and transferred safely**.
You turn to this layer when you create storage, plan capacity, set up HTTPS for a service, or investigate "storage volume creation failed".

:::tip Three kinds of storage first
**Object storage** is like a cloud drive: it holds large files such as model files and datasets, organized in "buckets" and reached by URL (RustFS, MinIO).
**Block storage** is like an external hard drive: it attaches a persistent disk to an instance, read and written like a local disk (Longhorn).
**Local disk** is like using one of the node's own disks directly: simple, but not shared across machines (Local Path Provisioner).
:::

## What this category solves

| Problem | Who handles it |
| --- | --- |
| Where models and datasets live and how they are shared | RustFS / MinIO (object storage) |
| Files survive an instance restart and can move across nodes | Longhorn (distributed block storage) |
| You just want to use one machine's local disk quickly | Local Path Provisioner |
| You already have NFS, Ceph or JuiceFS and want to connect it | The matching storage plugin |
| A service must run over HTTPS and renew certificates automatically | cert-manager |

## Which components are included

| Component | Purpose | Key traits | How the platform uses it |
| --- | --- | --- | --- |
| RustFS (distributed object storage, 0.0.77) | Provides S3-compatible object storage for large files and artifacts | Distributed by default with 4 replicas, exposes an API port and a console port | Operations Management → Storage Cluster → Create Storage Cluster, choose RustFS |
| MinIO (object storage, 5.4.0) | The platform's built-in S3-compatible object storage | Deployed with the platform as the platform's own data and artifact storage | Deployed with the platform; usually no separate install needed |
| Longhorn (distributed block storage, 1.10.1) | Gives Pods persistent volumes with cross-node redundancy | 3 replicas by default, data on a node-local path, can be set as the default storage class | Operations Management → Storage Cluster → Create Storage Cluster, choose Longhorn |
| Local Path Provisioner (local-disk storage, 0.0.34) | Provides persistent volumes from a node's local disk | Simple to deploy, not shared across nodes; it is the platform's default storage class | Operations Management → Storage Cluster; use it first when no other storage is installed |
| NFS / CephFS / JuiceFS (external shared storage) | Connects shared storage you already have as a usable storage class | Connects directly to your existing storage system and leaves existing data untouched | Operations Management → Storage Cluster → Create Storage Cluster, choose the matching type |
| cert-manager (certificate management, 1.19.2) | Issues and renews HTTPS certificates automatically | Renews automatically before expiry, so services never swap certificates by hand | Operations Management → System Apps, install the certificate component |

## How users use it

Once the storage components are installed, users do not operate the storage cluster directly; they work in the **AI Platform**:

1. In the left sidebar click **Workbench → Storage**.
2. Click **Create Storage Volume**.
3. Fill in the name, choose a **storage cluster**, enter the **capacity** and choose an **access mode**.
4. Click **Create** and wait in the list until the status becomes available.

Create inference services, training jobs and development environments mount this volume; files stay after the instance restarts or is deleted.

## When you need to care about it

- **A storage volume fails to create**: first go to **Operations Management → Storage Cluster** and confirm there is an available cluster with a healthy status.
- **You do not know which storage to pick**: choose **Longhorn** for cross-node and redundancy; **RustFS** for large files shared by several services; **Local Path Provisioner** for a single-machine trial.
- **Node disks fill up fast**: Longhorn stores data under a node-local path by default, so watch disk levels over time and plan for expansion.
- **You want HTTPS**: confirm **cert-manager** is installed and healthy, then configure a domain and certificate for the service.
- **Object storage must keep data long term**: plan the data capacity and log capacity together when creating the storage cluster.

:::warning Deleting storage loses data
Deleting a storage cluster or storage volume usually deletes the data inside it too, and it **cannot be recovered**. Back up the data first, and never delete a storage volume that an instance is still mounting.
:::

## What this page does not cover

Among the platform's open source components there is **no separate image/dependency scanning (SBOM, vulnerability scanning) component**. If you need that, plug a scanner into your own build pipeline and publish the artifacts to the platform's image registry.
