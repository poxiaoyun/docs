# FAQ

This page collects the open source component problems that come up most often during delivery and operations. **Find your situation under "Symptom", then follow the interface location or command under "What to do".**

:::info Two common prerequisites

First, platform system components are usually installed in the platform system namespace, so start by checking Pod status with `kubectl get pods -n rune-system`.

Second, every "install a component" action needs **platform administrator** rights, and the entry is **Cluster Management → select a cluster → Operations Management**.

:::

## Common questions

| Symptom | Possible cause | What to do |
| --- | --- | --- |
| A component is missing from the System Apps page | The component is not in this cluster's template set, or your account lacks permission | Sign in as platform administrator, go to **Cluster Management → Operations Management → System Apps** and click **Create System App** to see the available templates |
| A system app stays pending after creation | The cluster is missing the install controller, or the component is still pulling images | Run `kubectl get pods -n rune-system`, find the unhealthy Pod and read its events; confirm the cluster finished platform initialization |
| An inference service stays "updating" or will not start | Image will not pull, not enough resources, model files not ready, or engine and hardware do not match | Open the **Inference** instance detail to see the status; check **Cluster Status → Accelerator Status** for cards; use vLLM Ascend on Ascend and the ENX build for encrypted models |
| No logs in Log Management | The logging component is not installed, or the query time range is wrong | Confirm the logging component is installed under **Operations Management → System Apps**; widen the time range on the **All Logs** tab of **Operations Management → Log Management** |
| Monitoring charts are empty or alerts do not fire | The monitoring component is not installed, basic metrics are missing, or the scrape address is unreachable | Confirm monitoring is installed under **Operations Management → System Apps**; run `kubectl get pods -n rune-system` and check the monitoring Pods are ready |
| Creating a storage volume fails | No available storage cluster, no default storage class, or capacity above the limit | Confirm an available cluster under **Operations Management → Storage Cluster**; run `kubectl get sc` to confirm a default storage class; lower the capacity and retry |
| Node disks fill up quickly | Distributed storage data accumulating, or logs and image layers taking space | Run `kubectl get pv` to see volume usage; clean up unused storage volumes; plan larger disks for the storage components |
| Jobs keep queueing and Pods stay Pending | Not enough resources, queue is full, or the scheduling component is unhealthy | Confirm the scheduler is healthy under **Operations Management → Scheduler Management**; run `kubectl get pods -A --field-selector=status.phase=Pending` to see the reason |
| Pods restart by themselves or move to another node | Applying a new VPA recommendation recreates Pods, and Descheduler moves Pods off hot nodes | Check the VPA and Descheduler settings under **Operations Management → System Apps**; turn them off and observe if you do not need them |
| Domain access does not work | The ingress gateway is not installed, the domain does not resolve, or the gateway host name list lacks the domain | Confirm the ingress gateway is installed under **Operations Management → System Apps**; add the domain to the gateway route host names and check DNS |
| The browser reports an invalid HTTPS certificate | The certificate component is not installed, or issuance has not finished | Confirm the certificate component is healthy under **Operations Management → System Apps**; run `kubectl get certificate -A` to see issuance status |
| Autoscaling does nothing | The autoscaling component is not installed, or the custom metrics HPA needs are not connected | Install KEDA under **Operations Management → System Apps**; install Prometheus Adapter when you need to scale on business metrics |
| Several jobs cannot share one GPU | GPU virtualization is not enabled | Turn on **GPU virtualization** in the scheduling component; this works on NVIDIA only — see [Volcano & vGPU Splitting](/ecosystem/nvidia/volcano-vgpu) for configuration and requests. Ascend uses whole cards or the device-plugin approach |

## Still stuck

- First work out **which component** is involved: check the [open source components table](/ecosystem/open-source) to see who provides that capability.
- Then confirm the component **is installed and ready**: the entries are all under **Cluster Management → Operations Management** in **System Apps**, **Storage Cluster**, **Scheduler Management** and **Log Management**.
- If it is installed but behaves wrongly, go back to the matching category page and read that component's "When you need to care about it".
