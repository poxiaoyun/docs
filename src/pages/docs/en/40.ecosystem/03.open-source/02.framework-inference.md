# Framework and inference ecology

This page covers **how a model gets running on the platform**: an inference engine turns a model into a service others can call, and a fine-tuning framework trains an existing model further.
When you create an inference service or a training job in the **AI Platform**, the "template" you pick is one of the components here.

:::tip Inference engine vs. fine-tuning framework
An **inference engine** is like a shop that opens for business: your business code walks in and gets an answer.
A **fine-tuning framework** is like a training class for the model: it produces new model files, which are then handed back to an inference engine to go live.
:::

## What this category solves

| Question | Who handles it |
| --- | --- |
| Which engine turns a large model into an API service | Inference engines such as vLLM / SGLang / Xinference |
| The model does not fit on one card; how several cards cooperate | The engines' tensor parallelism (both vLLM and vLLM Ascend support it) |
| You need dialogue, embedding, speech and image models at the same time | Xinference (one service for several model types) |
| Model files must be encrypted and not directly readable | vLLM ENX / vLLM Ascend ENX (encrypted-model inference) |
| You only have a CPU or a very small amount of VRAM | llama.cpp |
| Take an existing model and give it extra lessons | LLaMA-Factory (fine-tuning) |
| No model is ready yet, but you want to integrate the API | mock-openai-api (mimics the OpenAI API) |

## Which components are included

| Component | Purpose | Key traits | How the platform uses it |
| --- | --- | --- | --- |
| vLLM (large-model inference engine, v0.27.1) | Turns a large model into an OpenAI-compatible inference service | High concurrent throughput, continuous batching, multi-card distributed inference | Workbench → Inference → Create, choose the vLLM template |
| vLLM ENX (encrypted-model inference) | Adds encrypted-model inference on top of vLLM | Enhanced model decryption and secure loading | Workbench → Inference → Create, choose the encrypted template |
| SGLang (high-performance inference engine, 0.5.17) | A high-throughput inference service suited to serving large language models | High performance, OpenAI-compatible | Workbench → Inference → Create, choose the SGLang template |
| SGLang PD (prefill/decode split, v0.5.8) | Splits inference into Prefill, Decode and Router stages | The three stages can each set replicas and resource specs, and scale independently | Workbench → Inference → Create, choose the PD template |
| Xinference (multi-type model inference, v2.12.0) | One service that offers several model capabilities at once | Supports LLM, embedding, reranking, image, speech, video and more | Workbench → Inference → Create, choose the Xinference template |
| llama.cpp (lightweight inference) | Runs open models on a CPU or with a small amount of VRAM | Written in C/C++, supports quantization, works with LLaMa/Qwen and others | Workbench → Inference → Create, choose the llama.cpp template |
| vLLM Ascend (Ascend inference engine, v0.23.0) | vLLM for Huawei Ascend NPUs | OpenAI-compatible, model download, tensor parallelism, LoRA | Workbench → Inference → Create on an Ascend cluster |
| vLLM Ascend ENX (Ascend encrypted inference) | Encrypted-model inference for the Ascend build of vLLM | Enhanced model decryption and secure loading | Workbench → Inference → Create on an Ascend cluster |
| LLaMA-Factory (fine-tuning framework) | Fine-tunes large models | Supports both training and serving modes; task progress is visible | Workbench → Traning&Fine tuning → Create, choose the LLaMA-Factory template |
| mock-openai-api (API mock service) | Mimics the OpenAI chat and completion APIs | Uses no cards, starts fast, returns mock results | Workbench → Inference → Create, for integration and demos |

## When you need to care about it

| Your situation | Which one to use |
| --- | --- |
| General large models on NVIDIA GPUs, aiming for high throughput | vLLM |
| Model files must be encrypted and not directly readable | vLLM ENX |
| You want a different engine and to compare throughput | SGLang |
| You want prefill and decode deployed separately and scaled separately | SGLang PD |
| One service must offer embedding, reranking, speech and image at once | Xinference |
| Only a CPU, or very little VRAM | llama.cpp |
| Huawei Ascend NPU | vLLM Ascend (choose the ENX build for encryption) |
| Fine-tune an existing model | LLaMA-Factory |
| No usable model yet, but you want to integrate the business API | mock-openai-api |

## Before you start

- Creating inference services and training jobs needs the **Administrator** or **Developer** role in the tenant, and a **cluster** and **workspace** chosen first.
- For an inference service to run, the cluster needs schedulable accelerator cards (or choose a CPU flavor); check whether cards are visible under **Cluster Status → Accelerator Status**.
- Put model files in **Storage** or object storage first, then mount or point to the model when creating the service.

:::warning Match the engine version to the hardware
Ascend machines can only use the Ascend build of the engine (vLLM Ascend); encrypted builds can only load encrypted models. Pick the wrong one and the service will not start, so confirm the hardware type and model format first.
:::
