# DCGM Exporter (GPU monitoring)

DCGM Exporter **periodically collects the state of every GPU** — utilization, memory usage, temperature,
power, clocks, ECC errors, NVLink bandwidth — and exposes it over HTTP for a monitoring system such as
Prometheus to scrape. With it installed, the platform can show per-card trends, capacity statistics and alerts.

Think of it as **an electricity meter on every card**: a card does not report its temperature and power on its
own, so something has to read the meter regularly.

## When it is required

- To see GPU utilization, memory, temperature and power in the platform (the panels under
  **Cluster Info → Accelerator Info** take their data from here).
- For alerts or capacity planning based on card state.

You can skip it if you only need resource scheduling, but the accelerator dashboards will then have no data.

## Platform defaults

| Setting | Default | Notes |
| --- | --- | --- |
| Enabled | On | Deployed together with the GPU Operator |
| Create ServiceMonitor | On | Lets the Prometheus Operator discover and scrape it; disable when that CRD is absent |
| Scrape interval | `30s` | Set by the ServiceMonitor |
| `honorLabels` | `true` | Keeps the exporter's own labels instead of letting the scraper overwrite them |
| Metrics port | `9400` | Path `/metrics` |

On the Ascend side of the same cluster the equivalent is NPU Exporter on port `8082`. The two exporters do not
interfere and can coexist.

## Verify

### 1. Check the Pods

```bash
kubectl get pod -n gpu-operator -o wide | grep dcgm
```

One Pod per GPU node, status `Running`.

### 2. Read the metrics directly

```bash
kubectl port-forward -n gpu-operator <dcgm-exporter-pod> 9400:9400
# in another terminal
curl -s localhost:9400/metrics | grep DCGM_FI_DEV_GPU_UTIL
```

Metric lines in the output mean collection works.

### 3. Confirm in Prometheus

If the cluster has Prometheus, query `DCGM_FI_DEV_GPU_UTIL`; seeing data means scraping works. Then go back to
**Cluster Management → select the cluster → Cluster Info → Accelerator Info** — the dashboards should show the
matching curves.

## Common metrics

| Meaning | Metric |
| --- | --- |
| GPU utilization (%) | `DCGM_FI_DEV_GPU_UTIL` |
| Framebuffer used / free (MiB) | `DCGM_FI_DEV_FB_USED` / `DCGM_FI_DEV_FB_FREE` |
| Framebuffer used (%) | `DCGM_FI_DEV_FB_USED_PERCENT` |
| Temperature (℃) | `DCGM_FI_DEV_GPU_TEMP` |
| Power draw (W) | `DCGM_FI_DEV_POWER_USAGE` |
| Power limit (W) | `DCGM_FI_DEV_POWER_MGMT_LIMIT` |
| Core / memory clock (MHz) | `DCGM_FI_DEV_SM_CLOCK` / `DCGM_FI_DEV_MEM_CLOCK` |
| XID errors | `DCGM_FI_DEV_XID_ERRORS` |
| ECC correctable / uncorrectable | `DCGM_FI_DEV_ECC_SBE_VOL_TOTAL` / `DCGM_FI_DEV_ECC_DBE_VOL_TOTAL` |
| NVLink bandwidth | `DCGM_FI_DEV_NVLINK_BANDWIDTH_TOTAL` |
| PCIe bandwidth | `DCGM_FI_PROF_PCIE_TX_BYTES` / `DCGM_FI_PROF_PCIE_RX_BYTES` |

## Labels on the metrics

| Label | Meaning |
| --- | --- |
| `gpu` | Card index within the node |
| `UUID` | Unique GPU identifier |
| `modelName` | Card model |
| `Hostname` | Node name |
| `namespace` / `pod` / `container` | Workload using the card (empty when idle) |

## Troubleshooting

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `pod` / `namespace` labels are always empty | No container is using that card right now | Expected; run a Pod that uses a GPU and look again |
| Accelerator dashboards show no data | Exporter disabled, or no ServiceMonitor | Check `kubectl get svc -n gpu-operator \| grep dcgm` and whether a Prometheus Operator exists |
| Port `9400` does not respond | Pod not ready, or the port was changed | Check the Pod status and readiness probe, then verify the Service port |
| Collection stops midway | DCGM and driver versions mismatch | Read the exporter logs; verify which driver versions that DCGM release supports |
| Need a custom set of metrics | — | Configure the exporter's metric groups and collection interval, then restart the Pod |

:::warning Stop the exporter before upgrading the driver
The exporter calls the DCGM API on a timer. Stop workloads first, then the exporter; after the upgrade restart
them in reverse order. Otherwise you get "half-read old driver" figures while the upgrade runs.
:::
