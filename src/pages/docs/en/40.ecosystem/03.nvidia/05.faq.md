# FAQ

The problems that come up most often when connecting NVIDIA GPUs are all in this table: find the closest symptom,
then run the commands under "what to do". Longer commands live in the "Full commands" section below.

## Quick troubleshooting table

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `nvidia-smi` on the host shows no cards | Driver not installed or not rebooted, or `nouveau` still holds the device | See [Drivers & Container Runtime](/ecosystem/nvidia/driver-runtime); confirm `lsmod \| grep nouveau` prints nothing |
| Device plugin Pod keeps restarting | Container toolkit not ready, or wrong container runtime type | Check `kubectl logs -n gpu-operator <device-plugin-pod>`; make sure the runtime type matches the node |
| No `nvidia.com/gpu` on the node | Driver problem, or the device plugin is not running | Run `nvidia-smi` on the node, then check `kubectl get pod -n gpu-operator \| grep device-plugin` |
| Pods requesting a card stay Pending | No free card, or a wrong resource name / count | `kubectl describe node <gpu-node>` for the remaining count; check the resource name under `limits` |
| Container fails with a CUDA initialisation error | The image requires a newer CUDA than the host driver supports | Check the `nvidia.com/cuda.driver.major` node label; use an image with a lower CUDA version or upgrade the driver |
| The system app never becomes ready | Images cannot be pulled, the app controller is missing, or the Prometheus Operator CRD is absent | Inspect `kubectl get pod -n gpu-operator` and `-n volcano-system`, and read the events of the failing Pod |
| Accelerator dashboards are empty | DCGM Exporter disabled, or no ServiceMonitor | See [DCGM Exporter](/ecosystem/nvidia/gpu-operator/dcgm-exporter) |
| Requests for `volcano.sh/vgpu-*` fail | vGPU not enabled, or all shares are in use | See [Volcano & vGPU Splitting](/ecosystem/nvidia/volcano-vgpu); enable GPU virtualisation and confirm the node resource |
| MIG labels have no effect | The card does not support that geometry, or jobs are using the cards | See [MIG instance partitioning](/ecosystem/nvidia/gpu-operator/mig-manager); test on an idle node first |
| The cluster has both Ascend and NVIDIA cards | Each scheduling bundle carries its own Volcano | Keep one set of scheduling components per cluster; do not add the NVIDIA components to a cluster that already runs the Ascend ones |
| The model in a node label does not match the card | Labels are detection results and may be stale | Restart GPU Feature Discovery to re-detect; never edit these labels by hand |
| After a driver upgrade the cluster no longer sees the cards | Upgrade order was wrong, so components hold stale driver handles | Stop workloads and components first: device plugin → monitoring exporter → driver, then restore in reverse order |

## Full commands

### One-pass health check

Run these in order to narrow the problem to a layer:

```bash
# Layer 1: does the host see the card?
nvidia-smi
lsmod | grep nouveau          # output here means nouveau is not fully blacklisted

# Layer 2: is the runtime installed, which runtime does the engine use?
nvidia-ctk --version
kubectl get node <gpu-node> -o jsonpath='{.status.nodeInfo.containerRuntimeVersion}{"\n"}'

# Layer 3: does the cluster see the card?
kubectl get node <gpu-node> -o jsonpath='{.status.allocatable}' | tr ',' '\n' | grep -E "nvidia|vgpu"
kubectl describe node <gpu-node> | grep -E "nvidia.com/gpu"
```

### Check the running versions

The image tag is the version:

```bash
kubectl get pod -n gpu-operator \
  -o jsonpath='{range .items[*]}{.metadata.name}{"  "}{.spec.containers[*].image}{"\n"}{end}'
kubectl get pod -n volcano-system \
  -o jsonpath='{range .items[*]}{.metadata.name}{"  "}{.spec.containers[*].image}{"\n"}{end}'
```

### Read a component's logs

```bash
kubectl logs -n gpu-operator <pod-name> --tail=100
kubectl logs -n gpu-operator <pod-name> -c <container-name> --tail=100
```

The device plugin and the vGPU device plugin are multi-container Pods, so **name the container explicitly** —
otherwise you only get the first container's logs.

### Find out who is holding a card

```bash
kubectl get pod -A -o jsonpath='{range .items[*]}{.metadata.namespace}{"/"}{.metadata.name}{"  "}{.spec.containers[*].resources.limits}{"\n"}{end}' | grep -E "nvidia.com/gpu|vgpu"
```
