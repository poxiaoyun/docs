# Products & Software Stack

## Product line

Kunlunxin calls all of its data centre accelerators XPU. The official site does not split the line into training
cards and inference cards; models are arranged by generation.

### First generation

| Model | What is known |
| --- | --- |
| K100 | First-generation product. Detailed specifications are not public |
| K200 | First-generation product. Detailed specifications are not public |

### Second generation

| Model | What is known |
| --- | --- |
| R100 | Second-generation product. Detailed specifications are not public |
| R200 series | Second-generation product. Detailed specifications are not public |
| RG800 | Aimed at edge deployments. Detailed specifications are not public |
| R480-X8 | Delivered as an accelerator group. Detailed specifications are not public |

### Third generation

| Model | Memory | Interface | TDP |
| --- | --- | --- | --- |
| P800 | 96 GB | PCIe 5.0 | 400 W |
| P800-OAM | 96 GB | PCIe 5.0 | 400 W |

The vendor publishes no comparison of the P800 and P800-OAM form factors, so check the server vendor's compatibility
list when choosing. The third generation is the only one with public specifications; for the first two, only the
model names can be found.

M100 and M300 were announced at Baidu World in November 2025, planned for 2026 and 2027. They are next-generation
plans, not current options.

:::warning R300 is an unconfirmed model
R300, which circulates online, has no product page on the Kunlunxin site and is an unconfirmed model. The claim
comes from second-hand sources and is not backed by an official one, so do not plan or troubleshoot against it.
:::

## Availability of material

This vendor deserves its own note, because there is genuinely little public material and it sits with third parties.

| Kind of material | Status |
| --- | --- |
| Official product pages | Available; models and brief specifications at `https://www.kunlunxin.com` |
| A standalone developer documentation site | Unconfirmed. Neither `developer.kunlunxin.com` nor `docs.kunlunxin.com` resolves |
| Layer-by-layer software stack detail | Mostly from the Tencent Cloud TKE component documentation. Third-party write-up, quoting official wording |
| Official GitHub organisation | The `kunlunxin` organisation does not exist; `github.com/kunlunxin/xpu-device-plugin` returns 404 |
| Public repositories | The one verified to exist is the inference-side `https://github.com/baidu/vLLM-Kunlun`, created in December 2025 |
| Docker images | The Docker Hub organisation `kunlunxpu` has plugin and exporter images, but the last updates stop at 2022 to 2023 |
| Gitee organisation | The `kunlunxin` organisation holds only two repositories, and neither is the device plugin |

That shapes how the following pages are written: the layering and the verification method can be stated, while
install commands and package names have to come from the driver package shipped with the card.

## Four layers of software stack

The stack as a whole is called XRE. The components named in public material sit in four layers:

| Layer | Components | Installed on | Purpose |
| --- | --- | --- | --- |
| Kernel driver | kmd inside XRE | Host | Lets the operating system see the card |
| User-space runtime | The user-space part of XRE, including `xpu-smi` | Host | Provides the runtime and device management tools |
| Compilers and operators | XDNN, XBLAS, XTDK, XCCL, XHPC | Host or workload image | Communication, operator and tuning dependencies |
| Frameworks and inference | XPyTorch (also written xPytorch), `xtorch_ops`, `XTCL`, vLLM-Kunlun | Workload image | Runs frameworks on the XPU |

There is also XDR, a compilable driver shipped as source for cases that need a specific kernel version.

The framework layer is written both as `XPyTorch` and as `xPytorch` in official material, so search for both when
looking things up.

## Version conventions

Kunlunxin does not publish separate version sequences for the driver, the stack and the frameworks, and no
compatibility matrix is available on the web. This section pins no versions: the three things to trust on site are
the notes in the driver package, what `xpu-smi` actually prints, and the specifications on the official product page.

| What you need | Where to look |
| --- | --- |
| Company and product models | `https://www.kunlunxin.com` |
| Driver and runtime version | Run `xpu-smi` on the machine |
| Software stack layers | Tencent Cloud TKE Kunlunxin component documentation (third-party write-up, quoting official wording) |
| Inference-side code | `https://github.com/baidu/vLLM-Kunlun` |
| A standalone developer documentation site | Unconfirmed; the related domains do not resolve |

:::tip When the three sources disagree
Trust `xpu-smi` on the machine first, then the notes in the driver package, and the third-party documentation last.
Version numbers and package names in third-party documentation go stale. It is fine for understanding the layers,
and not fine for copying commands.
:::
