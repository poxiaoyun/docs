# Products & Software Stack

## Product line

The data centre line is called **Instinct**, with model names starting at MI. AMD's own site does not sort the models
into "training cards" and "inference cards"; the MI350 series is listed for training and inference at the same time, and
only MI350P is explicitly described as aimed at distributed inference.

| Model | Memory | Form factor | Notes |
| --- | --- | --- | --- |
| MI355X | 288 GB HBM3E | OAM | CDNA 4 architecture, the current top tier |
| MI350X | 288 GB HBM3E | OAM | CDNA 4 architecture |
| MI350P | 288 GB HBM3E | PCIe | Listed for distributed inference, fits an air-cooled chassis |
| MI325X | 256 GB HBM3E | OAM | Previous generation |
| MI300X | 192 GB HBM3 | OAM | |
| MI300A | 128 GB HBM3 | APU | CPU and GPU in the same package |

Two things matter at selection time: **OAM cards need the baseboard that comes with the system** and cannot be plugged
in like a PCIe card, and **MI300A is an APU**, so its partitioning modes differ from the pure GPU models (see the
partitioning section in [Kubernetes components](/ecosystem/amd/k8s-components)).

## The software stack has four layers

ROCm is one name, but installation is a matter of four distinct layers, and skipping any of them stops everything above
it:

| Layer | Components | Installed on | Purpose |
| --- | --- | --- | --- |
| Kernel driver | AMD GPU Driver (`amdgpu`) | Host | Lets the operating system see the card and provides `/dev/kfd`, `/dev/dri/renderD*` |
| User-space runtime | ROCm (`rocminfo`, `amd-smi` and similar) | Host | Provides the HSA runtime and device management tools |
| Compilers and libraries | `amdclang`, HIP / HIPIFY, rocBLAS, hipBLASLt, MIOpen, rocFFT, RCCL, Composable Kernel | Host or image | Build and runtime dependencies for workload images |
| Containers and frameworks | AMD Container Toolkit, PyTorch / JAX / TensorFlow / ONNX Runtime / vLLM / SGLang / Triton | Host and workload image | Get the card into the container and the framework onto ROCm |

There is one naming trap: **`roc*` is a native ROCm library, `hip*` is the CUDA compatibility wrapper**.
When a missing library comes up, check which of the two the error names. A `hip*` reference means the code was migrated
from CUDA; a `roc*` reference means native ROCm code.

## Version numbering

From **7.0 onward ROCm splits the kernel driver and the user space into two independently released packages**: the
driver follows its own version sequence (starting in the 30.10 line) and the ROCm user space keeps its own version
numbers. Which driver to install is therefore no longer decided by the ROCm version alone. For compatibility, check
AMD's Compatibility matrix, which gives the driver-to-ROCm pairing for each model and operating system.

This section documents the method and does not pin versions. On site, the reference is always **AMD's official
Compatibility matrix plus the notes shipped with the card**.

| What to look up | Where to look |
| --- | --- |
| Models and specifications | `https://www.amd.com/en/products/accelerators/instinct.html` |
| Compatible driver and ROCm combinations | The Compatibility matrix under `https://rocm.docs.amd.com/projects/install-on-linux/en/latest/` |
| Installation methods | The same page, five options: package manager / `amdgpu-install` / pip / tarball / runfile |
| Container toolkit | `https://github.com/ROCm/container-toolkit` |
| Cluster components | `https://github.com/ROCm/gpu-operator` |
| Every ROCm component | `https://github.com/ROCm` |

:::tip Package manager or amdgpu-install
AMD's own comparison table is clear about this: `amdgpu-install` currently targets **Radeon and Ryzen only**, and it
installs the graphics driver together with ROCm. **On Instinct, the kernel driver follows the AMD Instinct data centre
documentation separately**, while the ROCm user space is best installed through the system package manager (apt / dnf /
zypper).
:::
