# Ascend Docker Runtime

This step installs a container runtime extension on **every NPU node**, so containers can see and use the NPUs.
Installing the host driver only means the machine itself recognizes the card; workloads run in containers, so this layer
is required before a container gets the card device and the driver interface.

Think of it as an **adapter between the card and the container**: the card lives on the host and the container is isolated,
and the adapter "leads" the card into the container.

## When you must install it

- Workloads run **in containers** (platform instances and inference services are both of this kind).
- You need **whole-card or virtualized scheduling**.
- You need **resumable or elastic training**.
- You need **inference card failure recovery / rescheduling**.

If the machine only does resource monitoring and runs no containerized workload, you can skip this page.

:::warning It must be installed before the device plugin
Ascend Device Plugin checks whether this component already exists at startup. **Install this component and restart the
container engine first, then start the device plugin.** If the order is reversed, the plugin often needs a restart or
reinstall before it recognizes the cards.
:::

## Before you start

- Install as the **root** user.
- Confirm the user ID of the `runc` file is `0`.
- The container engine (Docker or containerd) is already installed.
- The host driver is verified (`npu-smi info` shows the cards).
- Know your runtime scenario: Docker, containerd, or containerd integrated with Kubernetes.

## Steps

### 1. Confirm the runtime type

List the nodes:

```bash
kubectl get node
```

Check the installed container engine version:

```bash
docker --version
containerd --version
```

On a Kubernetes node you can also confirm it from the node description:

```bash
kubectl describe node <node-name> | grep -i runtime
```

Use the output to decide whether to follow the Docker or the containerd branch below.

### 2. Make the installer executable

```bash
cd <directory-containing-the-package>
chmod u+x Ascend-docker-runtime_<version>_linux-<arch>.run
```

### 3. Run the pre-install check first

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --check
```

If the check fails, fix what it reports before installing. Do not install on top of a failing check.

### 4. Install

**Docker scenario:**

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --install
```

**containerd scenario:**

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --install --install-scene=containerd
```

To specify the install path (must be an absolute path):

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --install --install-path=<absolute-path>
```

### 5. Restart the container engine

**Docker scenario:**

```bash
systemctl daemon-reload && systemctl restart docker
```

**containerd scenario:**

```bash
systemctl daemon-reload && systemctl restart containerd
```

### 6. Make the device plugin recognize it again

If the device plugin was already installed before this step, restart it, otherwise it will not pick up the runtime:

```bash
kubectl rollout restart daemonset/<device-plugin-daemonset> -n kube-system
```

## Confirm the result

- The `--check` in step 3 passes and step 4 reports no errors.
- After the restart in step 5, the container engine runs normally (`systemctl status docker` or `systemctl status containerd` shows active).
- When Ascend Device Plugin starts afterward, it recognizes the runtime; if the plugin was already running, it no longer reports runtime-related errors after the restart.

## FAQ

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| Installation cannot find the configuration file | The Docker / containerd configuration is not in the default path | Pass `--config-file-path` explicitly during installation |
| Installation fails in the containerd scenario | The runtime configuration in `config.toml` is wrong, or the cgroup version (v1/v2) does not match | Check the runtime configuration in `config.toml` and make sure the runtime path points to the correct `ascend-docker-runtime` |
| The device plugin still cannot see the cards after installation | The container engine was not restarted after installing, or the device plugin was not restarted | Restart the container engine, then restart the device plugin |
