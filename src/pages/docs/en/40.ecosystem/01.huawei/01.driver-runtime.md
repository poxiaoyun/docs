# Drivers and Runtime (Ascend)

This step installs the driver and firmware on **every machine that has NPUs**, so the host itself recognizes the cards.
The sign that it worked is simple: running `npu-smi info` shows the cards and the driver version. If the driver cannot be
installed, none of the cluster components that follow will work.

Think of the driver as the "graphics driver" of the card: without it, the operating system only knows that some hardware is
plugged in, but cannot use it.

:::info This page covers the host only
Nothing here involves Kubernetes. For cluster-side component installation see [MindCluster (cluster scheduling component)](/ecosystem/huawei/mindcluster);
how containers get access to the card is handled by the container runtime, see [Ascend Docker Runtime](/ecosystem/huawei/mindcluster/ascend-docker-runtime).
:::

## Before you start

- Confirm the node operating system is **openEuler**, and the kernel version is compatible with the target driver version.
- Have the **driver package** and **firmware package** (both `.run` installers) ready and uploaded to a directory the target machine can access.
- Confirm whether this is a **first-time install** or an **overlay install** (reinstalling on top of an existing driver without uninstalling) — it decides the install order, see the next step.
- Have **root** privileges.

## Steps

### 1. Check whether a driver is already installed

```bash
npu-smi info
```

- If it prints the NPU list and driver version, the driver is already installed; you can skip to "Verification".
- If the command is not found, or the list is empty, the driver is not installed or not loaded; continue below.

### 2. Determine the install order

Reversing the order is the most common mistake, so confirm the scenario first:

| Scenario | How to tell | Install order |
| --- | --- | --- |
| First-time install | Not installed at the factory, or uninstalled before reinstalling | **Driver → Firmware** |
| Overlay install | Already installed and not uninstalled, reinstalling or upgrading | **Firmware → Driver** |

### 3. Prepare the run user

The driver and firmware run as the `HwHiAiUser` user and group by default. If they do not exist in the environment, create them first:

```bash
groupadd HwHiAiUser
useradd -g HwHiAiUser -d /home/HwHiAiUser -m HwHiAiUser -s /bin/bash
```

If you want to use a different run user, specify it explicitly when installing the driver (see step 6), and make sure the
later software packages use a run user in the same group.

### 4. Install dependencies

```bash
yum makecache
yum install -y make dkms gcc kernel-headers-$(uname -r) kernel-devel-$(uname -r)
```

`dkms` rebuilds the driver automatically after a kernel update. Without it, the driver may install but fail to load.

### 5. Make the installers executable

Go to the directory holding the installers and replace the names with the actual ones:

```bash
cd <directory-containing-the-package>
chmod +x Ascend-hdk-<chip_type>-npu-driver_<version>_linux-<arch>.run
chmod +x Ascend-hdk-<chip_type>-npu-firmware_<version>.run
```

### 6. Install the driver

First-time install (default run user, effective for all users):

```bash
./Ascend-hdk-<chip_type>-npu-driver_<version>_linux-<arch>.run --full --install-for-all
```

For an overlay install, follow the order from step 2 and run the same command for the driver after the firmware.

To specify the run user (when not using the default `HwHiAiUser`):

```bash
./Ascend-hdk-<chip_type>-npu-driver_<version>_linux-<arch>.run \
  --full \
  --install-username=<username> \
  --install-usergroup=<usergroup>
```

### 7. Install the firmware

```bash
./Ascend-hdk-<chip_type>-npu-firmware_<version>.run --full
```

The install path is usually `/usr/local/Ascend`; take the installation output as the source of truth.

### 8. Reboot if prompted

```bash
reboot
```

The driver usually needs a reboot to finish loading after installation. The installation output will say so explicitly —
follow the prompt.

## Verification

After the reboot, run:

```bash
npu-smi info
```

The output usually shows the **version line of the command itself**, the **number and model of the cards**, each card's
**health status (Health should be OK)**, temperature, power, and HBM usage. As long as the cards are listed and their
health is normal, the driver loaded successfully.

If a card does not appear in the list, or its health status is not normal, troubleshoot with the FAQ below.

If you also need CANN (ToolKit / Kernel / Runtime), continue with the official installation guide for the matching
version only after the driver and firmware are verified.

## FAQ

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| `npu-smi: command not found` | The driver is not installed, or the machine was not rebooted after installing | Confirm the installation output reports success, reboot as prompted, then retry |
| `npu-smi info` produces output but shows no cards | The driver has not finished loading | Confirm the reboot completed; if it still fails, check that `dkms` and the kernel headers are present |
| Installation reports missing Linux tools / dkms / dependencies | The yum source is unavailable, or dependencies are incomplete | Run `yum makecache` first, then add `make`, `dkms`, `gcc`, `kernel-headers`, `kernel-devel` |
| Abnormal behavior after an overlay install | The install order does not match the scenario | Overlay install uses **Firmware → Driver**; first-time install uses **Driver → Firmware** |
| Installation reports that a version is not satisfied | Driver, firmware, and CANN versions do not match | Their versions must come from the same release batch; rely on the installation output and the official installation guide |

:::warning Versions must match as a set
The driver, firmware, CANN, and the later MindCluster components all have version compatibility requirements. **Do not pick
a version from memory** — always use the version combination shipped with the release package, otherwise you may get an
installation error at best, or an unusable card after installation at worst.
:::

## Version baselines and reference links

This page deliberately does not pin a version: **driver version, firmware version, NPU model, OS kernel and
CANN must all come from the same release batch**, with the combination shipped in the release package as the
authority. Record these four items on the handover sheet before you start — every later troubleshooting step
depends on them:

- NPU model
- Driver version / firmware version
- CANN version
- The MindCluster version to install (see the "Version baselines" note in [MindCluster (cluster scheduling components)](/ecosystem/huawei/mindcluster))

The official Ascend documentation directory changes with each release, so **do not follow a link pinned to one
version while downloading a different version**:

- Ascend community (software downloads and documentation entry point): https://www.hiascend.com/developer/download
- Installing the NPU driver and firmware (enter by version under "Software Installation"): https://www.hiascend.com/document
