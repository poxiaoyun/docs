# Products & software stack

## Product line

The official pages split the line into inference cards and train-and-infer cards. There is no ranked list of
"current mainstream models", so match on form factor and memory rather than on the number in the model name.

| Model | Role | Memory | Key specs | Source |
| --- | --- | --- | --- | --- |
| MLU370-S4 | Inference card | 24 GB LPDDR5 | Single slot, 150 W, 256 TOPS INT8 / 24 TFLOPS FP32 | Official product page |
| MLU370-X4 | Inference card | 24 GB LPDDR5 | Single slot, 150 W, 256 TOPS INT8 / 24 TFLOPS FP32 | Official product page |
| MLU370-X8 | Train and infer | 48 GB | Dual-die 370, MLU-Link 200 GB/s | Official product page |
| MLU290-M5 | Early training card | Not listed item by item on the official product page | OAM form factor | Official material |
| MLU590 | Not verifiable on the official product page | Not verified | Mentioned only in third-party material | Third-party lead |

:::warning About the MLU590
No specification page for the MLU590 could be verified on Cambricon's product pages; that row comes from
third-party material and is not treated as fact. To confirm whether it exists and what it carries, go through
Cambricon directly or through a server vendor's compatibility list.
:::

The S4 and X4 carry the same official compute and memory figures, so the difference is not at that level. The
difference against the X8 is worth knowing: **the X8 is dual-die, 48 GB, and talks over MLU-Link**, which is the tier
multi-card training needs.

Cambricon publishes no "current mainstream model" statement, and this section does not invent one. Take the model from
the server vendor's compatibility list and the delivery sheet.

## Training or inference

| Workload | Tier the official material points to |
| --- | --- |
| Inference | MLU370-S4, MLU370-X4, single-slot low-power form factors |
| Training and inference | MLU370-X8, dual-die with MLU-Link, the tier that carries multi-card communication |

An inference card is not limited to inference, but it has no MLU-Link path, so multi-card parallel training is not
what it was designed for.

## Four layers in the software stack

Neuware is one name for several things; when installing, keep the four layers apart:

| Layer | Components | Installed where | What it does |
| --- | --- | --- | --- |
| Kernel driver | Neuware driver package | Host | Lets the OS see the card and provides `/dev/cambricon_devX`, `/dev/cambricon_ctl`, `/dev/cambricon_ipcmY` |
| Toolchain | CNToolkit (CNCC, CNAS, CNGDB, CNPerf, CNDev/CNDrv, CNRT) | Host or image | Compiles BANG C / BANGPy kernels, and covers assembly, debugging and profiling |
| Runtime and operators | CNNL (operators), CNCL (communication), MagicMind (inference engine) | Workload image | The direct dependency of the workload; multi-card training runs on CNCL |
| Framework adapters | torch_mlu, Cambricon TensorFlow | Workload image | Makes PyTorch and TensorFlow run on MLU |

One thing to watch at the framework layer: what gets installed is each vendor's own adapter package, not stock
frameworks plus an environment variable. With no `torch_mlu` in the image, PyTorch starts fine but sees no MLU device.

## Version pairing

Neuware names a whole set of things, and the driver, CNToolkit, CNNL / CNCL and the framework adapters each carry
their own version that has to line up with the others. There is no fixed formula published for the pairing, so check
the version notes on the developer site and the notes shipped with the package.

| What you need | Where to look |
| --- | --- |
| Company and product line | `https://www.cambricon.com/` |
| Developer docs, driver and toolchain downloads | `https://developer.cambricon.com/` |
| Product documentation | `https://cambricon.com/docs/` |
| Open-source repositories | `https://github.com/Cambricon` |
| Open-source repositories (domestic mirror) | `https://gitee.com/organizations/cambricon/projects` |

:::tip Match the whole server first
MLU cards usually ship inside a complete server, and the card, mainboard, power and cooling are matched by the
server vendor. Checking a model against that vendor's compatibility list beats hunting for a "mainstream model" in a
third-party ranking; the same model can arrive with different Neuware versions from different vendors.
:::
