# Drivers & container runtime

This layer is host-only. The cluster side, device plugin and monitoring, is covered in
[Kubernetes components](/ecosystem/cambricon/k8s-components).

The install is done when the device nodes appear: `/dev/cambricon_devX`, `/dev/cambricon_ctl` and
`/dev/cambricon_ipcmY`. Without those three, every cluster component on top is wasted effort.

## Prerequisites

| Item | Requirement |
| --- | --- |
| Operating system | A distribution matched to the target Neuware version; the list is in the official installation notes |
| Card | MLU370 series and similar, within the server vendor's compatibility list |
| Driver package | From Cambricon's official channels, shipped with the server or downloaded from the developer site |
| Kernel | The driver loads as a kernel module, so a kernel upgrade means reinstalling the driver |
| Permissions | The account running workloads, and container processes, must be able to read and write the three device nodes |

The device nodes fall into three kinds, which is what makes them useful when troubleshooting:

| Device node | What it is |
| --- | --- |
| `/dev/cambricon_devX` | Card device node, one per card, where X is the index |
| `/dev/cambricon_ctl` | Control node, used by management tools to talk to the driver |
| `/dev/cambricon_ipcmY` | Inter-card communication node, used by multi-card jobs |

A missing `/dev/cambricon_ctl` leaves most management tools unusable; a missing `ipcm` node usually shows up as a
multi-card job that will not start or times out on communication.

## Installing the driver

The driver is part of Neuware and comes in the official installer. Follow the official documentation:

1. Get the driver package that matches the card model and the OS version from official channels.
2. Run the installer on every machine that has a card; it compiles and loads a kernel module along the way.
3. Confirm the device nodes exist afterwards. If they do not, check whether the kernel module loaded.
4. Repeat the install after a kernel upgrade; the module does not follow along by itself.

:::warning Commands follow the official version
How the Cambricon driver installs varies by release and by distribution, and the official documentation gives the
complete commands for the version you are on. This page describes the flow; open the official installation notes
first and swap in the package names and parameters for your release.
:::

## Container runtime and toolchain

Once the host sees the cards, containers need access to the same device nodes. Follow the official container runtime
notes for that step; the platform makes no assumptions here.

An image needs two things besides the workload code:

| Content | Comes from | What breaks without it |
| --- | --- | --- |
| CNToolkit runtime parts | The CNToolkit package | The compiled output will not run in the container, or runtime libraries are missing |
| Framework adapter | torch_mlu or Cambricon TensorFlow | The framework starts but sees no MLU device |

The versions inside the image have to line up with the host driver. Mixing versions across the boundary is the most
common trap, and it shows up as a library loading failure or a device initialisation error.

## Verification

List the device nodes on the host:

```bash
ls -l /dev/cambricon_dev* /dev/cambricon_ctl /dev/cambricon_ipcm*
```

All three node families present means the driver layer is in place. For the container check, follow the minimal
example in the official documentation and confirm the same device nodes are visible inside the container.

## Upgrade and removal

Before touching the driver, shut the layers above it down:

1. Stop the running workloads.
2. Stop the cluster-side device plugin and monitoring components.
3. Then upgrade the driver.

The device plugin polls the driver interface on a timer. Upgrading underneath it tends to leave a state where the
plugin runs but reports the wrong device count, and only a plugin restart clears it. Follow the official removal
steps when uninstalling, and confirm both the device nodes and the kernel module are gone before installing the new
version.
