# Overview

This page is the "map" of the cluster-side components. Check it before you start: what each component does, which images it needs,
and whether the machines and the cluster meet the requirements. **Checking first avoids getting half way through an installation before you discover a version mismatch.**

## What Kubernetes is

Kubernetes (k8s for short) is an open source **container orchestration platform**. It deploys, scales, and manages containerized applications automatically.
It groups a set of machines into a **cluster** and schedules them as one: you submit a task and it picks a suitable machine to run it.

Think of the cluster as an **office building** and each server as a room in it. The DCUs are installed in a few of those rooms,
but the building management (Kubernetes) does not know which rooms have cards or whether a card still has free capacity.
The components below are what "registers" the cards with the building management.

## The components

| Component | One-line description | Analogy |
| --- | --- | --- |
| DCU-Label-Node | Checks whether the node has a card, and if so labels the node with the card information | Hanging a name plate on the room |
| DCU-Exporter | Collects card temperature, power, memory, utilization, and other metrics for monitoring to scrape | A power meter fitted on the card |
| DCU-Device-Plugin | Registers the card as a resource the cluster can allocate, so workloads can request it | Registering the card's residence |
| vDCU-Scheduler | Works with the device plugin to carry out dynamic vDCU allocation | A seating scheduler for shared cards |

Each component is deployed separately. Here are their responsibilities, so the boundaries are clear:

- **DCU-Label-Node**: deployed as a DaemonSet (one Pod per node). At runtime it checks whether the node has a DCU,
  and if it does, it automatically creates node labels describing the DCU information.
- **DCU-Exporter**: exposes DCU and vDCU monitoring metrics and can be integrated with Prometheus to monitor temperature, power, memory usage, and more in real time.
- **DCU-Device-Plugin**: exposes DCU and vDCU to Kubernetes and handles resource registration, scheduling, and allocation;
  it supports physical cards, pre-segmented vDCU, and dynamically segmented vDCU.
- **vDCU-Scheduler**: made up of two components, `k8s-vdcu-admission-webhook` and `k8s-vdcu-scheduler`,
  which work with DCU-Device-Plugin to carry out dynamic vDCU allocation.

## System requirements

Confirm every item before installing. Fix anything that is not satisfied first:

| Category | Requirement |
| --- | --- |
| Hardware | A Hygon DCU is installed. Currently supported models: Z100L, K100/K100-AI/K100-AI-ECO, and the BW series |
| Software | Driver version ≥ 6.2.26; k8s version ≥ 1.18 |
| OS | Linux (Ubuntu 20.04 and above, or CentOS 7.6 and above, recommended); Windows is not supported |

## Check before you install

Run the commands below in order and confirm the output meets expectations before you continue.

### 1. Confirm the driver version and that the modules are loaded

```bash
lsmod | grep -E "hydcu|hycu"
```

Seeing the driver modules means the host side is ready. You can check the driver version with the matching tool; it must be ≥ 6.2.26.

### 2. Confirm the cluster version

```bash
kubectl version
```

The `Server` version in the output must be ≥ 1.18.

### 3. Confirm the operating system

```bash
cat /etc/os-release
```

Confirm it is a supported Linux distribution and version.

### 4. Confirm the images can be pulled

On a node, check whether the images are already present (Docker environments):

```bash
docker images | grep -E "dcu-label-node|dcu-exporter|dcu-device-plugin|vdcu"
```

With containerd, use:

```bash
ctr -n k8s.io c ls | grep -E "dcu-|vdcu"
```

:::warning Do not continue with a driver below 6.2.26

The components depend on driver interfaces from 6.2.26 and above. With an older driver, the components can install successfully but still will not detect the card.
Upgrade the driver first, following [DCU driver installation](/ecosystem/hygon/driver-runtime).

:::
