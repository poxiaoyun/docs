# DCU driver installation

This step installs the driver **on every machine that has a DCU**, so the host itself recognizes the card.
There are two signs of success: the driver service `hymgr` is running, and `lsmod` shows the driver modules.
**If the driver is not installed, none of the cluster components that follow can work.**

Think of the driver as the "graphics card driver": without it the operating system only knows that a piece of hardware is plugged in, but cannot use it.

:::info This page covers the host only

No Kubernetes is involved here. For the cluster-side components, see [Kubernetes components](/ecosystem/hygon/k8s-components).

:::

## Before you start

- Confirm the operating system and the hardware model of the machine, then find the matching driver version in the compatibility list below.
- Get the driver package (the `.run` file) from the vendor channel and upload it to a directory the target machine can reach.
- You need **root** permission and the ability to install build tools and kernel headers.

## Driver compatibility list

Check this table when you pick a driver. Different hardware models need different drivers and DTK (development toolkit) versions:

| Driver version | Supported hardware | Recommended DTK version |
| --- | --- | --- |
| rock-4.0-23-5.6.25 | Z100/Z100L | 21.04/21.10/22.04 |
| rock-4.5.2-5.11.40 | Z100/Z100L | 22.04/22.10/23.04 |
| rock-5.2.0-5.16.18 | Z100/Z100L | 22.10/23.04 |
| rock-5.2.0-5.16.29 | Z100/Z100L/K100 | 23.04/23.10 |
| rock-5.7.1-6.2.26+ | Z100/Z100L/K100/K100-AI | 24.04/25.04 |
| rock-6.3.8+ | BW1000/K100-AI/K100/Z100L/Z100 | 25.04 |

## Steps

### 1. Install the dependency packages

Run the commands for your operating system.

CentOS:

```bash
yum install -y rpm-build gcc-c++ cmake automake elfutils-libelf-devel libdrm libdrm-devel pciutils
yum install -y kernel-devel-`uname -r` kernel-modules-extra
```

Ubuntu:

```bash
apt install -y gcc g++ cmake automake libelf-dev libdrm-amdgpu1 libtinfo5 pciutils libdrm-dev
apt install -y linux-headers-`uname -r` linux-modules-extra
```

### 2. Download the driver and make it executable

Download the matching `.run` package, then grant the execute permission:

```bash
chmod +x rock*.run
```

Driver download address: `https://cancon.hpccube.com:65024/6/main/latest%E9%A9%B1%E5%8A%A8`

### 3. Install the driver

```bash
./rock*.run
```

To see the available installation parameters:

```bash
./rock*.run -h
```

You do not need to uninstall the old driver first — the installation removes it automatically.

### 4. Restart the driver service

```bash
systemctl restart hymgr
```

### 5. Answer the prompts during installation

Two kinds of questions come up during installation. Answer them by this table:

| Prompt | Meaning | What to choose |
| --- | --- | --- |
| `Do you want to remove legacy hymgr config file? [Y/n]:` | Whether to regenerate `/etc/hymgr.cfg` | Choose `yes` to regenerate it, or `no` to keep the existing file. If unsure, keep it (`no`) |
| `Update vbios? [y/N]:` (K100/K100-AI environments) | Whether to update the card firmware | For a first installation, choose `y` and reboot the physical machine; later you can choose `N`. If rebooting the physical machine is tightly restricted in your environment, you may skip the update |

## Verify that the driver is loaded

Run:

```bash
lsmod | grep -E "hydcu|hycu"
```

Seeing the driver modules listed means the driver loaded successfully. **The module names differ by driver version.**

Drivers 6.2.x and below show `hydcu`:

```text
hydcu                1435342  0
hydcu_sched            34432  1 hydcu
hyttm                  61919  1 hydcu
hykcl                  46567  3 hydcu_sched,hydcu,hyttm
hy_extra               32140  3 hydcu_sched,hydcu,hykcl
```

Drivers 6.3.x and above show `hycu`:

```text
hycu                 3371008  2
hycu_sched             45056  1 hycu
hyttm                  86016  2 hycu,hydrm_ttm_helper
hykcl                  40960  5 hycu,hycu_sched,hyttm
hy_extra               65536  2 hycu,hycu_sched
```

## Common problems

| Symptom | Possible cause | What to do |
| --- | --- | --- |
| Installation fails, reporting missing build tools | The dependency packages are incomplete, or the `cmake` / `gcc` version is too low | Newer drivers require `cmake` later than 3.2 and `gcc` later than 7.3. Upgrade them first, then install again |
| Installation fails, reporting that kernel headers are not found | The `kernel-devel` version does not match the running kernel | Check the kernel version with `uname -r` and install the exactly matching `kernel-devel` |
| `lsmod` does not show the driver modules | The driver was not installed, or the service was not restarted afterwards | Confirm the installation output reported success, then run `systemctl restart hymgr` |
| The container cannot read DCU process information | On 6.3.* drivers the debug path is not mounted | When calling Docker, mount `/sys/kernel/debug` into the container |

:::warning Keep the versions matched

The driver, the DTK, and the kernel headers you install later must all match. **Do not pick a version number from memory** —
use the combination shipped with the release package. Otherwise the installation may fail at best, or the card may be unusable after installation at worst.

:::
