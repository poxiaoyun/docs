# DCU-Device-Plugin (MIG mode)

MIG mode manages **MIG instances that are already created on the host**: the host splits one card into several shares in a hardware way first,
and each share is exposed to the cluster as an independent schedulable resource. A task simply requests an instance of the matching size.

Think of MIG as **using partitions to divide one card into several separate small rooms**: the rooms do not affect each other, and the isolation is stronger than software segmentation.

## When you must install it

- When you need **stronger isolation** and finer, hardware-level segmentation than software segmentation gives you.
- This requires MIG to be enabled on the host and the needed MIG instances to be created (for the actual splitting, refer to Hygon's official Multi-Instance user manual).

If you do not split cards, or you use another segmentation route, you do not need this component. See the comparison below.

## MIG or vDCU dynamic segmentation

Both approaches let several tasks share one card. They differ in **when the split happens** and **how strong the isolation is**:

| Item | MIG mode | vDCU dynamic segmentation |
| --- | --- | --- |
| How it splits | Hardware-level split | Software dynamic split |
| When it splits | Instances are created on the host in advance | Split automatically at submit time, based on the request |
| Manual preparation before use | Yes — create the MIG instances first | No |
| Isolation | Stronger | Moderate |
| Resource name | `hygon.com/dcu-mig-*` | `hygon.com/dcunum` and others |
| Good for | Many tasks coexisting, with high requirements on isolation and stability | Task sizes that change often, and maximizing utilization |
| Can it coexist with the other | No | No |

**How to choose:**

- Task sizes are fixed and you need strong isolation → choose **MIG mode**.
- Task sizes change often and you want on-demand splitting with automatic reclamation → choose **[vDCU dynamic segmentation mode](/ecosystem/hygon/k8s-vdcu-dynamic-splitting)**.

:::warning Enable MIG and you lose vDCU

Once MIG is enabled, vDCU virtualization is unavailable. An environment can only take one of the two routes, so decide first
whether your workloads need isolation or flexibility.

:::

## Before you start

- MIG is enabled on the host and the needed MIG instances are created.
- The driver is installed on every machine that has a card, and the component image is available somewhere the cluster can pull from.
- You have the deployment file `k8s-dcu-plugin-mig.yaml`.

## Steps

### 1. Label the node for MIG mode

```bash
kubectl label nodes <node-name> dcu-mode=mig
```

### 2. Deploy

```bash
kubectl apply -f k8s-dcu-plugin-mig.yaml
```

## Verify

### 1. Check the Pods

```bash
kubectl get pod -n kube-system -owide | grep dcu-device-plugin-mig
```

There should be one Pod per node that has a card, in `Running` state.

### 2. Check the node resources

```bash
kubectl describe node <node-name>
```

Seeing something like `hygon.com/dcu-mig-2g-15gb: 1` in the `Capacity` field of the output means the node has a MIG instance of that size.
The size names depend on the instances you actually created — trust the real output on the node.

## How to request one

When requesting, replace the resource name with a size that actually exists on the node:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: dcu-mig-pytorch-demo
spec:
  containers:
    - name: dcu-mig-pytorch-demo
      image: image.sourcefind.cn:5000/dcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: ["/bin/bash", "-c", "--"]
      args: ["sleep infinity & wait"]
      resources:
        limits:
          hygon.com/dcu-mig-4g-31gb: 1
```

## Common problems

| Symptom | Possible cause | What to do |
| --- | --- | --- |
| No MIG resource on the node | MIG is not enabled on the host, or no instance was created | Confirm on the host that MIG is enabled and instances are created, then restart the device plugin |
| A resource name cannot be requested | The resource name does not match the real size on the node | Use `kubectl describe node <node-name>` to see the real size name in `Capacity` |
| vDCU features are unavailable | MIG is enabled | This is expected: MIG and vDCU cannot coexist, so pick one |
