# vDCU dynamic segmentation mode

In dynamic segmentation mode you **do not split the card in advance**. A task states how much compute and how much memory it needs,
and the plugin automatically cuts a matching vDCU out of the card for it. When the task finishes, the vDCU is reclaimed and the card returns to the available pool.
This capability is provided by the device plugin together with vDCU-Scheduler (or the HAMi scheduler).

Think of it as **shared office seats**: you do not reserve a desk for every person; whoever comes uses one, leaves when done, and the free seat can be used by someone else.

## When you must install it

- You have many small and medium tasks whose sizes change often, and you want to maximize card utilization.
- You need to specify compute and memory per task dynamically, without creating instances by hand in advance.

If you only run tasks of a fixed size, use pre-segmented vDCU in standard mode or [MIG mode](/ecosystem/hygon/k8s-device-plugin-mig) instead.

## How to choose between the three segmentation approaches

| Item | Pre-segmented vDCU (standard mode) | MIG mode | vDCU dynamic segmentation |
| --- | --- | --- | --- |
| When it splits | Split into fixed sizes in advance | Split on the host at hardware level in advance | Split on demand at submit time |
| Manual preparation before use | Yes — create the vDCUs first | Yes — create the MIG instances first | No |
| Isolation | Moderate | Stronger | Moderate |
| Resource name | `hygon.com/dcu-share-*` | `hygon.com/dcu-mig-*` | `hygon.com/dcunum` and others |
| Extra component | None | None | Needs vDCU-Scheduler |
| Good for | Many tasks of a fixed size coexisting | Strong isolation, many tasks coexisting | Sizes that change often, maximizing utilization |

**How to choose:**

- Fixed sizes → use pre-segmented vDCU in standard mode.
- Strong isolation required → use [MIG mode](/ecosystem/hygon/k8s-device-plugin-mig).
- Sizes change often and you want the best utilization → use dynamic segmentation on this page.

:::warning Dynamic segmentation and MIG cannot coexist

In one environment you can only take one route: dynamic segmentation or MIG. Once MIG is enabled, vDCU virtualization is unavailable.

:::

## Before you start

- The driver is installed on every machine that has a card, and the component images are available somewhere the cluster can pull from.
- You have three deployment files: `vdcu-admission-webhook.yaml`, `vdcu-scheduler.yaml`, and `k8s-dcu-plugin-hami.yaml`.
- You have permission to run `kubectl apply` against the cluster.

## Steps

### 1. Put a fixed label on the node

The device plugin queries this label during deployment, so set it on the nodes that have cards first:

```bash
kubectl label nodes <node-name> dcu=on
```

### 2. Deploy the three components in order

```bash
kubectl apply -f vdcu-admission-webhook.yaml
kubectl apply -f vdcu-scheduler.yaml
kubectl apply -f k8s-dcu-plugin-hami.yaml
```

## Verify

### 1. Check the component Pods

```bash
kubectl get pod -n kube-system -owide | grep vdcu
```

The `vdcu-admission-webhook`, `vdcu-scheduler`, and device plugin Pods should all be `Running`.

### 2. Check the node resources

```bash
kubectl describe node <node-name>
```

Seeing `hygon.com/dcunum: 4` in the `Capacity` field of the output means the node has 4 available vDCU resources.

## How to request one

A task tells the cluster how many vDCUs it needs through three resource fields:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: vdcu-pytorch-demo
spec:
  containers:
    - name: vdcu-pytorch-demo
      image: image.sourcefind.cn:5000/dcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: ["/bin/bash", "-c", "--"]
      args: ["sleep infinity & wait"]
      resources:
        limits:
          hygon.com/dcunum: 1      # request 1 vDCU
          hygon.com/dcucores: 60   # request 60% of the compute
          hygon.com/dcumem: 3000   # request 3000 MB of memory
```

| Resource field | Meaning |
| --- | --- |
| `hygon.com/dcunum` | How many vDCUs to request |
| `hygon.com/dcucores` | The compute to request, as a percentage |
| `hygon.com/dcumem` | The memory to request, in MB |

## Usage limits

- Each container can request **at most 1 vDCU**. If you request more than 1, the cluster reduces the request to 1 and only 1 takes effect.

## Uninstall and redeploy

If you uninstall the dynamic segmentation components or redeploy them, you must also clean up the leftover resources by hand —
otherwise the redeployment may fail:

```bash
kubectl delete secrets -n kube-system admission-webhook-dcu-certs
kubectl delete mutatingwebhookconfigurations mutating-webhook-dcu-cfg
```

:::warning Stop your workloads before uninstalling

Cleaning up these two items removes the webhook configuration and certificates, which can affect tasks that are using vDCU.
**Stop your workloads before you do this.**

:::
