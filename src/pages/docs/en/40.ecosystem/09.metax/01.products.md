# Products & Software Stack

## Product lines

MetaX accelerators come in four lines, but only two show up in a cluster: general compute for both training and
inference runs on the Xiyun C series, and inference-only runs on the N series. The graphics line, G, has a single
model today. The X series in the website navigation has no official positioning statement.

The Xiyun C series is positioned by MetaX as one line for both training and inference, and is not split further into
training and inference cards:

| Model | Notes |
| --- | --- |
| C500 | One of the models explicitly covered by K8s software package 0.11.2 |
| C550 | One of the models explicitly covered by K8s software package 0.11.2 |
| C500X | One of the models explicitly covered by K8s software package 0.11.2 |
| C588 | Listed on the official website; K8s coverage not stated |
| C600 | Newest flagship; K8s support version unconfirmed |

The N series is tiered by workload rather than by raw compute:

| Model | Workload it targets |
| --- | --- |
| N100 | Traditional CV and video |
| N260 | Generative and large-model inference, explicitly covered by K8s software package 0.11.2 |
| N300 | Cloud inference, also used in appliances and workstations; K8s support version unconfirmed |

The other two lines are not relevant to cluster integration today:

| Series | Models | Positioning |
| --- | --- | --- |
| G | G100 | Graphics |
| X | X206 / X301 / X302 | Three models appear in the website navigation; MetaX has not stated what this line is for |

Start selection from **which models the K8s software package covers**. Version 0.11.2 explicitly covers Xiyun
C500 / C500-P / C500X / C550 and the N260; for C588, C600 and N300, confirm cluster support with MetaX before
committing hardware.

## Five layers in the software stack

MXMACA is one name covering several layers. Installing means keeping the following five straight; miss one and nothing
downstream runs:

| Layer | Components | Installed on | Purpose |
| --- | --- | --- | --- |
| Kernel driver | KMD / UMD (`metax.ko`) | Host | Lets the operating system use the card; shipped with `k8s-driver-image` |
| User-space runtime | MXMACA® SDK, `macaRT` | Host or workload image | Provides the runtime interfaces and device management |
| Compiler and operators | `mxcc`, MCCL, mcBLAS, mcDNN, mcFFT, mcRAND, mcThrust, mcCUB, mcSPARSE, mcSOLVER | Workload image | Build and run dependencies; MCCL handles multi-card communication |
| Framework adapters | mcPyTorch, `vLLM-metax`, `paddle-metax-gpu` | Workload image | Lets PyTorch, vLLM and PaddlePaddle run on MetaX cards |
| Container runtime | `metax-container-runtime`, `metax-docker` | Host | Gives containers access to the devices; official base images are named like `maca-c500` and `mxc500-maca` |

When a library is missing, work out which layer the error comes from. A library starting with `mc` (mcBLAS, mcDNN and
so on) is the operator layer, `mxcc` is the compiler, and only a framework that cannot see the device sends you to the
adapter layer.

## Version conventions

This section describes methods, not pinned versions. The one cluster-side version with an explicit statement is
**K8s software package 0.11.2**, which covers Xiyun C500 / C500-P / C500X / C550 and the N260. For C600 and N300 the
K8s support version is unconfirmed, so align the package version with MetaX before putting either on a cluster.

| What you need | Where to look |
| --- | --- |
| Product lines, models and specs | `https://developer.metax-tech.com/` |
| Drivers and software packages | MetaX Software Center, `https://developer.metax-tech.com/softnova/index` |
| vLLM adapter | `https://github.com/MetaX-MACA/vLLM-metax` |
| Monitoring exporter | `https://github.com/MetaX-MACA/mxExporter` |

On site, always go by **whatever the Software Center currently ships, plus the notes bundled with the package**.

:::tip mcPyTorch is not an operator library
The official operator libraries are mcBLAS, mcDNN, mcFFT, mcRAND, mcThrust, mcCUB, mcSPARSE and mcSOLVER. mcPyTorch
is not among them. Like `vLLM-metax` and `paddle-metax-gpu`, it belongs to the framework adapter layer: a missing
operator library means checking those `mc` packages, and only a framework complaining about the device sends you here.
:::
