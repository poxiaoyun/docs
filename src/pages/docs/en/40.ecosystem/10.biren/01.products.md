# Products and Software Stack

## Product line

The accelerator line is sold under the Biren product name. In chiplet terms the silicon comes in two tiers, BR106 and BR166, where BR166 is built from two BR106 chiplets. Each chip is split into models by form factor:

| Generation | Model | Form factor and role |
| --- | --- | --- |
| BR106 (single chiplet) | Biren 106M | Air-cooled OAM, training |
| BR106 | Biren 106L | Liquid-cooled OAM, training |
| BR106 | Biren 106B | 2 slot FHFL PCIe, inference |
| BR106 | Biren 106C | PCIe, aimed at inference |
| BR166 (two BR106 chiplets) | Biren 166M | Training |
| BR166 | Biren 166L | Training |
| BR166 | Biren 166C | Inference |

The form factor split within the three BR166 models is not itemised officially, so confirm it against the delivery list when choosing. The product matrix also lists BR110, aimed at edge and cloud inference.

By role the line falls into two groups:

| Group | Models |
| --- | --- |
| Training cards | 106M, 106L, 166M, 166L |
| Inference cards | 106B, 106C, 166C, BR110 |

The earlier BR100 and BR104 are no longer in the current product matrix on the official site, and the prospectus does not list them as models on sale either. Their current supply status is unconfirmed. Do not go looking for either part on the basis of older material.

| Production | BR106 / BR166 in full form factors are in mass production, with several thousand-card clusters delivered |
| Roadmap | BR20X planned for release within 2026, with FP8 / FP4 support and Blink 2.0 |
| Known background | Added to the US Entity List in 2023-10 |

166L and 166M went into mass production in 2025-08, and 166C in 2025-12. These lines matter for delivery judgement: the cards are on sale and there is a clear date for the next generation, but the company reports an adjusted net loss of CNY 874 million, so weigh long-term supply and fallback options together when selecting.

## Software stack layers

The official platform name is **BIRENSUPA™**, and the official description splits the stack into four layers. The documentation pages publish the platform name and the layer split only; they do not enumerate component names or versions.

| Layer | Official name | What it covers |
| --- | --- | --- |
| First | Driver and HAL | The driver and hardware abstraction between the card and the operating system |
| Second | Programming platform | Programming interfaces such as compilation, operators and communication |
| Third | Framework layer | Connects upward to deep learning frameworks |
| Fourth | Solution layer | Training and inference solutions for specific scenarios |

Third-party SDK write-ups mention the names below. They have never been listed directly on the official documentation pages, so treat them as leads:

| Name seen in third-party material | Category | Official verification |
| --- | --- | --- |
| BRCC | Compiler | Not listed on the documentation pages |
| suBLAS, suDNN, suFFT, suRAND, suCCL | Operator and communication libraries | Not listed on the documentation pages |
| suInfer | Inference suite | Not listed on the documentation pages |
| brvllm | vLLM integration | Not listed on the documentation pages |
| BRML, suDCGM | Management and monitoring | Not listed on the documentation pages |
| `brsmi` (BR-SMI) | Command line tool | Confirmed to exist, but it is not a metrics exporter |

## Version conventions

Biren publishes no single compatibility matrix covering driver, firmware, SDK and frameworks. The hardest version line available today comes from the device plugin repository: driver ≥ 1.2.2. For everything else, take the delivery documentation shipped with the cards and the developer community as the source of truth, and do not pin version numbers in documentation.

:::tip Do not match third-party component names against the official line
Third-party write-ups on BIRENSUPA list a run of `su*` component names. The official documentation pages do not give those names directly, only the platform name and the four-layer split. When chasing a missing library against such a list, check the current component naming in the developer community first. A name that does not match does not mean the environment is broken.
:::
