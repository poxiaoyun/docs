# API Overview

The platform's APIs come in **two groups**. Before you call anything, work out which group you are using — otherwise it is very easy to get the address wrong.

| Item | Management plane | Data plane |
| --- | --- | --- |
| Path prefix | `/api/...` | `/airouter-data/v1/...` |
| Who it is for | The console pages themselves | Your programs, scripts and external apps |
| Authentication | Your browser sign-in state (sent automatically) | An API key in the request header |
| Typical use | Managing keys, checking usage, reading and writing platform configuration | Sending one model conversation |
| Can you call it directly | Not conveniently (it depends on the browser session) | Yes — this is the one built for programs |

In one line: **to call a model from a program outside the browser, use the data plane `/airouter-data/v1`; the management plane is what the pages themselves use, and you normally do not need to call it by hand.**

## Run the smallest example first

Before calling anything, prepare an API key — see [API Keys](/airouter/token). Then replace `YOUR_DOMAIN`, `YOUR_API_KEY` and `YOUR_MODEL` below with real values:

```bash
curl --request POST 'https://YOUR_DOMAIN/airouter-data/v1/chat/completions' \
  --header 'Authorization: Bearer YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "YOUR_MODEL",
    "stream": false,
    "messages": [
      {"role": "user", "content": "Hello, introduce yourself"}
    ]
  }'
```

The data plane is compatible with OpenAI's Chat Completions API, so you can also use the official OpenAI SDK — just point `base_url` at `https://YOUR_DOMAIN/airouter-data/v1`.

## Request headers, one by one

| Header | Required | Description |
| --- | --- | --- |
| `Authorization` | Required | Written as `Bearer YOUR_API_KEY` |
| `Content-Type` | Required | Always `application/json` |
| `Accept` | For streaming | Set to `text/event-stream` to receive tokens one by one |
| `X-Tenant` | As needed | The tenant that owns the model; the value must be URL-encoded |
| `X-Workspace` | As needed | The workspace that owns the model; URL-encoded |
| `X-Channel` | As needed | Which channel to use; URL-encoded |

Common request-body parameters (the same as OpenAI's):

| Parameter | Description |
| --- | --- |
| `model` | The model name to call; you can see it in the Marketplace |
| `messages` | The array of conversation content, containing `role` and `content` |
| `stream` | Set to `true` to receive tokens one by one, which suits a chat interface |
| `temperature` / `top_p` | Control how random the answer is; usually adjust only one of them |
| `max_tokens` | The maximum length of a single answer |

## What else the data plane offers

| Endpoint | Purpose |
| --- | --- |
| `POST /airouter-data/v1/chat/completions` | Chat completions; the most common one |
| `POST /airouter-data/v1/embeddings` | Turn text into vectors, for retrieval and clustering |
| `POST /airouter-data/v1/rerank` | Re-rank results |
| `GET /airouter-data/v1/models` | List the models the current key can use |
| `POST /airouter-data/v1/audio/speech` | Text to speech |
| `POST /airouter-data/v1/audio/transcriptions` | Speech to text |
| `POST /airouter-data/v1/responses` | A second compatible API used much like Chat Completions |

## What the management plane offers

The management plane is split further by path prefix, each group covering one area. The endpoints below are the ones the console pages actually call; field details are up to the back end.

| Prefix | Responsible for | Typical endpoint |
| --- | --- | --- |
| `/api/iam` | Identity: sign-in, users, tenants, members and roles, captcha, multi-factor authentication, SSH keys | `GET /api/iam/current/roles` |
| `/api/cloud` | Compute control: clusters, workspaces, instances, flavors, quotas, scheduling, logs | `GET /api/cloud/tenants/{tenant}/clusters/{cluster}/workspaces` |
| `/api/ai` | Instance runtime metrics | `GET /api/ai/tenants/{tenant}/.../instances/{instance}/metrics/{metric}` |
| `/api/moha` | Moha Hub: models, datasets, images, organizations | `GET /api/moha/organizations/{org}/images` |
| `/api/airouter/v1` | Model gateway management plane: keys, call logs, usage, gateway settings | `GET /api/airouter/v1/me/tokens`, `GET /api/airouter/v1/me/usage/dashboard` |
| `/api/license` | License records | `GET /api/license/records` |

The model gateway management plane under `/api/airouter/v1` splits into two kinds:

- Endpoints starting with `/me/...` operate on **the signed-in user's own** data, such as `me/tokens`, `me/usage/dashboard`, `me/audit/records`, `me/models` and `me/profile`.
- Endpoints without `/me` belong to **platform management** and need a platform admin, such as `channels`, `tokens`, `moderation/policies` and `usage/dashboard`. There are also tenant- and workspace-scoped forms, such as `tenants/{tenant}/workspaces/{workspace}/channels/{channel}`.

:::warning Do not call the management plane with a Bearer key

The management plane authenticates with the browser sign-in state, and the page carries the session automatically when it calls. If you take a key and call `/api/...` outside the browser, it will usually fail, and it is not suitable for scripting. To call models programmatically, use the data plane.

:::

## Where to get the API documentation

1. **API docs in the Marketplace**: go to [AIrouter](/airouter/), open **Models**, and open any model. The page has **API docs** with copyable cURL, Python and Go samples, already filled in with the current gateway address.
2. **The gateway's own docs page**: the deployed model gateway provides Swagger online documentation (opened by whoever deployed it, usually at `/swagger/index.html`), showing the full management-plane endpoint list and field definitions.

## Status codes and rate limits

| Status code | Meaning | What to do |
| --- | --- | --- |
| `200` | Success | — |
| `400` | A request parameter is wrong | Check the request-body field names and formats |
| `401` | Not authenticated, or the sign-in state expired | Sign in again for the management plane; check the API key for the data plane |
| `403` | No permission | See the [Permission Guide](/reference/permissions) |
| `404` | Resource not found | Check the model name, tenant and workspace |
| `429` | Rate limited | Lower your call frequency and retry |
| `5xx` | Server error | Retry later; if it keeps failing, contact an administrator |

Rate limits are configured **per API key**, on two dimensions:

| Dimension | Meaning |
| --- | --- |
| RPM | Requests allowed per minute |
| TPM | Tokens allowed per minute |

You can view and adjust them in [API Keys](/airouter/token). Hitting the limit returns `429`.
