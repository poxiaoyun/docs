# Reference documentation

This chapter holds practical reference material. You do not read it from start to finish — you look things up as needed. Each of the four pages solves one kind of problem:

| Page | What problem it solves | Who needs it |
| --- | --- | --- |
| [API Overview](/reference/api-overview) | Which API groups exist, who each is for, how they authenticate, and where to get the docs | Developers who want to call models from a program |
| [Permission Guide](/reference/permissions) | What each of the three roles can do, why a button is missing, and how to request access | Everyone, admins especially |
| [Build & Environment](/reference/build-and-env) | What to install to run the console locally, which environment variables exist, and what changing them does | People who deploy and maintain the console |
| [FAQ](/reference/faq) | "Symptom → cause → what to do", grouped by topic | Your first stop when something goes wrong |

## Suggested order

1. If you only want to know "why is this button missing" → go straight to the [Permission Guide](/reference/permissions).
2. If you want to call a model from a program → read the [API Overview](/reference/api-overview) first, then [API Keys](/airouter/token).
3. If you want to deploy the console into your own environment → read [Build & Environment](/reference/build-and-env).
4. If you hit an error → read the [FAQ](/reference/faq). If it is not there, look up the term in the [Glossary](/guide/glossary) and come back.
