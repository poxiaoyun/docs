This page explains how the console project (`XiaoShi-Rune-Console`) builds two outputs — Console and BOSS — and the environment variables involved in local development, images and deployment.

---

## Two build outputs

The same codebase distinguishes the two platforms through the `VITE_PLATFORM` environment variable, which changes both the output directory and the base path:

| `VITE_PLATFORM` | Output directory | Base path | Platform enum |
|-----------------|------------------|-----------|---------------|
| unset (default) | `dist/console` | `/console` | `Platform.CONSOLE` |
| `boss` | `dist/boss` | `/boss` | `Platform.BOSS` |

Evidence: `src/global-config.ts:30-38` (`BasePath` and the `Platform` enum) and `vite.config.ts:52-59,90-92` (`base` and `build.outDir`).

`VITE_ASSETS_DIR` can override the static asset directory separately; when unset it matches the base path (`src/global-config.ts:38`).

## Build information injection

At build time Vite's `define` injects the following values into `__BUILD_INFO__` (`vite.config.ts:32-40`) for the UI to display:

| Field | Source | Fallback |
|-------|--------|----------|
| `buildDate` | `BUILD_DATE` | Current ISO timestamp |
| `version` | `GIT_VERSION` | `development` |
| `gitCommit` | `GIT_COMMIT` | `unknown` |
| `gitBranch` | `GIT_BRANCH` | `unknown` |
| `nodeVersion` | Node version at build time | Retrieved automatically |

## Common commands

Scripts in `package.json`:

| Command | Purpose |
|---------|---------|
| `pnpm dev` | Start the Vite dev server |
| `pnpm build` | `tsc && vite build`, produces the Console build |
| `pnpm build:boss` | Builds the BOSS version with `VITE_PLATFORM=boss` |
| `pnpm start` / `pnpm preview` | Preview the build output |
| `pnpm test` | Run vitest |
| `pnpm lint` / `pnpm fm:check` | ESLint / Prettier checks |

Environment requirements: Node `>=20` and package manager `pnpm@10.15.0` (the `engines` and `packageManager` fields in `package.json`).

The Makefile's `make build` builds both outputs in sequence, passing `BUILD_DATE`, `GIT_VERSION`, `GIT_COMMIT` and `GIT_BRANCH` and setting `NODE_OPTIONS=--max-old-space-size=8192` (`Makefile:1-31`).

## Local development proxy

The dev server listens on port `8000` (`vite.config.ts:60-62`). Because the back end is on a different port, Vite configures these proxies (`vite.config.ts:63-88`):

| Front-end path | Proxy target | Description |
|----------------|--------------|-------------|
| `/api` | `PROXY_TARGET` | Management-plane APIs, with WebSocket enabled |
| `/moha` | `PROXY_TARGET` | Moha-related requests |
| `/airouter-data` | `PROXY_TARGET` | LLM data plane |
| `/console/airouter-data` | `PROXY_TARGET` | Strips the `/console` prefix before forwarding |
| `/avatars` | `PROXY_TARGET` + `/api/iam/avatars` | Avatars and other static resources |

When `PROXY_TARGET` is unset it defaults to `https://rune.develop.xiaoshiai.cn` (`vite.config.ts:55`).

## Environment variables

| Variable | Stage | Purpose | Code location |
|----------|-------|---------|---------------|
| `VITE_PLATFORM` | Build | Selects `console` / `boss` | `src/global-config.ts:37`, `vite.config.ts:54` |
| `VITE_ASSETS_DIR` | Build | Overrides the asset directory | `src/global-config.ts:38` |
| `PROXY_TARGET` | Dev | Back-end address for the local proxy | `vite.config.ts:55` |
| `BUILD_DATE` / `GIT_VERSION` / `GIT_COMMIT` / `GIT_BRANCH` | Build | Injected build information | `vite.config.ts:34-37` |
| `NODE_OPTIONS` | Build | Raises the Node memory limit | `Makefile` |
| `LISTEN_PORT` | Runtime | nginx listen port | `Dockerfile`, `nginx.conf.template` |
| `API_SERVER` | Runtime | Rune API address | `deploy/console/templates/deployment.yaml` |
| `LLM_ROUTER_SERVER` | Runtime | LLM data-plane address | `deploy/console/templates/deployment.yaml` |

## Containerisation and deployment

### Image

The `Dockerfile` is based on `nginx:alpine`, copies `dist` into the image and uses `nginx.conf.template` as the nginx template (default `LISTEN_PORT=8080`).

### nginx behaviour

`nginx.conf.template` handles:

- `/healthz`, returning `{"status":"ok",...}`;
- `/console/` and `/boss/` mapping to `dist/console/` and `dist/boss/`, with an SPA fallback (rewriting to the respective `index.html` when no file matches);
- hashed static assets (js/css/images/fonts) cached immutably for one year, with `gzip_static` enabled (paired with the `.gz` files produced by `vite-plugin-compression` at build time);
- `/` redirecting to `/console/` and `/boss/` redirecting to `/boss/dashboard`.

### Helm

`deploy/console` provides a Helm chart: `apiServer`, `llmRouterServer` and `containerPorts.http` in `values.yaml` are injected as the container environment variables `API_SERVER`, `LLM_ROUTER_SERVER` and `LISTEN_PORT`, and liveness/readiness probes target `/healthz`. `make package-helm` / `make release-helm` package and push the chart.

### CI

`.github/workflows/build.yml` runs, on push / PR: `pnpm lint` → `pnpm fm:check` → `pnpm test` → `make build` → docker buildx build and push; on tags it additionally publishes the Helm chart.

> ⚠️ **Note**: `nginx.conf.template` only references `LISTEN_PORT` — it never uses `API_SERVER` / `LLM_ROUTER_SERVER`, and it contains no reverse-proxy configuration for `/api`, `/airouter-data` or `/moha`. Those two variables are injected by the Deployment but unused by the template; how requests to `/api` and `/airouter-data` are forwarded (presumably by an outer gateway or Ingress) is not confirmed in this repository.
