## Accounts and sign-in

### Q: How do I create a platform account?

**A:** There are two entries:

1. **Self-registration**: the sign-in page links to `/auth/sign-up` (`src/routes/sections/auth.tsx:35-42`). The form fields are `username`, `password`, `email`, `phone` and a verification `code`, plus an agreement checkbox (`src/auth/view/centered/centered-sign-up-view.tsx:147-184`), submitted to `POST /api/iam/register` (`src/services/iam.ts:32-36`).
2. **Administrator-created account**: a platform administrator creates the account in the BOSS back office.

> ⚠️ **Note**: The visibility of the registration entry is controlled by the global setting `enableBossSignup` (default `false`, `src/settings/global/settings-config.ts:16`). In the Console build the entry is always shown; in the BOSS build the switch must be enabled first (`src/auth/view/centered/centered-sign-up-view.tsx:80-82`, `centered-sign-in-view.tsx:687`). The back-office path used to create accounts is documented in another chapter and is not confirmed here.

### Q: When does the login captcha appear?

**A:** The sign-in page shows the captcha based on the configuration returned by the login API. The captcha is fetched from `GET /api/iam/login-captcha` (`src/services/iam.ts:16-19`) and its `provider` may be:

| provider | Interaction |
|----------|-------------|
| `Slider` | Drag a slider puzzle |
| `Graphic` | Type the characters in the image |

Triggers include a locked login (`LoginLocked`) and similar cases (`src/auth/view/centered/centered-sign-in-view.tsx:282-312`).

> ⚠️ **Note**: The captcha validity period is decided by the back end; there is no timeout constant in the front-end code, so it is not confirmed.

### Q: I forgot my password

**A:** The sign-in page links to `/auth/reset-password`. The reset flow first requests a verification code through `POST /api/iam/send-code` (`src/services/account.ts:73-77`). The delivery channel and validation rules are back-end concerns and are not confirmed.

### Q: How do I set up multi-factor authentication (MFA)?

**A:** The endpoints exist: `POST /api/iam/init-mfa` to initialise and `POST /api/iam/verify-mfa` to verify (`src/services/account.ts:44-54`).

> ⚠️ **Note**: The recovery-code mechanism and any enforcement policy after binding cannot be confirmed from the front-end code.

### Q: Does the platform support SSO / LDAP?

**A:** The login configuration endpoint `GET /api/iam/login-config` returns `allowSignup` and a `methods` list; entries may be of type `OAuth2`, `OIDC`, `SAML`, `OTP`, `WebAuthn` and so on (`src/types/iam.ts:18-44`). Whether they are enabled therefore depends on the deployment.

> ⚠️ **Note**: Which external identity providers are supported and how they are configured is a back-end/deployment concern that cannot be confirmed from the front end.

## Sessions and tokens

### Q: How is the login session stored?

**A:** The session token is stored in a **cookie** named `user_session` (`src/auth/authn/token.ts:3`). The console's axios instance does **not** inject an `Authorization` header (`src/lib/axios.ts:21-28`); management-plane endpoints authenticate through the cookie the browser sends automatically.

> ⚠️ **Note**: The session lifetime is issued by the back end; there is no related constant in the front end, so it is not confirmed. Once expired you must sign in again.

### Q: What is the difference between an API key and a login session?

**A:**

| Item | Login session | API key |
|------|---------------|---------|
| Carrier | `user_session` cookie | A string token (the `apiKey` field) |
| Created via | Automatically after sign-in | ChatApp → My Tokens |
| Typical use | Console pages calling management-plane APIs | Calling the conversation data plane with `Authorization: Bearer` |
| Management API | — | `GET /api/airouter/v1/me/tokens` (`src/services/api-key.ts:128-133`) |

### Q: How do I sign out?

**A:** Call `POST /api/iam/logout` (`src/services/iam.ts:27-30`); the front end then clears the `user_session` cookie (`src/auth/authn/token.ts:9-11`).

## Tenants and workspaces

### Q: What is a tenant and how do I switch?

**A:** A tenant is a resource-isolation unit. The list of tenants the current user can access comes from `GET /api/iam/current/tenants` (`src/services/tenant.ts:6-9`). After sign-in, users belonging to more than one tenant land on the tenant selection page `/auth/select-tenant` (`src/routes/sections/auth.tsx`).

### Q: How do I create a new tenant?

**A:** The entry is `/auth/regist-tenant`; the form only needs `name`, `email` and `phone` (`src/auth/view/centered/centered-regist-tenant-view.tsx:37-41`) and submits to the tenant registration endpoint. On success it goes straight to the Rune dashboard (same file, `:71-79`).

### Q: Where do I create a workspace?

**A:** The workspace list page is `/rune/tenants/:tenant/workspaces` (`src/routes/paths.ts:539`). Creation is scoped to a specific cluster: `/rune/tenants/:tenant/clusters/:cluster/workspaces?action=create` (`src/routes/paths.ts:542-543`). In other words, you must pick a cluster before creating a workspace.

> ⚠️ **Note**: The role needed to create a workspace follows from the `workspace:*` and similar permissions derived in the [Permission Model](./permissions); whether the server performs an additional check is not confirmed.

### Q: Why are some buttons missing?

**A:** The console uses `can(action, resource)` to decide which entries to hide (`src/auth/authz/context.tsx:153-167`). The role-to-permission mapping is in the [Permission Model](./permissions). Ask an administrator to adjust your role if you need more permissions.

## ChatApp

### Q: How do I start a conversation in the playground?

**A:** The Experience page is `/rune/chatapp/experience`. It first fetches the account's API keys (`GET /api/airouter/v1/me/profile`) and uses the first one as the data-plane token by default (`src/pages/chatapp/chat.tsx:114-117`). If there is no key, the page points you to [My Tokens](/rune/chatapp/token) (`src/pages/chatapp/chat.tsx:466-475`).

### Q: Which parameters can I tune?

**A:** The parameter panel exposes the following fields, ranges and defaults (`src/pages/chatapp/chat.tsx:59-77`, `src/pages/chatapp/components/chat-params.tsx`):

| Parameter | Default | Range / step |
|-----------|:---:|--------------|
| `temperature` | `0.7` | `0` ~ `1.999`, step `0.1` |
| `topP` | `0.8` | `0.1` ~ `1.0` |
| `maxTokens` | `4096` | `0` ~ `32768`, step `10` |
| `systemPrompt` | empty | Text |
| `stop` | empty | Submitted as `null` when empty |

Deep thinking is on by default; when off the request body sends `reasoning_effort: 'none'`, when on it sends `'high'` (`src/pages/chatapp/chat.tsx:169`).

### Q: Streaming does not work

**A:** Chat requests use SSE (`Accept: text/event-stream`, `src/pages/chatapp/chat.tsx:141-145`). Things to check:

1. Make sure no proxy/WAF interrupts the long-lived connection;
2. Make sure the channel does not return a single JSON response (the page handles the two cases differently, `src/pages/chatapp/chat.tsx:204-210`);
3. Check the browser console for aborts or CORS errors.

### Q: I am being rate limited

**A:** The data plane rate limits per API key through `rateLimitRPM` and `rateLimitTPM`. Exceeding them returns `429`. Adjust the two values in [My Tokens](/rune/chatapp/token); `0` or empty means that dimension is unlimited.

### Q: Where can I see call statistics?

**A:** ChatApp → Usage (route `/rune/chatapp/analysis`). Data comes from `GET /api/airouter/v1/me/usage/dashboard` (`src/services/usage.ts:110-122`); the page defaults to today and refreshes every 30 seconds.

## Troubleshooting

### Q: The page returns 401 / 403

**A:**

| Symptom | Likely cause | Action |
|---------|--------------|--------|
| `401` | Not signed in, or the cookie session has expired | Sign in again |
| `403` | The current role lacks permission for the operation | See the [Permission Model](./permissions); ask an administrator to adjust your role |

### Q: The comparison page is empty after a refresh

**A:** The comparison history is kept in page memory and cleared on refresh. This is the expected behaviour of the current implementation.

### Q: Upload or download operations fail

**A:** Each module's upload implementation and size limits are decided by its own back end; the front-end code cannot give a single answer.

> ⚠️ **Note**: The maximum file size, support for resumable uploads, and similar details are not confirmed.
