# Rune 控制台

Rune 控制台是你在浏览器里使用智算平台的地方，把模型部署成服务、跑微调训练、开开发环境、装应用，都在这个界面完成。这一页帮你把界面认全：左侧每个菜单是干什么的、顶部的区域和工作空间有什么区别、为什么所有功能的操作方式都长得一样。读完你就能自己找到要用的功能，并按统一套路部署出第一个实例。

:::tip 三个类比先建立直觉

- 集群（界面上叫「区域」）≈ 一栋机房大楼，里面有很多台机器。
- 工作空间 ≈ 大楼里的一间办公室，同事之间共享同一间。
- 实例 ≈ 用模板在办公室里开出来的一台机器，推理服务、微调任务、开发环境都是实例。

:::

## 开始之前

- 先登录并选择租户。
- **首页** 和 **应用市场** 对所有成员开放；**工作台** 和 **可观测性** 两个分组要求你的租户角色是 **管理员** 或 **开发者**，普通成员看不到这两个分组。
- 使用任何功能前，先确认页面左上角已经选好 **区域** 和 **工作空间**。

## 先认识顶部的两个选择器

页面左上角有两个选择器，所有页面的数据都跟着它们变：

| 选择器 | 通俗解释 | 说明 |
| --- | --- | --- |
| 区域 | 一栋机房大楼，决定用哪批机器 | 换了区域，能用的算力和工作空间都会跟着变 |
| 工作空间 | 大楼里的一间办公室，同事共享 | 不同办公室里的实例互相看不见 |

- 切换 **区域** 后，系统会自动帮你选中该区域下的第一个工作空间。
- 切换 **工作空间** 后，左侧所有列表都会刷新成这个空间的资源。

:::tip 详情页里切不动是正常的
打开某个实例详情或存储卷详情时，这两个选择器会变成不可点，防止你误切换。想切回别的空间，先返回列表页再切。
:::

## 左侧菜单结构

登录后的左侧导航分成三组：

| 分组 | 菜单项 | 用途 |
| --- | --- | --- |
| 首页 | 首页、应用市场 | 看当前空间的家底、逛现成模板 |
| 工作台 | 推理服务、训练与微调、开发服务、应用实例、我的模板、文件存储 | 部署和管理你的实例 |
| 可观测性 | 指标、日志、模型评测 | 看训练曲线、查运行日志、评估模型 |

工作台和可观测性需要你的租户角色是 **管理员** 或 **开发者**。

## 所有实例都长一个样

不管你要部署哪种东西，它们在平台里都叫「实例」，只是类型不同：

| 菜单 | 你可以用它做什么 |
| --- | --- |
| 推理服务 | 把模型部署成在线服务，别人可以调用 |
| 训练与微调 | 拿现成模型再补课，让它更懂你的业务 |
| 开发服务 | 开一个带 Jupyter / VSCode 的交互式开发环境 |
| 应用实例 | 部署通用应用，例如 Web 界面、工具类服务 |
| 指标 | 部署实验追踪服务，记录训练曲线 |
| 模型评测 | 部署评测服务，给模型打分 |

因为它们共用同一套模型，所以操作套路完全一致。学会部署推理服务后，其他类型只是各有几个专属参数。

## 部署任何东西的通用四步

1. 左侧菜单点进对应功能，例如 **推理服务**。
2. 点右上角 **创建…** 按钮（例如 **创建推理服务**），进入模板选择页。
3. 选一个模板、确认 **版本**，点 **部署**；也可以在 **应用市场** 里挑好模板再点 **部署**。
4. 填写基础信息和参数，点 **确定** 提交。

:::tip 表单里要填什么由模板决定
除了「名称、描述」这类固定项，其余参数都来自所选模板。不同模板要填的东西不一样，不要把某一页的字段清单直接套到另一个模板上。
:::

## 实例详情页能看到什么

在列表里点实例名称进入详情，所有类型共享同一套页面：

| 页签 / 菜单 | 内容 |
| --- | --- |
| 概览 | 基本信息、容器组列表；应用实例还多一个存储卷列表 |
| 监控 | 实例的资源使用曲线 |
| 日志 | 实例的运行日志 |
| 事件 | 系统事件流，用来排查失败原因 |
| 右上角 **操作** | 编辑、启动 / 停止、扩缩容、删除等 |

:::warning 删除会连资源一起清掉
点 **操作** 里的 **删除** 需要二次确认。删除实例会同时释放它占用的计算资源和关联资源，无法恢复。
:::

## 结果确认

- 创建后在对应列表里能看到这条实例，**状态** 列先显示 等待中 / 执行中，稍后变成 **运行中** 或 **健康**。
- 如果状态停在 **处理失败**，进详情页的 **事件** 和 **日志** 页签找原因。
