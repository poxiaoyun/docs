# 批量推理

批量推理解决的是「**有一大批数据要跑，但不需要一直开着一个服务**」的问题。
你把数据放在文件存储（S3）里，提交一个任务写明输入、输出和推理参数，平台会用空闲的执行器把这条数据队列跑完，结果直接写回你的存储桶。
读完这一页，你能独立创建一个批量推理任务、看懂它的状态和进度，并知道跑砸了怎么重来。

:::tip 把它想成一条流水线
推理服务是「开一家门店，随时有人来问」；批量推理是「把一箱原料送进车间，做完再装箱送回来」。
车间（执行器）不是你专属的，谁的任务先排上谁先用，所以会有**排队中**这个状态。
:::

## 认识概念

| 名词 | 通俗解释 | 可以理解成 |
| --- | --- | --- |
| 批量推理 | 一次处理一批数据的任务，跑完就结束，不产生可访问的实例 | 把整箱原料送进车间加工 |
| 任务 | 一次提交的批处理作业，有自己的名称、状态和执行历史 | 一张加工单 |
| 输入数据 | 放在 S3 里的待处理文件或目录前缀 | 送进车间的原料 |
| 输出位置 | 结果写回的 S3 目录，同名文件会被覆盖 | 加工完送回哪个货架 |
| 执行器 | 真正干活的那个运行单元，用它自己配置的模型和凭据 | 车间里接这张单的工人 |
| 执行记录 | 任务每次被领取执行的一次尝试，重跑会新增一条 | 加工单的一次流转记录 |

:::info 任务不是实例
批量推理**不会**在推理服务列表里留下一个可以调用地址的实例，所以它不占着算力干等，也不会出现在首页的工作负载统计里。
:::

## 开始之前

- 你的租户角色需要是**管理员**或**开发者**。如果左侧看不到 **批量推理**，说明当前环境没有启用该功能。
- 左上角**区域**和**工作空间**已经选好。
- 准备好 S3 的**服务地址、存储桶、对象路径**，以及一对**访问密钥 ID / 访问密钥**；私有桶还需要会话令牌（可选）。
- 数据和结果要放在执行器能访问到的存储桶里；不确定就先问平台管理员执行器配了哪些存储。

## 看任务列表

左侧 **工作台** 分组里点 **批量推理**。页面顶部是标题和 **刷新**，下面是筛选条和任务表格。

![批量推理列表：状态与任务类型筛选、五列表格、右上角「创建任务」](/assets/screenshots/rune/batch-inference-01.png)

| 列 | 看什么 |
| --- | --- |
| 任务名称 | 点名称进入任务详情 |
| 状态 | 见下面的状态表 |
| 任务类型 | **大模型文本生成** 或 **目标检测** |
| 创建时间 | 什么时候提交的 |
| 完成时间 | 结束（成功、失败或取消）的时间；没结束就是空 |

筛选条有两个下拉加一个搜索框：

| 控件 | 可选值 |
| --- | --- |
| 状态 | 排队中 / 运行中 / 取消中 / 已取消 / 已完成 / 部分成功 / 失败 |
| 任务类型 | 大模型文本生成 / 目标检测 |
| 搜索 | 按任务名称搜索 |

状态一共七种，含义差别很大：

| 状态 | 含义 | 接下来能做什么 |
| --- | --- | --- |
| 排队中 | 正在等匹配的**执行器**和并发名额 | 等；长时间不动找管理员查执行器状态 |
| 运行中 | 执行器正在处理数据 | 等，或按需取消 |
| 取消中 | 已请求停止，正在等当前执行结束或取消截止时间 | 等它变成已取消 |
| 已取消 | 已经停下，已写入的结果保留 | 可重新提交或删除 |
| 已完成 | 全部输入处理成功 | 可删除 |
| 部分成功 | 部分输入成功、部分失败 | 看失败原因后重新提交，或删除 |
| 失败 | 整体执行失败 | 看失败原因后重新提交，或删除 |

## 创建批量推理任务

1. 在列表页点右上角 **创建任务**。
2. 页面会先加载可用的任务类型；如果一个都没有，会提示「没有可用任务类型，请联系管理员检查 Batch 服务」。
3. 按下面的四步填完表单，提交后自动跳到这个任务的详情页。

### 第一步 基本信息

| 字段 | 怎么填 | 说明 |
| --- | --- | --- |
| 任务名称 | 例如 `qwen-batch-0715` | 必填，最长 256 个字符 |
| 任务类型 | **大模型文本生成** 或 **目标检测** | 必选；切换类型会重置下面的参数 |
| 描述 | 例如「7 月客服语料批量打标」 | 选填，最长 4096 个字符 |

### 第二步 填输入数据

| 字段 | 怎么填 | 说明 |
| --- | --- | --- |
| S3 服务地址 | 例如 `https://s3.example.com` | 必填，必须是 http(s) 地址，不能带用户名密码、查询参数或片段 |
| 存储桶 | 例如 `my-dataset` | 必填，不能包含斜杠 |
| 对象路径 / 前缀 | 文本生成填 JSONL 文件或包含 JSONL 的目录 | 必填 |
| 访问密钥 ID | S3 的 AK | 必填 |
| 访问密钥 | S3 的 SK | 必填，输入后不回显 |
| S3 区域 | 例如 `cn-east-1` | 选填，放在 **附加配置** 里 |
| 寻址方式 | **路径式** 或 **虚拟主机式** | 默认路径式；桶域名风格不同时改这里 |
| 会话令牌 | 临时凭据才需要 | 选填，也在 **附加配置** 里 |

输入卡右上角有 **输入模板**，点开是可直接照抄的样例：

- **大模型文本生成**：每行一个 JSON，必须带唯一的 `id` 和 `request_body.messages`（也兼容顶层的 `messages`）。`request_body` 里的参数会覆盖任务级公共参数，**模型由执行器指定**。
- **目标检测**：可以是单张图片、图片目录前缀，或一份 JSONL 清单；清单每行包含唯一的非负整数 `id` 和 `image.path`，图片路径相对于输入存储桶。

### 第三步 填输出位置

字段和输入一样：地址、存储桶、路径、密钥，以及附加配置。差别只有两点：

- 输出路径可以留空；但**与输入在同一个存储桶时必须分开**，否则提交时报「同一存储桶中的输入输出路径不能相同或互相包含」。
- 结果**直接写入**你填的目录，同名文件会被覆盖。

### 第四步 调推理参数

面板标题是 **推理参数**，右侧有一句说明：任务由符合条件的执行器领取，并使用该执行器配置的模型；重新执行时可能换成别的模型。

大模型文本生成常用这几个：

| 参数 | 默认值 | 怎么用 |
| --- | --- | --- |
| 温度 | 见页面默认值 | 控制随机性，范围 0–2；越低越稳定，越高越多样。通常只调它和核采样概率中的一个 |
| 核采样概率（top_p） | 见页面默认值 | 从累计概率达到此值的候选里采样，范围 0–1；越低候选越窄 |
| 系统提示词 | 留空 | 给每条输入设统一的角色和指令，会替换输入里原有的 system 消息；逐条的 `request_body.system` 可以覆盖 |
| 最大生成 Token 数 | 见页面默认值 | 每条输入最多生成多少 Token；必须在执行器的输出预算内 |

目标检测类任务用 **置信度阈值** 取代上面几个文本参数。

需要模型支持的额外参数时，点 **添加自定义参数**，填 **自定义参数名 / 值类型 / 自定义参数值**：

- 参数名必须以字母或下划线开头，只含字母、数字、下划线，最长 128 个字符；
- 不能和平台管理的参数重名；
- 值类型有文本 / 数字 / 布尔值 / JSON，JSON 可填数组或对象。

:::warning 提交前的两条硬校验
1. **S3 地址**必须是 http(s)，且不能包含账号密码、查询参数或片段。
2. **同一存储桶内输入与输出路径不能重叠**（相同、或互相包含都算）。想省事就分两个桶，或者一个放 `input/` 一个放 `output/`。
:::

## 任务详情看什么

提交成功后进入 **任务详情**，从上到下是五块：

| 区块 | 内容 |
| --- | --- |
| 基本信息 | 状态、任务类型、创建时间、完成时间、**任务 ID**（可复制）、描述；右上角 **刷新** |
| 推理参数 | 这次任务实际使用的参数清单（右侧栏） |
| 最近一次执行 | **执行进度**（已处理 / 总数）、成功条数、失败条数、执行器、实际模型 / 版本、开始时间、执行 ID |
| 数据与结果 | 输入路径、输出目录、输入 / 输出 S3 服务地址、结果目录、结果文件 |
| 执行历史 | 表格：执行 ID / 状态 / 进度 / 执行器 / 失败原因 / 开始时间 |

几条读法：

- **已处理 / 总数** 是进度；总数还没统计出来时显示「待统计」，不要误以为卡住了。
- 结果文件请到对象存储里看。任务结束前、或执行失败 / 取消时，文件可能不完整。
- 排队中时页面会直接提示「任务正在等待匹配…执行器及可用并发名额」；取消中会提示正在等执行结束。长时间排队请找管理员查执行器状态和配置。
- 还没被领取时，执行历史为空并提示「尚未分配执行器」。


## 取消、重新提交、删除

这三个操作都在任务详情页，按当前状态决定能不能点：

| 操作 | 什么状态可用 | 会发生什么 |
| --- | --- | --- |
| 取消任务 | 排队中、运行中 | 排队中的立即取消；运行中的会请求停止，等当前执行结束或取消截止时间到达后完成取消。已写入的结果保留 |
| 重新提交 | 已取消、失败、部分成功 | 用原参数和输入输出位置重新排队，**重新处理全部输入**，可能再次产生推理费用。任务 ID 和执行历史保留，新结果写入原输出目录并**覆盖同名文件** |
| 删除任务 | 已完成、已取消、失败、部分成功 | 永久删除任务及其全部执行历史，**无法恢复**；S3 里的输入数据和已生成的结果文件会保留 |

:::warning 重新提交前先确认三件事
1. **凭据是否还有效**：存储凭据过期时，弹窗里可以展开 **替换存储凭据** 重新填访问密钥 ID / 访问密钥 / 会话令牌。
2. **输出目录会不会被覆盖**：同名结果会被直接覆盖，想保留上一次结果就先换一个输出目录。
3. **还会不会再花钱**：重新提交会重新跑全部输入，按执行器的用量再次计费。
:::

如果点开弹窗后状态已经变了（别人取消了、任务已经跑完），页面会提示「任务当前状态不支持此操作」，关掉弹窗刷新即可。

## 计费与配额要注意什么

批量推理和「开一个实例」在费用与额度上的算法不一样，动手前先记住三点：

| 关注点 | 说明 |
| --- | --- |
| 不产生实例 | 任务跑完就结束，不会在推理服务列表里留下实例，也不会长期占着工作空间的算力配额 |
| 重跑会再花一次 | **重新提交**会重新处理全部输入，等于再跑一遍，可能再次产生推理费用；改输出目录可以保留上一次结果 |
| 排队和执行器有关 | 排队中说明在等**执行器**和它的并发名额，这不是工作空间配额不够。提示没有可用并发名额时，找管理员查执行器配置 |

:::warning 结果文件会覆盖
同一个输出目录里，重新提交会直接覆盖同名文件。想留档就先换一个输出目录，或在结果目录里另建子目录。
:::

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 任务长时间停在排队中 | 没有匹配任务类型和参数要求的执行器，或并发名额已满 | 联系管理员检查执行器状态与配置；或稍后再看 |
| 提交时报「同一存储桶中的输入输出路径不能相同或互相包含」 | 输入和输出用了同一个桶的相同或嵌套目录 | 换成独立目录或独立桶 |
| 提交时报地址格式错误 | S3 地址带了查询参数、账号密码，或不是 http(s) | 只填协议 + 域名，例如 `https://s3.example.com` |
| 任务显示部分成功 | 部分输入处理失败，其余成功 | 进执行历史看**失败原因**，修好数据后重新提交 |
| 重新提交后又失败，提示凭据问题 | 原来的访问密钥过期了 | 在重新提交弹窗里展开 **替换存储凭据** 换一对密钥 |
| 结果目录里找不到文件 | 任务还没结束，或执行失败 / 取消导致结果不完整 | 等任务进入已完成，或去执行历史看失败原因 |
| 左侧没有「批量推理」菜单 | 当前环境未启用批量推理 | 联系管理员确认是否需要开启 |
