# 创建工作负载

在 Rune 里，「工作负载」不是一个独立的资源类型，而是对所有 **Instance（实例）** 的统称。推理服务、微调任务、开发环境、应用、实验、评测都是实例，只是 `category`（实例类型）不同。因此创建任何工作负载都走同一套流程：**选择模板 → 填写基本信息 → 填写模板参数 → 提交**。

## 实例数据模型

一个实例的核心字段如下（见 `src/types/instance.ts`）：

| 字段 | 说明 |
| --- | --- |
| `id` | 实例唯一标识，对应 K8s 资源名，创建后不可修改 |
| `name` | 显示名称 |
| `description` | 描述 |
| `type` | 实例类型，即 `category`（`inference` / `tune` / `im` / `app` / `experiment` / `evaluation`） |
| `product` | 来源产品模板信息：`id` / `name` / `version` / `url` |
| `values` | 模板参数集合，即 Schema 表单填写/JSON 编辑的内容 |
| `extensions` | 实例扩展配置 |
| `cluster` / `namespace` | 所属集群与工作空间命名空间 |
| `status` | 运行状态，见下文状态枚举 |

## 创建步骤

1. **进入部署入口**：在实例列表页右上角点击「创建<资源类型>」按钮，会跳转到该类型的产品列表 `/rune/products/:category`；也可以从应用市场 `/rune/app-market` 中某个模板的详情页点「部署」直接进入。按钮文案由 i18n key `create_resource` 渲染（文案模板为 `创建{{resource}}`，`resource` 取该类型的导航名，如「推理服务」「应用实例」），即渲染为「创建推理服务」「创建应用实例」等，不是「部署」。
2. **选择模板与版本**：在产品列表/详情页选定具体产品模板和版本。版本决定了可用的参数 Schema。
3. **填写基本信息**：表单的基础区只有三个字段。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 实例 ID，编辑态禁用不可改 |
| `name` | ✅ | 显示名称 |
| `description` | — | 描述，多行文本 |

4. **填写模板参数**：模板参数由该版本的 JSON Schema 动态渲染，支持两种模式，可随时切换：

| 模式 | 说明 |
| --- | --- |
| 图形模式 | 由 SchemaForm 按 Schema 渲染表单控件 |
| JSON 模式 | 直接编辑参数 JSON；JSON 非法时无法提交 |

> 💡 提示: 是否存在「规格」「存储卷」「副本数」等具体字段，完全取决于所选模板的 Schema，而不是控制台的固定步骤。不同模板的参数字段可能完全不同。

5. **提交**：点击「确认」后创建实例。

## 创建后去哪里看

提交成功后，在对应类型的实例列表中查看，路径为
`/rune/tenants/:tenant/clusters/:cluster/workspaces/:workspace/<category>s`（如 `.../ims`、`.../inferences`）。

列表通用列包括：名称、模板（产品名 + 版本）、规格（Flavor，由 `values.flavor` 解析）、状态、创建时间等；推理类型额外展示模型与副本数列。微调、开发环境、应用、实验、评测类型的创建者列被移到列表末尾，其余类型紧跟在模板列之后。

## 实例状态枚举

状态字段为 `status.phase`，前端枚举 `InstanceStatusPhaseEnum` 共 12 个取值：

| 状态 | 说明 |
| --- | --- |
| `Reconciling` | 正在调和（创建/更新中） |
| `Installed` | Helm Chart 已安装 |
| `Pending` | 等待调度或资源 |
| `Running` | 运行中 |
| `Healthy` | 健康 |
| `Unhealthy` | 不健康 |
| `Degraded` | 降级运行 |
| `Paused` | 已暂停 |
| `Succeeded` | 已完成 |
| `PartialFailed` | 部分失败 |
| `Failed` | 失败 |
| `Terminating` | 正在删除 |

> ⚠️ 注意: 不同文档页面曾使用过 `Installed → Healthy → Succeeded/Failed` 的简写状态机，实际前端枚举以上表为准。
