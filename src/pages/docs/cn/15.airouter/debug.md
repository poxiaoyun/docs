# 参数配置

模型回答不合适的时候——太发散、太死板、说到一半被截断——先别急着换模型，改几个参数往往就有效。这一页讲清楚参数在哪调、每个参数管什么，以及出现什么现象该动哪一个。

:::info 这一页不是一个独立页面
聚合网关顶部导航里没有「调试」入口。参数调节是在 [模型体验](./experience.md) 和 [模型对比](./compare.md) 两页里，通过顶部的 **参数配置** 弹窗完成的。本页说明这个弹窗。
:::

## 在哪儿打开参数

| 页面 | 怎么打开 |
| --- | --- |
| **模型体验** | 点对话区顶部那一排里的调参图标（鼠标悬停显示 **参数配置**）。窗口足够宽时，也可以直接在右侧 **参数设置** 面板里改 |
| **模型对比** | 左栏和右栏顶部各有一个调参图标，两侧参数**互不影响**，可以分别设置 |

同一页里的两处入口（弹窗与右侧面板）改的是同一份参数，在一处改，另一处会同步。

:::info 两处入口的滑杆刻度不一样
右侧面板：**Temperature** 最右拖到 `2`，**Max Tokens** 每拖一格 128。
弹窗里：**Temperature** 最右是 `1.999`，**Max Tokens** 每格 10。
两处改的是同一个值，只是拖动时的档位不同，模型最后收到的还是同一个数。
:::

上图是弹窗形态的 **参数配置**：从上到下依次是 **System**（多行）、**Top P**、**Temperature**、**Max Tokens**、**Stop**，每个滑杆右侧都有数字框，可以敲精确值。注意截图里**参数配置**窗口挡住了一部分对话区，属正常现象，关掉即可。

## 改完什么时候生效

- 改动会**立刻记住**，关闭弹窗不会丢。
- 但只对**之后发送的消息**生效。已经发出去、已经收到的回答不受影响。
- 想让改动作废，重新打开弹窗改回来即可；弹窗里的 **System** 和 **Stop** 一填上内容，右上角就会出现清除按钮，可以一键清空（右侧面板里没有这个按钮）。

## 五个参数分别管什么

| 参数 | 默认值 | 可填范围 | 作用 |
| --- | --- | --- | --- |
| **System** | 空 | 任意文字 | 系统提示词，给模型定人设和规矩，例如「你是一个AI助手」。留空就不加 |
| **Top P** | `0.8` | 0.1 ~ 1.0，步长 0.1 | 控制取词范围，取值越大，生成的随机性越高 |
| **Temperature** | `0.7` | 0 ~ 1.999，步长 0.1 | 控制随机性和多样性。数值越高越发散，越低越稳定 |
| **Max Tokens** | `4096` | 0 ~ 32768，步长 10 | 一条回复最多生成多少 Token。填 `0` 表示不限制 |
| **Stop** | 空 | 任意文字 | 生成时一旦遇到这段内容就停住。留空则不生效 |

:::tip 两个小经验
- **Temperature** 和 **Top P** 都在影响随机性，建议只调整其中一个，另一个保持默认，否则很难判断是哪个起了作用。
- 数字填超范围会被自动拉回允许区间（例如 **Top P** 填 `2` 会变成 `1`），不用自己盯着边界。
:::

![窗口拉宽到 1536px 以上时，对话区右侧出现「模型信息」与「参数设置」面板](/assets/screenshots/airouter/debug-02.png)

窗口拉宽后右侧会自动出现 **模型信息** + **参数设置** 两块。面板里只有 `Temperature`、`Max Tokens`、`Top P` 三个滑杆，`System` 与 `Stop` 收在底部的 **更多参数** 里；密钥则用面板顶部的 **API 密钥 / 访问凭证** 下拉框切换。和弹窗改的是同一份参数，改一处另一处同步。

## 出现这些情况，就动这个参数

| 现象 | 在这一页怎么做 |
| --- | --- |
| 回复被截断，说到一半就没了 | 把 **Max Tokens** 调大（最多 32768）；填 `0` 表示不限制 |
| 每次回答都不一样、容易跑题 | 调低 **Temperature**，比如 0.1 ~ 0.3 |
| 回答太死板、来回重复 | 调高 **Temperature**，比如 0.8 ~ 1.2 |
| 希望它固定用某种身份或风格回答 | 在 **System** 里把身份和要求写清楚 |
| 总是在某段内容之后突然停住 | 检查 **Stop** 里是不是填了东西，清空它 |
| 想验证是模型的问题还是参数的问题 | 去 [模型对比](./compare.md)，两侧选同一个模型，只改一侧参数 |
| 报错：请求过于频繁、配额不足、无效的 API 密钥、上下文长度超出限制 | 这些和参数无关，报错文案显示在对话页的消息位置上，对照 [模型体验](./experience.md) 的常见问题处理 |

## 不同场景的调参建议

| 场景 | 建议 |
| --- | --- |
| 事实性问答、按资料回答 | **Temperature** 调到 0.1 ~ 0.3，**Top P** 适当调低 |
| 写代码 | **Temperature** 调到 0.2 ~ 0.4，并在 **System** 里写明语言和代码风格 |
| 创意写作、头脑风暴 | **Temperature** 调到 0.8 ~ 1.2 |
| 回答总是写不完 | 调大 **Max Tokens** |
| 只想让模型答得更简短 | 在 **System** 里写明字数或格式要求，比调参数更直接 |

:::warning 不是所有模型都认这些参数
参数会原样带进这次调用，但**能不能生效取决于模型自己**：有些模型不支持 Temperature 之类的设置，或对取值有自己的限制。页面不会拦截，所以改完没变化时，先换一个支持该参数的模型试试。
:::

## 结果确认

参数改完后发一条新消息，观察回答是否符合预期：变短、变稳、不再被截断，就说明生效了。同一组参数想反复验证，去 [模型对比](./compare.md) 固定成两侧对照最直观。
