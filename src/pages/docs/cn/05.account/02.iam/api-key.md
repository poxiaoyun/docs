# API Key

API Key 是一对给**程序**用的账号密码，由 AccessKey（简称 AK）和 SecretKey（简称 SK）组成。
当你要让脚本、外部工具或自建应用代替你调用平台接口时，就用这对密钥证明身份，
而不是靠人手输入账号密码。这页会带你在 **访问密钥** 页里把它生成出来，并说清它为什么只显示一次。

:::tip 类比
账号密码是给人用的钥匙，API Key 是给机器用的门禁卡。机器不会输密码，就靠这张卡进出。
:::

## 开始之前

- 这是你自己账号的设置，登录后就能操作，不需要额外的租户角色。
- 先想清楚这对密钥要交给哪个程序使用，生成后你要在那边把它填上。
- 一个账号只有一对密钥：生成新密钥会替换旧密钥。

## 先弄清两个词

| 名词 | 通俗解释 |
| --- | --- |
| Access Key | 相当于「用户名」，可以出现在请求里，列表里也一直能看到 |
| Secret Key | 相当于「密码」，只在生成的那一刻显示一次，窗口关掉就再也看不到 |

## 访问密钥页里有什么

**访问密钥** 页上有两个区块，本页讲第一个：

| 区块 | 说明 | 详细步骤 |
| --- | --- | --- |
| **API Key** | 说明文字是 **用于通过 API 访问服务。** | 本页 |
| **SSH 密钥** | 说明文字是 **管理用于 SSH 身份验证的公钥。** | [SSH 密钥](/account/iam/ssh-key) |

## 生成密钥

1. 点击右上角头像 → **个人设置**。
2. 点击页签 **访问密钥**，找到 **API Key** 区块。
3. 点击区块右侧的动作按钮。还没有密钥时是 **生成**，已经有密钥时是 **重新生成**。
4. 弹出确认窗，确认文案是其中之一：

   | 按钮 | 确认文案 |
   | --- | --- |
   | **生成** | 生成后请立即保存 Secret Key，它只展示一次。 |
   | **重新生成** | 重新生成会立即替换现有密钥，旧密钥随即失效。 |

5. 在确认窗里再点一次 **生成** / **重新生成**。
6. 弹出结果窗，标题 **生成成功**，里面有两个可复制的字段：**Access Key** 和 **Secret Key**。

:::warning Secret Key 只出现这一次
结果窗里的提示写着 **请牢记以下Access Key与Secret Key, Secret Key仅在此出现一次!**
请当场点复制，粘贴到密码管理器或程序的配置里，再关窗口。窗口一关，页面上就再也看不到它。
:::

## 结果确认

生成成功后：

- **API Key** 区块下方的列表里出现一行，显示密钥名称和 Access Key。
- Secret Key 只存在于刚才那个结果窗里，列表里不会显示。

## 密钥丢了或者泄露了

| 情况 | 怎么办 |
| --- | --- |
| Secret Key 忘了保存 | 无法再查看，只能点 **重新生成** 换一对 |
| 怀疑密钥被别人看到 | 立刻 **重新生成**，并把所有使用旧密钥的程序改成新值 |
| 想把密钥彻底作废 | 页面没有单独的「删除密钥」按钮，**重新生成** 就是作废旧 Key 的方法 |

:::warning 重新生成之后要更新程序
重新生成会立刻让旧 Key 失效。请把所有用到旧密钥的脚本、应用配置同步换成新值，
否则这些程序会因为凭据无效而报错。
:::

:::warning 绝不能把密钥提交到 Git
Access Key 和 Secret Key 一旦写进代码并提交到仓库，任何能看到仓库的人都等于拿到了你的凭据。
正确做法是放在环境变量或本机配置文件里，并确保这些文件不会被提交。
:::
