# IAM API Key（AK/SK）

API 密钥是一对给**程序**用的账号密码，由 AccessKey（简称 AK）和 SecretKey（简称 SK）组成。
当你要让脚本、外部工具或自建应用代替你调用平台接口时，就用这对密钥证明身份，
而不是靠人手输入账号密码。这页会带你把它生成出来，并说清它为什么只显示一次。

:::tip 类比
账号密码是给人用的钥匙，API 密钥是给机器用的门禁卡。机器不会输密码，就靠这张卡进出。
:::

## 开始之前

- 这是你自己账号的设置，登录后就能操作，不需要额外的租户角色。
- 先想清楚这对密钥要交给哪个程序使用，生成后你需要在那边把它填上。

## 先弄清两个词

| 名词 | 通俗解释 |
| --- | --- |
| AccessKey | 相当于「用户名」，可以出现在请求里，页面列表里也一直能看到 |
| SecretKey | 相当于「密码」，只在生成的那一刻显示一次，之后页面不再展示 |

## 生成密钥

1. 点击右上角头像 → **个人设置**。
2. 点击顶部的 **API Key** 页签。
3. 还没有密钥时，页面中间是空内容；已经有密钥时，这里会列出密钥名称和 AccessKey。
4. 点击页面底部的 **生成** 按钮。如果已有密钥，这个按钮显示为 **重新生成**。
5. 页面顶部出现绿色提示 **生成成功**，下面同时列出这次的 **AccessKey** 和 **SecretKey**，各带一个复制按钮。

:::warning SecretKey 只显示这一次
成功提示里明确写着「请牢记以下Access Key与Secret Key, Secret Key仅在此出现一次!」。
提示关掉之后，页面上就再也看不到这串 SecretKey 了，请当场复制并保存到你的密码管理工具里。
:::

## 结果确认

生成成功后会同时发生两件事：

- 页面顶部出现绿色的 **生成成功** 提示，并展示 AccessKey 与 SecretKey。
- 页面下方列表里的 AccessKey 更新为这一次生成的值。

回到 **API Key** 页签，列表里能看到的只有密钥名称和 AccessKey，
SecretKey 只出现在刚才那条成功提示中。

## 密钥丢了或者泄露了怎么办

| 情况 | 怎么办 |
| --- | --- |
| SecretKey 忘了保存 | 页面无法再次查看，只能点击 **重新生成** 换一对新密钥 |
| 怀疑密钥被别人看到 | 立刻点击 **重新生成**，并把所有使用旧密钥的程序改成新值 |
| 想把密钥彻底作废 | 页面没有删除按钮，只能用 **重新生成** 换一对新密钥 |

:::warning 重新生成之后要更新程序
重新生成会给你一对新的 AccessKey 和 SecretKey。请把所有用到旧密钥的脚本、
应用配置都改成新的，否则这些程序可能因为拿不到有效凭据而报错。
:::

:::warning 绝不能把密钥提交到 Git
AccessKey 和 SecretKey 一旦写进代码并提交到 Git 仓库，任何能看到仓库的人都等于拿到了你的凭据。
正确做法是把密钥放在环境变量或本机配置文件里，并确保这些文件不会被提交。
:::
