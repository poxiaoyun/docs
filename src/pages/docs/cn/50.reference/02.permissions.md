本文说明控制台前端使用的权限模型：权限字符串长什么样、由哪些角色推导出来、以及不同作用域下能看到什么。

> ⚠️ 注意: 当前版本的前端权限**由角色在前端推导**，而不是从后端拉取权限清单。`src/auth/authz/context.tsx:28-31` 的注释明确写着「根据角色模拟生成权限列表，后端暂无 /permissions API 时使用，后续可直接替换为 API 调用」。因此本文描述的是**界面级**权限控制，服务端是否做同等校验不在本文范围内。

---

## 权限字符串格式

权限用 `resource:action` 表示，例如 `instance:create`、`workspace:list`。判定逻辑在 `src/auth/authz/context.tsx:153-167`：

1. 若拥有 `*:*`，直接放行（系统管理员）；
2. 若拥有 `${resource}:*`，该资源下任意操作放行；
3. 否则精确匹配 `${resource}:${action}`；
4. 若调用 `can()` 时传入了 `service`，则匹配三段式 `${service}:${resource}:${action}`。

> 💡 提示: 业务代码中常见的写法是 `can('create', 'instance')` / `can('list', 'workspace')`，参数顺序为**先操作、后资源**（`src/auth/authz/types.ts:18-24`）。

## 作用域模型

角色记录的数据结构是 `UserRole`（`src/types/member.ts:22-29`），每条记录包含用户名，以及可选的 `tenant`、`workspace`、`cluster` 字段和 `roles` 数组。由这些字段组合出三种作用域：

| 作用域 | 判定条件（`roles` 含 `admin`） | 管理界面 |
|--------|------------------------------|---------|
| **系统级** | 无 `tenant` 且无 `workspace` | BOSS |
| **租户级** | 有 `tenant`、无 `workspace` | Console |
| **工作空间级** | 有 `tenant` 且有 `workspace` | Console |

角色枚举定义在 `src/types/tenant.ts:18-22`，只有三个值：`admin`、`member`、`developer`。所谓「租户管理员」并不是独立的枚举值，而是**角色为 `admin`、并带有 `tenant` 作用域**的记录；系统管理员则是**没有 `tenant`/`workspace` 的 `admin`**。

> ⚠️ 注意: 当前推导逻辑中没有针对「工作空间级 `admin`」的分支——带 `workspace` 的 `admin` 记录不会生成任何权限。该场景是否为预期行为，暂未确认。

## 角色对应的权限

下表逐条对应 `generatePermissionsFromRoles()`（`src/auth/authz/context.tsx:32-85`），最终结果会去重：

| 角色记录 | 生成的权限 |
|----------|-----------|
| `admin`，无 `tenant`、无 `workspace`（系统管理员） | `*:*` |
| `admin` + `tenant`（租户管理员） | `workspace:*`、`member:*`、`quota:*`、`instance:*`、`image:*`、`template:*`、`volume:*` |
| `developer` + `tenant` | `workspace:list`、`workspace:get`、`instance:*`、`image:list`、`image:get`、`template:list`、`template:get` |
| `member` + `tenant` | `workspace:list`、`workspace:get`、`instance:list`、`instance:get`、`image:list`、`image:get` |

由此可以推出界面上各角色的差异：

| 能力 | 系统管理员 | 租户管理员 | 开发者 | 成员 |
|------|:---:|:---:|:---:|:---:|
| 查看工作空间 | ✅ | ✅ | ✅ | ✅ |
| 创建/编辑/删除工作空间 | ✅ | ✅ | ❌ | ❌ |
| 实例全部操作 | ✅ | ✅ | ✅ | ❌ |
| 查看实例 | ✅ | ✅ | ✅ | ✅ |
| 查看镜像 | ✅ | ✅ | ✅ | ✅ |
| 创建/编辑/删除镜像 | ✅ | ✅ | ❌ | ❌ |
| 查看模板 | ✅ | ✅ | ✅ | ❌ |
| 创建/编辑/删除模板 | ✅ | ✅ | ❌ | ❌ |
| 成员管理 | ✅ | ✅ | ❌ | ❌ |
| 配额管理 | ✅ | ✅ | ❌ | ❌ |
| 存储卷管理 | ✅ | ✅ | ❌ | ❌ |
| 访问 BOSS | ✅ | ❌ | ❌ | ❌ |

> 💡 提示: 系统管理员的 `*:*` 让 `can()` 对任意资源、任意操作都返回 `true`，等同于「拥有全部权限」。

## 角色获取与刷新

- 角色数据来自 `GET /api/iam/current/roles`（`src/services/account.ts:98-101`），在认证成功后自动拉取（`src/auth/authz/context.tsx:109-123`）。
- 未登录时权限列表被清空（`src/auth/authz/context.tsx:113-116`）；拉取失败时同样清空并结束 loading（`:139-143`）。
- `refresh()` 会重新请求角色接口（`src/auth/authz/context.tsx:210`），可用于登录、切换租户/工作空间后刷新权限。
- `hasRole(role, scope?)` 用于简单的角色判断：若当前用户是系统管理员，则对任意角色查询都返回 `true`（`src/auth/authz/context.tsx:182-200`）。

## 常见问题

### 页面上的按钮为什么不见了？

界面会根据 `can()` 的结果隐藏无权限的入口和操作按钮。如果需要更高权限，请联系租户管理员调整角色。

### 切换租户后权限没有变化？

权限与角色记录绑定，切换租户后需要重新获取角色列表。控制台在登录状态变化时会自动触发（`src/auth/authz/context.tsx:109-123`）；若仍不生效，可刷新页面。
