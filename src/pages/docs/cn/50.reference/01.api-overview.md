本文按控制台前端代码里**实际发起**的请求，说明平台后端 API 的路径划分、鉴权方式和典型端点。

> 💡 提示: 控制台是单页应用，所有请求都指向 `window.location.origin`（`src/global-config.ts:48`），由同域名下的反向代理按路径前缀分发到不同后端服务。

---

## 两条链路：管理面与数据面

| 对比项 | 管理面 | 数据面 |
|--------|--------|--------|
| 路径前缀 | `/api/...` | `/airouter-data/v1/...` |
| 典型用途 | 管理 Token、查询用量、读写平台配置，以及 IAM / Cloud / Moha 的资源操作 | 调用大模型对话（OpenAI 兼容 Chat Completions） |
| 鉴权 | 浏览器 Cookie `user_session`（自动携带） | 请求头 `Authorization: Bearer <API Key>` |
| 调用方 | 控制台页面内部的 axios 实例 | 控制台页面、外部程序 |

> ⚠️ 注意: 早期文档把 LLM 的 `base_url` 写成 `/api/airouter/v1`，这是**管理面**前缀，不是对话接口地址。对话接口在 `/airouter-data/v1`。

---

## 管理面 API

### 鉴权方式

- 登录成功后，会话令牌保存在名为 `user_session` 的 Cookie 中（`src/auth/authn/token.ts:3`）；退出登录时通过 `Cookies.remove('user_session', { path: '/' })` 清除（同文件 `:9-11`）。
- 全局 axios 实例只统一设置 `Content-Type: application/json`，`baseURL` 为当前站点源（`src/lib/axios.ts:10-15`）。
- 请求拦截器**不注入** `Authorization` 头——注入逻辑被注释掉（`src/lib/axios.ts:21-28`）。管理面鉴权完全依赖浏览器自动携带的 Cookie。
- 因此管理面接口不适合在浏览器之外用 Bearer Token 调用；如需程序化调用 LLM，请使用下面的数据面。

### 服务域（按路径前缀）

| 前缀 | 服务 | 典型端点 | 代码位置 |
|------|------|---------|---------|
| `/api/iam` | IAM：登录/注册、用户、租户、成员与角色、SSH Key、验证码、MFA | `POST /api/iam/login`、`GET /api/iam/current/roles`、`GET /api/iam/captcha` | `src/services/iam.ts`、`src/services/account.ts` |
| `/api/cloud` | Cloud：集群、工作空间、实例、规格、配额、调度、日志 | `GET /api/cloud/tenants/{tenant}/clusters/{cluster}/workspaces` | `src/services/workspace.ts`、`src/services/instance.ts`、`src/services/flavor.ts` |
| `/api/ai` | AI：实例运行指标 | `GET /api/ai/tenants/{tenant}/.../instances/{instance}/metrics/{metrics}` | `src/services/instance.ts` |
| `/api/moha` | Moha：模型、数据集、镜像、组织 | `GET /api/moha/organizations/{org}/images` | `src/services/image.ts`、`src/services/tenant-config.ts` |
| `/api/airouter/v1` | LLM 网关管理面：Token、调用日志、用量、全局设置 | `GET /api/airouter/v1/me/tokens`、`GET /api/airouter/v1/me/usage/dashboard` | `src/services/api-key.ts`、`src/services/usage.ts`、`src/services/runtime-config.ts` |
| `/api/license` | 授权记录 | `GET /api/license/records` | `src/services/license.ts` |

> ⚠️ 注意: 上表只覆盖控制台前端发起过的端点。后端完整的 API 契约（字段定义、错误码、服务端权限校验）不在前端代码中，暂未确认。

## 数据面 API（LLM 网关）

### 地址

Chat Completions 端点为 `{origin}/airouter-data/v1/chat/completions`（`src/pages/chatapp/chat.tsx:159`、`src/pages/chatapp/docs.tsx:38-41`）。模型广场内的 API 文档示例使用同一地址（`src/pages/chatapp/components/model-docs-content.tsx:39-40`）。

### 请求头

| Header | 是否必需 | 说明 |
|--------|---------|------|
| `Authorization` | 必需 | `Bearer <API Key>`，Key 在 ChatApp → 我的 Token 中创建 |
| `Content-Type` | 必需 | `application/json` |
| `Accept` | 流式对话时 | `text/event-stream` |
| `X-Tenant` | 按需 | 模型所属租户；值需 URL 编码 |
| `X-Workspace` | 按需 | 模型所属工作空间；值需 URL 编码 |
| `X-Channel` | 按需 | 指定调用的渠道；值需 URL 编码 |

控制台页面在打开模型体验时，会先读取当前用户的 API Key 列表（`GET /api/airouter/v1/me/profile`，`src/services/api-key.ts:182-184`），并默认取第一个 Key 作为 Bearer 令牌（`src/pages/chatapp/chat.tsx:114-117`）。`X-Tenant` / `X-Workspace` / `X-Channel` 由所选模型带出，并做 `encodeURIComponent` 编码后写入请求头（`src/pages/chatapp/chat.tsx:141-157`）。

### 兼容性与示例

数据面与 OpenAI Chat Completions 兼容，可直接使用官方 SDK——把 `base_url` 指向 `{origin}/airouter-data/v1` 即可。控制台内置了 cURL、Python（requests）、Go 三种示例（`src/pages/chatapp/docs.tsx:43-111`）。

```bash
curl --request POST '{origin}/airouter-data/v1/chat/completions' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "YOUR_MODEL",
    "stream": false,
    "messages": [{"role": "user", "content": "你好，介绍一下你自己"}]
  }'
```

请求体字段与参数默认值见[模型体验](/rune/chatapp/experience)与[参数调试](/rune/chatapp/debug)。

## 状态码与限速

| 状态码 | 含义 |
|--------|------|
| `200` | 请求成功 |
| `400` | 请求参数错误 |
| `401` | 未认证或会话已过期 |
| `403` | 无权限 |
| `404` | 资源不存在 |
| `429` | 触发限速，降低频率后重试 |
| `5xx` | 服务端错误 |

Token 限速按**每个 API Key** 配置，字段为 `rateLimitRPM`（每分钟请求数）与 `rateLimitTPM`（每分钟 Token 数，表单以 K 为单位）——见[我的 Token](/rune/chatapp/token)。

> ⚠️ 注意: 登录接口、验证码是否另有独立的频率限制，前端代码中没有体现，暂未确认。
