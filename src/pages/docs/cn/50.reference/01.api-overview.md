# API 概览

平台的接口分成**两组**，用之前先搞清你在用哪一组，否则很容易把地址写错。

| 对比项 | 管理面 | 数据面 |
| --- | --- | --- |
| 地址前缀 | `/api/...` | `/airouter-data/v1/...` |
| 给谁用 | 控制台页面自己 | 你的程序、脚本、外部应用 |
| 认证方式 | 浏览器登录状态（自动携带） | 请求头里的 API 密钥 |
| 典型场景 | 管理密钥、查用量、读写平台配置 | 发起一次模型对话 |
| 你能直接调用吗 | 不方便（依赖浏览器会话） | 可以，这是给程序用的 |

一句话结论：**要在浏览器之外用程序调用模型，用数据面 `/airouter-data/v1`；管理面是页面自己在用的，通常不需要你手工调用。**

## 先跑通最小示例

在调用之前，先准备一个 API 密钥，见 [API 密钥](/airouter/token)。然后把下面命令里的 `你的平台域名`、`你的API密钥`、`你的模型名` 换成真实值：

```bash
curl --request POST 'https://你的平台域名/airouter-data/v1/chat/completions' \
  --header 'Authorization: Bearer 你的API密钥' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "你的模型名",
    "stream": false,
    "messages": [
      {"role": "user", "content": "你好，介绍一下你自己"}
    ]
  }'
```

数据面与 OpenAI 的 Chat Completions 接口兼容，所以你也可以直接用 OpenAI 官方 SDK，只要把 `base_url` 指向 `https://你的平台域名/airouter-data/v1` 即可。

## 请求头逐项说明

| 请求头 | 是否必需 | 说明 |
| --- | --- | --- |
| `Authorization` | 必需 | 写成 `Bearer 你的API密钥` |
| `Content-Type` | 必需 | 固定 `application/json` |
| `Accept` | 流式对话时 | 写成 `text/event-stream` 才会逐字返回 |
| `X-Tenant` | 按需 | 指定模型所属租户，值需要 URL 编码 |
| `X-Workspace` | 按需 | 指定模型所属工作空间，值需要 URL 编码 |
| `X-Channel` | 按需 | 指定走哪个渠道，值需要 URL 编码 |

常见请求体参数（与 OpenAI 一致）：

| 参数 | 说明 |
| --- | --- |
| `model` | 要调用的模型名，在模型广场里能看到 |
| `messages` | 对话内容数组，包含 `role` 和 `content` |
| `stream` | 设为 `true` 时逐字返回，适合聊天界面 |
| `temperature` / `top_p` | 控制回答的随机性，通常只调其中一个 |
| `max_tokens` | 单次回答的最大长度 |

## 数据面还有哪些接口

| 接口 | 用途 |
| --- | --- |
| `POST /airouter-data/v1/chat/completions` | 对话补全，最常用 |
| `POST /airouter-data/v1/embeddings` | 文本向量化，用于检索、聚类 |
| `POST /airouter-data/v1/rerank` | 结果重排序 |
| `GET /airouter-data/v1/models` | 列出当前密钥可用的模型 |
| `POST /airouter-data/v1/audio/speech` | 语音合成 |
| `POST /airouter-data/v1/audio/transcriptions` | 语音转文字 |
| `POST /airouter-data/v1/responses` | 另一套兼容接口，用法类似 Chat Completions |

## 管理面有哪些接口

管理面按路径前缀再分成几组，各自负责一个领域。下面列出的是控制台页面实际会调用的接口，字段细节以后端为准。

| 前缀 | 负责 | 典型接口 |
| --- | --- | --- |
| `/api/iam` | 身份：登录、用户、租户、成员与角色、验证码、多因素认证、SSH 密钥 | `GET /api/iam/current/roles` |
| `/api/cloud` | 算力控制：集群、工作空间、实例、规格、配额、调度、日志 | `GET /api/cloud/tenants/{租户}/clusters/{集群}/workspaces` |
| `/api/ai` | 实例运行指标 | `GET /api/ai/tenants/{租户}/.../instances/{实例}/metrics/{指标}` |
| `/api/moha` | 魔哈 Hub：模型、数据集、镜像、组织 | `GET /api/moha/organizations/{组织}/images` |
| `/api/airouter/v1` | 大模型网关管理面：密钥、调用日志、用量、网关设置 | `GET /api/airouter/v1/me/tokens`、`GET /api/airouter/v1/me/usage/dashboard` |
| `/api/license` | 授权记录 | `GET /api/license/records` |

大模型网关管理面在 `/api/airouter/v1` 下还分成两类：

- `/me/...` 开头的接口，操作**当前登录用户自己**的数据，例如 `me/tokens`、`me/usage/dashboard`、`me/audit/records`、`me/models`、`me/profile`。
- 不带 `/me` 的接口，属于**平台管理**范畴，需要平台管理员身份，例如 `channels`（渠道）、`tokens`（令牌）、`moderation/policies`（审查策略）、`usage/dashboard`；也有按租户和工作空间限定范围的写法，例如 `tenants/{租户}/workspaces/{工作空间}/channels/{渠道}`。

:::warning 管理面不要用 Bearer 密钥硬调
管理面靠浏览器登录状态鉴权，页面调用时会自动带上会话。你在浏览器之外拿一个密钥去调 `/api/...`，通常不会成功，也不适合做成脚本。要程序化调用模型，请用数据面。
:::

## 从哪里拿接口文档

1. **模型广场里的 API 文档**：进入 [AIRouter](/airouter/)，打开 **模型广场**，点开任意模型，页面里有 **API 文档**，里面提供 cURL、Python、Go 三种可直接复制的示例，并且已经填好了当前的网关地址。
2. **网关自带的接口文档页**：平台部署的大模型网关提供 Swagger 在线文档（由部署方开放，通常是 `/swagger/index.html` 路径），能看到管理面接口的完整列表与字段定义。

## 状态码与限速

| 状态码 | 含义 | 怎么办 |
| --- | --- | --- |
| `200` | 成功 | — |
| `400` | 请求参数有误 | 检查请求体字段名和格式 |
| `401` | 未认证或登录状态已过期 | 管理面重新登录；数据面检查 API 密钥 |
| `403` | 无权限 | 见[权限说明](/reference/permissions) |
| `404` | 资源不存在 | 检查模型名、租户、工作空间是否正确 |
| `429` | 触发限速 | 降低调用频率后重试 |
| `5xx` | 服务端错误 | 稍后重试；持续失败请联系管理员 |

限速按**每个 API 密钥**单独配置，有两个维度：

| 维度 | 含义 |
| --- | --- |
| RPM | 每分钟允许的请求数 |
| TPM | 每分钟允许消耗的 Token 数 |

在 [API 密钥](/airouter/token) 里可以查看和调整。调到上限会返回 `429`。
