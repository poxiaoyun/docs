# 构建与环境

这篇给要**在本地跑起控制台**、或要**把控制台部署到自己的环境**的人。读完你能独立完成：装环境、启动开发服务器、构建出两个版本、看懂每个环境变量的作用。

## 一段命令跑起来

```bash
# 安装依赖（首次）
pnpm install

# 启动本地开发服务器
pnpm dev
```

打开 `http://localhost:8000` 即可。本地开发服务器本身不含后端，它会把 `/api`、`/airouter-data` 等请求**代理转发**到一台后端地址，详见下面的「本地开发代理」。

## 开始之前

| 要求 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | `>= 20` | 低于这个版本安装依赖或启动会失败 |
| pnpm | `10.15.0` | 项目指定了这个包管理器版本 |
| 一个可访问的后端 | — | 本地默认指向开发环境后端，需要有对应的账号 |

## 常用命令

| 命令 | 做什么 |
| --- | --- |
| `pnpm install` | 安装依赖 |
| `pnpm dev` | 启动开发服务器，端口 `8000` |
| `pnpm build` | 类型检查后构建，产出普通用户界面 |
| `pnpm build:boss` | 构建 BOSS 版界面 |
| `pnpm preview` / `pnpm start` | 预览构建产物 |
| `pnpm test` | 运行单元测试 |
| `pnpm lint` | 检查代码规范 |
| `pnpm fm:check` | 检查代码格式 |
| `make build` | 依次构建两个版本，并注入构建信息、放大 Node 内存上限 |

## 两份构建产物

同一个代码库能构建出**两套界面**，靠一个环境变量切换。这是最容易搞混的地方：

| `VITE_PLATFORM` | 产物目录 | 访问路径 | 界面 |
| --- | --- | --- | --- |
| `console`（默认） | `dist/console` | `/console` | 普通用户的智算平台、聚合网关、魔哈 Hub |
| `boss` | `dist/boss` | `/boss` | 平台管理员的 BOSS 门户 |

`VITE_ASSETS_DIR` 可以单独指定静态资源目录；不设置时跟访问路径一致。

:::warning 改了这两个变量，访问地址会跟着变
`VITE_PLATFORM` 同时决定产物目录和页面的基路径。如果你只改了产物目录却忘了网关里的路径映射，页面会白屏或资源 404。改之前先确认部署侧的路由也一起改。
:::

## 本地开发代理

开发服务器监听 `8000` 端口，构建产物的预览服务监听 `3080` 端口。因为后端不在同一端口，开发服务器把下面这些路径转发出去：

| 前端路径 | 转发到的位置 | 用途 |
| --- | --- | --- |
| `/api` | `PROXY_TARGET` | 所有管理面接口 |
| `/moha` | `PROXY_TARGET` | 魔哈 Hub 相关请求 |
| `/airouter-data` | `PROXY_TARGET` | 模型对话的数据面 |
| `/console/airouter-data` | `PROXY_TARGET`（去掉 `/console` 前缀） | 带前缀写法时的数据面 |
| `/avatars` | `PROXY_TARGET` + `/api/iam/avatars` | 头像等静态资源 |

`PROXY_TARGET` 不设置时默认指向开发环境后端 `https://rune.develop.xiaoshiai.cn`。

## 环境变量一览

| 变量 | 用在什么阶段 | 控制什么 | 改了会怎样 |
| --- | --- | --- | --- |
| `VITE_PLATFORM` | 构建 | 构建 `console` 还是 `boss` | 产物目录和访问路径一起变 |
| `VITE_ASSETS_DIR` | 构建 | 静态资源目录 | 设错会导致图片、图标等资源 404 |
| `PROXY_TARGET` | 本地开发 | 开发服务器转发到的后端地址 | 本地所有接口指向新的后端；填错就全部调不通 |
| `BUILD_DATE` | 构建 | 界面显示的构建时间 | 只影响展示的版本信息 |
| `GIT_VERSION` | 构建 | 界面显示的版本号 | 只影响展示的版本信息 |
| `GIT_COMMIT` | 构建 | 界面显示的提交号 | 只影响展示的版本信息 |
| `GIT_BRANCH` | 构建 | 界面显示的分支名 | 只影响展示的版本信息 |
| `NODE_OPTIONS` | 构建 | Node 可用内存上限 | 值太小，构建到一半可能内存不足而失败 |
| `LISTEN_PORT` | 运行 | 容器内 nginx 监听的端口 | 容器端口变化；要和 Service 里的端口保持一致 |
| `API_SERVER` | 运行 | 后端 API 服务地址 | 部署模板会把它注入容器，地址填错页面调不通接口 |
| `LLM_ROUTER_SERVER` | 运行 | 模型数据面服务地址 | 部署模板会把它注入容器，地址填错对话类功能不可用 |

:::tip 哪些变量是给谁用的
- 只做本地开发：真正需要关心的只有 `PROXY_TARGET`。
- 要出构建产物：关心 `VITE_PLATFORM`，需要版本号时再带上 `GIT_*` 和 `BUILD_DATE`。
- 要部署到集群：关心 `LISTEN_PORT`、`API_SERVER`、`LLM_ROUTER_SERVER`，它们由部署模板注入。
:::

## 构建信息是怎么进去的

构建时会把下面几个值写入页面，供界面展示版本信息。缺省值如下：

| 展示项 | 来源变量 | 没有传时显示 |
| --- | --- | --- |
| 构建时间 | `BUILD_DATE` | 当前时间 |
| 版本号 | `GIT_VERSION` | `development` |
| 提交号 | `GIT_COMMIT` | `unknown` |
| 分支名 | `GIT_BRANCH` | `unknown` |
| Node 版本 | 构建时自动获取 | — |

## 容器化与部署

### 镜像

镜像基于 `nginx:alpine`，把构建好的 `dist` 目录复制进去，用一份 nginx 模板做配置，容器内默认监听 `8080`。

### 容器内的 nginx 负责什么

| 职责 | 具体行为 |
| --- | --- |
| 健康检查 | `/healthz` 返回 `{"status":"ok"}` |
| 托管页面 | `/console/` 指向 `dist/console/`，`/boss/` 指向 `dist/boss/` |
| 单页应用回退 | 访问的文件不存在时，回退到各自的 `index.html`，刷新页面不会 404 |
| 缓存 | 带哈希的 js、css、图片、字体会被长期缓存 |
| 跳转 | `/` 跳到 `/console/` |

### Helm 部署

部署包在 `deploy/console` 下。里面的 `apiServer`、`llmRouterServer`、`containerPorts.http` 三个值，会分别注入容器的 `API_SERVER`、`LLM_ROUTER_SERVER`、`LISTEN_PORT` 环境变量，并给容器配上 `/healthz` 的存活与就绪探针。也就是说：**改后端地址不用重新打包镜像，改部署包里的值即可。**

### 持续集成

代码推送或发起合并请求时会依次执行：代码规范检查 → 格式检查 → 单元测试 → 构建两个版本 → 构建并推送镜像；打标签时额外发布 Helm Chart。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 安装或启动报 Node 版本错误 | Node 低于 20 | 升级 Node，并用 pnpm 安装依赖 |
| 构建到一半内存不足 | Node 可用内存上限偏低 | 调大 `NODE_OPTIONS` 的值 |
| 本地页面能开，接口全报错 | `PROXY_TARGET` 指向的后端不可达 | 改成你能访问的后端地址 |
| 部署后页面白屏、资源 404 | 构建时的访问路径与网关映射不一致 | 确认 `VITE_PLATFORM` 与网关里的路径配置一致 |
| 容器起来了但探针失败 | `LISTEN_PORT` 与探针/Service 端口不一致 | 让三者保持一致 |
