本文说明控制台工程（`XiaoShi-Rune-Console`）如何构建出 Console / BOSS 两份产物，以及本地开发、镜像与部署环节涉及的环境变量。

---

## 两份构建产物

同一个代码库通过环境变量 `VITE_PLATFORM` 区分两个平台，产物与访问基路径都随之改变：

| `VITE_PLATFORM` | 产物目录 | 基路径 | 平台枚举 |
|-----------------|---------|--------|---------|
| 未设置（默认） | `dist/console` | `/console` | `Platform.CONSOLE` |
| `boss` | `dist/boss` | `/boss` | `Platform.BOSS` |

依据：`src/global-config.ts:30-38`（`BasePath` 与 `Platform` 枚举）、`vite.config.ts:52-59,90-92`（`base` 与 `build.outDir`）。

`VITE_ASSETS_DIR` 可单独覆盖静态资源目录，未设置时与基路径一致（`src/global-config.ts:38`）。

---

## 构建信息注入

构建时通过 Vite 的 `define` 把下列值注入代码中的 `__BUILD_INFO__`（`vite.config.ts:32-40`），供界面展示版本信息：

| 字段 | 来源 | 缺省 |
|------|------|------|
| `buildDate` | `BUILD_DATE` | 当前时间 ISO 字符串 |
| `version` | `GIT_VERSION` | `development` |
| `gitCommit` | `GIT_COMMIT` | `unknown` |
| `gitBranch` | `GIT_BRANCH` | `unknown` |
| `nodeVersion` | 构建时 Node 版本 | 自动获取 |

## 常用命令

`package.json` 中的脚本：

| 命令 | 作用 |
|------|------|
| `pnpm dev` | 启动 Vite 开发服务器 |
| `pnpm build` | `tsc && vite build`，产出 Console 版 |
| `pnpm build:boss` | 以 `VITE_PLATFORM=boss` 构建 BOSS 版 |
| `pnpm start` / `pnpm preview` | 预览构建产物 |
| `pnpm test` | 运行 vitest |
| `pnpm lint` / `pnpm fm:check` | ESLint / Prettier 检查 |

环境要求：Node `>=20`，包管理器 `pnpm@10.15.0`（`package.json` 的 `engines` 与 `packageManager`）。

Makefile 的 `make build` 会依次构建两份产物，并把 `BUILD_DATE`、`GIT_VERSION`、`GIT_COMMIT`、`GIT_BRANCH` 传入，同时设置 `NODE_OPTIONS=--max-old-space-size=8192`（`Makefile:1-31`）。

## 本地开发代理

开发服务器监听 `8000` 端口（`vite.config.ts:60-62`）。因为后端不在同一端口，Vite 配置了以下代理（`vite.config.ts:63-88`）：

| 前端路径 | 代理目标 | 说明 |
|----------|---------|------|
| `/api` | `PROXY_TARGET` | 管理面接口，开启 WebSocket |
| `/moha` | `PROXY_TARGET` | Moha 相关请求 |
| `/airouter-data` | `PROXY_TARGET` | LLM 数据面 |
| `/console/airouter-data` | `PROXY_TARGET` | 去掉 `/console` 前缀后转发 |
| `/avatars` | `PROXY_TARGET` + `/api/iam/avatars` | 头像等静态资源 |

`PROXY_TARGET` 未设置时默认指向 `https://rune.develop.xiaoshiai.cn`（`vite.config.ts:55`）。

## 环境变量一览

| 变量 | 阶段 | 作用 | 代码位置 |
|------|------|------|---------|
| `VITE_PLATFORM` | 构建 | 选择 `console` / `boss` | `src/global-config.ts:37`、`vite.config.ts:54` |
| `VITE_ASSETS_DIR` | 构建 | 覆盖资源目录 | `src/global-config.ts:38` |
| `PROXY_TARGET` | 开发 | 本地代理后端地址 | `vite.config.ts:55` |
| `BUILD_DATE` / `GIT_VERSION` / `GIT_COMMIT` / `GIT_BRANCH` | 构建 | 注入构建信息 | `vite.config.ts:34-37` |
| `NODE_OPTIONS` | 构建 | 提升 Node 内存上限 | `Makefile` |
| `LISTEN_PORT` | 运行 | nginx 监听端口 | `Dockerfile`、`nginx.conf.template` |
| `API_SERVER` | 运行 | Rune API 地址 | `deploy/console/templates/deployment.yaml` |
| `LLM_ROUTER_SERVER` | 运行 | LLM 数据面地址 | `deploy/console/templates/deployment.yaml` |

## 容器化与部署

### 镜像

`Dockerfile` 基于 `nginx:alpine`，把 `dist` 复制进镜像，并用 `nginx.conf.template` 作为 nginx 模板（默认 `LISTEN_PORT=8080`）。

### nginx 行为

`nginx.conf.template` 负责：

- `/healthz` 健康检查，返回 `{"status":"ok",...}`；
- `/console/` 与 `/boss/` 分别指向 `dist/console/`、`dist/boss/`，并做 SPA 回退（未命中文件时重写到各自的 `index.html`）；
- 带哈希的静态资源（js/css/图片/字体）设置一年 immutable 缓存，并启用 `gzip_static`（配合构建期的 `vite-plugin-compression` 生成 `.gz`）；
- `/` 重定向到 `/console/`，`/boss/` 重定向到 `/boss/dashboard`。

### Helm

`deploy/console` 提供 Helm Chart：`values.yaml` 中的 `apiServer`、`llmRouterServer`、`containerPorts.http` 分别注入容器环境变量 `API_SERVER`、`LLM_ROUTER_SERVER`、`LISTEN_PORT`，并为容器配置 `/healthz` 的存活与就绪探针。`make package-helm` / `make release-helm` 负责打包与推送。

### CI

`.github/workflows/build.yml` 在 push / PR 时依次执行：`pnpm lint` → `pnpm fm:check` → `pnpm test` → `make build` → docker buildx 构建并推送镜像；打 tag 时额外发布 Helm Chart。

> ⚠️ 注意: `nginx.conf.template` 中只引用了 `LISTEN_PORT`，并未出现 `API_SERVER` / `LLM_ROUTER_SERVER`，也没有 `/api`、`/airouter-data`、`/moha` 的反向代理配置。这两个变量由 Deployment 注入但模板未使用；前端请求到 `/api`、`/airouter-data` 的转发如何完成（推测由外层网关或 Ingress 处理），在本仓库中暂未确认。
