# 渠道管理

渠道是网关背后对接的**一家模型供应商**——你可以把它理解成一条电话线路。调用方只提交模型名，由网关决定走哪条线路。这一页教你从零建好一条渠道，并确认它真的能用。

读完你能完成：新建一条指向某家供应商（或自建模型服务）的渠道、选对上行协议、把模型写进去、控制哪些人能用，以及在需要时停用或删除。

:::tip 渠道像一条电话线路
同一个「客服号码」背后可以接不同的线路。哪条线路通、哪条线路便宜，由总机决定。渠道就是网关这些可切换的线路：地址、密钥、能接哪些模型，都写在一条渠道里。
:::

## 开始之前

- 权限：需要平台管理员账号（能进入 Boss 管理控制台）。
- 先准备好：供应商给你的**接口地址**和 **API 密钥**（一般是 `sk-` 开头的一串字符）。
- 先在平台上建好**租户**——新建渠道时必须选一个租户，并填一个工作空间。
- **先定价**：这条渠道要用的模型，必须已经在 [费率方案](/boss/gateway/rate-plans) 的平台默认方案里有当前有效的价格。没定价的模型会让「启用」失败，见下方「先定价才能启用」。

## 认识概念

| 名词 | 通俗解释 |
| --- | --- |
| 渠道 | 一条上游配置：地址、密钥、能用的模型、谁能用 |
| 供应商 | 这条渠道对接的是哪家厂商。它决定界面里默认带出的端点地址 |
| API Base 类型 | 上游接口说哪种「方言」：OpenAI（Chat Completions）还是 Anthropic（Messages API） |
| 端点 | 供应商的接口地址（API Base），请求实际发到这里 |
| 可见性 | 这条渠道对谁开放：公开 / 内部 / 私有 |
| 优先级 | 多条渠道都能接同一个模型时，先走哪条 |
| RPM / TPM / QPS / 并发 | 四层速度上限：每分钟请求数、每分钟 Token、每秒请求数、同时进行中的请求数 |

## 渠道列表怎么看

| 列 | 含义 |
| --- | --- |
| 名称 | 渠道名称，方便你自己区分 |
| 供应商 | 上行是供应商名称，下行是接口地址 |
| 可见性 | 公开 / 内部 / 私有 |
| 适用模型 | 这条渠道支持哪些模型，点开可展开 |
| 优先级 | 数值越大越优先 |
| RPM / TPM | 显示为「∞」表示不限制；TPM 以 `K` 为单位 |
| 状态 | 绿色对勾表示已启用，灰色叉号表示未启用 |
| 租户 | 上行是集群，下行是工作空间 |
| 所有者 | 谁创建的这条渠道 |
| 创建时间 | 渠道创建时间 |

列表上方有**搜索框**（按名称找），以及 **可见性** 和 **供应商** 两个筛选。勾选多行后可以一次性**批量删除**，删除前会再确认一次。

渠道列表把「供应商」和「端点」压在同一格里：上行是供应商名称，下行是接口地址。截图里 **优先级** 只有一个渠道是 `10`，其余都是 `0`——数值越大越先被选中。表格右侧还有 **状态**、**租户**、**所有者** 等列，窗口不够宽时要横向滚动才能看到。

## 新建一条渠道

1. 在 **渠道管理** 页面点击右上角 **创建渠道**。
2. 按下面四小节从上到下填完表单。
3. 点页面底部的 **确认** 保存。

填错了也不用重来：回到列表点 **编辑** 就能改。

### 归属与名称

| 表单项 | 怎么填 | 说明 |
| --- | --- | --- |
| 租户 | 搜索并选择一个租户 | 必填；已被禁用的租户不可选，编辑已有渠道时这一项锁定 |
| 工作空间 | 例如 `default` | **必填**，用于区分同一租户下的不同空间 |
| 名称 | 例如 `my-openai` | 必填，自己看得懂即可 |
| 可见性 | 公开 / 内部 / 私有 | 必填，默认「公开」 |
| 优先级 | 例如 `0` | 必填，默认 `0`，数值越大越优先 |
| 启用 | 默认开启 | 关闭则这条渠道不会被选中 |

![「创建渠道」表单上半部分：租户、工作空间、名称、供应商、可见性、优先级](/assets/screenshots/boss/gateway-channel-02.png)

创建表单的前两项 **租户** 与 **工作空间** 都是必填；选好 **供应商** 后，下面的 **端点** 会自动带出该供应商的默认地址。看不到密钥字段是因为它在这一屏下面，需要往下滚。

如果你用的是 vLLM、TGI 这类自建推理服务，通常选 **OpenAI Compatible**，然后手动填入它的接口地址，并把服务实际提供的模型名逐个写进 **支持模型**。
:::

### 协议与出站

这两项决定网关用什么格式跟上游说话，是新增的必选项。

| 表单项 | 选项 | 说明 |
| --- | --- | --- |
| API Base 类型 | **OpenAI**（Chat Completions）/ **Anthropic**（Messages API） | 标明这个端点属于哪种上游 API。网关按它拼接路径；调用方协议不一致时由网关自动转换 |
| /v1/responses 出站 | **上游原生 Responses**（默认）/ **网关拼历史** | 只在 API Base 类型为 OpenAI 时可选。调用方走 `/v1/responses` 时怎么发出去 |

- 选 **OpenAI** 时，如果上游本身支持 `/responses`，保持 **上游原生 Responses**；如果只是一个兼容 Chat Completions 的端点，选 **网关拼历史**，由网关把多轮历史拼成 Chat 请求。
- 选 **Anthropic** 时，这一项固定为 **网关拼历史**，不用改。

### 模型与能力

| 表单项 | 怎么填 | 说明 |
| --- | --- | --- |
| 上游 API 密钥 | 供应商给的密钥 | 每行填一个，可填多个轮换使用。编辑时留空表示保留原密钥 |
| 支持模型 | 例如 `gpt-4o-mini` | 每行一个模型名，至少填一个 |
| 模型能力 | 只读标签 | 保存后由系统按模型计算，显示 tools、视觉等能力 |
| 高级能力覆盖 | JSON | 一般留空；只有某个模型的能力判断不对时才写 |

**高级能力覆盖** 的格式是「模型名 → 能力项」的对象，例如：

```json
{ "my-model": { "tools": true, "videoInput": false } }
```

写错格式会提示「能力覆盖必须是模型名到布尔能力项的 JSON 对象」，改对才能保存。

:::warning 改「支持模型」会重新校验定价
给已启用的渠道新增模型时，控制面会检查这些模型是否都有平台默认价。有缺价就整单保存失败，并点名缺价的模型。
:::

## 限流怎么填

| 字段 | 取值范围 | 留空或 `0` 的含义 |
| --- | --- | --- |
| RPM | `0`–`10000` | 不限制每分钟请求数 |
| TPM(K) | `0`–`100000` | 不限制每分钟 Token 数（单位 K，1K = 1000 Token） |
| QPS | 大于等于 `0`，无上限 | 不限制每秒请求数 |
| 并发 | 大于等于 `0`，无上限 | 不限制同时进行中的请求数 |

这里的限流是加在**渠道**上的；[API 密钥](/boss/gateway/api-keys) 上还能再设一层，两层会同时生效，任何一层先到上限都会拒绝请求。

## 可见性怎么选

| 选择 | 谁能用到这条渠道 |
| --- | --- |
| **公开** | 所有已认证的调用方。注意这不等于允许匿名访问 |
| **内部** | 只有所选租户的成员 |
| **私有** | 只有这条渠道的所有者 |

:::warning 缩小可见范围要谨慎
可见范围调小后，原来能用这条渠道的调用方会立刻用不了它。改动前先确认没有正在依赖它的业务。
:::

## 先定价才能启用

网关有一条硬规则：**一条渠道处于启用状态时，它服务的每个模型此刻都必须能被平台默认方案覆盖**。所以启用（以及给已启用渠道加模型）时会先校验价格。

- 表单里「启用」下方固定写着：**启用前，渠道里的模型必须已有平台默认价。未定价时请联系管理员。**
- 保存失败时会提示：**这些模型尚未定价，暂时不能启用渠道：**（后面跟着缺价的模型名）。**请联系管理员先定价。**
- 处理办法：到 [费率方案](/boss/gateway/rate-plans) 的平台默认方案里给这些模型 **设置价格**（精确模型名、`gpt-*` 这类通配、或 `*` 全部模型都算覆盖），再回来启用。

:::info 为什么这么严
如果允许「先启用、后补价」，用户能调通、账单上却是「未定价」，对账时根本说不清这笔钱该收多少。所以校验放在保存这一步，而不是等调用发生后才发现。
:::

## 验证渠道是否可用

页面上**没有「测试」按钮**，需要发一次真实请求来验证。

1. 确认渠道的状态是「已启用」，且 **支持模型** 里包含你要测的模型名。
2. 用任意一个有效 **API 密钥**，对这个模型发一次真实调用。
3. 左侧菜单进入 **用户管理 → 调用日志**，能看到刚才这次调用、且结果是 **成功**，就说明这条渠道通了。

如果调用日志里看到失败，先检查端点地址、API Base 类型、上游 API 密钥和模型名是否与供应商文档一致。

## 日常操作

在列表每一行末尾的折叠菜单里，可以执行：

| 操作 | 说明 |
| --- | --- |
| 启用 / 禁用 | 一键切换这条渠道是否参与选路，切换后列表会自动刷新。启用同样要先过定价校验 |
| 更改可见性 | 弹窗里只能改**可见性**这一项，不会动租户或工作空间 |
| 编辑 | 回到表单修改渠道各项配置 |
| 删除 | 需要在确认弹窗里**手动输入渠道名称**才能删除 |

勾选多行后还能 **批量删除**，同样需要二次确认。

:::warning 删除不可撤销
删除渠道后无法恢复，引用它的调用会立刻失去这条线路。停用通常比删除更安全——停用可以随时再启用。
:::

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 保存时提示「这些模型尚未定价」 | 平台默认方案没覆盖渠道里的某个模型 | 到 [费率方案](/boss/gateway/rate-plans) 给缺价模型加一条当前有效的价格，再保存 |
| 调用日志里没有记录 | 渠道未启用，或没有调用方在用 | 确认渠道状态为已启用，并实际发一次请求 |
| 调用失败、提示鉴权错误 | 上游 API 密钥填错或已失效 | 编辑渠道，重新粘贴密钥 |
| 请求总是走不到这条渠道 | 可见性范围不含当前调用方，或优先级过低 | 调整可见性或优先级 |
| 上游报 404、路径不对 | API Base 类型选错，或端点里多写/少写了 `/v1` | 按供应商文档核对该选 OpenAI 还是 Anthropic，并看端点下方的「保存后大致请求」提示 |
| 修改了供应商但端点没变 | 编辑时不会自动覆盖已有端点 | 手动把端点改成正确的地址 |
| 模型能用但工具调用不生效 | 能力判断与实际不符 | 在 **高级能力覆盖** 里按模型补 JSON |
