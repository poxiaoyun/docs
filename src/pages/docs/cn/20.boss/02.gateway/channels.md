# 渠道管理

渠道是网关背后对接的**一家模型供应商**——你可以把它理解成一条电话线路。调用方只提交模型名，由网关决定走哪条线路。这一页教你从零建好一条渠道，并确认它真的能用。

读完你能完成：新建一条指向某家供应商（或自建模型服务）的渠道、把它绑定到若干模型、控制哪些人能用到它，以及在需要时停用或删除。

:::tip 渠道像一条电话线路
同一个「客服号码」背后可以接不同的线路。哪条线路通、哪条线路便宜，由总机决定。渠道就是网关这些可切换的线路：地址、钥匙、能接哪些模型，都写在一条渠道里。
:::

## 开始之前

- 权限：需要平台管理员账号（能进入 Boss 管理控制台）。
- 先准备好：供应商给你的**接口地址**和 **API 密钥**（一般是 `sk-` 开头的一串字符）。
- 先在平台上建好**租户**——新建渠道时必须选一个租户。

## 认识概念

| 名词 | 通俗解释 |
| --- | --- |
| 渠道 | 一条上游配置：地址、密钥、能用的模型、谁能用 |
| 可见性 | 这条渠道对谁开放（所有人 / 某个租户 / 只有自己）。界面上「租户」那一项写全了是「租户 / 工作空间」 |
| 优先级 | 多条渠道都能接同一个模型时，先走哪条 |
| RPM / TPM | 速度上限：每分钟最多多少次请求 / 多少 Token |
| 端点 | 供应商的接口地址，请求实际发到这里 |

## 进入渠道管理

1. 顶部导航点击 **大模型网关**。
2. 展开 **模型服务**，点击 **渠道管理**。
3. 页面右上角就是 **创建渠道** 按钮，列表里是已经建好的渠道。

## 渠道列表怎么看

| 列 | 含义 |
| --- | --- |
| 名称 | 渠道名称，方便你自己区分 |
| 模型服务供应商 / 端点 | 上行是供应商类型，下行是接口地址 |
| 可见性 | 公开、租户 / 工作空间、私有 |
| 适用模型 | 这条渠道支持哪些模型，点开可展开 |
| 优先级 | 数值越大越优先 |
| RPM / TPM | 显示为「∞」表示不限制；TPM 以 `K` 为单位 |
| 状态 | 绿色对勾表示已启用，灰色叉号表示未启用 |
| 租户 / 工作空间 | 租户级或私有渠道会显示归属 |
| 所有者 | 谁创建的这条渠道 |
| 创建时间 | 渠道创建时间 |

列表支持多选，右上角有 **刷新** 按钮可手动重新拉取。上方可按 **可见性** 和 **模型服务供应商** 两个条件筛选。

![渠道管理列表：名称、模型服务供应商 / 端点、可见性、适用模型、优先级、RPM / TPM](/assets/screenshots/boss/gateway-channel-01.png)

渠道列表把「供应商」和「端点」压在同一格里：上行是供应商类型，下行是接口地址。截图里 **优先级** 只有 `pipellm` 是 `10`，其余都是 `0`——数值越大越先被选中。`RPM / TPM` 显示 `∞ / ∞` 表示这两个渠道都没有限速。表格右侧还有 **状态**、**租户 / 工作空间**、**所有者** 等列，窗口不够宽时要横向滚动才能看到。

## 新建一条渠道

1. 在 **渠道管理** 页面点击右上角 **创建渠道**。
2. 在表单里逐项填写：

   | 表单项 | 怎么填 | 说明 |
   | --- | --- | --- |
   | 租户 | 搜索并选择一个租户 | 必填；已被禁用的租户不可选 |
   | 工作空间 | 例如 `default` | 选填，用于进一步区分归属 |
   | 名称 | 例如 `my-openai` | 必填，自己看得懂即可 |
   | 模型服务供应商 | 从下拉里选一家 | 必填，见下方「支持的供应商」 |
   | 端点 | 供应商的接口地址 | 必填；新建时选好供应商会自动带出默认地址 |
   | 可见性 | 公开、租户 / 工作空间、私有 | 必填，默认「公开」 |
   | 优先级 | 例如 `0` | 必填，默认 `0`，数值越大越优先 |
   | 启用 | 默认开启 | 关闭则这条渠道不会被选中 |
   | RPM | 例如 `600` | 选填，`0`–`10000`，留空表示不限制 |
   | TPM(K) | 例如 `48000` | 选填，`0`–`100000`，单位是 K（1K = 1000 Token/分钟） |
   | 上游 API 密钥 | 供应商给的密钥 | 每行填一个，可填多个轮换使用 |
   | 支持模型 | 例如 `gpt-4o-mini` | 每行填一个模型名 |

3. 端点输入框下方会实时显示这条渠道最终调用的地址，形如 `Chat: <你的端点>/chat/completions`，对照一下是否和供应商文档一致。
4. 确认无误后点击 **确认**。

填错了也不用重来：回到列表点 **编辑** 就能改。

![「创建渠道」表单上半部分：租户 / 工作空间、工作空间、名称、模型服务供应商 / 端点、端点](/assets/screenshots/boss/gateway-channel-02.png)

创建表单的第一项 **租户 / 工作空间** 必填；选好 **模型服务供应商** 后，下面的 **端点** 会自动带出该供应商的默认地址。看不到密钥字段是因为它在这一屏下面，需要往下滚。

### 支持的供应商

下拉里有 10 种供应商，选择后会自动带出默认端点（编辑已有渠道时不会覆盖你已填的地址）。

| 下拉名称 | 典型场景 | 默认端点 |
| --- | --- | --- |
| openai | 官方 OpenAI | `https://api.openai.com` |
| openai-compatible | 自建 / 兼容 OpenAI 的服务 | 需自己填写 |
| dashscope (通义千问) | 阿里云通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| baidu (百度千帆) | 百度千帆 | `https://qianfan.baidubce.com/v2` |
| moonshot (月之暗面) | Kimi | `https://api.moonshot.cn/v1` |
| zhipu (智谱) | 智谱清言 | `https://open.bigmodel.cn/api/paas/v4` |
| siliconflow (硅基流动) | 聚合平台 | `https://api.siliconflow.cn/v1` |
| openrouter | 聚合平台 | `https://openrouter.ai/api/v1` |
| doubao (豆包) | 火山方舟豆包 | `https://ark.cn-beijing.volces.com/api/v3` |
| deepseek (DeepSeek) | DeepSeek | `https://api.deepseek.com/v1` |

:::tip 自建模型服务怎么接
如果你用的是 vLLM、TGI 这类自建推理服务，通常选 **openai-compatible**，然后手动填入它的接口地址，并把服务实际提供的模型名逐个写进 **支持模型**。
:::

### 可见性怎么选

| 选择 | 谁能用到这条渠道 |
| --- | --- |
| **公开** | 所有已认证的调用方 |
| **租户 / 工作空间** | 只有所选租户的成员 |
| **私有** | 只有创建这条渠道的人 |

:::warning 缩小可见范围要谨慎
可见范围调小后，原来能用这条渠道的调用方会立刻用不了它。改动前先确认没有正在依赖它的业务。
:::

### RPM / TPM 怎么填

- 两个值都留空或填 `0`，表示**不限制**。
- RPM 上限 `10000`，TPM 上限 `100000`（单位 K，即每分钟十万个 K Token）。
- 这里的限流是加在**渠道**上的；API 密钥上还能再设一层限流，两层会同时生效。

## 验证渠道是否可用

页面上**没有「测试」按钮**，需要发一次真实请求来验证。

1. 确认渠道的状态是「已启用」，且 **支持模型** 里包含你要测的模型名。
2. 用任意一个有效 **API 密钥**，对这个模型发一次真实调用。
3. 左侧菜单进入 **用户管理 → 调用日志**，能看到刚才这次调用、且结果是 **成功**，就说明这条渠道通了。

如果调用日志里看到失败，先检查端点地址、上游 API 密钥和模型名是否与供应商文档一致。

## 日常操作

在列表每一行末尾的折叠菜单里，可以执行：

| 操作 | 说明 |
| --- | --- |
| 启用 / 禁用 | 一键切换这条渠道是否参与选路，切换后列表会自动刷新 |
| 更新可见性 | 弹窗里只能改**可见性**这一项，不会动租户或工作空间 |
| 编辑 | 回到表单修改渠道各项配置 |
| 删除 | 需要在确认弹窗里**手动输入渠道名称**才能删除 |

:::warning 删除不可撤销
删除渠道后无法恢复，引用它的调用会立刻失去这条线路。停用通常比删除更安全——停用可以随时再启用。
:::

## 结果确认

回到 **渠道管理** 列表，能看到新建的渠道，状态为绿色对勾；在 **调用日志** 里能查到经由它的成功调用，就说明配置生效了。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 调用日志里没有记录 | 渠道未启用，或没有调用方在用 | 确认渠道状态为已启用，并实际发一次请求 |
| 调用失败、提示鉴权错误 | 上游 API 密钥填错或已失效 | 编辑渠道，重新粘贴密钥 |
| 请求总是走不到这条渠道 | 可见性范围不含当前调用方，或优先级过低 | 调整可见性或优先级 |
| 修改了供应商但端点没变 | 编辑时不会自动覆盖已有端点 | 手动把端点改成正确的地址 |
