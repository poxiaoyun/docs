# 调用日志

调用日志记录**每一次**经过网关的请求，包括调用方、渠道、模型、耗时、Token 数和费用。它是排查问题、核对用量、追溯敏感内容的主要依据。

读完你能完成：按时间、用户、密钥、渠道、模型筛出想要的记录，读懂费用和标准两列，并打开某条记录查看请求与响应详情。

:::tip 像小区的监控录像
数据看板给你「今天小区进出多少人」的统计；调用日志是逐帧的监控录像，谁在几点、从哪个门进来、去了哪栋楼都记得清清楚楚。出问题时，就靠它逐条回看。
:::

## 开始之前

- 权限：需要平台管理员账号（能进入 Boss 管理控制台）。
- 需要 **网关配置** 里的 **启用审计日志** 处于开启状态，否则不会记录新的调用。

## 进入调用日志

1. 顶部导航点击 **大模型网关**。
2. 展开 **用户管理**，点击 **调用日志**。

## 怎么筛选

页面顶部是筛选工具条：

| 筛选项 | 说明 |
| --- | --- |
| 时间范围 | 今日 / 昨日 / 近 3 日 / 近一周 / 自定义 |
| 开始日期、结束日期 | 仅在选「自定义」时可填 |
| 用户 | 按用户名模糊查询 |
| API 密钥 | 按密钥查询 |
| 渠道 | 下拉选择，选项是**渠道名称**，含「全部」。注意这里不是按供应商筛 |
| 模型 | 按模型名模糊查询 |

工具条上有 **刷新** 和 **重置**：重置会把时间范围恢复为「今日」。

:::info 没有「结果」筛选器
界面上没有按成功 / 失败筛选的选项。要定位失败请求，可以观察列表中带红色标记的行，或按用户、模型先缩小范围。
:::

## 列表里有什么

| 列 | 含义 |
| --- | --- |
| 时间 | 请求发生时间，下方小字是这次调用的结果；点它可打开详情 |
| 渠道 | 实际路由到的渠道，显示为 `# 名称`，下方小字是供应商 / 租户 / 集群 / 工作空间 |
| 用户 | 发起调用的用户，带租户名 |
| API 密钥 | 使用的密钥，点击可复制 |
| 模型 | 请求的模型 |
| 耗时 | 端到端耗时；有首 Token 时间时，会同时显示「首 token」与「耗时」 |
| Token 数 | 输入 / 输出两行；有缓存用量时再补缓存读、缓存写 |
| 费用 | 本次应付金额；未算出来时显示「未定价」 |
| 标准 | 本次使用的单价，以及是哪一层价格算的 |

结果不是「成功」的行，左侧会固定显示一条红色竖线，方便一眼扫到异常。

![调用日志：顶部时间范围与筛选条件，表格按时间倒序列出每次调用](/assets/screenshots/boss/gateway-audit-01.png)

调用日志的筛选条比用户侧多两个维度——**用户** 与 **渠道**，因为这里看的是全平台的调用。表格里 **API 密钥** 一列是调用用的那把密钥，**用户** 一列是发起调用的人。

### 费用怎么读

费用列有三种状态，别混在一起看：

| 显示 | 含义 | 要不要处理 |
| --- | --- | --- |
| 金额（如 `0.006 CNY`） | 这次调用的应付金额，来自计价快照 | 不用 |
| 金额 + **参考价** | 当前显示的是美元折算值，人民币金额才是记账值 | 不用，仅展示 |
| **未定价** | 没有任何有效价格覆盖，这次没算出钱 | 要：到 [费率方案](/boss/gateway/rate-plans) 补价，或在 [计价异常](/boss/gateway/usage-events) 补价 |
| 金额 + **套餐抵扣 N 点** | 费用先由套餐点数抵扣，副行写明扣了多少点 | 不用 |

### 标准怎么读

「标准」列回答的是「这个金额是按哪条价格算出来的」。格式大致是：

> 输入价 / 补全价 · 缓存读 · 缓存写（价层 #方案ID 按 模型名 计价）

括号里的**价层**是这条记录最有价值的信息，取值有七种：

| 价层 | 含义 |
| --- | --- |
| 专属费率 | 这把 API 密钥上单独绑的价格 |
| 套餐费率 | 生效中的套餐所挂的方案 |
| 账户费率 | 这个人的计费账户上绑的方案 |
| 租户默认 | 租户自己的默认方案 |
| 平台默认 | 全平台默认方案 |
| 模型目录价 | 迁移期的目录兜底，不是目标状态 |
| 补价 | 管理员在计价异常里人工指定的价格 |

看到「模型目录价」，说明这次是靠兜底价算出来的；看到「补价」，说明这条是人工补的。

## 查看某次调用的详情

1. 点击某条记录的 **时间** 列（或时间旁的查看详情图标）。
2. 弹窗里有若干标签页：

   | 标签页 | 内容 |
   | --- | --- |
   | 基本信息 | 请求 ID、用户、渠道、模型、耗时、状态码、Token 明细等 |
   | 请求数据 | 发给模型的请求内容（只读） |
   | 响应数据 | 模型返回的内容（只读） |
   | 元数据 | 附加信息（只读） |
   | 内容审查 | 敏感内容报告，仅当这次调用命中过审核时才出现 |

3. 各标签页没有内容时会显示「无数据」。

### 结果状态

| 结果 | 含义 |
| --- | --- |
| 成功 | 请求正常完成 |
| 失败 | 请求出错 |
| 已拦截 | 被内容审核拦下 |
| 超出配额 | 达到套餐点数或额度上限，未继续处理 |

## 记录会保留多久

页面本身**没有保留期设置，也没有清理入口**。也就是说：

- 你无法在界面上删除或设定自动清理调用日志。
- 记录实际保留多久，取决于平台的部署与数据库策略。

如果因为容量或合规原因需要清理历史记录，请联系平台运维处理。

## 结果确认

设定好时间范围后，列表出现对应记录、点开某条能看到请求与响应内容，就说明查询正常。要验证某个渠道或密钥是否在用，用对应的筛选条件过滤，看是否还有记录产生。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 查不到任何记录 | 审计日志被关闭，或时间范围太窄 | 到 [网关配置](/boss/gateway/config) 确认审计开关，放宽时间范围 |
| 某条请求显示失败 | 上游渠道故障、密钥无效等 | 打开详情看错误信息，再到 [渠道管理](/boss/gateway/channels) 检查渠道 |
| 费用列显示「未定价」 | 五层价都没有命中这个模型 | 到 [费率方案](/boss/gateway/rate-plans) 补明细，或在 [计价异常](/boss/gateway/usage-events) 补价 |
| 状态是「已拦截」 | 命中了内容审核策略 | 到 [命中记录](/boss/gateway/sensitive-hits) 查看具体命中了什么 |
| 想删除旧记录 | 页面不提供清理功能 | 联系平台运维处理 |
