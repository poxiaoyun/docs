# 网关配置

网关配置是网关的**总控台**：限流开不开、审不审内容、缓存留多久、上游失败要不要重试、哪些 IP 能访问——这些影响全平台的行为都在这里统一设置。

读完你能完成：按需开关各项能力、配置选路偏好与 IP 白名单、调整缓存与重试策略，并知道每一项改完是立刻生效还是要等一下。

:::tip 这里改的是「整车设置」
渠道管理、模型配置管的是具体零件；网关配置管的是整车的行为——要不要踩刹车（限流）、要不要过安检（审核）、空调多久换一次气（缓存）。改动会影响整个平台的调用。
:::

## 开始之前

- 权限：需要平台管理员账号（能进入 Boss 管理控制台）。
- 建议改前先想清楚影响面：这些参数对**全平台**生效，不是某个租户或某条渠道。

## 进入网关配置

1. 顶部导航点击 **大模型网关**。
2. 展开 **平台设置**，点击 **网关配置**。

## 页面从上到下有哪些板块

1. 路由配置
2. 核心开关
3. 安全配置
4. 缓存配置
5. 渠道回退策略
6. 缓存管理

页面底部有 **重置** 和 **保存更改** 两个按钮：没有改动时保存按钮是灰的；**重置** 会把表单恢复成最近一次加载的服务端配置。

![网关配置：路由配置（首选 / 屏蔽供应商）、核心开关、安全配置、缓存配置](/assets/screenshots/boss/gateway-config-01.png)

配置页是一长条表单，从上往下依次是 **路由配置**、**核心开关**、**安全配置**、**缓存配置**、**渠道回退策略**、**缓存管理**。五个核心开关里 **启用内容审核** 和 [敏感词库 / 策略管理](./moderation.md) 是配套的：关掉它，那套规则就不再生效。改完记得点页面底部的保存按钮，改完的生效时机见本页最后一节。

## 核心开关

| 开关 | 默认 | 打开后 / 关闭后 |
| --- | --- | --- |
| 启用限流 | 开启 | 关闭后，所有针对用户、租户、渠道的 RPM / TPM 限制立即失效 |
| 启用审计日志 | 开启 | 关闭后不再记录请求的元数据，能显著减轻存储压力，但历史请求无法追溯 |
| 启用内容审核 | 开启 | 关闭后所有输入输出不再做敏感词检测，直接放行 |
| 启用计费 | 开启 | 关闭后不再生成用量费用数据（费用快照） |
| 允许欠费使用 | 关闭 | 关闭时，账户余额不足会拒绝新的请求 |

:::warning 关闭这些开关要慎重
- 关闭**限流**：上游可能在流量突增时被打爆。
- 关闭**审计日志**：之后无法追溯历史上谁调用了什么。
- 关闭**内容审核**：违规内容会直接进出。
建议只在调试或紧急处置时临时关闭，处理完尽快恢复。
:::

:::info 启用计费 ≠ 扣款
「启用计费」只控制**费用快照**是否生成，也就是调用日志和看板上的金额数字。它不代表平台会从账户余额里扣钱——网关本身不做充值、扣款或支付。
:::

## 路由配置

决定多条渠道都可用时优先走谁。

| 配置项 | 怎么填 | 说明 |
| --- | --- | --- |
| 首选供应商 | 输入供应商标识后回车，可多个 | 多个供应商同时可用时，优先选这里的 |
| 屏蔽供应商 | 输入供应商标识后回车，可多个 | 这里的供应商被全局禁用，即使它的渠道已启用也不选 |

- 两个都是**自由输入**的多值框，没有预置下拉，填的就是供应商的名字（例如 `openai`、`siliconflow`）。
- **首选是偏好，屏蔽是硬限制**：首选填错最多是不生效，屏蔽填错会直接切断该供应商的全部流量。

:::warning 屏蔽供应商等于紧急断线
把某个供应商加进屏蔽列表后，所有走它的请求都会失败。把它当作紧急切断故障或合规风险供应商的开关，用完记得移除。
:::

## 安全配置

| 配置项 | 说明 |
| --- | --- |
| 全局 IP 白名单 | 只有来自白名单的 IP 才能访问网关；留空表示允许所有来源 |

支持的写法：

| 写法 | 示例 |
| --- | --- |
| 单个 IPv4 | `192.168.1.100` |
| IPv4 网段 | `10.0.0.0/8` |

校验规则与密钥的白名单一致：只接受 IPv4、每段 `0`–`255`、禁止前导零；**不接受 `*`，也不支持 IPv6**。

如果你输入的 IP 不是该网段的网络地址（例如 `192.168.1.100/24`），页面会提示规范化后的网段和实际覆盖范围，按提示确认即可。

:::warning 别把自己关在门外
白名单一旦配置，来源不在其中的请求都会被拒绝。配之前务必确认**你自己的管理 IP** 已经在列表里，否则连后台请求也会被挡。
:::

## 缓存配置

缓存能减少每次请求都查数据库的开销，代价是配置改动要等缓存过期才完全体现。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用渠道缓存 | 开启 | 把渠道配置缓存在内存中 |
| 渠道缓存 TTL (秒) | `300` | 渠道缓存的有效时间 |
| 启用用户/租户缓存 | 开启 | 缓存用户与租户的绑定关系 |
| 用户/租户缓存 TTL (秒) | `600` | 用户/租户缓存的有效时间 |
| 启用计费缓存 | 开启 | 缓存计费账户信息 |
| Token 缓存 TTL (秒) | `300` | 密钥信息的有效时间 |
| 计费账户缓存 TTL (秒) | `300` | 计费账户信息的有效时间 |
| Token 绑定缓存 TTL (秒) | `300` | 密钥与渠道绑定关系的有效时间 |

时间越短数据越新，越长性能越好。所有 TTL 都填**秒**。

### 缓存管理

点击 **重建缓存**，系统会强制清除并重建所有缓存索引，并在完成后提示形如「缓存重建成功：12 个渠道，34 个用户」。

什么时候用它：当渠道的启用/禁用状态和实际表现对不上时。

:::warning 重建缓存会短暂加负载
重建期间会集中访问数据库，可能造成瞬时压力。请在低峰期操作，不要频繁点击。
:::

## 渠道回退策略

当一条上游渠道失败时，是就此报错，还是换一条再试，由这里控制。它只影响**对话类**请求。

| 配置项 | 默认 | 取值范围 |
| --- | --- | --- |
| 启用渠道回退 | 开启 | — |
| 单渠道最大重试次数 | `1` | `0`–`5` |
| 最大降级次数 | `2` | `0`–`10` |
| 重试间隔 (毫秒) | `0` | 大于等于 `0` |

怎么理解这两个数字：

- 「单渠道最大重试次数」= `1`，表示同一条渠道最多请求 **2 次**（第一次 + 重试 1 次）。
- 「最大降级次数」= `2`，表示最多切换尝试 **3 条渠道**。

:::info 重试会拉长等待
重试和降级都会让用户多等一会儿。对响应速度敏感的业务，可以把这两个值适当调低。
:::

## 改完什么时候生效

| 配置 | 生效时机 |
| --- | --- |
| 核心开关、路由、白名单、渠道回退 | 点 **保存更改** 后即时生效 |
| 缓存相关的开关与 TTL | 需等缓存自然过期，或点 **重建缓存** 让它立即刷新 |

## 结果确认

点 **保存更改** 后，页面右上角会出现「配置保存成功」的提示。要验证某次改动，例如屏蔽了某个供应商，可以到 [调用日志](/boss/gateway/audit) 观察相关请求是否不再路由到它。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 保存按钮点不动 | 表单没有改动 | 修改任意一项后按钮会变为可用 |
| 改了缓存时间没变化 | 缓存还没过期 | 点 **重建缓存** 立即刷新 |
| 后台自己访问不了网关 | 全局白名单没包含自己的 IP | 先把管理 IP 加进白名单 |
| 渠道状态和实际不一致 | 内存缓存未刷新 | 使用 **重建缓存** |
