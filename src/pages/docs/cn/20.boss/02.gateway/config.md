# 网关配置

网关配置是网关的**总控台**：限流开不开、审不审内容、算不算钱、扣不扣钱、缓存留多久、上游失败要不要换路、哪些 IP 能访问——这些影响全平台的行为都在这里统一设置。

读完你能完成：按正确顺序打开计费相关开关、配置选路偏好与 IP 白名单、调整缓存与回退策略，并知道每一项改完是立刻生效还是要等一下。

:::tip 这里改的是「整车设置」
渠道管理、模型配置管的是具体零件；网关配置管的是整车的行为——要不要踩刹车（限流）、要不要过安检（审核）、油表准不准（计费）。改动会影响整个平台的调用。
:::

## 开始之前

- 权限：需要平台管理员账号（能进入 Boss 管理控制台）。
- 建议改前先想清楚影响面：这些参数对**全平台**生效，不是某个租户或某条渠道。
- 涉及计费的三个开关有明确顺序，不要跳步，见下方「三个计费开关的开启顺序」。

## 路由配置

决定多条渠道都可用时优先走谁。

| 配置项 | 怎么填 | 说明 |
| --- | --- | --- |
| 首选供应商 | 输入供应商标识后回车，可多个 | 多个供应商同时可用时，优先选这里的 |
| 屏蔽供应商 | 输入供应商标识后回车，可多个 | 这里的供应商被全局禁用，即使它的渠道已启用也不选 |

- 两个都是**自由输入**的多值框，没有预置下拉，填的就是供应商的标识（例如 `openai`、`siliconflow`）。
- **首选是偏好，屏蔽是硬限制**：首选填错最多是不生效，屏蔽填错会直接切断该供应商的全部流量。

:::warning 屏蔽供应商等于紧急断线
把某个供应商加进屏蔽列表后，所有走它的请求都会失败。把它当作紧急切断故障或合规风险供应商的开关，用完记得移除。
:::

## 核心开关

一共 8 个开关，分三组看：基础能力、价格来源、扣费链路。

| 开关 | 默认 | 打开后 / 关闭后 |
| --- | --- | --- |
| 启用限流 | 开启 | 关闭后，所有针对用户、租户、渠道的 RPM / TPM 限制立即失效 |
| 启用审计日志 | 开启 | 关闭后不再记录请求的元数据，能显著减轻存储压力，但历史请求无法追溯 |
| 启用内容审核 | 开启 | 关闭后所有输入输出不再做敏感词检测，直接放行 |
| 启用计费 | 开启 | 关闭后不再记录计价数据，也就没有费用快照 |
| 目录价兜底 | 开启 | 费率方案都没命中时，暂时用模型目录里的价格。迁移期默认开启，费率覆盖完成后应关闭 |
| 允许欠费使用 | 关闭 | **固定关闭，不可修改**。是否放行由余额预检和账户信用额度决定 |
| 启用事后扣费 | 关闭 | 按已算出的费用快照扣减账户余额 |
| 启用余额预检 | 关闭 | 请求上游之前检查账户余额；余额不足或账户冻结时拒绝请求 |

:::warning 关闭这些开关要慎重
- 关闭**限流**：上游可能在流量突增时被打爆。
- 关闭**审计日志**：之后无法追溯历史上谁调用了什么。
- 关闭**内容审核**：违规内容会直接进出。
建议只在调试或紧急处置时临时关闭，处理完尽快恢复。
:::

:::info 「允许欠费使用」为什么是灰的
这个开关固定关闭，页面上的说明写着：全局欠费保持关闭，是否允许继续使用由**余额预检和账户信用额度**决定，不靠这个开关放行。想给某个人放宽额度，请到 [计费账户](/boss/gateway/billing-accounts) 设信用额度。
:::

:::info 目录价兜底只是过渡
它是迁移期的回滚手段：费率方案没覆盖时，最后一层去模型目录里找价。等费率方案把模型都覆盖了就应该关掉它——否则「未定价」会被悄悄算成一个目录价，缺价问题就被藏住了。
:::

## 三个计费开关的开启顺序

**启用计费**、**启用事后扣费**、**启用余额预检** 不能一起打开，按下面的顺序一步一步来：

1. 先开 **启用计费**。这一步只生成计价快照，不动任何人的钱。
2. 到 [调用日志](/boss/gateway/audit) 核对一批快照：金额是否合理、选价层是否符合预期、有没有大量「未定价」。
3. 快照没问题后再开 **启用事后扣费**。从此按快照扣减账户余额。
4. 观察一段时间，确认余额变动和流水都对得上，最后再开 **启用余额预检**。从此余额不足会在请求上游之前就被拒绝。

:::warning 跳过顺序的代价
先开扣费、后开计费，等于在没有任何金额依据的情况下动钱；先开预检、后核对快照，会把本来能正常调用的用户挡在门外。顺序错了不一定报错，但账会乱。
:::

## 安全配置

| 配置项 | 说明 |
| --- | --- |
| 全局 IP 白名单 | 只有来自白名单的 IP 才能访问网关；留空表示允许所有来源 |

支持的写法：

| 写法 | 示例 |
| --- | --- |
| 单个 IPv4 | `192.168.1.100` |
| IPv4 网段 | `10.0.0.0/8` |

校验规则与密钥的白名单一致：只接受 IPv4、每段 `0`–`255`、禁止前导零；**不接受 `*`，也不支持 IPv6**。

如果你输入的 IP 不是该网段的网络地址（例如 `192.168.1.100/24`），页面会提示规范化后的网段和实际覆盖范围，按提示确认即可。

:::warning 别把自己关在门外
白名单一旦配置，来源不在其中的请求都会被拒绝。配之前务必确认**你自己的管理 IP** 已经在列表里。
:::

## 缓存配置

缓存能减少每次请求都查数据库的开销，代价是配置改动要等缓存过期才完全体现。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用渠道缓存 | 开启 | 把渠道配置缓存在内存中 |
| 渠道缓存 TTL (秒) | `300` | 渠道缓存的有效时间 |
| 启用用户/租户缓存 | 开启 | 缓存用户与租户的绑定关系 |
| 用户/租户缓存 TTL (秒) | `600` | 用户/租户缓存的有效时间 |
| 启用计费缓存 | 开启 | 缓存计费账户信息 |
| Token 缓存 TTL (秒) | `300` | 密钥信息的有效时间 |
| 计费账户缓存 TTL (秒) | `300` | 计费账户信息的有效时间 |
| Token 绑定缓存 TTL (秒) | `300` | 密钥与渠道绑定关系的有效时间 |

时间越短数据越新，越长性能越好。所有 TTL 都填**秒**。

## 渠道回退

当一条上游渠道失败时，是就此报错，还是换一条再试，由这里控制。它只影响**对话类**请求；非对话请求、被指定到固定渠道的请求、以及已经开始流式输出字节的请求都不走回退。

| 配置项 | 默认 | 取值 / 说明 |
| --- | --- | --- |
| 启用名单内换路 | 开启 | 关掉后不再在名单内重试或换渠道，但仍可走固定兜底 |
| 可重试状态码 | `500,502,503,504,429` | 只有这些状态码才会重试、换下一名，或进入固定兜底 |
| 同一渠道额外重试次数 | `1` | `0`–`5`，**不含首次**。默认 1 表示每条渠道最多打 2 次 |
| 最多再换渠道次数 | `2` | `0`–`10`，默认 2 表示合计最多 3 条渠道；固定兜底不计入这个上限 |
| 重试间隔 (毫秒) | `0` | 同一渠道再次请求前的等待时间 |
| 换路间隔 (毫秒) | `0` | 换到下一条渠道前的等待时间 |
| 启用固定兜底 (last-resort) | 关闭 | 名单内换路关掉或次数用尽后，仍可再试一条固定渠道和模型 |
| 兜底渠道 | 空 | 仅在开启固定兜底时可选；须对调用方可见，建议选公开渠道 |
| 兜底模型 | 空 | 仅在开启固定兜底时可选；名单耗尽后改写请求模型再打兜底渠道 |

怎么理解这两个数字：**同一渠道额外重试次数** = `1`，表示同一条渠道最多请求 2 次（第一次 + 重试 1 次）；**最多再换渠道次数** = `2`，表示最多切换尝试 3 条渠道。

:::info 重试会拉长等待
重试和换路都会让用户多等一会儿。对响应速度敏感的业务，可以把这几项适当调低。
:::

## 缓存管理

点击 **重建缓存**，系统会强制清除并重建所有缓存索引，并在完成后提示形如「缓存重建成功：12 个渠道，34 个用户」。

什么时候用它：当渠道的启用/禁用状态和实际表现对不上时。

:::warning 重建缓存会短暂加负载
重建期间会集中访问数据库，可能造成瞬时压力。请在低峰期操作，不要频繁点击。
:::

## 改完什么时候生效

| 配置 | 生效时机 |
| --- | --- |
| 核心开关、路由、白名单、渠道回退 | 点 **保存更改** 后即时生效 |
| 缓存相关的开关与 TTL | 需等缓存自然过期，或点 **重建缓存** 让它立即刷新 |

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 保存按钮点不动 | 表单没有改动 | 修改任意一项后按钮会变为可用 |
| 「允许欠费使用」点不了 | 这个开关固定关闭 | 用账户信用额度 + 余额预检控制放行 |
| 改了缓存时间没变化 | 缓存还没过期 | 点 **重建缓存** 立即刷新 |
| 后台自己访问不了网关 | 全局白名单没包含自己的 IP | 先把管理 IP 加进白名单 |
| 渠道状态和实际不一致 | 内存缓存未刷新 | 使用 **重建缓存** |
| 打开扣费后余额被扣错 | 快照还没核对就开了扣费 | 先关掉事后扣费，按顺序重新走一遍 |
