# 计价异常

计价异常是计费链路的**兜底页**。有些调用发生之后没能算出金额——最常见的原因是那个模型没有价格。这一页把它们列出来，并允许你指定一条价格、写清原因，把它补成一个确定的金额。

读完你能完成：按状态找出需要处理的用量、判断这批异常是「缺价」还是「计价失败」、给一条用量补价，以及知道怎么从根上消掉缺价。

:::tip 像超市结账时扫不出条码
东西已经拿走了（调用已经发生），但收银机扫不出价格（没有价目）。收银员会把它放到一边，等主管来指定一个价格再结账。计价异常就是那张「待定价格」的台面。
:::

## 开始之前

- 权限：需要平台管理员账号（能进入 Boss 管理控制台）。
- 补价前先想清楚该用哪条价格：补价是**人工指定一条费率明细**，所以最好先在 [费率方案](/boss/gateway/rate-plans) 把缺的价格补上，再回来处理历史用量。
- 补价需要填原因，原因会留痕，请写清依据（例如「模型新上线，价格已在默认方案补齐」）。

## 认识概念

| 名词 | 通俗解释 |
| --- | --- |
| 缺价 | 这次调用没有命中任何有效价格，所以算不出钱 |
| 失败 | 计价过程本身出错了，不是没价 |
| 待计价 | 用量已经记下，还没轮到计价 |
| 计价中 | 正在算，通常只是一瞬间 |
| 已计价 | 已经算出金额，正常结束 |
| 补价 | 人工指定一条费率明细，把这条用量重新算一次 |
| 计价快照 | 计价当时用到的单价与金额，事后不会随改价变化 |

## 四张统计卡与筛选

页面顶部并排四张可点的统计卡，卡面写着「N 条」：

| 统计卡 | 点它会做什么 |
| --- | --- |
| 缺价 | 只看没有命中价格的用量（**默认选中**） |
| 失败 | 只看计价过程出错的用量 |
| 待计价 | 只看还没开始计价的用量 |
| 计价中 | 只看正在计价的用量 |

点哪张卡，下面的列表就按哪个状态过滤；当前选中的卡片会高亮。换个状态就是换一张卡，没有额外的下拉筛选。

![计价异常页：顶部四张状态统计卡（缺价默认选中），下方列表与补价操作](/assets/screenshots/boss/gateway-usage-events-01.png)

:::info 这一页没有搜索框
列表只能按状态切换，不能按用户或模型搜索。想定位某个人的异常，先看「用户」列，或用 [调用日志](/boss/gateway/audit) 反查这个人最近的调用。
:::

## 列表列

| 列 | 含义 |
| --- | --- |
| 时间 | 这次调用发生的时间 |
| 用户 | 发起调用的人 |
| 模型 | 计价用的模型名；下方小字「请求 xxx」是调用方实际请求的名字 |
| 用量 | 输入 / 输出 / 合计 三个 Token 数 |
| 计价状态 | 缺价 / 失败 / 待计价 / 计价中 / 已计价 |
| 费用 | 算出来的金额；缺价时显示「未定价」 |

:::info 「请求 xxx」这一行为什么重要
渠道可以把调用方的模型名映射成上游的真实模型名再转发出去。计价认的是**映射后的名字**，所以当「模型」和「请求」不一致时，缺价往往就出在这层映射上——价格里写的是其中一个名字，实际去查的却是另一个。
:::

## 为一条用量补价

补价只对**缺价**的用量出现。

1. 确认顶部选中的是 **缺价** 卡。
2. 找到要处理的那条用量，在行末点 **补价**。
3. 在弹出的「为 xxx 补价」窗口里选一条 **费率明细**（必填）。选项按「方案名 / 模型匹配 / 输入价」列出，都是现有方案里已有的价格。
4. 填 **原因**（必填）。
5. 点 **补价**。

保存后这条用量会重新计价，金额从「未定价」变成补价后的数字，状态也会从缺价转为已计价。

:::warning 补价是逐条的
这一页只提供单条补价，没有批量入口。缺价很多时，正确的做法不是一条条补，而是先去 [费率方案](/boss/gateway/rate-plans) 把整个模型的价格补上，让后续调用不再缺价，再回头处理这批历史用量。
:::

## 缺价怎么根治

按这个顺序处理，比事后一条条补价省事得多：

1. **先定价**：在 [费率方案](/boss/gateway/rate-plans) 的平台默认方案里，给缺价的模型加一条当前有效的价格。模型名要和渠道里写的、调用方请求的完全一致。
2. **再启用/改渠道**：渠道启用前会校验价格，缺价会被拦下。新增模型时同理，见 [渠道管理](/boss/gateway/channels)。
3. **核对映射**：如果模型名对得上却仍然缺价，检查渠道是否把请求映射成了另一个上游模型名，而价格里只有其中一个。
4. **最后补历史**：剩下的历史缺价，用上面的补价逐条处理。

## 已计价的费用去哪看

这一页只处理**没算出来**的用量。已经算出金额的调用不会出现在这里，逐条费用、选价层和套餐抵扣点数都在 [调用日志](/boss/gateway/audit) 里看。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 缺价多得处理不完 | 模型整体没有价格 | 到费率方案补整个模型的价格，再回来补历史 |
| 明明定价了还是缺价 | 模型名大小写、空格不一致，或渠道做了模型映射 | 逐字符核对三处模型名 |
| 补价后金额还是不对 | 选的明细不是这条用量该用的价 | 重新补一次，选正确的明细；原因写清更正依据 |
| 状态一直是「待计价」 | 计价任务还没跑到 | 稍等并刷新；长时间不动请联系运维 |
| 找不到批量补价 | 这一页只支持逐条 | 按上节「缺价怎么根治」先补价格 |
| 费用列显示「未定价」 | 这条用量还没算出金额 | 补价，或先给模型补价格 |
