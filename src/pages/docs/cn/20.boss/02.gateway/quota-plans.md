# 额度计划

额度计划是管理员设置的**用量硬上限**。它只管「一个周期内最多用多少」，完全不参与定价——同样的调用，价格还是由 [费率方案](/boss/gateway/rate-plans) 决定。

读完你能完成：建一份额度计划、把它绑到某些用户或密钥上、看谁快用完了、以及给某个人重置额度。

:::tip 额度计划像手机套餐里的「流量封顶」
它不管每兆多少钱（那是价目表的事），只管这个月用到多少就断网。封顶和计费是两套独立的闸门，可以同时生效。
:::

## 开始之前

- 权限：需要平台管理员账号（能进入 Boss 管理控制台）。
- 先想清楚限谁：限**用户**（按人累计）还是限**API 密钥**（按密钥累计）。这个选择建好之后不能改。
- 额度计划和套餐是两套机制：套餐决定「先扣谁的点数」，额度计划决定「用到一个上限就停」。两者同时生效。

## 认识概念

| 名词 | 通俗解释 |
| --- | --- |
| 额度计划 | 一份用量上限的模板，可以绑给多个对象 |
| 主体 | 这份额度限制谁：用户 或 API 密钥（界面上叫 Token） |
| 计量额度 | 按什么计量。目前固定为 Token |
| 周期 | 从第一次用量开始滚动 N 天 / 每个自然日 / 每个自然月 |
| Token 上限 | 一个周期内最多能用多少 Token，填正整数 |
| 绑定 | 把某个用户或密钥挂到这份计划上，从此受它限制 |
| 水位 | 已用量与上限的对比，绑定页里用进度条和「已用 / 上限」显示 |
| 重置券 | 允许「额外重来一轮」的次数。用它清零已用量会扣掉 1 次 |

## 列表怎么看

| 列 | 含义 |
| --- | --- |
| 名称 | 计划名称；点名称进入绑定页 |
| 主体 | 用户 / Token |
| 计量额度 | 目前都是 Token |
| 周期 | 滚动 N 天 / 每个自然日 / 每个自然月 |
| Token 上限 | 一个周期内允许的最大 Token 数 |
| 绑定数 | 有多少个对象绑在这份计划上，点数字也能进绑定页 |
| 状态 | 启用 / 停用 |
| 自动绑定 | 是 / 否。是表示之后新建的账户会自动绑上这份计划 |

行末菜单有 **编辑**、**绑定**、**删除**。

## 创建额度计划

1. 点右上角 **创建额度计划**。
2. 填 **名称**。名称不能以 `subscription:` 开头（那是订阅投影计划的保留前缀）。
3. 选 **主体**：用户 或 Token。**建好之后不能改**。
4. **计量额度** 目前固定为 Token，选项只有一项。
5. 选 **周期**：
   - **滚动 N 天**：从第一次用量开始滚动计算，再填 **周期天数**（`1`–`366`）；
   - **每个自然日**：每天 0 点重新计时；
   - **每个自然月**：每个自然月重新计时。
6. 填 **Token 上限**，必须是正整数。
7. 按需打开 **启用** 和 **新建账户时自动绑定**。
8. 点 **保存**。

:::info 自动绑定只影响之后新建的账户
打开「新建账户时自动绑定」不会把已有账户补绑上去，只对之后新建的计费账户生效。已有的人要手动 **绑定**。
:::

## 绑定与解绑

1. 在列表点计划 **名称**（或行末 **绑定**）进入「（计划名）的绑定」页。
2. 点右上角 **绑定对象**，按主体类型选择用户或密钥。
3. 想解绑时，在那一行点 **解绑** 并确认：「解除「某对象」与这个额度计划的绑定？」

绑定页的列：

| 列 | 含义 |
| --- | --- |
| 用户 / Token | 绑定的对象。主体是 Token 时显示对象 ID |
| 额度使用量 | 已用 / 上限，带进度条 |
| 额度重置时间 | 这一轮什么时候重新开始计算 |
| 重置券 | 剩余次数（只有主体是用户时才有这一列） |

:::warning 解绑不会退回已用量
解绑只是让这个对象不再受上限约束，已经用掉的量不会清零，也不会因此获得更多额度。
:::

## 查看水位与重置额度

在绑定页可以直观看到每个对象的「水位」：进度条越满，越接近被拦住。

要给某个对象**立刻重来一轮**：

1. 在绑定页找到那一行，点 **重置额度**。
2. 选择 **使用重置券** 或 **不使用重置券**：
   - 用券会扣掉该对象 1 次重置券，并清零这份额度计划的已用量；
   - 不用券只清已用量，次数不变。
3. 点确认。确认文案会说明：**套餐点数不受影响**。

:::info 重置只清这份计划的用量
一个对象可能同时受多份额度计划约束。重置只清当前这一份的已用量，其他计划的用量照旧。
:::

## 与套餐点数、超额扣费的关系

三者的分工可以这样记：

| 机制 | 管什么 | 用完之后 |
| --- | --- | --- |
| [套餐点数](/boss/gateway/billing-plans) | 先扣谁的钱 | 看订阅上的 **超额扣费** 开关：开则扣余额，关则拒绝 |
| [计费账户](/boss/gateway/billing-accounts) | 钱够不够 | 余额不足且超出信用额度时拒绝 |
| 额度计划 | 用量能到多少 | 到达上限即拒绝，与余额无关 |

所以可能出现「账户里还有钱，但被额度计划拦住」的情况——这不是计费出错。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 绑定页显示 `-1 / -1` | 服务端还没算出这个对象的水位 | 刷新一次；长期如此联系运维，这不代表额度是负数 |
| 用户还有余额却被拒 | 撞到了额度计划的 Token 上限 | 提高上限、重置额度，或解绑 |
| 新建的人没被自动绑定 | 打开自动绑定之前账户就已经存在 | 手动 **绑定** |
| 主体选错了 | 主体建好之后不能改 | 删掉重建一份，再把对象迁过去 |
| 名称保存不了 | 名称以 `subscription:` 开头 | 那是订阅投影的保留前缀，换个名字 |
| 删掉计划后用量变多 | 删除会同时去掉所有绑定，只影响上限不改价格 | 属正常；需要继续限制就重建并重新绑定 |
