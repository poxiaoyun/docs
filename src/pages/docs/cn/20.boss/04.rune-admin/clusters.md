# 集群管理

集群（可以理解成一栋机房大楼）是平台算力的来源。一个集群里有很多台机器（节点），每台机器里可能插着若干张加速卡。你要做的第一件事，就是把这栋「大楼」接进平台，平台才认识它、才能把资源分给用户。

读完这页，你能完成：接入一个新集群、测试连接是否通、把它上线给租户用、并在接入后确认节点都上来了。

:::tip 三个词对照

- **集群** ≈ 一栋机房大楼。
- **节点** ≈ 大楼里的一台服务器。
- **加速卡（GPU / NPU）** ≈ 服务器里专门算 AI 的「引擎」。

:::

## 开始之前

- 你需要 **系统管理员** 账号。
- 准备好目标集群的 **kubeconfig**（连接集群的「钥匙串」文件，见下方说明）。
- 确认平台网络能访问该集群的 API 地址（通常是 `https://<集群地址>:6443`）。

## 集群列表怎么看

左侧菜单点击 **智算平台** 分组下的 **集群管理**，列表里有这些列：

| 列 | 说明 |
| --- | --- |
| 名称 | 点击集群名称进入详情；名称下方是描述 |
| 版本 | 目标集群的 Kubernetes 版本，取不到时显示 `-` |
| 上线状态 | 已上线 / 已下线；只有**已上线**的集群对租户可见 |
| 连接状态 | 平台与集群是否连得上 |
| 创建时间 | 集群接入平台的时间 |

每一行的操作：

| 操作 | 说明 |
| --- | --- |
| 终端 | 打开集群的网页终端，可直接执行 `kubectl` 命令 |
| 上线 / 下线 | 切换集群对租户是否可见，会弹确认框 |
| 编辑 | 进入编辑页 |
| 删除 | 删除集群，会弹确认框 |

## 接入一个新集群

1. 左侧菜单点击 **智算平台** → **集群管理**。
2. 点击右上角 **创建集群**。
3. 在 **集群配置** 卡片中依次填写：

| 表单项 | 怎么填 | 说明 |
| --- | --- | --- |
| 名称 | 例如 `prod-gpu-01` | 先填名称，下面的 ID 会自动生成；ID 也可以手动改，**创建后不能修改** |
| 描述 | 例如「生产 GPU 机房 A 区」 | 可选，方便自己区分 |
| kubeconfig | 粘贴目标集群的 kubeconfig 内容 | 必填，格式见下 |

4. 填完后点击 **测试连接**，确认平台能连上这个集群。
5. 连接没问题后点击 **确定**，完成接入。

:::warning kubeconfig 是一把高权限钥匙

kubeconfig 里含有访问该集群的凭证。建议为平台单独创建一个专用的服务账号，并只授予平台需要的权限，不要直接使用集群管理员的个人凭证。

:::

测试连接的两个结果：

- 成功：表单顶部出现 **连接成功** 提示，并显示探到的集群版本。
- 失败：表单顶部显示失败原因，按提示检查地址、证书或网络后重试。

:::info 只在表单里能测连接

列表页的操作列里**没有**「测试连接」，它只出现在创建 / 编辑表单中。另外，只有 **名称** 和 **kubeconfig** 都填了，**测试连接** 按钮才可点。

:::

### kubeconfig 从哪来

kubeconfig 是连接集群的配置文件，一般由集群管理员提供。你可以在能访问该集群的机器上执行下面的命令，把完整内容复制出来：

```bash
kubectl config view --raw
```

它长这样（`server`、证书和密钥会被替换成真实值）：

```yaml
apiVersion: v1
kind: Config
clusters:
  - cluster:
      server: https://your-k8s-api-server:6443
      certificate-authority-data: <base64-ca>
    name: my-cluster
contexts:
  - context:
      cluster: my-cluster
      user: admin
    name: my-context
current-context: my-context
users:
  - name: admin
    user:
      client-certificate-data: <base64-cert>
      client-key-data: <base64-key>
```

## 上线 / 下线集群

**上线状态** 决定租户能不能看到并使用这个集群：

| 操作 | 效果 |
| --- | --- |
| 上线 | 集群对租户可见，可用于资源分配和部署 |
| 下线 | 对租户隐藏，不能再部署新实例；**已经部署的实例不受影响** |

## 用网页终端执行命令

在列表操作列点击 **终端**，会打开一个网页终端，已经自动连到目标集群，可以直接敲 `kubectl`：

```bash
kubectl get nodes
kubectl get pods -A
kubectl top nodes
```

:::warning 终端权限很高

网页终端具备集群管理员权限，请谨慎操作，避免在生产集群执行破坏性命令。

:::

## 接入后：确认节点都上来了

集群接入后，平台会开始接管这个集群的机器。请按下面步骤确认机器都被识别到：

1. 点击集群名称进入详情页。
2. 左侧 **运维管理** 分组点击 **工作负载**，切到 **节点** 标签，逐条核对机器是否都在列表里。
3. 需要看每台机器的 CPU / 内存负载时，点左侧 **节点状态**；需要看加速卡时，点 **加速卡信息**。

> 节点没有全部出现时，先检查 kubeconfig 用的账号是否有读取节点的权限，以及集群本身是否处于正常状态。

## 集群详情里的子页

点进一个集群后，左侧子菜单分三组：

| 分组 | 子页 |
| --- | --- |
| 集群信息 | 集群信息、节点状态、加速卡信息 |
| 资源管理 | 资源池、资源规格、租户配额 |
| 运维管理 | 工作负载、存储集群、系统应用、调度器管理、日志管理 |

其中：

- **集群信息** 只看基础看板；**节点状态** 看机器，**加速卡信息** 看卡，详见 [节点与加速卡状态](/boss/rune-admin/nodes-gpu)。
- **资源池 / 资源规格 / 租户配额** 是资源分配的地方，详见 [资源池](/boss/rune-admin/resource-pools)、[资源规格](/boss/rune-admin/flavors)、[租户配额](/boss/rune-admin/tenants)。
- **工作负载** 按对象类型浏览集群里的各种资源，详见 [工作负载](/boss/rune-admin/resources)。
- **存储集群** 和 **系统应用** 都是「一键部署中间件 / 存储」的入口，详见 [存储集群与运行时](/boss/rune-admin/storage-runtime) 与 [系统应用](/boss/rune-admin/systems)。
- **调度器管理** 和 **日志管理** 详见 [日志与调度器](/boss/rune-admin/observability)。

## 结果确认

- 列表里出现新集群，**连接状态** 显示为已连接，**上线状态** 按需显示为已上线。
- 进入集群详情，**工作负载 → 节点** 能看到该集群的机器。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 测试连接失败 | 地址 / 证书 / 网络不通 | 核对 kubeconfig 是否完整、平台能否访问集群 API |
| 列表里没有「测试连接」 | 它只在表单里 | 进入创建或编辑页再测 |
| 编辑时改不了 ID | ID 创建后不可修改 | 如确需更换，只能删除后重新接入 |
| 租户看不到集群 | 集群未上线 | 在列表点 **上线** 并确认 |
