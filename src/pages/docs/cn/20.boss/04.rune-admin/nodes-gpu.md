# 节点与加速卡状态

这两个页面用来从「机器视角」看集群：

- **节点状态** 看每台机器（节点）的健康和负载。
- **加速卡信息** 看每张加速卡（GPU / NPU，服务器里专门算 AI 的「引擎」）的使用率、显存和温度。

它们是排查「是机器出问题了，还是卡不够用了」的主要入口。

## 开始之前

- 需要 **系统管理员** 账号。
- 前置：集群已接入平台，并且已经安装监控采集组件。

## 进入方式

1. 顶部导航点击 **智算平台**，再在左侧栏 **智算平台** 分组下点击 **集群管理**，点进目标集群。
2. 左侧 **集群信息** 分组下：
   - 看机器：点击 **节点状态**。
   - 看卡：点击 **加速卡信息**。

:::info 这两个页面是看板，不是机器清单

它们都是「按名字把监控看板聚在一起」渲染出来的，本身**没有节点表格**，不显示节点角色、IP、CPU / 内存明细、标签或污点。要看这类节点对象信息，请到 **运维管理 → 工作负载** 的 **节点** 标签。

:::

## 节点状态看什么

节点状态把名字里含 `node` 的监控看板聚到一起，适合关注：

- 节点是否在线（Ready / NotReady）。
- CPU 与内存使用率。
- 节点压力告警（内存压力、磁盘压力等）。
- 节点之间的负载是否均衡。

![节点状态页：上方是服务器资源总览表（主机总数 5），下方是最近 7 天 P99 使用率与整体负载趋势图](/assets/screenshots/boss/cluster-nodes-01.png)

节点状态页是给物理机做体检的：上面一张资源总览表列出每台主机，下面几张图看趋势。顶部那行小字里的 `当前选中主机【k8s-node8】实例：192.168.0.107:9100` 是 node-exporter 的抓取地址，排查某台机器时可以照着这个地址去查。

## 加速卡信息看什么

加速卡信息把**名称或标题里含 `gpu` 或 `npu`** 的监控看板聚到一起，适合关注：

- 加速卡使用率。
- 显存占用。
- 卡与卡之间的负载是否均衡。
- 某些型号设备的繁忙与空闲情况。

:::info 加速卡看板的排列顺序

如果集群里同时有 NPU 看板和 NVIDIA GPU 看板，**NPU 看板会排在 NVIDIA 的 GPU 看板前面**（平台会把靠后的 NPU 看板前移），方便国产加速卡优先展示。

:::

![加速卡信息页（NPU 集群监控）：五张汇总卡与下方的使用率、显存、功耗趋势图](/assets/screenshots/boss/cluster-gpu-01.png)

加速卡信息页顶部是五张汇总卡：**NPU 总数**、**NPU 节点数**、**平均 NPU 使用率**、**平均 HBM 使用率**、**集群总功耗**。截图里这台集群全是 0，说明它没有接 NPU 卡（纯 CPU + GPU 集群），这种情况下这一页本来就该是空的——不是页面坏了，排查顺序见本节。

## 推荐排查顺序

1. 先看 **集群信息**，判断是整体异常还是局部异常。
2. 怀疑机器故障，进 **节点状态** 看是哪几台机器。
3. 怀疑算力不够或卡分配不均，进 **加速卡信息** 看卡。
4. 要落到具体对象，再去 **工作负载** 或 **日志管理** 交叉排查。

## 结果确认

- 看板能正常出图，说明节点 / 加速卡的监控数据已经采集上来。
- 看板一直空白：到 **系统应用** 检查节点监控、加速卡监控组件是否已部署。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 加速卡信息里看不到卡 | 未安装加速卡监控组件 | 到 **系统应用** 部署对应组件 |
| 想看节点的 IP、角色等明细 | 这两个页面不提供 | 去 **工作负载 → 节点** 查看 |
| 同一型号只显示汇总容量 | 该型号未上报逐设备指标 | 属正常现象，汇总容量仍可参考 |
