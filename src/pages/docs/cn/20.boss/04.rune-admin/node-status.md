# 节点状态

节点状态是**按机器看集群**的看板：集群里每台服务器是否在线、CPU 和内存用了多少、有没有压力、机器之间负载是否均衡。怀疑「某台机器出问题了」时先看这一页。

读完这页，你能找到 **节点状态** 入口、看懂页面上几块图各自回答什么问题，并知道它和 **工作负载 → 节点** 的分工。

:::tip 三个词对照

- **集群** ≈ 一栋机房大楼。
- **节点** ≈ 大楼里的一台服务器。
- **加速卡（GPU / NPU）** ≈ 服务器里专门算 AI 的「引擎」，单独看 **加速卡信息**。

:::

## 开始之前

- 需要 **系统管理员** 账号。
- 前置：集群已接入平台，并且已经安装节点监控采集组件（可在 **系统应用** 里部署）。

## 进入方式

1. 顶部导航点击 **智算平台**，再在左侧栏 **智算平台** 分组下点击 **集群管理**。
2. 点进目标集群。
3. 左侧 **集群信息** 分组下点击 **节点状态**。

## 这一页看什么

节点状态把名字里含 `node` 的监控看板聚在一起，用来回答：

| 问题 | 看哪里 |
| --- | --- |
| 机器都在线吗 | 节点是否 Ready / NotReady |
| 机器忙不忙 | CPU 与内存使用率 |
| 机器有没有隐患 | 节点压力（内存压力、磁盘压力等） |
| 负载均衡吗 | 各节点之间的使用率对比 |

页面顶部可以切换主机，并设置时间窗与自动刷新；下面是资源总览表和趋势图。

![节点状态页：上方是服务器资源总览表，下方是最近 7 天的 P99 使用率与整体负载趋势图](/assets/screenshots/boss/cluster-nodes-01.png)

节点状态页是给物理机做体检的：上面一张资源总览表按主机逐行列出，下面几张图看趋势。顶部那行小字里的抓取地址（例如 `192.168.0.107:9100`）是 node-exporter 的地址，排查某台机器时可以照着它去查监控源。

:::info 这里是看板，不是节点清单
这一页**没有**节点表格，不显示节点角色、IP、标签、污点这类对象信息。要看这些，请到 **运维管理 → 工作负载** 切到 **节点** 标签。
:::

## 常见排查顺序

1. 先看 **集群信息**，判断是整体异常还是局部异常。
2. 怀疑机器故障，进 **节点状态** 看是哪几台机器。
3. 怀疑算力不够或卡分配不均，进 **加速卡信息** 看卡。
4. 要落到具体对象，再去 **工作负载** 或 **日志管理** 交叉排查。

## 结果确认

- 看板能正常出图，说明节点监控数据已经采集上来。
- 图表一直空白：到 **系统应用** 检查节点监控组件是否已部署。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 图表一直空白 | 集群未安装节点监控采集组件 | 到 **系统应用** 部署监控组件 |
| 想看节点的 IP、角色等明细 | 这一页不提供 | 去 **工作负载 → 节点** 查看 |
| 某台机器没有数据 | 该机器的采集组件异常或被隔离 | 检查该节点上的采集组件与网络 |
