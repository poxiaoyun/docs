# 资源池

资源池就是把集群这台「机房大楼」里的机器，按用途划成几个「功能区」：一个池给推理、一个池给训练、一个池留给平台自己。同一台机器**同一时间只属于一个资源池**；没有明确划走的机器都在系统保留的 **默认** 池里。

读完这页，你能完成：新建一个资源池、看懂某个池的容量与节点归属、把某台机器改到另一个池、以及删除不再用的池。

:::tip 三个词对照

- **集群** ≈ 一栋机房大楼。
- **节点** ≈ 大楼里的一台服务器。
- **资源池** ≈ 把大楼里的机器划成几个「功能区」，不同部门分着用。

:::

## 开始之前

- 你需要 **系统管理员** 账号。
- 前置：集群已接入平台，并且资源池已完成初始化。
- 配额要选资源池，所以顺序上建议先建池、再发配额。

## 进入方式

1. 顶部导航点击 **智算平台**，再在左侧栏 **智算平台** 分组下点击 **集群管理**。
2. 点进目标集群。
3. 左侧 **资源管理** 分组点击 **资源池**。

## 页面长什么样

页面是「左边池列表 + 右边详情」的两栏结构：

| 区域 | 内容 |
| --- | --- |
| 左栏 | 资源池卡片列表，顶部显示「共 N 个资源池 · 默认资源池置顶」，可搜索、可翻页（每页 20 个）、可设置刷新间隔（**默认关闭**不自动刷新） |
| 右栏 | 选中池的健康标签、容量快照、节点与加速卡树，以及 **编辑信息 / 删除** 菜单 |

右栏上方有状态标签帮你判断这个池是否正常：

| 标签 | 含义 |
| --- | --- |
| 同步 | 节点归属是否已经同步成功 |
| 节点健康 | 池里的机器是否 Ready、是否有压力 |

**容量快照** 给的是节点数、可分配 CPU、可分配内存与物理设备供给；下面的**节点与加速卡树**按 Node → 设备展开，可以逐台机器看归属。

![资源池管理：默认资源池置顶，左栏是各资源池，右栏是容量快照与节点 / 加速卡树](/assets/screenshots/boss/cluster-pools-01.png)

页头写着「划分集群节点，并按 Node → 设备查看容量、健康与当前监控；**当前不包含调度**」——最后半句很重要：这里划好的池本身还不直接决定调度，调度要靠规格与配额配合。

## 创建资源池

1. 在资源池页面点击右上角 **创建资源池**。
2. 填写三项：

   | 表单项 | 怎么填 | 说明 |
   | --- | --- | --- |
   | 显示名 | 例如 `推理专用` | 界面上展示的名字 |
   | 唯一 ID | 例如 `pool-inference` | 系统里的唯一标识，创建后不可修改 |
   | 描述 | 例如「推理业务专用」 | 可选，一句话说明 |

3. 点 **确定** 保存。

:::info 创建时不选机器
新建表单里**没有**选节点的步骤。池建好是空的，机器归属要到 **节点归属** 里逐台调整。
:::

## 调整节点归属

1. 在资源池页面打开 **节点归属**（地址带 `?intent=node-membership` 的那个工作台）。
2. 上方是节点列表，支持搜索、按状态筛选、调整每页条数。
3. 找到要调整的机器，点它的 **编辑资源池**。
4. 选择目标资源池后点 **确认调整**。
5. 该行显示的归属立即更新；批量调整就逐台重复这一步。

:::tip 为什么是逐台改
节点归属以**节点**为单位维护，不提供「选中一批机器一次性挪到另一个池」的入口。这样每次变更的影响范围清晰，出问题也容易回滚。
:::

## 编辑资源池信息

1. 在左栏选中目标池。
2. 右栏菜单点 **编辑信息**。
3. 修改显示名或描述（唯一 ID 不可改）。
4. 保存。

## 删除资源池

1. 在左栏选中目标池（**默认池没有删除入口**）。
2. 右栏菜单点 **删除**。
3. 确认框提示「确认删除 {名称}？此操作不可撤销。」，确认后删除。

删除后，池里的机器回到 **默认** 池。删除默认池时，系统提示「Scheduling 将自动重建默认资源池」——也就是说默认池是系统保底结构，删了会被重建。

:::warning 删除前先确认没有业务在用
资源池被资源规格或配额引用时，相关业务会失去可用的机器范围。删之前先确认这些池不再被使用。
:::

## 资源和租户是怎么关联的

资源池本身不会直接发给某个租户，它通过两步挂上关系：

1. **资源规格** 可以绑定某个资源池，决定这份规格能落到哪些机器，见 [资源规格](/boss/rune-admin/flavors)。
2. **配额** 在「资源池 + 资源项」这一层把额度发给租户，见 [租户资源](/boss/rune-admin/tenants)。

## 默认资源池

- 系统保留一个默认池，**置顶显示**，不显示同步与监控状态。
- 未分配给其他池的机器都归在默认池里。
- 删除其他资源池后，里面的机器回到默认池。
- 默认池删除后由系统自动重建。

## 结果确认

- 左栏的计数从「共 N 个资源池」变成 N+1，并出现新卡片。
- 选中新池，右栏 **容量快照** 里的节点数、可分配 CPU / 内存有数值（前提是已有机器归属）。
- 调整归属后，机器的 **同步** 状态最终变为已同步。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 新池里没有机器 | 创建时不选机器 | 到 **节点归属** 逐台设置 |
| 页面数据不自动刷新 | 刷新间隔默认关闭 | 手动点刷新，或自己设一个刷新间隔 |
| 某台机器改不了归属 | 权限不足，或该机器状态异常 | 确认账号权限，检查节点健康 |
| 删除不了默认池 | 默认池由系统保底 | 属正常现象；删了也会被自动重建 |
| 池被删除后业务报没有可用节点 | 规格或配额还指向这个池 | 重新建池并把规格、配额指过去 |
