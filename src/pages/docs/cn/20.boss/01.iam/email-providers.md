# 邮件服务

邮件服务决定**平台的邮件从哪个邮箱、通过哪台 SMTP 服务器发出去**。用户在登录、注册、改邮箱、绑定身份验证器时收到的验证码，都是这里配的服务发出去的。

读完这页，你能完成：新增一个邮件服务、填 SMTP 与发件模板、测试连接、分配发送用途，以及安全地换掉正在用的登录发件服务。

:::tip 一个服务 = 一个发件通道
把邮件服务想成「一台发信机 + 一段模板」。你可以配多台（例如通知用一台、验证码用一台），但**同一类用途在同一时刻只能挂在一台上**，避免同一个人收到两封不一样的验证码。
:::

## 认识概念

| 名词 | 通俗解释 |
| --- | --- |
| SMTP | 发邮件用的标准协议，你需要主机、端口、账号和密码 |
| SMTP 主机 | SMTP 服务器的域名或 IP，**不含** `smtp://` 这类协议前缀，也不含端口 |
| 传输加密模式 | 连接怎么加密：自动、隐式 TLS、STARTTLS |
| 发送用途 | 这台服务专门发哪类邮件，例如只发登录验证码 |
| 占位符 `%s` | 邮件正文里代表验证码的位置，发送时会被替换成真实验证码 |
| 测试连接 | 用当前 SMTP 配置检查连接与认证，**不发信、不保存配置** |

## 开始之前

- 你需要**系统管理员**账号。
- 准备好邮件服务商给的：SMTP 主机、端口、用户名、密码（有的服务商叫「授权码」）。
- 确认发件邮箱已经在服务商那边验证过、允许用来发信。

## 列表怎么看

进入 **账户管理 → 系统管理 → 邮件服务**，列表有四列：

| 列 | 说明 |
| --- | --- |
| 名称 | 服务的名字，点击进入详情 |
| 发送用途 | 全部用途，或具体几种（登录、注册、账户资料修改、找回密码、MFA 绑定、MFA 验证）；没分配时显示 **未分配用途** |
| SMTP 主机 | 配置的服务器地址 |
| 发件邮箱 | 邮件里的发件地址 |

右上角新建。行操作有 **编辑** 和 **删除**；**只有「未分配用途」的服务才能删除**——已经承担发送任务的服务删不掉，需要先清空它的用途。

## 新建一个邮件服务

1. 进入 **账户管理 → 系统管理 → 邮件服务**。
2. 点新建按钮，按下面四段填写。

### 第一段：基本配置

| 字段 | 说明 |
| --- | --- |
| Logo | 显示在列表里的图标，可选 |
| 名称 | 服务的显示名，例如「企业邮箱」 |

### 第二段：发送用途

| 选项 | 含义 |
| --- | --- |
| 全部用途 | 这台服务承担所有邮件发送。**不能**和下面的具体用途同时选 |
| 登录 | 登录时用的邮箱验证码 |
| 注册 | 注册时用的邮箱验证码 |
| 账户资料修改 | 用户改邮箱、改手机号时发的验证码 |
| 找回密码 | 自助找回密码的验证码。**当前属预留用途**，见下方说明 |
| MFA 绑定 | 绑定身份验证器时的验证码 |
| MFA 验证 | 登录时的二次验证码 |

规则：

- **全部用途**与具体用途**互斥**，只能二选一。
- 同一渠道里，**每项用途在同一时刻只能关联一个服务**。
- 清空所有用途后，这台服务就不参与发送，也就允许删除了。

:::warning 「账户资料修改」和「找回密码」不是一回事
界面上 **账户资料修改** 对应改邮箱/改手机号，**找回密码** 对应自助重置密码。两个名字很像，别勾错。目前登录页的「找回密码」只有一句提示「当前平台尚未提供自助找回密码。请联系平台管理员重置密码」，所以勾 **找回密码** 只是把用途预留好，**不会**让用户立刻能自助重置。忘记密码仍需管理员在[用户管理](/boss/iam/users)里重置。
:::

### 第三段：SMTP 配置

| 字段 | 怎么填 | 说明 |
| --- | --- | --- |
| SMTP 主机 | 例如 `smtp.example.com` | 只填域名或 IP，不含协议前缀和端口 |
| SMTP 端口 | 例如 `465`、`587`、`25` | 按服务商给的值填 |
| 传输加密模式 | **自动** / **隐式 TLS** / **STARTTLS** | 自动由平台判断；STARTTLS 是机会式升级，不保证强制加密 |
| SMTP 用户名 | 服务商给的用户名 | 仅当服务器允许无认证发送时才留空 |
| SMTP 密码 | 密码或授权码 | 已有配置时留空表示沿用已保存的密码 |
| 测试连接 | 按钮 | 用当前填的内容检查连接与认证；**不发送邮件、不保存配置**。成功提示「本次 SMTP 连接及认证检查通过。」 |

:::info 测试通过 ≠ 邮件能送达
测试连接只验 SMTP 连接和认证。发件邮箱是否被服务商允许、正文模板是否有效、收件方是否把它当垃圾邮件，都要靠实际发一封才能确认。
:::

### 第四段：发件人与模板

| 字段 | 说明 |
| --- | --- |
| 发件邮箱 | 例如 `noreply@example.com`，用户看到的发件地址 |
| 发件人名称 | 显示在收件箱里的发件人名字 |
| 邮件主题 | 例如「验证码」 |
| 邮件正文 | 例如「您的验证码是 %s。请勿向他人泄露。如非本人操作，请忽略此邮件。」 |

:::warning 正文必须保留一个 %s
`%s` 是验证码的占位位置，发送时会被替换成真实验证码。请**保留它**，也不要在这里填一个真实验证码；漏掉占位符会导致验证码无法出现在邮件里。
:::

## 换掉正在用的登录发件服务

直接删旧服务是行不通的（有用途就删不掉），顺序要这样走：

1. 到 **认证策略 → 登录与注册**，先**关闭**邮箱验证码登录。
2. 回到邮件服务，把旧服务上的 **登录** 用途取消。
3. 给新服务勾上 **登录** 用途并保存。
4. 回到 **认证策略**，重新打开邮箱验证码登录。

中途某一步保存失败时，先核对已经存下的配置再继续，避免出现「旧服务已解绑、新服务没生效」的空窗。

## 结果确认

| 你想确认的事 | 去哪里看 |
| --- | --- |
| 配置保存了 | 列表里出现该服务，SMTP 主机和发件邮箱正确 |
| 连接没问题 | 编辑页点 **测试连接**，看到「本次 SMTP 连接及认证检查通过。」 |
| 用途挂上了 | 列表的 **发送用途** 列显示对应的用途名 |
| 验证码真能收到 | 退出登录，走一次邮箱验证码登录，看是否收到邮件 |

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 测试连接报认证失败 | 用户名/密码错，或服务商要求用授权码 | 用服务商给的授权码；确认用户名是完整邮箱地址还是短名 |
| 测试连接报超时 | 主机/端口不对，或端口被防火墙挡住 | 核对端口与加密模式组合（465 配隐式 TLS、587 配 STARTTLS 最常见） |
| 测试通过但用户收不到信 | 发件邮箱未验证、被判垃圾邮件、正文缺占位符 | 换已验证的发件邮箱；检查正文是否保留了 `%s`；让对方查垃圾箱 |
| 保存时提示用途冲突 | 该项用途已经挂在另一个服务上 | 先去那个服务取消该用途，再回来勾 |
| 删除按钮不可用 | 服务还带着用途 | 先清空 **发送用途** 再删 |
| 登录页没有邮箱验证码入口 | 没有服务承担 **登录** 用途，或认证策略里该登录方式关着 | 两处都检查一遍 |
