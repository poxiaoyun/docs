# 模型卡片

模型卡片就是模型详情页的**介绍页**，打开仓库时默认看到的那一页（页签叫 **模型介绍**）。左边是正文，右边是一栏概况信息。

别人值不值得下载、敢不敢用，基本靠这一页决定。把正文写好，是上传模型之后最值得花时间的一步。

## 正文来自哪里

正文就是仓库根目录里的 `README.md`。你改这个文件，卡片内容就跟着变。

1. 打开模型仓库，点击 **文件** 标签页。
2. 在文件列表里找到 `README.md`，点击行末的编辑图标。
3. 用 Markdown 写内容，填好 **提交信息**，提交。
4. 回到 **模型介绍** 标签页，就能看到更新后的卡片。

还没有 `README.md` 时，在 **文件** 页点 **添加文件**，选 **新建文件**，文件名填 `README.md` 即可。

> 在线编辑只支持不超过 2 MiB 的文本文件。README 很大或想用本地编辑器，就用 Git / SDK 把 `README.md` 传上来，见[模型的上传](/moha/models/upload)。

:::tip README 里可以直接放仓库里的图片
用相对路径引用同仓库的文件，例如 `![效果图](images/demo.png)`，平台会自动把它替换成能访问的地址。
:::

## 右侧信息栏有什么

右侧区块是**根据仓库信息自动生成**的，只有对应信息存在时才会出现，不需要你手动配置。

| 区块 | 出现条件 | 里面是什么 |
| --- | --- | --- |
| 用户评分 / 下载次数 | 一定会出现 | 平均分、参与人数、累计下载量 |
| Safetensors | 检测到模型统计信息 | 模型尺寸、张量类型；仓库根目录有 `chat_template.jinja` 时还会出现聊天模板 |
| 推荐 | 平台标注了推荐语 | 推荐指数和推荐说明 |
| 模型系谱 | 声明了基模型或衍生关系 | 上游基模型和下游衍生模型，可点开查看 |
| 训练关系 / 被空间使用 | 一定会出现 | 该模型用到的数据集、引用该模型的空间 |
| 硬件依赖 | 模型资源 | 运行所需的加速卡、显存等要求 |

## 关于评分

- 评分是一到五星，点一次就生效。
- 已经有人评过分后，星级变为只读，不能改。
- 鼠标悬停在评分数上能看到「几人参与」。

## 写好模型卡片的建议

在 README 里覆盖这几块，别人一看就懂：

- **这个模型能干什么**：任务类型、适用场景。
- **怎么用**：一段最小可运行的加载代码。
- **训练数据和方法**：用了什么数据、怎么训练的。
- **评测结果**：在什么数据集上得到什么分数。
- **局限和注意事项**：不适合什么场景、有什么风险。
- **许可证**：允许别人怎么用。

:::tip 元数据也要填
详情页右侧区块和模型库的筛选条件，都依赖创建仓库时填的许可证、分类、框架、标签等信息。
在 **设置** 标签页里可以把这些元数据补全。
:::
