# 创建空间

创建一个空间分两步走：先在表单里把「跑什么、跑在哪、给谁看」定下来，提交后再把应用代码推上去。这一页讲清楚表单里每个字段的意思，以及哪些选项提交后就再也改不了。

## 认识概念

| 名词 | 通俗解释 |
| --- | --- |
| 空间 | 用代码搭建并发布到网上的在线应用，别人打开链接就能用 |
| 接入SDK | 应用的「脚手架」，决定平台用什么方式把你的代码跑起来 |
| 部署工作空间 | 应用实际运行的位置，由一个 **区域** 加一个 **工作空间** 组合确定 |
| 规格 | 分配多少 CPU、内存和加速卡；不选就用平台的默认实例 |
| 定时运行 | 只在指定时段运行，时段外副本数降为 0 |

:::tip 接入SDK、部署工作空间、规格三者的关系
可以理解成「开一家店」：接入SDK 决定你开的是什么类型的店（咖啡馆还是书店），部署工作空间是店铺地址，规格是店面大小。地址和店铺类型一旦定下就搬不动了，店面大小以后还能改。
:::

## 开始之前

- 已经登录魔哈，并且是某个组织的成员——空间必须挂在组织下面。
- 准备好一份能跑起来的应用代码（例如 Gradio、Streamlit 应用或 Docker 镜像）。
- 如果组织里已有共享的部署工作空间，先向组织管理员确认该用哪一个。

## 打开创建表单

1. 顶部导航点击 **空间**。
2. 点页面顶部的 **创建空间**。

从首页的快捷创建入口、或 **我创建的** 页签右上角的 **创建空间** 也能进同一个表单。

![创建空间表单：空间区块（名称、ID、组织、描述）、元数据区块、部署配置、定时运行](/assets/screenshots/moha/create-space-01.png)

## 填写基本信息

| 表单项 | 怎么填 | 说明 |
| --- | --- | --- |
| 名称 | 例如 `我的问答机器人` | 必填，是给别人看的显示名，之后可以在设置里改 |
| ID | 自动生成，一般不用管 | 名称下方会显示 `ID: xxx`；点铅笔图标可以手动指定 |
| 组织 | 从下拉里选 | 必填，决定这个空间归谁所有；从组织主页进入时已固定，不能改 |
| 描述 | 例如 `基于知识库的客服问答` | 可留空，建议一句话说清它解决什么问题 |

ID 由名称自动生成：中文会转成拼音，非法字符替换成短横线，只能以字母或数字开头、只含字母数字和 `.` `_` `-`，最长 63 个字符。**ID 创建后不能修改**，提交前请确认。

## 填写元数据

| 表单项 | 怎么填 |
| --- | --- |
| 许可证 | 从下拉里单选，说明别人可以怎么用这个空间 |
| 领域 | 多选，例如多模态、计算机视觉、自然语言处理 |
| 场景 | 多选，描述应用的使用场合 |

这三项都可以留空，但填得越全，别人越容易在空间列表里筛到你。留空后也能在 **设置** 的 **元数据** 卡片补。

## 选择接入SDK与部署工作空间

在 **部署配置** 区块里：

1. **接入SDK**：选择应用模板。这个选项决定了平台怎么构建并启动你的应用。
2. **部署工作空间**：先选 **区域**，再选 **工作空间**。必须先选区域，工作空间列表才会出来。
3. 两项都选好后，页面会带出对应的 Git 地址，稍后推代码就用它。

:::warning 这两项创建后不可修改
**接入SDK** 和 **部署工作空间** 提交后就固定了，设置页里也只能看不能改。如果选错了，只能重建一个空间。提交前请和同事确认区域与工作空间没选错。
:::

## 选择规格与环境变量

**规格** 决定这个空间分到多少 CPU、内存和加速卡。不勾选任何规格时，平台会按默认实例运行——这也是最省事的做法，先用默认规格跑通，不够再调。

需要给应用传配置时，在 **环境变量** 里逐条添加：

| 字段 | 说明 |
| --- | --- |
| 变量名 | 应用代码里读取的键，例如 `MODEL_NAME`；同一份配置里不能重名 |
| 变量值 | 这个键对应的值 |

点 **添加环境变量** 增加一组，点垃圾桶图标删除。留空的键或值无法提交。

## 定时运行（可选）

如果这个空间只在某些时段有人用（例如只在工作时间提供服务），在 **定时运行** 区块里打开开关，选择运行方式：

| 运行方式 | 还要填什么 |
| --- | --- |
| **每天固定时段** | 开始时间、结束时间 |
| **按星期运行** | 运行日（可多选）、开始时间、结束时间 |
| **仅运行一次** | 开始日期、结束日期、开始时间、结束时间 |

再填写 **时区**（IANA 写法，如 `Asia/Shanghai`）。不开启就按固定副本数一直运行。这一项创建后还能在 **设置** 里改。

## 添加成员与设置可见性

1. 在 **成员** 区块点 **添加成员**，填 **用户名**、选 **角色**：

| 角色 | 权限 |
| --- | --- |
| **管理员** | 可以管理成员、改设置，也能发布和停止空间 |
| **读写** | 可以推送代码和改文件 |
| **只读** | 只能查看 |

2. 在 **可见性** 区块选一个档位：

| 选项 | 谁能看到 |
| --- | --- |
| **公开** | 任何人，包括未登录访客 |
| **内部** | 该组织的成员 |
| **私有** | 只有仓库成员 |

默认值取决于入口：从 **我创建的** 进来默认 **私有**，从组织主页进来默认 **内部**。

3. 点 **确定** 提交，想放弃点 **取消**。

## 结果确认

- 提交后页面跳到这个空间的 **概览**，因为还没有代码，会显示一段上手说明（`git lfs install` → `git clone` → 写 `app.py` → 提交）。
- 顶部状态标签显示 **部署中**，说明平台已经开始准备实例。
- **文件** 页签里能看到仓库目录结构，说明仓库创建成功。
- 接着按概览里的说明把代码推上去，再回到概览点 **操作** → **发布**，见[发布、停止与重新发布](/moha/spaces/operations)。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 选完区域后工作空间还是空的 | 这个区域下没有你组织可用的工作空间 | 换一个区域，或联系组织管理员开通 |
| 提交时提示名称格式不对 | 名称里带了空格或中文标点 | 改用字母、数字和 `.` `_` `-` |
| 提交后状态一直是 **部署中** | 实例还在调度，或者配置有问题 | 打开 **操作** → **日志** 看具体卡在哪一步 |
| 想换接入SDK或工作空间 | 这两项提交后不可修改 | 只能新建一个空间，把代码推过去 |
