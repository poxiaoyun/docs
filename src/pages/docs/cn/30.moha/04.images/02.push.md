# 推送镜像与管理标签

镜像不是「上传文件」，而是用 Docker 的 `push` 推上来的。这一页给出从登录到推送的完整命令，再讲怎么在 **标签** 页签里管理版本、做漏洞扫描。

## 认识概念

| 名词 | 通俗解释 |
| --- | --- |
| 镜像仓库 | 存放镜像的地方，魔哈里每个镜像都有自己的仓库地址 |
| 标签（tag） | 一个镜像的版本名，例如 `v1.0`、`latest`；同一个镜像可以有多个标签 |
| 摘要（digest） | 镜像内容的唯一指纹，内容不变摘要就不变 |
| 架构 | 镜像适配的 CPU 架构，例如 `linux/amd64`、`linux/arm64` |
| 镜像扫描 | 检查镜像里已安装的软件有没有已知漏洞 |

:::tip 标签和摘要的区别
标签像「书名」，你可以把同一本书换个名字重新出版；摘要是「内容的指纹」，改一个字指纹就变。所以正式发布建议同时记住标签和摘要。
:::

## 开始之前

- 已经在本地把镜像构建好，`docker images` 能看到它。
- 你在目标组织里能写这个镜像仓库，或者你自己就是仓库的所有者。
- 本机装有 Docker，并且能访问平台地址。

## 第一步：登录镜像仓库

1. 打开这个镜像的详情页，点右上角的 **推送镜像**。
2. 弹窗里第一段是 **登录镜像仓库**，命令形如：

```bash
docker login <镜像仓库地址> -u <用户名> -p <访问令牌>
```

3. 点命令右侧的复制图标，粘贴到终端执行。看到 `Login Succeeded` 就说明登录成功。

:::warning 这条命令里带着你的令牌
弹窗里为了安全会显示成掩码，但复制出来的内容是真实令牌。不要在共享屏幕、录屏或聊天群里粘贴这条命令。
:::

## 第二步：给本地镜像打标签

推送前必须让本地镜像的名字符合平台的地址格式，这一步用 **标记镜像** 命令：

```bash
docker tag <本地镜像> <镜像仓库地址>/<组织>/<镜像名>:<标签>
```

例如本地镜像是 `my-app:dev`，要推到 `ai-lab` 组织下名为 `chatbot` 的镜像，标签用 `v1.0`：

```bash
docker tag my-app:dev <镜像仓库地址>/ai-lab/chatbot:v1.0
```

弹窗里给出的 `<tag>` 默认取这个镜像已有的第一个标签，换掉它即可。

## 第三步：推送

```bash
docker push <镜像仓库地址>/<组织>/<镜像名>:<标签>
```

推送大镜像可能要几分钟，终端里会按层显示进度。看到每一层都是 `Pushed`，并且最后打印出 digest，就说明推送完成。

推送完成后回到镜像详情页的 **标签** 页签，刷新一下就能看到新标签。

## 标签页里有什么

**标签** 页签是这个镜像所有版本的清单：

| 列 | 含义 |
| --- | --- |
| **标签** | 版本名，例如 `main`、`v1.0` |
| **拉取镜像** | 这个标签的 `docker pull` 命令，带一键复制 |
| **架构** | 这个标签下包含哪些架构；同一个标签可以同时有 amd64 和 arm64 |
| **更多操作** | 展开后可以做 **镜像扫描** 和 **删除 tag** |

点开某个标签，会展开 **镜像扫描** 区块，按架构逐行列出：

| 列 | 含义 |
| --- | --- |
| **摘要** | 该架构镜像的 digest |
| **架构** | `操作系统/CPU 架构`，例如 `linux/amd64` |
| **扫描状态** | 未扫描、排队中、扫描中、扫描完成、扫描错误 |
| **大小** | 这一份镜像的体积 |

## 拉取一个镜像

1. 在 **标签** 页签找到要用的标签。
2. 在 **拉取镜像** 一列点复制，得到 `docker pull <镜像仓库地址>/<组织>/<镜像名>:<标签>`。
3. 粘贴到终端执行。如果是私有镜像，先按上面的「第一步」登录一次。
4. Docker 会按你的机器架构自动选择对应的那一层。

## 扫描漏洞

1. 在 **标签** 页签展开某个标签。
2. 在某个架构那一行点 **镜像扫描**。
3. 扫描过程中按钮变成 **停止扫描**，想中断就点它。
4. 扫描完成后，这一行会显示四档漏洞数量：**严重**、**高危**、**中危**、**低危**；没有发现问题时显示 **未发现漏洞**。
5. 点数量标签打开 **CVE 报告**，逐条看漏洞 ID、包名、严重程度、版本和修复版本。

:::info 扫描是按架构分别做的
同一个标签下的 amd64 和 arm64 是两份不同的内容，要各自扫描。推送新内容后需要重新扫描，旧报告不会自动更新。
:::

## 删除标签

在 **更多操作** 里点 **删除 tag**，弹窗会提示：删除后无法再通过这个 tag 拉取镜像，该 tag 下所有架构的扫描任务、状态和漏洞报告也会一起删除；其他 tag 和镜像内容不受影响。

:::warning 删标签前先确认没人依赖它
如果 CI 或其他服务写死了这个 tag，删除后它们会立刻拉不到镜像。重新推出同名 tag 之后，还需要重新扫描。
:::

## 修改镜像的元数据

| 想改什么 | 去哪里 |
| --- | --- |
| 分类、加速框架 | **设置** → **元数据** |
| 简介正文（详情页那段 Markdown） | **设置** → **简介** |
| 可见性 | **设置** → **可见性** → **更改可见性** |
| 别名、描述 | **设置** → **基本信息** |

镜像没有文件页和快照页：内容的版本由标签管理，历史由镜像仓库自己保存。

## 结果确认

- `docker push` 结束后终端最后一行打印出 `digest: sha256:...`，说明推送成功。
- **标签** 页签里出现刚推的标签，**架构** 一列至少有一项。
- 点 **拉取镜像** 复制命令，在另一台机器上执行能拉下来，说明权限和地址都对。
- 扫描完成后这一行出现漏洞数量或 **未发现漏洞**。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| `denied: requested access to the resource is denied` | 没登录，或账号在这个仓库没有写权限 | 重新执行 **登录镜像仓库** 命令；确认角色是管理员或读写 |
| `unauthorized` | 令牌过期（登出后旧令牌立即失效） | 到 **访问令牌** 页重新复制，再登录一次 |
| 推送成功但标签页看不到 | 页面还没刷新 | 点标签页的刷新图标 |
| 拉下来的镜像跑不起来 | 架构不匹配 | 在 **架构** 一列确认有这个平台，或显式指定 `--platform` |
| 扫描一直停在排队中 | 扫描任务较多 | 稍后刷新；持续不动就联系平台管理员 |
