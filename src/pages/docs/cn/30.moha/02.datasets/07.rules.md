# 数据集文件规范

这一页是上传前的**避坑清单**。平台的限制是硬性的，不符合会被直接拒绝；建议部分是帮你少走弯路的经验。

## 命名规则

| 项目 | 规则 | 示例 |
| --- | --- | --- |
| 仓库名称 | 以字母或数字开头，可以包含字母、数字、点 `.`、下划线 `_`、连字符 `-` | `chinese-qa-v2` |
| 仓库 ID | 以小写字母开头，只能用小写字母、数字、连字符；**创建后不能改** | `chinese-qa-v2` |
| 文件 / 文件夹名 | 不能为空或纯空格，不能含控制字符，单个名称不超过 255 字节 | `train-2026-01.parquet` |
| 文件路径 | 从仓库根目录算起的相对路径，总长度不超过 1024 字节 | `train/part-0001.parquet` |
| 保留名称 | 不能创建 `.git` 目录，也不能提交 `.gitattributes`、`.gitmodules` | — |

> 名称里不要用中文、空格和斜杠，否则提交时会报格式错误。

## 大小与数量上限

| 限制项 | 上限 | 超过会怎样 |
| --- | --- | --- |
| 网页一次上传的文件数 | 100 个 | 提示「文件数量超过100个，请使用 Moha SDK 上传」 |
| 网页一次上传的总大小 | 100 MiB | 提示「文件总量超过100MB，请使用 Moha SDK 上传」 |
| 单个文件（走普通 Git，不走 LFS） | 5 MB | 推送被拒绝，提示改用 Git LFS 或 Moha SDK |
| 在线新建 / 编辑文本文件 | 2 MiB | 只能改用上传文件或 SDK |
| 提交信息 | 必填，第一行不超过 200 字符 | 无法提交 |

:::warning 大文件必须走 Git LFS
用普通 Git 提交超过 5 MB 的新文件会被服务端直接拒绝，这不是网络问题，是平台的硬性限制。
请先执行 `git lfs track "*.parquet"` 之类的命令登记，再 `git add`；或者直接改用 SDK 上传。
:::

:::tip 限制以页面提示为准
平台管理员可以为某个仓库配置更严格的上传限制。如果页面上提示的上限和这里不一样，以页面提示为准。
:::

## 目录组织建议

按用途分目录，别人一眼就能看懂：

```text
chinese-qa/
├── README.md            # 数据集说明，会被渲染成介绍页
├── train/
│   └── part-0001.parquet
├── validation/
│   └── part-0001.parquet
└── test/
    └── part-0001.parquet
```

- 目录名用英文小写，用 `-` 或 `_` 连接。
- 文件名带上版本或日期，例如 `train-2026-01.parquet`。
- 大文件切分成多个小块，方便别人按需下载。

## 内容合规要求

平台会校验文件的大小、路径和命名。**内容本身是否合规，需要你自己把关**：

- 不要上传违反法律法规、侵犯他人著作权或包含恶意代码的内容。
- 不要上传未经处理的他人个人信息。
- 上传前请确认你有权分发这份数据。

## 隐私与安全建议

- 上传前对个人信息做**脱敏处理**：姓名、手机号、身份证号、住址等。
- 在 README 里注明数据来源和使用限制。
- 敏感数据把可见性设为 **个人** 或 **租户内**，不要设为 **公开**。

## 许可证选择

在仓库元数据里填写许可证，告诉别人可以怎么用这份数据：

| 许可证 | 含义 |
| --- | --- |
| CC BY 4.0 | 允许自由使用，需注明出处 |
| CC BY-SA 4.0 | 允许使用，衍生作品需用同样的许可证 |
| CC BY-NC 4.0 | 仅允许非商业使用 |
| Apache 2.0 | 宽松许可，适合代码型数据 |

## 提交前自检

- [ ] 名称只用字母、数字、`-`、`_`、`.`
- [ ] 大文件已经用 Git LFS 登记，或改用 SDK 上传
- [ ] 网页上传没有超过 100 个文件 / 100 MiB
- [ ] 目录按用途分好，文件名带日期或版本
- [ ] 个人信息已脱敏，许可证已填写
