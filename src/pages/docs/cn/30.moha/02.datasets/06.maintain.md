# 数据集的维护

数据集不是传完就不管了。数据会补充、会修错、会调整格式。这一页讲怎么安全地做这些改动。

![数据集的快照页：表格列出标题、分支、提交信息、创建者、创建时间，每行可做差异 / 回滚 / 删除快照](/assets/screenshots/moha/repo-dataset-freezes-01.png)

快照和分支是两回事：**分支** 是一条可以继续往前走的线，**快照** 是把某一刻拍下来存档，不会被后续提交改动。回滚会以一条新提交的形式撤销改动，历史记录仍然保留。

## 版本管理：分支 + 快照

| 名词 | 通俗解释 |
| --- | --- |
| 分支 | 数据的一条时间线。`main` 是正式版；清洗、试验性的改动建议开新分支 |
| 快照 | 给当前状态拍一张照片存档，随时能回到那一刻 |
| 回滚 | 把某条分支恢复到某张快照对应的状态 |

在 **文件** 标签页左上角的 **分支：xxx** 按钮里，可以同时切换分支和快照，见[模型版本](/moha/models/version)（数据集用法相同）。

:::tip 发布给别人之前先拍快照
把数据集分享给同事之前，先做一次快照。这样对方引用的是固定版本，你后续再改数据也不会影响他。
:::

## 追加数据

推荐在本地克隆后提交推送，改动记录清清楚楚：

```bash
cd my-dataset
cp /path/to/new-data/*.parquet .

git add .
git commit -m "追加 2026-01 训练数据"
git push origin main
```

只想临时补一个小文件，也可以直接在网页操作：进入 **文件** 标签页，点 **添加文件** → **上传文件**，填好 **提交信息** 后提交。

## 修改和删除文件

在 **文件** 标签页，鼠标移到某一行文件上，行末会出现操作图标：

| 图标 | 作用 | 注意 |
| --- | --- | --- |
| 编辑 | 在线修改文本文件内容 | 不超过 2 MiB 的文本文件才支持 |
| 删除 | 从当前分支删除该文件 | 需要手动输入文件名确认 |

:::warning 删除影响的是整个分支
删除文件后，所有查看这条分支的人都会看不到它。虽然历史记录里还留着这次改动，但**当前分支上的文件确实没了**。
删除前请确认没有别人正在依赖这个文件。
:::

## 回滚一次改动

如果新提交的数据有问题，可以把它撤销掉：

```bash
# 撤销最近一次提交的改动，并生成一条新的撤销记录
git revert HEAD
git push origin main
```

如果只是想退回到某个较早的固定状态，用页面上的**快照回滚**更直观，见[模型版本](/moha/models/version)。

:::warning 回滚不可逆
回滚会把目标分支重置到快照对应的提交，**提交历史可能被改写**。回滚前请确认没有人正在基于这条分支工作。
:::

## 清理与归档的建议

- **删掉过期文件**：在本地删除后提交推送，别让仓库里堆着没人用的旧数据。
- **归档历史版本**：确实需要保留的旧数据，单独开一条分支，或做一次快照固定下来。
- **优先用快照而不是长期保留大量分支**：分支太多时，切换版本会很乱。

:::warning 大文件的历史会一直占空间
Git 会保留每次提交的历史，反复提交大文件会让仓库越来越大。建议一开始就用合适的数据格式（如 Parquet），并定期清理不再需要的历史大文件。
:::
