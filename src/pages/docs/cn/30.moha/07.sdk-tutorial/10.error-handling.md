# 错误处理与常见问题

脚本跑挂了，先别急着改代码。SDK 抛出的异常就那么几类，消息里也一定写清了是哪个仓库、哪个文件出的问题。
这一页给你一张「报错信息 → 含义 → 怎么办」的对照表，以及几个能直接抄的处理套路。

## 怎么读一条报错

1. 看**异常类名**，先判断大类：认证、找不到、网络、上传还是参数。
2. 看**消息里的对象**：是哪个组织、哪个仓库、哪个文件、哪个分支。
3. 到下面的对照表里找同一条消息，按「怎么办」处理。

## 异常类型一览

```
HubException（SDK 所有异常的基类）
├── RepositoryNotFoundError   找不到仓库，或没有权限
├── AuthenticationError       认证失败
├── HTTPError                 服务端返回错误状态，或网络请求失败
├── FileNotFoundError         文件在仓库里找不到（SDK 定义的这个类；本地文件缺失时抛的是同名内置异常）
└── UploadError               上传操作失败
```

| 异常 | 什么时候出现 |
| --- | --- |
| `HubException` | 基类，捕获它就能兜住 SDK 自己的异常 |
| `RepositoryNotFoundError` | 服务端返回 404：仓库不存在、没权限，或路径写错 |
| `AuthenticationError` | 服务端返回 401：令牌无效/过期，或没提供认证信息 |
| `HTTPError` | 服务端返回其他 4xx/5xx，或请求根本没发出去（网络、超时） |
| `UploadError` | 上传请求被服务端拒绝或中断 |
| `FileNotFoundError` | 要上传的本地文件/目录不存在（Python 内置的那个同名异常） |

:::warning 两个容易踩的坑

1. `HTTPError` **不能**从 `xiaoshiai_hub` 顶层导入，要写成 `from xiaoshiai_hub.exceptions import HTTPError`。其他几个异常都可以从顶层导入。
2. `FileNotFoundError` 有重名问题：SDK 顶层也导出了一个同名异常，但本地文件缺失时抛出的是 **Python 内置的** `FileNotFoundError`。所以别用 `from xiaoshiai_hub import FileNotFoundError` 把内置名覆盖掉，否则你的 `except` 捕不到。

:::

## 报错信息对照表

### 认证相关

| 报错信息 | 含义 | 怎么办 |
| --- | --- | --- |
| `AuthenticationError: Authentication failed` | 服务端返回 401：令牌无效或过期，也可能压根没传 | 重新生成访问令牌；确认 `token`（或 `username`/`password`）传到了 |
| `AuthenticationError: Authentication failed: ...` | 上传时服务端返回 401 | 同上，重点检查 `token` 参数 |
| `AuthenticationError: Invalid username or password` | 登录时账号或密码错误 | 确认账号密码；用访问令牌登录可以绕开密码问题 |
| `AuthenticationError: Server did not return a token` | 登录成功但服务端没返回令牌 | 确认平台地址指向的是魔哈平台，而不是别的服务 |
| `AuthenticationError: Login request failed: ...` | 登录请求本身失败（网络、超时） | 检查网络和平台地址 |
| `ValueError: Endpoint must be an HTTP(S) URL including the scheme, for example https://hub.example.com` | 平台地址没带 `https://` | 补全协议头，不要只写域名 |

### 仓库与文件相关

| 报错信息 | 含义 | 怎么办 |
| --- | --- | --- |
| `RepositoryNotFoundError: Resource not found` | 服务端返回 404。可能仓库不存在、没权限，也可能是文件/分支路径写错 | 用 `list_repositories()` 或 `moha list model` 核对组织名和仓库名；私有仓库确认有权限 |
| `RepositoryNotFoundError: Repository not found: <组织>/<类型>/<仓库>. Please create the repository first.` | 上传或下载前检查发现仓库不存在 | 先建仓库：`moha create model 组织/仓库名` |
| `RepositoryNotFoundError: Repository not found: ...`（上传阶段） | 上传请求时服务端返回 404 | 同上 |
| `ValueError: Invalid repo_id format: <...>. Expected 'organization/repo_name'` | 仓库 ID 不是「组织/名称」两段 | 写成 `组织/仓库名`，别多也别少斜杠 |
| `ValueError: organization is required when scope is 'organization'` | 按组织查询却没给组织名 | `scope="organization"` 时必须同时传 `organization=` |
| `ValueError: Invalid scope: <...>. Must be one of: all, public, create, favorite, organization` | `scope` 取值不在允许范围 | 改成五个允许值之一 |
| `ValueError: Path is not a file: <...>` | 把目录给了只收文件的接口 | 改用 `upload_folder()` |
| `ValueError: Path is not a directory: <...>` | 把文件给了只收目录的接口 | 改用 `upload_file()` |
| `HTTPError: Product version '<v>' not found for product '<id>'.` | 建空间时指定的模板版本不存在 | 用 `get_product()` / `list_products()` 确认可用版本 |

### 上传下载相关

| 报错信息 | 含义 | 怎么办 |
| --- | --- | --- |
| `FileNotFoundError: File not found: <路径>` | 要上传的本地文件不存在 | 检查路径、文件是否被移动 |
| `FileNotFoundError: Folder not found: <路径>` | 要上传的本地目录不存在 | 同上 |
| `UploadError: Upload failed: <原因>` | 服务端拒绝了上传请求 | 按后面的原因处理：多为权限、配额或文件过大 |
| `UploadError: Request failed: <原因>` | 上传请求在网络层失败 | 检查网络、代理；大文件建议重试 |
| `HTTPError: Request failed: <原因>` | 请求根本没发出去：连不上、超时、域名解析失败 | 检查平台地址、网络和代理设置 |

### 加密相关

| 报错信息 | 含义 | 怎么办 |
| --- | --- | --- |
| `Error: --encrypt requires an encryption password. Set MOHA_ENCRYPTION_PASSWORD or use --encryption-password.` | 命令行开了加密却没给密码 | 补 `--encryption-password`，或设置环境变量 `MOHA_ENCRYPTION_PASSWORD` |
| `Unsupported encryption algorithm: <...>. Choices: AES, SM4, AES-256-CTR, SM4-CTR` | 算法名写错 | 用允许的四种写法之一 |
| `ValueError: 'XXX' is not a valid Algorithm` | Python 侧 `algorithm` 传了 `AES` / `SM4` 之外的值 | 只传 `AES` 或 `SM4` |
| `ValueError: AES requires 32-byte key, got N bytes` | 数据密钥长度和算法不匹配 | 确认算法和申请密钥时用的算法一致 |
| `ValueError: SM4 requires 16-byte key, got N bytes` | 同上 | 同上 |
| `ValueError: Unsupported algorithm: <...>` | 底层加密拿到未知算法 | 用 `AES` 或 `SM4` |
| `FileNotFoundError: Source file not found: <路径>` | 要加密的文件不存在 | 检查路径 |

### 命令行与服务端

| 报错信息 | 含义 | 怎么办 |
| --- | --- | --- |
| `Error: invalid choice '<...>'.` / `Error: unknown command '<...>'.` | 子命令或资源名写错 | 用 `moha -h` 看可用命令 |
| `Error: no current organization selected. Run 'moha organization use <organization>' first.` | 没选当前组织，却用了不带组织前缀的仓库名 | 先 `moha organization use 组织名` |
| `Error: username and password cannot be empty` | 登录时账号或密码为空 | 补上，或改用 `--token` |
| `Error: --mine requires a saved username or --username.` | 用了 `--mine` 但不知道你是谁 | 先登录，或加 `--username` |
| `Error: upload requires: <repo_id> <local_path> [path_in_repo]` | `moha upload` 参数个数不对 | 按「仓库 本地路径」的顺序写 |
| `Not logged in` / `Run 'moha login' to log in.` | 本机没有登录信息 | 运行 `moha login <平台地址>` |
| `Multiple pods are available. Use --pod <name> to select one.` | 空间有多个运行实例，日志命令不知道该看哪个 | 加 `--pod <实例名>` |
| `Multiple containers are available. Use --container (-c) <name> to select one.` | 一个实例里有多个容器 | 加 `--container <容器名>` |
| `No pods found for this Space` | 空间没有运行中的实例 | 先用 `moha status` 确认空间已上线 |
| `Pod not found: <名称>` | `--pod` 指定的实例名不对 | 用 `moha status` 查真实实例名 |
| `RevisionNotFound` | 镜像端点找不到这个分支/标签 | 用 `moha refs 组织/仓库名` 查看可用引用 |
| `EntryNotFound` | 镜像端点找不到这个文件或路径 | 核对文件名，或先列目录 |
| `Error: AI API URL is not configured.` | 没用过 `moha ai-config` 就来调 AI 助手 | 先运行 `moha ai-config` 配置接口地址和密钥 |

## 几个能直接抄的处理套路

### 套路一：分层捕获，给不同错误不同提示

```python
from xiaoshiai_hub import (
    AuthenticationError,
    HubException,
    RepositoryNotFoundError,
    moha_hub_download,
)
from xiaoshiai_hub.exceptions import HTTPError

try:
    path = moha_hub_download(repo_id="ai-lab/qwen2-7b", filename="config.json")
except RepositoryNotFoundError:
    print("仓库不存在或没权限，检查组织和仓库名")
except AuthenticationError:
    print("认证失败，检查访问令牌")
except HTTPError as e:
    print(f"请求失败（状态码 {e.status_code}）：{e}")
except HubException as e:
    print(f"其他 SDK 错误：{e}")
```

### 套路二：网络抖动就重试

```python
import time

from xiaoshiai_hub import HubException, moha_hub_download

def download_with_retry(repo_id, filename, max_retries=3):
    for attempt in range(max_retries):
        try:
            return moha_hub_download(repo_id=repo_id, filename=filename)
        except HubException:
            if attempt == max_retries - 1:
                raise
            wait = 2 ** attempt          # 2 秒、4 秒……
            print(f"第 {attempt + 1} 次失败，{wait} 秒后重试")
            time.sleep(wait)
```

:::warning 重试前先分清错误类型
认证失败、仓库不存在这类错误，重试一百次也没用。只对网络类错误（`HTTPError` 里消息带 `Request failed`）做重试；参数或权限问题请直接改配置。
:::

### 套路三：打开详细日志定位问题

```python
import logging

logging.basicConfig(level=logging.INFO)
logging.getLogger("xiaoshiai_hub").setLevel(logging.DEBUG)
```

命令行加 `-v` 看基本诊断、`-vvv` 看更详细（含脱敏后的请求信息）。`-v` 要写在子命令前面，例如 `moha -vvv download ai-lab/qwen2-7b`。密码、令牌和文件内容在日志里都会被脱敏。

## 常见问题

### 登录信息存在哪？

命令行登录后，令牌、平台地址、用户名和当前组织都存在 `~/.moha/config.json`。更早的版本可能还留着 `~/.moha/token.json`，登录成功后会清理掉。

### 怎么退出登录、清掉本地令牌？

```bash
moha logout
```

这会删掉保存的令牌，但不会动其他配置。想彻底清掉，手工删除 `~/.moha/config.json` 即可。

### 怎么确认当前登录的是谁、连的是哪个平台？

```bash
moha whoami
```

### 怎么走代理？

`HTTP_PROXY` / `HTTPS_PROXY` 环境变量对 SDK 和命令行都生效：

```bash
export HTTPS_PROXY="http://proxy.example.com:8080"
```

### 大文件下载中断了怎么办？

SDK 不支持断点续传，重跑会从头下载。文件确实很大时，建议先用 `snapshot_download(..., allow_patterns=[...])` 只拉需要的部分，或者拆成单文件逐个下。详见 [上传、下载与文件同步](./transfer)。

### 想并发下载多个文件？

SDK 没有内置并发，需要自己用线程池调 `moha_hub_download()`，示例见 [上传、下载与文件同步](./transfer)。
