# HubClient API 详解

`HubClient` 是魔哈 SDK 的 Python 入口，让你在代码里完成网页上能做的仓库管理：列仓库、建仓库、查分支、改可见性、读写文件、发布空间。
适合「一次建几十个仓库」「把上传写进训练脚本」「CI 里检查版本」这类不想手点的场景。

## 开始之前

- 已装好 SDK：`pip install moha-hub`。
- 准备好一个访问令牌（在网页的 **访问令牌** 页面生成），或你的账号密码。
- 平台地址和令牌建议用环境变量传入，不要写死在代码里。

## 最小可运行示例

```python
from xiaoshiai_hub import HubClient

# 平台地址也可以放在 MOHA_ENDPOINT 环境变量里，这里显式传更直观
client = HubClient(
    base_url="<平台地址>",
    token="<访问令牌>",
)

# 列出我能看到的模型仓库
for repo in client.list_repositories(repo_type="models"):
    print(f"{repo.organization}/{repo.name} - {repo.description}")
```

:::tip 初始化时不会校验令牌
`HubClient(...)` 构造时只是把认证信息装上，不会立刻联网。令牌错了要等第一次发请求才报错。
:::

## 客户端初始化

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `base_url` | `str` | 环境变量 `MOHA_ENDPOINT` 的值 | 平台地址，要带 `https://` |
| `token` | `str` | 无 | 访问令牌，推荐用这个 |
| `username` | `str` | 无 | 用户名，要和 `password` 一起传 |
| `password` | `str` | 无 | 密码，要和 `username` 一起传 |

传了 `token` 就用令牌；只传用户名和密码时用 Basic 认证。两者都不传不会当场报错，但第一个请求就会认证失败。

### 返回值长什么样

接口返回的是数据类对象，常用的几个：

`Repository`（仓库）

| 字段 | 含义 |
| --- | --- |
| `name` / `organization` | 仓库名 / 所属组织 |
| `owner` / `creator` | 负责人 / 创建者 |
| `type` | `models`、`datasets` 或 `spaces` |
| `visibility` | `public`、`internal` 或 `private` |
| `description` | 仓库描述 |
| `metadata` | 元数据，例如 license、tasks、tags、frameworks |
| `defaultBranchSize` / `repositoryStorageSize` | 默认分支大小 / 仓库占用字节数，可能为空 |

`Ref`（分支或标签）：`name`、`ref`、`type`（`branch` 或 `tag`）、`hash`、`is_default`。

`GitContent`（文件或目录）：`name`、`path`、`type`（`file`、`dir`、`symlink`、`submodule`）、`size`、`hash`、`content`、`entries`（只有目录才有）。

## 仓库管理接口一览

| 函数 | 用途 | 主要参数 | 返回值 |
| --- | --- | --- | --- |
| `list_repositories()` | 列仓库 | `repo_type`、`scope`、`organization`、`mycreated` | `List[Repository]` |
| `get_repository_info()` | 查单个仓库 | `organization`、`repo_type`、`repo_name` | `Repository` |
| `create_repository()` | 建仓库 | `repo_name`、`description`、`visibility`、`metadata`、`base_model`、`relationship` | 无 |
| `update_repository()` | 改描述、可见性、元数据 | 上列字段，另加 `annotations` | 无 |
| `delete_repository()` | 删仓库 | `organization`、`repo_type`、`repo_name` | 无 |
| `list_organizations()` | 列组织 | `organization_type`、`username` | `List[Organization]` |
| `get_organization()` | 查组织 | `organization` | `Organization` |
| `list_images()` | 列镜像 | `scope`、`organization`、`mycreated` | `List[Image]` |
| `create_image()` / `update_image()` / `get_image()` / `delete_image()` | 镜像增删改查 | `organization`、`image_name`、`visibility`、`repo` 等 | `Image` 或无 |
| `list_repository_stats()` / `get_repository_stats()` | 仓库统计 | 仓库定位参数 | `List[Dict]` / `Dict` |

> 除 `list_*`、`get_*` 这类查询接口外，建、改、删接口都**没有返回值**，成功与否靠「没抛异常」判断，再用查询接口确认结果。

### 列仓库：`scope` 决定列谁

`scope` 默认是 `all`。

| `scope` | 列出什么 |
| --- | --- |
| `all` | 传了 `organization` 就列该组织可见仓库，否则列全局公开仓库 |
| `public` | 公开仓库 |
| `create` | 我创建的 |
| `favorite` | 我收藏的 |
| `organization` | 指定组织内的仓库，此时 `organization` 必填 |

```python
# 我创建的模型
mine = client.list_repositories(repo_type="models", scope="create")

# 某个组织内的模型；mycreated=True 时只看自己建的
org_models = client.list_repositories(
    repo_type="models",
    scope="organization",
    organization="my-org",
    mycreated=True,
)
```

`repo_type` 填 `models`、`datasets` 或 `spaces`。

### 建仓库并标明来源模型

```python
client.create_repository(
    organization="my-org",
    repo_type="models",
    repo_name="my-new-model",
    description="在 qwen2-7b 上微调得到的模型",
    visibility="internal",
    metadata={
        "license": ["apache-2.0"],
        "tasks": ["text-generation"],
        "frameworks": ["pytorch"],
    },
    base_model=["ai-lab/qwen2-7b"],   # 来源模型，可选
    relationship="finetune",           # 与来源模型的关系
)
```

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `visibility` | `internal` | 可选 `public`、`internal`、`private` |
| `metadata` | 无 | 键值都是列表，例如 `{"license": ["apache-2.0"]}` |
| `base_model` | 无 | 来源模型列表，例如 `["ai-lab/qwen2-7b"]` |
| `relationship` | 无 | `adapter`、`finetune`、`quantized`、`merge`、`repackage` |

`relationship` 只在填了 `base_model` 时才有意义。建完仓库不会返回对象，用 `get_repository_info()` 确认。

### 改描述和可见性

```python
client.update_repository(
    organization="my-org",
    repo_type="models",
    repo_name="my-model",
    description="更新后的描述",
    visibility="public",
    metadata={"tags": ["llm", "fine-tuned"]},   # 和旧值合并
)
```

不传的字段保持原值；`metadata`、`annotations` 是**合并**，不是整体覆盖。

:::warning 删除仓库不可恢复
`delete_repository()` 会连同里面的所有文件和版本一起删掉，删完找不回来。删之前先确认没有别的服务还在拉它。
:::

## 分支与版本

| 函数 | 用途 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `get_repository_refs()` | 列分支和标签 | `organization`、`repo_type`、`repo_name` | `List[Ref]` |
| `get_default_branch()` | 查默认分支名 | 同上 | `str`（找不到时返回 `main`） |
| `create_branch()` | 建分支 | 同上，另加 `branch_name`、`from_branch` | 无 |
| `delete_branch()` | 删分支 | 同上，另加 `branch_name` | 无 |

```python
refs = client.get_repository_refs("ai-lab", "models", "qwen2-7b")
for ref in refs:
    kind = "分支" if ref.type == "branch" else "标签"
    mark = "（默认）" if ref.is_default else ""
    print(f"[{kind}] {ref.name}{mark} -> {ref.hash[:8]}")

# 从 main 拉一个开发分支
client.create_branch(
    organization="my-org",
    repo_type="models",
    repo_name="my-model",
    branch_name="dev",
    from_branch="main",
)
```

`create_branch()` 遇到分支已存在会直接返回不报错，`delete_branch()` 遇到分支不存在也一样。这两个调用可以放心写进脚本重复执行。

## 读写仓库里的文件

| 函数 | 用途 | 参数 |
| --- | --- | --- |
| `get_repository_content()` | 看某个目录下有什么 | `branch`、`path`（留空表示根目录） |
| `create_file()` | 写一个小文本文件（README、配置） | `branch`、`file_path`、`content`、`message` |
| `delete_file()` | 删一个文件 | `branch`、`file_path`、`message` |
| `download_file()` | 下载单个文件 | `branch`、`file_path`、`local_path`、`show_progress` |

```python
# 看根目录下有什么
content = client.get_repository_content("ai-lab", "models", "qwen2-7b", branch="main")
for item in content.entries or []:
    print(item.type, item.path, item.size)

# 写一个 README
client.create_file(
    organization="my-org",
    repo_type="models",
    repo_name="my-model",
    branch="main",
    file_path="README.md",
    content="# My Model\n\n这是微调后的模型。",
    message="Add README",
)

# 下载一个文件到本地
client.download_file(
    organization="ai-lab",
    repo_type="models",
    repo_name="qwen2-7b",
    branch="main",
    file_path="config.json",
    local_path="./downloaded_config.json",
)
```

:::tip 大文件不要用 create_file
`create_file()` 是把文件内容编码后塞进请求体，只适合小文本文件。模型权重、数据集这类大文件请用 [上传、下载与文件同步](./transfer) 里的 `upload_file()` 和 `moha_hub_download()`。
:::

## 空间（Space）

| 函数 | 用途 | 参数 |
| --- | --- | --- |
| `list_clusters()` | 列可用集群 | `organization` |
| `list_cluster_workspaces()` | 列集群下的工作空间 | `organization`、`cluster_id` |
| `list_workspace_flavors()` | 列工作空间规格 | `organization`、`cluster_id`、`workspace_id` |
| `list_products()` / `get_product()` | 列 / 查应用模板 | `organization`、`product_id` |
| `create_space_repository()` | 建空间仓库 | `repo_name`、`cluster`、`namespace`、`product_id`、`product_version`、`visibility`、`flavor`、`env`、`description` |
| `deploy_space()` / `redeploy_space()` / `stop_space()` | 上线 / 重启 / 停止 | `organization`、`repo_name` |
| `get_space_status()` | 查状态 | `organization`、`repo_name` |
| `list_space_pods()` / `stream_space_logs()` | 查运行实例 / 流式看日志 | `organization`、`repo_name`、`pod` 等 |

```python
clusters = client.list_clusters("my-org")
workspaces = client.list_cluster_workspaces("my-org", clusters[0].id)
flavors = client.list_workspace_flavors("my-org", clusters[0].id, workspaces[0].id)
products = client.list_products("my-org")

client.create_space_repository(
    organization="my-org",
    repo_name="my-gradio-app",
    cluster=clusters[0].id,
    namespace=workspaces[0].id,
    product_id="gradio",
    product_version="latest",
    visibility="internal",
    flavor=flavors[0].id if flavors else None,
    env=[{"name": "MODEL_NAME", "value": "llama-7b"}],
    description="我的 Gradio 应用",
)

client.deploy_space("my-org", "my-gradio-app")
status = client.get_space_status("my-org", "my-gradio-app")
print(status.phase, status.healthy)
```

- `cluster` 和 `namespace` 都必须填上面列表接口返回的 `id`，不能填名字。
- `product_version` 要和模板里真实存在的版本对得上，否则会报「找不到产品版本」。
- `stream_space_logs()` 依赖 `websocket-client`，正常安装 SDK 时会一起装上。`pod` 传 `list_space_pods()` 返回的名字；一个空间有多个容器时还要指定容器名。

## 加密相关接口

| 函数 | 用途 |
| --- | --- |
| `generate_data_key()` | 向 KMS 申请数据密钥，用于信封加密 |
| `set_repository_encrypted()` / `cancel_repository_encrypted()` | 给仓库打上 / 取消「已加密」标记 |
| `get_repository_encryption()` | 查某个版本下加密文件的密钥与算法信息 |

```python
data_key = client.generate_data_key(algorithm="AES", password="<加密密码>")
print(len(data_key.plaintext_key), data_key.encrypted_key[:16])
```

`generate_data_key(algorithm="AES", password=...)` 的算法默认是 `AES`，也可以传 `SM4`。上传时的完整加密流程见 [数据加密](./encryption)。

## 完整示例：建仓库、写说明、拉分支、再确认

```python
from xiaoshiai_hub import HubClient

client = HubClient(base_url="<平台地址>", token="<访问令牌>")

client.create_repository(
    organization="my-org",
    repo_type="models",
    repo_name="finetuned-model",
    description="微调模型",
    visibility="internal",
)

client.create_file(
    organization="my-org",
    repo_type="models",
    repo_name="finetuned-model",
    branch="main",
    file_path="README.md",
    content="# Finetuned Model\n\n基于自定义数据微调。",
    message="Add README",
)

client.create_branch(
    organization="my-org",
    repo_type="models",
    repo_name="finetuned-model",
    branch_name="dev",
    from_branch="main",
)

info = client.get_repository_info("my-org", "models", "finetuned-model")
print(info.organization, info.name, info.visibility)
```

## 常见报错

| 报错 | 含义 | 怎么办 |
| --- | --- | --- |
| `AuthenticationError: Authentication failed` | 令牌无效或过期，也可能压根没传认证信息 | 重新生成令牌；检查 `token` 或 `username`/`password` 传对没 |
| `RepositoryNotFoundError: Resource not found` | 服务端返回 404：仓库不存在、没权限，或路径写错 | 用 `list_repositories()` 核对组织名和仓库名；私有仓库确认自己有权限 |
| `ValueError: Invalid repo_id format: ... Expected 'organization/repo_name'` | 仓库 ID 不是「组织/名称」两段 | 检查是否漏了组织名，或多写了斜杠 |
| `ValueError: organization is required when scope is 'organization'` | 选了按组织查询却没给组织名 | `scope="organization"` 时必须同时传 `organization=` |
| `HTTPError: Product version '...' not found for product '...'.` | 建空间时指定的模板版本不存在 | 用 `get_product()` 或 `list_products()` 确认可用版本 |
| `HTTPError: HTTP <状态码>: <原因>` | 服务端返回了 4xx / 5xx（401、404 会变成上面两个错） | 4xx 多为参数问题，5xx 稍后重试 |
| `HTTPError: Request failed: ...` | 网络层失败：连不上、超时、域名解析不了 | 检查平台地址、网络和代理设置 |

> 能从 `xiaoshiai_hub` 直接导入的异常只有 `HubException`、`RepositoryNotFoundError`、`FileNotFoundError`、`AuthenticationError` 和 `UploadError`；`HTTPError` 要从 `xiaoshiai_hub.exceptions` 导入。详见 [错误处理与常见问题](./error-handling)。
