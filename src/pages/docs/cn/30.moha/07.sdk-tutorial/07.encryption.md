# 数据加密与安全传输

如果你不想让模型权重、数据集在平台上是「明文躺着」，可以在上传时加密：文件在**你自己的机器上**就被加密，平台存的是密文。
这一页讲清楚用哪些算法、密码从哪来、哪些文件会被加密、以及下载之后怎么还原成明文。

:::tip 信封加密是什么
可以把每个文件想成一个保险箱：SDK 先随机生成一把「数据钥匙」去锁文件，再用你的密码把「数据钥匙」锁起来，塞进文件最前面的头部。
所以你只需要记一个密码；换文件时数据钥匙会自动重新生成。
:::

## 开始之前

- 已装好 SDK（`pip install moha-hub`），并且已经在命令行登录或准备好访问令牌。
- 想清楚一个**加密密码**，并记牢：密码丢了文件就还原不回来。
- 确认你要加密的文件确实符合下面的条件（大小 + 扩展名），否则加密不会生效。

## 核心概念

| 名词 | 通俗解释 |
| --- | --- |
| 信封加密 | 用随机数据钥匙锁文件，再用你的密码锁住这把钥匙；文件里存的是「被锁住的钥匙」 |
| 数据密钥 | 真正用来加密文件的随机钥匙，AES 模式 32 字节，SM4 模式 16 字节；不用你自己生成 |
| KMS | 平台的密钥服务，负责根据你的密码和算法下发数据密钥 |
| CTR 模式 | 一种流式加密方式，可以边读边加密，不需要把整个大文件读进内存 |
| 加密标记 | 仓库上的一个标记：只要上传过加密文件，平台就会给仓库打上，网页端之后不能再写 |

## 用哪些算法

| 写法 | 实际算法 | 密钥长度 | 说明 |
| --- | --- | --- | --- |
| `AES` | AES-256-CTR | 32 字节 | 默认，性能好，一般选它 |
| `SM4` | SM4-CTR | 16 字节 | 国密算法，有国密合规要求时用 |

命令行还接受 `AES-256-CTR` 和 `SM4-CTR` 两种写法，效果分别等同于 `AES` 和 `SM4`。Python 侧只接受 `AES` 或 `SM4`。

加密用的是 Python 的 `cryptography` 库，已随 SDK 一起安装，不需要额外装东西。

## 加密发生在哪一步

整个过程都在上传前完成，平台收到的是密文：

1. 你调用上传函数并给出密码，SDK 先把密码发给平台的 KMS，换回一对钥匙：一把**明文数据密钥**、一把**被加密的数据密钥**。
2. SDK 在本地为每个文件生成随机的 16 字节初始向量（IV），用数据密钥把文件内容加密。
3. 加密结果写成一个新文件，结构是：4 字节的元数据长度 + 元数据（含「被加密的数据密钥」和算法名）+ 16 字节 IV + 密文正文。
4. SDK 上传这个密文文件，仓库里的文件名不变，内容已经是密文，文件会略微变大。
5. 只要本次有文件被加密，SDK 会给仓库打上**加密标记**。

打上标记之后，网页端不能再往这个仓库添加文件（会提示改用 `moha-sdk`），后续写入要继续走 SDK 或命令行。

## 最小可运行示例

命令行：

```bash
# 上传文件夹并加密，密码走环境变量更安全
export MOHA_ENCRYPTION_PASSWORD="<加密密码>"

moha upload ai-lab/my-model ./model \
  --encrypt \
  --algorithm AES \
  --message "加密上传"
```

Python：

```python
from xiaoshiai_hub import upload_file

upload_file(
    path_file="./model.safetensors",
    path_in_repo="model.safetensors",
    repo_id="ai-lab/my-model",
    encryption_password="<加密密码>",
    algorithm="AES",
    commit_message="加密上传权重",
)
print("已加密上传")
```

## 参数说明

| 参数 | 命令行 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 是否加密 | `--encrypt` / `-e` | 关 | 必须显式打开，不会自动加密 |
| 加密密码 | `--encryption-password` 或环境变量 `MOHA_ENCRYPTION_PASSWORD` | 无 | 两边都没有时直接报错，不会悄悄明文上传 |
| 算法 | `--algorithm` / `-a` | `AES` | 可选 `AES`、`SM4`、`AES-256-CTR`、`SM4-CTR` |
| 临时目录 | `--temp-dir` | 自动创建 | 只影响上传时存放密文临时文件的位置，会自动清理 |

Python 侧对应 `encryption_password` 和 `algorithm` 两个参数，`upload_file()` 与 `upload_folder()` 都有。

:::warning 密码丢了就还原不回来
平台只保管「按你的密码加密过的数据密钥」，没有你的密码无法还原明文。加密上传前请把密码存到密码管理器或 CI Secret 里。
:::

## 哪些文件会被加密

加密只对同时满足两个条件的文件生效：

1. 文件大小 **大于等于 5 MB**；
2. 扩展名在下面的名单里。

| 类别 | 扩展名 |
| --- | --- |
| 模型权重 | `.safetensors`、`.bin`、`.pt`、`.pth`、`.ckpt`、`.h5`、`.onnx`、`.mlmodel`、`.model` |
| 数据与数组 | `.arrow`、`.npy`、`.npz`、`.msgpack` |
| 压缩包 | `.zip`、`.tar`、`.tgz`、`.gz`、`.bz2`、`.xz`、`.7z`、`.rar`、`.ftz` |
| 其他 | `.wasm` |

:::warning 小文件和文本文件不会被加密
小于 5 MB 的文件，以及 `.json`、`.md`、`.txt`、`.yaml` 这类不在名单里的文件，即使你传了密码也**会以明文上传**。这样做是为了让配置文件、说明文档还能在网页上正常查看。所以不要把敏感内容放在这些文件里。
:::

## 下载与解密

**SDK 的下载函数不解密**：`moha_hub_download()`、`snapshot_download()` 和命令行的 `moha download` 都会把密文原样下载下来。
SDK 自带说明里给出的做法是：下载后另用 `xpai-enc` 命令行工具解密（具体命令以该工具的说明为准）。

要还原成一个文件，需要凑齐三样东西：

| 需要什么 | 从哪来 |
| --- | --- |
| 上传时用的密码 | 你自己保存的 |
| 算法（`AES` 或 `SM4`） | 上传时指定的，或从文件头部读出来 |
| 该文件「被加密的数据密钥」 | 平台可以查到，见下面 |

平台可以按版本给出仓库里每个加密文件的「被加密的数据密钥」和算法：

```python
from xiaoshiai_hub import HubClient

client = HubClient(base_url="<平台地址>", token="<访问令牌>")

info = client.get_repository_encryption(
    organization="ai-lab",
    repo_type="models",
    repo_name="my-model",
    reference="main",
)
for item in info.get("files", []):
    print(item["path"], item["algorithm"], item["encryptedKey"][:16])
```

拿到这些东西后，还原的路径是：用密码把「被加密的数据密钥」解开，得到明文数据密钥 → 再用它和文件头里的 IV 按对应算法解出正文。
所以真正不能丢的是**密码**，其余信息都能从文件本身或平台取回。

## 安全建议

- 不要把密码写死在仓库代码里，优先用环境变量或 CI Secret。
- 不同项目用不同密码，降低一个密码泄露带来的影响。
- 加密只覆盖符合名单的大文件，敏感的小文本请自己先处理过再上传。
- 需要让团队成员都能解密时，密码要通过安全渠道单独分发，不要跟着仓库一起传。

## 常见报错

| 报错 | 含义 | 怎么办 |
| --- | --- | --- |
| `Error: --encrypt requires an encryption password. Set MOHA_ENCRYPTION_PASSWORD or use --encryption-password.` | 开了加密却没给密码 | 补 `--encryption-password`，或设置环境变量 `MOHA_ENCRYPTION_PASSWORD` |
| `Unsupported encryption algorithm: XXX. Choices: AES, SM4, AES-256-CTR, SM4-CTR` | 算法名写错了 | 改成名单里的写法 |
| `ValueError: AES requires 32-byte key, got N bytes` | 数据密钥长度和算法不匹配（通常是算法和密钥对不上） | 确认算法是 `AES` 还是 `SM4`，重新申请数据密钥 |
| `ValueError: SM4 requires 16-byte key, got N bytes` | 同上，SM4 的密钥被当成 AES 的用了 | 同上 |
| `FileNotFoundError: Source file not found: ...` | 要加密的本地文件不存在 | 检查文件路径 |
| 上传成功但文件还是明文 | 文件小于 5 MB，或扩展名不在名单里 | 见上面「哪些文件会被加密」；这是预期行为 |
| 下载下来打不开、乱码 | 下载的是密文，没有解密 | 用上传时的密码按上面的方法还原 |
