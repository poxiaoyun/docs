# 上传、下载与文件同步

这一页讲上传下载的进阶用法：仓库太大不想全下、只想拉某个分支、上传时想跳过缓存和日志、下载中断了怎么办。
如果你还没跑通过一次上传下载，先看 [5 分钟快速开始](./quick-start)。

## 开始之前

- 已装好 SDK 并登录（命令行 `moha whoami` 能看到登录状态）。
- 目标仓库必须**已经存在**。上传和下载都不会自动建仓库，仓库不存在会直接报错。
- 本地磁盘留够空间：整仓下载是「逐个文件完整下载」，不会跳过任何未过滤掉的文件。

## 最小可运行示例

```python
from xiaoshiai_hub import moha_hub_download, upload_file

# 下载一个文件：repo_id 是「组织/仓库名」
path = moha_hub_download(
    repo_id="ai-lab/qwen2-7b",
    filename="config.json",
    local_dir="./models",
    token="<访问令牌>",
    base_url="<平台地址>",
)
print("下载到：", path)

# 上传一个文件：注意前两个参数是「本地路径」「仓库内路径」
upload_file(
    path_file="./README.md",
    path_in_repo="README.md",
    repo_id="my-org/my-model",
    token="<访问令牌>",
    base_url="<平台地址>",
)
```

:::tip 两个函数的参数顺序不一样
`moha_hub_download(repo_id, filename)` 是「先仓库、后文件」；`upload_file(path_file, path_in_repo, repo_id)` 是「先本地文件、再仓库内路径、最后仓库」。传错顺序是最常见的报错来源。
:::

## 下载

| 函数 | 什么时候用 | 代价 |
| --- | --- | --- |
| `moha_hub_download()` | 只要一两个文件（配置文件、tokenizer） | 每个文件单独一次请求，文件多了要循环调用 |
| `snapshot_download()` | 要整个仓库，或要按规则批量挑文件 | 会先把仓库目录走一遍来数文件，仓库大时多一轮请求 |

两个函数都**不做解密**：加了密的文件下载下来仍是密文，需要另行处理，见 [数据加密](./encryption)。

### 下单个文件：`moha_hub_download()`

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `repo_id` | `str` | — | 必须是「组织/仓库名」两段 |
| `filename` | `str` | — | 文件在仓库里的路径 |
| `repo_type` | `str` | `models` | `models`、`datasets` 或 `spaces` |
| `revision` | `str` | 无 | 分支名或提交 SHA，不填走默认分支 |
| `local_dir` | `str` | 无 | 存到哪个目录 |
| `show_progress` | `bool` | `True` | 是否显示进度条 |
| `base_url` / `token` / `username` / `password` | `str` | 无 | 认证信息，不传就找环境变量和本地登录状态 |

存到哪：

- 传了 `local_dir` → `local_dir/filename`，例如 `./models/config.json`。
- 没传 `local_dir` → 直接按 `filename` 的相对路径存到当前目录，例如 `filename="data/config.yaml"` 会存成 `./data/config.yaml`。

```python
# 只下权重文件，之后再手动处理
weights = moha_hub_download(
    repo_id="ai-lab/qwen2-7b",
    filename="model.safetensors",
    local_dir="./models",
)
```

### 下整个仓库：`snapshot_download()`

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `repo_id` | `str` | — | 「组织/仓库名」 |
| `repo_type` | `str` | `models` | `models`、`datasets` 或 `spaces` |
| `revision` | `str` | 无 | 分支名或提交 SHA |
| `local_dir` | `str` | 无 | 下载目录；不填会存到 `./downloads/组织_类型_仓库名` |
| `allow_patterns` | `str` 或列表 | 无 | 只下载匹配的文件 |
| `ignore_patterns` | `str` 或列表 | 无 | 跳过匹配的文件 |
| `show_progress` | `bool` | `True` | 是否显示进度条 |

```python
from xiaoshiai_hub import snapshot_download

repo_path = snapshot_download(
    repo_id="ai-lab/qwen2-7b",
    local_dir="./models/qwen2-7b",
)
print("下载到：", repo_path)
```

> 整仓下载结束后会顺带累加一次仓库的下载量统计。这个上报失败不会让下载失败，只记一条警告。单文件下载不会累加。

### 只下需要的文件

`allow_patterns` 是「白名单」，`ignore_patterns` 是「黑名单」。匹配时用**文件名**或**仓库内完整路径**任一命中就算命中。

| 想要的效果 | 怎么写 |
| --- | --- |
| 只下 safetensors 权重 | `allow_patterns="*.safetensors"` |
| 只下配置和权重 | `allow_patterns=["*.safetensors", "*.json"]` |
| 只下某个目录 | `allow_patterns="weights/*"` |
| 全下但不要旧的 bin 权重 | `ignore_patterns="*.bin"` |
| 跳过缓存和临时文件 | `ignore_patterns=["*.pyc", "__pycache__", "*.tmp"]` |

```python
# 白名单和黑名单可以一起用
repo_path = snapshot_download(
    repo_id="ai-lab/qwen2-7b",
    allow_patterns=["*.safetensors", "*.json"],
    ignore_patterns=["*.tmp"],
    local_dir="./models/qwen2-7b",
)
```

:::warning 黑名单优先
`ignore_patterns` 的优先级高于 `allow_patterns`：一个文件只要命中黑名单就一定不下，哪怕它也命中了白名单。所以要下「除了某个文件之外的全部」时，只写黑名单就好。
:::

代价：过滤是在**服务端列目录之后、下载之前**做的，所以过滤不会减少「数文件」那一轮的请求次数，只是少下了文件、省了流量和磁盘。

### 按版本下载

`revision` 可以填分支名或提交 SHA。不填就走仓库的默认分支。

```python
# 拉开发分支
snapshot_download(repo_id="ai-lab/qwen2-7b", revision="dev", local_dir="./dev")

# 拉某个提交，精确复现当时的文件
snapshot_download(repo_id="ai-lab/qwen2-7b", revision="abc123def456", local_dir="./pinned")
```

想看仓库里有哪些分支和提交，用 [HubClient API](./hub-api) 里的 `get_repository_refs()`，或在命令行跑 `moha refs <组织/仓库名>`。

### 命令行写法

```bash
# 整个仓库下到 ./downloads
moha download ai-lab/qwen2-7b -o ./downloads

# 只下指定的几个文件
moha download ai-lab/qwen2-7b config.json tokenizer.json -o ./downloads

# 按规则过滤，并指定分支
moha download ai-lab/qwen2-7b \
  --include "*.json" --exclude "*.log" \
  --revision dev -o ./downloads

# 下单个文件
moha download-file ai-lab/qwen2-7b config.json -o ./downloads
```

`moha download` 后面直接跟文件名时，会逐个调用单文件下载；不跟文件名时才走整仓下载。

## 上传

| 函数 | 什么时候用 | 代价 |
| --- | --- | --- |
| `upload_file()` | 更新一个文件、补一个配置 | 一次调用一个文件，多文件要自己循环 |
| `upload_folder()` | 上传整个模型或数据集目录 | 逐个文件串行处理，文件多时比较慢 |

两个函数按文件大小自动选通道：**小于 5 MB** 的文件会把内容编码后随请求一次提交；**大于等于 5 MB** 的文件走大文件通道，先申请上传地址再直传，并带进度条。

### 传单个文件：`upload_file()`

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `path_file` | `str` | — | 本地文件路径 |
| `path_in_repo` | `str` | — | 文件在仓库里的路径 |
| `repo_id` | `str` | — | 「组织/仓库名」 |
| `repo_type` | `str` | `models` | `models`、`datasets` 或 `spaces` |
| `revision` | `str` | `main` | 传到哪个分支 |
| `commit_message` | `str` | 自动生成 | 提交信息，不填会用「Upload 文件名」 |
| `commit_description` | `str` | 无 | 提交描述，会接在提交信息后面 |
| `encryption_password` | `str` | 无 | 加密密码，见 [数据加密](./encryption) |
| `algorithm` | `str` | 无 | 加密算法 `AES` 或 `SM4` |
| `base_url` / `token` / `username` / `password` | `str` | 无 | 认证信息 |

```python
# 传到仓库里的子目录
upload_file(
    path_file="./weights/model.safetensors",
    path_in_repo="weights/v1.0/model.safetensors",
    repo_id="my-org/my-model",
    commit_message="上传 v1.0 权重",
)

# 传到数据集仓库
upload_file(
    path_file="./train.json",
    path_in_repo="data/train.json",
    repo_id="my-org/my-dataset",
    repo_type="datasets",
)
```

### 传整个目录：`upload_folder()`

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `folder_path` | `str` | — | 本地目录 |
| `repo_id` | `str` | — | 「组织/仓库名」 |
| `repo_type` | `str` | `models` | `models`、`datasets` 或 `spaces` |
| `revision` | `str` | `main` | 传到哪个分支 |
| `allow_patterns` | 列表 | 无 | 只上传匹配的文件 |
| `ignore_patterns` | 列表 | 无 | 跳过匹配的文件 |
| `path_in_repo` | `str` | 无 | 把这些文件放进仓库的哪个子目录 |
| `commit_message` / `commit_description` | `str` | 自动生成 | 提交信息 / 描述 |
| `temp_dir` | `str` | 自动创建 | 加密时的临时目录 |
| `encryption_password` / `algorithm` | `str` | 无 | 加密密码 / 算法 |

```python
from xiaoshiai_hub import upload_folder

# 上传 PyTorch 项目，跳过环境和缓存
upload_folder(
    folder_path="./my_model",
    repo_id="my-org/my-model",
    ignore_patterns=[
        ".*",              # 隐藏文件
        "venv/*",          # 虚拟环境
        "__pycache__/*",   # Python 缓存
        "*.pyc",
        "build/*",
        "dist/*",
    ],
    commit_message="上传微调后的模型",
)

# 只上传权重和索引文件，并统一放到 weights 子目录
upload_folder(
    folder_path="./output",
    repo_id="my-org/my-model",
    path_in_repo="weights",
    allow_patterns=["*.safetensors", "*.index.json"],
)
```

> 上传目录时会自动跳过 `.git` 和 `.gitattributes`，不用你自己写进 `ignore_patterns`。

代价：

- 小于 5 MB 的文件会**一次读进内存**再随请求提交，文件特别多时请求体会比较大。
- 大文件按 5 MB 为界走直传通道，但**没有断点续传**，中途断了要整个文件重传。

### 命令行写法

```bash
# 上传目录
moha upload my-org/my-model ./my_model

# 上传目录并过滤
moha upload my-org/my-model ./my_model \
  --ignore "*.log" --exclude ".git*"

# 上传单个文件到指定路径
moha upload-file ./config.yaml my-org/my-model --path-in-repo configs/config.yaml
```

`moha upload` 会自动判断：给的是目录就走目录上传，给的是文件就走单文件上传。历史上「本地路径在前、仓库在后」的写法也仍然可用。

## 中断、重试与并发

这三点 SDK **没有内置**，需要你自己补一层：

| 需求 | SDK 的情况 | 怎么办 |
| --- | --- | --- |
| 断点续传 | 不支持。下载用覆盖写，中断后重跑会从头下 | 大文件尽量一次下完；中断就重跑，或用支持续传的外部工具 |
| 自动重试 | 不支持。网络抖动会直接抛异常 | 自己包一层循环捕获异常后重试 |
| 并发下载 | 不支持。整仓下载是逐个文件串行 | 自己用线程池调 `moha_hub_download()` 并发 |

自己补重试和并发的写法（这段是你要自己写的逻辑，不是 SDK 自带能力）：

```python
import time
from concurrent.futures import ThreadPoolExecutor

from xiaoshiai_hub import HubException, moha_hub_download

FILES = ["config.json", "tokenizer.json", "vocab.json"]

def fetch(name, max_retries=3):
    for attempt in range(max_retries):
        try:
            return moha_hub_download(
                repo_id="ai-lab/qwen2-7b",
                filename=name,
                local_dir="./models",
                show_progress=False,
            )
        except HubException:
            if attempt == max_retries - 1:
                raise
            time.sleep(2 ** attempt)   # 2、4 秒……逐步拉长间隔

# 并发下多个文件；线程数别开太大，避免把服务端打满
with ThreadPoolExecutor(max_workers=4) as pool:
    for path in pool.map(fetch, FILES):
        print("已下载：", path)
```

并发的代价：每个任务各自建连接、各自校验一次仓库存在性，令牌是共享的；线程开太多会被限流或拖慢别人。文件数不多时，串行其实更省事。

## 该选哪个函数

| 场景 | 用哪个 |
| --- | --- |
| 只要一两个文件 | `moha_hub_download()` |
| 要整个仓库 | `snapshot_download()` |
| 要仓库的一部分 | `snapshot_download()` + `allow_patterns` / `ignore_patterns` |
| 更新一个文件 | `upload_file()` |
| 上传一个目录 | `upload_folder()` + `ignore_patterns` |

## 常见报错

| 报错 | 含义 | 怎么办 |
| --- | --- | --- |
| `ValueError: Invalid repo_id format: ... Expected 'organization/repo_name'` | 仓库 ID 不是两段 | 写成 `组织/仓库名`，别多也别少斜杠 |
| `RepositoryNotFoundError: Repository not found: ... Please create the repository first.` | 目标仓库不存在，或你没权限 | 先在网页建好仓库，或核对组织名和仓库名 |
| `FileNotFoundError: File not found: ...` | 本地要上传的文件或目录不存在 | 检查本地路径写对没、文件是否还在 |
| `ValueError: Path is not a file: ...` | 给 `upload_file()` 传了个目录 | 目录请改用 `upload_folder()` |
| `ValueError: Path is not a directory: ...` | 给 `upload_folder()` 传了个文件 | 文件请改用 `upload_file()` |
| `UploadError: Upload failed: ...` | 上传请求被服务端拒绝 | 看后面的原因：多为权限、配额或文件过大 |
| `HTTPError: Request failed: ...` | 网络层失败 | 检查网络、代理和平台地址 |
