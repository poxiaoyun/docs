# 性能优化

魔哈本身不提供模型量化/剪枝等训练侧工具。本文只覆盖与魔哈仓库能力直接相关的优化点：文件传输、存储格式与推理接入。

## 文件传输

| 场景 | 建议 |
| --- | --- |
| 大文件上传 | 使用 Git LFS 追踪（`git lfs track "*.safetensors"` 等） |
| 只做校验/构建 | `GIT_LFS_SKIP_SMUDGE=1 git clone <url>`，避免拉取大文件 |
| 按需拉取 | `git lfs pull --include="*.safetensors"` |
| 目录批量上传 | 使用文件页的上传会话（`uploadFolder` 能力） |

> ⚠️ 注意: 单次上传的体积与文件数上限由服务端 `capabilities.limits` 下发（`maxFiles` / `maxTotalBytes` / `maxManifestBytes` / `maxPathBytes` / `maxEditableBytes`），前端未写死阈值。

## 存储格式

- 权重优先使用 `.safetensors`：加载更快，且详情页会展示 Safetensors 统计（模型体积、张量类型）。
- 数据集优先使用 Parquet / JSONL 等列式或流式格式，配合 Git LFS。
- 仓库根目录存在 `chat_template.jinja` 时，模型卡片会提供对话模板的只读查看入口。

## 推理接入

| 方式 | 说明 |
| --- | --- |
| Transformers | 通过 `HF_ENDPOINT=https://<控制台地址>/moha/huggingface` 直接加载 |
| vLLM | `pip install vllm` + `vllm serve`，提供 OpenAI 兼容接口 |
| SGLang | `pip install "sglang[all]"` + `python -m sglang.launch_server` |

这些示例都能在模型详情页的 **使用方式** 弹窗中直接复制，请求自动带上 `HF_ENDPOINT` 与 `HF_TOKEN`。

## Space 运行规格

- Space 的 `flavorID` 决定 CPU/内存/GPU 规格，可在部署配置中选择。
- 修改部署参数后系统会先保存再自动重启，无需手动二次重启。
- 运行异常时通过 Pod 日志（`.../pods/{pod}/logs`）定位问题。

> ⚠️ 注意: 模型量化、剪枝、蒸馏属于训练侧技术，与魔哈仓库功能无关，请参考对应框架的官方文档。
