# CI/CD 流程

把「代码一提交就自动把产物传上魔哈」「部署前自动拉取指定模型」这类动作写进流水线，让魔哈跟你的代码仓库联动起来。这一页给出可以直接抄的配置，把占位值换成你自己的即可。

## 开始之前
- 一个**给流水线专用的访问令牌**，到 [访问令牌](/moha/quickstart/token) 生成。建议用专门的账号，权限越小越好。
- 知道你的**控制台地址**、**组织名**，以及要操作的**仓库名**。
- 流水线环境里能装 Python 3.10 或更高版本。

## 第一步：把令牌放进流水线的 Secret
1. 生成访问令牌。
2. 在你的 CI 平台（GitHub Actions、GitLab CI 等）把它保存为一个 Secret，例如 `MOHA_TOKEN`。
3. 在配置里用变量引用它，**不要**把令牌明文写进 YAML。

:::warning 令牌泄露等于账号被接管
一旦令牌被写进配置文件、提交进仓库或打进构建日志，任何能看到它的人都能操作你的仓库。只放在 Secret 里，发现泄露立即重新生成。
:::

## 方式一：用 moha 命令行
### 登录并选好组织
每条流水线先跑一次登录，命令后面就不用再带令牌了：

```bash
pip install "moha-hub[upload]"
moha login "https://<你的控制台地址>" --token "$MOHA_TOKEN"
moha org use "<你的组织名>"
```

预期效果：`moha whoami` 能显示当前登录用户；`moha org list` 里当前组织前面会有一个 `*`。

### 上传产物
```bash
moha upload <组织>/<仓库> ./dist \
  --revision main \
  --message "publish ${GITHUB_SHA}" \
  --exclude ".git*" \
  --exclude "*.log"
```

预期效果：命令结束后输出一条提交记录，仓库的 **文件** 页签里能看到新文件。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--revision` / `-r` | 上传到哪个分支，默认 `main` |
| `--message` / `-m` | 提交信息 |
| `--include` / `--exclude` | 只上传 / 排除匹配的文件，可重复写 |
| `--encrypt` | 加密模型文件后上传（配合 `--encryption-password`） |

### 拉取资源
```bash
# 只拉需要的文件，速度快很多
moha download <组织>/<仓库> \
  --include "*.json" \
  --include "*.safetensors" \
  --local-dir ./artifacts
```

预期效果：文件出现在 `./artifacts` 目录里。下载单个文件可以用 `moha download-file <组织>/<仓库> <文件路径>`。

### 触发空间重新发布
```bash
moha redeploy <组织>/<空间名>          # 重新发布
moha status   <组织>/<空间名>          # 查看运行状态
moha logs     <组织>/<空间名> -n 100   # 看最近 100 行日志
```

`moha logs` 还支持 `--follow` / `-f` 实时跟踪，`--container` / `-c` 指定容器（空间有多个容器时用得到）。需要下线用 `moha stop`。

## 方式二：直接用 Git
模型、数据集、空间的仓库本质都是 Git 仓库，也可以像推代码一样推文件：

```bash
git lfs install
git clone https://<用户名>:<访问令牌>@<你的控制台地址>/moha/<组织>/<类型>/<仓库>.git
cd <仓库>
cp -r ../dist/* .
git add .
git commit -m "publish ${GITHUB_SHA}"
git push origin main
```

其中 `<类型>` 取 `models`、`datasets` 或 `spaces`。

:::tip 不需要大文件时跳过下载
只想校验构建、不想拉 LFS 大文件时，克隆加上 `GIT_LFS_SKIP_SMUDGE=1` 前缀，会快很多。
:::

## 完整示例：GitHub Actions
```yaml
name: 发布到魔哈

on:
  push:
    branches: [main]

jobs:
  publish:
    runs-on: ubuntu-latest
    env:
      # 这三个值都从 Secret / 仓库变量里取，不要写死在文件里
      MOHA_TOKEN: ${{ secrets.MOHA_TOKEN }}
      MOHA_ENDPOINT: https://<你的控制台地址>
      MOHA_ORGANIZATION: <你的组织名>
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: 安装 SDK
        run: pip install "moha-hub[upload]"

      - name: 登录魔哈
        run: moha login "$MOHA_ENDPOINT" --token "$MOHA_TOKEN"

      - name: 选择组织
        run: moha org use "$MOHA_ORGANIZATION"

      - name: 上传产物
        run: |
          moha upload "$MOHA_ORGANIZATION/my-model" ./dist \
            --revision main \
            --message "publish ${GITHUB_SHA}" \
            --exclude ".git*" --exclude "*.log"

      - name: 重新发布空间
        run: moha redeploy "$MOHA_ORGANIZATION/my-space"
```

## 常见问题
| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| `moha: command not found` | 没装 SDK，或没加进 PATH | 先 `pip install "moha-hub[upload]"`，并确认当前 Python 环境的 bin 目录在 PATH 里 |
| 登录报地址格式错误 | 控制台地址没带 `https://` | `moha login` 的地址必须带协议头 |
| 上传报权限错误 | 令牌对应的账号在这个仓库没有写权限 | 在仓库 **设置** 里把该账号加为读写或管理员 |
| `404` 找不到仓库 | 组织名或仓库名写错 | 先用 `moha info model <组织>/<仓库>` 确认仓库存在 |
