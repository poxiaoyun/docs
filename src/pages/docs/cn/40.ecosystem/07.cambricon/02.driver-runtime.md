# 驱动与容器运行时

这一层只涉及宿主机。集群侧的设备插件与监控组件在 [Kubernetes 组件](/ecosystem/cambricon/k8s-components) 里讲。

装完的标志是设备节点出现：`/dev/cambricon_devX`、`/dev/cambricon_ctl`、`/dev/cambricon_ipcmY`。这三个节点不到位，后面所有集群组件都白装。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 操作系统 | 与目标 Neuware 版本配套的发行版，具体清单看官方安装说明 |
| 加速卡 | MLU370 系列等，需在整机厂商的兼容列表内 |
| 驱动包 | 从寒武纪官方渠道获取，随整机交付或从开发者站点下载 |
| 内核 | 驱动以内核模块形式加载，升级内核后要重新装一遍驱动 |
| 权限 | 跑业务的账号与容器进程要能读写上面三个设备节点 |

设备节点分三类，排障时按类别判断问题出在哪一层：

| 设备节点 | 说明 |
| --- | --- |
| `/dev/cambricon_devX` | 卡设备节点，每张卡一个，X 是序号 |
| `/dev/cambricon_ctl` | 控制节点，管理工具与驱动通信走它 |
| `/dev/cambricon_ipcmY` | 卡间通信节点，多卡任务会用到 |

`/dev/cambricon_ctl` 缺失时管理工具基本都不可用，`ipcm` 缺失时通常表现为多卡任务起不来或者通信超时。

## 装驱动

驱动是 Neuware 的一部分，由官方安装包提供。步骤按官方文档走：

1. 从官方渠道取与卡型、操作系统版本匹配的驱动包。
2. 在每台有卡的机器上执行安装程序，过程中会编译并加载内核模块。
3. 装完确认设备节点出现，没有的检查内核模块是否加载成功。
4. 装了新内核之后重复一次，内核模块不会自动跟着走。

:::warning 命令以官方当前版本为准
寒武纪驱动的安装方式随版本和发行版变化，官方文档里给的是对应版本的完整命令。
这一页只描述流程，动手前先打开官方安装说明，把包名与参数换成本地这一版的。
:::

## 容器运行时与工具链

宿主机认到卡之后，要让容器里也能拿到这些设备节点。这一步按官方文档的容器运行时说明做，平台侧不做假设。

容器镜像里除了业务代码，还要带两样东西：

| 内容 | 来自 | 少了会怎样 |
| --- | --- | --- |
| CNToolkit 运行部分 | CNToolkit 安装包 | 容器里跑不起来编译产物，或找不到运行时库 |
| 框架适配包 | torch_mlu 或 Cambricon TensorFlow | 框架能起来但看不到 MLU 设备 |

镜像里的版本要与宿主机驱动对上。跨版本混搭是最常见的坑，症状是库加载失败或设备初始化报错。

## 验证

宿主机上列出设备节点：

```bash
ls -l /dev/cambricon_dev* /dev/cambricon_ctl /dev/cambricon_ipcm*
```

三个节点都出来，说明驱动这层就位。容器里的验证方式照官方文档给的最小示例做，确认容器内可见同一批设备节点即可。

## 升级与卸载

升级驱动之前先把上层停干净：

1. 停掉在跑的业务任务。
2. 停掉集群侧的设备插件与监控组件。
3. 再动驱动。

设备插件会周期性读驱动接口，带着它升驱动容易留下一个「插件在跑但上报的设备数不对」的状态，只能靠重启插件恢复。卸载按官方文档的卸载步骤执行，卸完确认设备节点与内核模块都清掉，再装新版本。
