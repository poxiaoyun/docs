# 平台适配现状

平台上「认识一张卡」要经过几处相互独立的逻辑：镜像登记、模型元数据、规格展示、集群组件。同一家厂商在这几处的状态经常不一样，在界面上找不到某样东西时，先分清是配置没做还是本来就没有。

寒武纪的情况是：前半段基本都在，后半段缺两件。

## 逐层核对

| 层 | 位置 | 对寒武纪的现状 |
| --- | --- | --- |
| 镜像加速器类型 | 镜像登记时的加速器选项 | **已登记**：`Neuware(寒武纪)` |
| 模型元数据型号 | 模型卡片可选的加速卡型号 | **已登记 4 个**：MLU220 / MLU270 / MLU370 / MLU590 |
| 模型元数据的后端枚举 | 模型元数据里的 hardware_backends | **已包含** `mlu` |
| 规格的加速卡标签 | 规格标签上写的 GPU / NPU / MLU 字样 | **已支持**：显示 `MLU` |
| 规格的型号名 | 由资源名与型号拼出的规格名 | **前缀不会被剥掉**。平台剥前缀的名单只有 nvidia / amd / intel / huawei 四家，其余厂商的型号名原样参与拼接 |
| 规格的厂商图标 | 规格标签上的小图标 | **没有**，寒武纪没有专属图标 |
| 集群调度组件 | 集群管理 → 运维管理 → 系统应用 | **没有**，平台只内置了 NVIDIA 与昇腾两套 |

型号枚举里有 MLU590，这一点与官网产品页的情况不一致，[产品与软件栈](/ecosystem/cambricon/products) 里已经标了来源性质，按第三方线索看待。

## 现在能做什么

- **镜像元数据**：登记镜像时把加速器类型选成 `Neuware(寒武纪)`，检索和筛选能用上。
- **模型元数据**：模型卡片里能选 MLU220 / MLU270 / MLU370 / MLU590 四个型号；`hardware_backends` 里有 `mlu`，跨厂商的模型清单可以按后端筛。
- **规格标签**：加速卡标签显示 `MLU`，与 GPU、NPU 的规格在列表里能区分开。
- **算力调度**：只要节点上的设备插件把卡报成 `cambricon.com/mlu`，平台侧的配额、规格、任务申请都能按这个资源名走，多卡任务由 Volcano 排。

## 还不能做什么

| 缺的能力 | 影响 | 补法 |
| --- | --- | --- |
| 一键安装集群组件 | 系统应用里点不到，装机要多走几步命令 | 按 [Kubernetes 组件](/ecosystem/cambricon/k8s-components) 手工部署设备插件与 mlu-exporter |
| 厂商专属图标 | 规格标签上只有文字 `MLU`，没有小图标 | 属展示层设计，不影响调度 |
| 型号名前缀处理 | 型号字段里带的前缀不会被剥掉，规格名会和 NVIDIA / AMD 那几家显示形态不同 | 建规格时把型号名填成希望显示的样子 |
| 平台预置监控看板 | MLU 指标要自己接 Prometheus，平台不会自动带 | 部署 mlu-exporter，建 ServiceMonitor 抓 30108 端口 |
| 分区切分模板 | 平台只有华为 NPU 的分片模板，没有 MLU 的 | 切分由驱动与设备插件侧完成，不经过平台 |

## 手工接入的完整顺序

平台的系统应用里没有寒武纪，所以前四步都在集群外完成：

1. 每台有卡的机器装 Neuware 驱动，确认 `/dev/cambricon_devX`、`/dev/cambricon_ctl`、`/dev/cambricon_ipcmY` 出现。
2. 同一批机器装容器运行时工具链，容器里能看到同一批设备节点。
3. 构建并部署设备插件，注意官方没有预编译镜像、构建依赖驱动包里的 `cndev.h`，确认节点出现 `cambricon.com/mlu`。
4. 部署 mlu-exporter，确认 30108 端口能抓到 `/metrics`。
5. 回到平台，按 `cambricon.com/mlu` 建资源规格与配额，提交一个申请 1 张卡的任务验一遍。

第 5 步是唯一需要动平台界面的地方，前面四步都在集群侧。
