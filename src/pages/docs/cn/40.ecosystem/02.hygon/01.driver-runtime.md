# DCU 驱动安装

这一步是在每台插了 DCU 的机器上装驱动，让宿主机自己认识这张卡。装完的标志有两个：
驱动服务 `hymgr` 正常运行，并且用 `lsmod` 能看到驱动模块。驱动装不上，后面所有集群组件都无从谈起。

驱动是操作系统使用这张卡的基础软件，没有它，系统只知道插了一块硬件。

:::info 本页只管宿主机这一层
这里不涉及 Kubernetes：集群侧的组件安装见 [Kubernetes 组件](/ecosystem/hygon/k8s-components)。
也不涉及 DTK / DAS 等上层软件栈，那是业务环境的事，平台接入不需要装；
三层软件栈分别是什么见 [海光（DCU）](/ecosystem/hygon)。
:::

## 开始之前

- 确认机器的操作系统与硬件型号，并在下面的兼容列表里找到对应的驱动版本。
- 从厂商渠道获取驱动安装包（`.run` 文件），并上传到目标机器上能访问的目录。
- 具备 **root** 权限，且能安装编译工具与内核头文件。

## 驱动兼容列表

选驱动时对照这张表，硬件型号不同，需要的驱动和开发工具包（DTK）版本也不同：

| 驱动版本 | 支持硬件 | 推荐 DTK 版本 |
| --- | --- | --- |
| rock-4.0-23-5.6.25 | Z100/Z100L | 21.04/21.10/22.04 |
| rock-4.5.2-5.11.40 | Z100/Z100L | 22.04/22.10/23.04 |
| rock-5.2.0-5.16.18 | Z100/Z100L | 22.10/23.04 |
| rock-5.2.0-5.16.29 | Z100/Z100L/K100 | 23.04/23.10 |
| rock-5.7.1-6.2.35-V1.6.7d | Z100/Z100L/K100/K100-AI | DTK 24.04.* |
| rock-6.3.8+ | BW1000/K100-AI/K100/Z100L/Z100 | DTK 25.04.* |
| rock-6.3.28-V1.3.0b 起 | BW 系列（BW1000/BW1100/BW150/BW100/BW10） | DTK 25.04.* |
| rock-6.3.30-V1.4.1a 起 | K100-AI/K100/Z100L/Z100；BW 系列 | DTK 26.04.* |

### 怎么读驱动包的名字

驱动包命名有两代写法，看到包名先判断是哪一代：

| 写法 | 例子 | 含义 |
| --- | --- | --- |
| 旧：`rock-<ROCm 版本>-<驱动版本>-V<包版本>.run` | `rock-5.7.1-6.2.35-V1.6.7d.run` | `5.7.1` 是兼容的 ROCm 版本，`6.2.35` 是驱动版本 |
| 新：`rock-<驱动版本>-V<包版本>.run` | `rock-6.3.30-V1.4.1a.run` | 只剩驱动版本与包版本 |
| BW 系列部分包：`z-rock-...` | `z-rock-6.3.28-1.3.0b.run` | BW 系列（含 BW1100）的专用包 |

**DTK 版本必须与驱动版本对应**：DTK 24.04.* 配 6.2.x 驱动，25.04.* 配 6.3.x 早期驱动，
26.04.* 配 6.3.30 及以后的驱动。DTK 与驱动不配套时，常见表现是「`hy-smi` 能看卡，但一跑框架就报错」。

:::info 驱动与框架的版本是两组对应关系
驱动 ↔ DTK 是一组对应；AI 框架的安装包（PyTorch / vLLM 的 whl）↔ DTK 是另一组。
两组都要对上，任务才能真正跑起来。装之前先确认这两组版本。
:::

### 按 DTK 代际选驱动与固件

如果现场已经定好了 DTK 版本（业务镜像依赖它），就按 DTK 代际反过来挑驱动和 VBIOS，不要只看卡型号：

| 产品 / DTK 代际 | 驱动版本 | VBIOS 版本 |
| --- | --- | --- |
| BW1000 / BW1100 / BW150 / BW100 / BW10 | `z-rock-6.3.28-1.3.0b` | `z.6.312.002400Q.998006` |
| K100-AI / Z100L / K100（配 DTK 24.04.*） | `rock-6.2.35-1.6.7d` | `5.719.001200r.710209` |
| K100-AI / Z100L / K100（配 DTK 25.04.* 及以上） | `rock-6.3.28-1.3.0b` 及以上 | `6.312.002400Q.998006` 及以上 |

上表整理自海光光合开发者社区的开发部署指南。**现场以随包提供的版本组合为准**，
换驱动或换固件前先确认与已有 DTK 是否配套。

## 先确认硬件在场

装驱动之前先确认卡插好、系统也识别到了，省得把硬件问题当成驱动问题：

```bash
lspci -nn | grep -e Display -e Co-processor | grep -i -E "hygon|haiguang|Chengdu"
```

| 型号 | 在 `lspci` 里显示为 |
| --- | --- |
| Z100 / Z100L | `Display controller` |
| K100 / K100-AI / BW 系列 | `Co-processor` |

顺便看一眼末尾的 `rev` 版本号：`rev 01` 表示设备正常；`rev ff` 表示设备已经处于异常状态，
**普通重启不一定能恢复**，需要硬重启（DC）或掉电重启（AC）。

:::info BAR 地址超出 44 bit 会跑不起来
DCU 的 BAR 寄存器地址必须在 44 bit 以内。装驱动前可以用 `lspci -vvv` 看 `Region` 段的地址范围
（BW 系列的 device ID 是 `1d94:6320`，K100-AI 是 `1d94:6210`）。超出时要在 BIOS 里调低
MMIO High Base —— 菜单位置各整机厂商不同，以整机手册为准。
:::

## 操作步骤

### 1. 安装依赖包

根据操作系统类型执行对应命令：

CentOS：

```bash
yum install -y rpm-build gcc-c++ cmake automake elfutils-libelf-devel libdrm libdrm-devel pciutils
yum install -y kernel-devel-`uname -r` kernel-modules-extra
```

Ubuntu：

```bash
apt install -y gcc g++ cmake automake libelf-dev libdrm-amdgpu1 libtinfo5 pciutils libdrm-dev
apt install -y linux-headers-`uname -r` linux-modules-extra
```

### 2. 下载驱动并加执行权限

驱动与 DTK 的下载入口：

| 用途 | 地址 |
| --- | --- |
| 光合开发者社区（总入口） | `https://developer.sourcefind.cn/` |
| DTK 与工具包 | `https://download.sourcefind.cn:65024/1/main` |
| 驱动（主） | `https://download.sourcefind.cn:65024/6/main/latest` |
| 驱动（备用） | `https://cancon.hpccube.com:65024/6/main/latest` |
| 驱动镜像仓库 | `https://developer.sourcefind.cn/servicelist` |
| 模型仓库 | `https://developer.sourcefind.cn/modelzoo` |

上传到目标机器后赋权：

```bash
chmod +x rock*.run
```

### 3. 安装驱动

```bash
./rock-<版本>.run -A
```

安装新驱动不需要先卸载旧驱动，安装过程会自动卸载老驱动。常用参数：

| 参数 | 作用 |
| --- | --- |
| `-A` | 全自动安装：驱动、配置、VBIOS 与互联固件一起处理，**推荐** |
| `-D` | 开发者模式：只装驱动 / HAL / 配置，不动作 VBIOS |
| `-a` | 驱动升级策略：`0` 自动 / `1` 忽略版本 / `2` 询问 |
| `-u` | VBIOS 更新策略：`0` 自动 / `1` 询问 / `2` 不更新 |
| `-H` | 互联固件（HY Switch）策略：`0` 自动 / `1` 询问 / `2` 不更新 |
| `-t` | DCU 互联类型（PCIe 2 卡 / 4 卡、OAM 2/4/8 卡直连等），BW 系列支持 |
| `-s` | 使能 vGPU 软件调度（一分四切分） |
| `-d` | 安装时先不加载驱动，装完重启生效 |
| `-h` | 查看当前包支持的全部参数 |

:::warning 参数以当前包为准
参数会随驱动版本略有增减。动手前先执行 `./rock-<版本>.run -h` 看一遍；
上面这张表用来理解各项的含义，不要当成跨版本的固定接口。
:::

多卡直连的机器（OAM 整机）通常还要用 `-t` 指定互联拓扑。它只在 **BW 系列**上支持，
K100-AI 不支持；不确定时不要乱填，填错会影响多卡通信：

| `-t` 取值 | 互联类型 | 适用 |
| --- | --- | --- |
| `0` | PCIE_2HCU | PCIe 标卡 2 卡直连 |
| `1` | PCIE_4HCU | PCIe 标卡 4 卡直连 |
| `4` | OAM_2HCU | OAM 2 卡直连 |
| `5` | OAM_4HCU | OAM 4 卡直连 |
| `6` | OAM_8HCU | OAM 8 卡直连 |
| `10` | OAM_7HSW_8HCU | 8 卡经 7 个 HY Switch 互联 |
| `11` | OAM508_7HSW_8HCU | OAM508 规格 |
| `NONE` / `KEEPOLD` | 禁用 hlink / 沿用旧类型 | 按需 |

### 4. 重启驱动服务

```bash
systemctl restart hymgr
```

### 5. 按提示回答安装过程中的询问

安装时会遇到两类询问，按下面的原则回答：

| 询问 | 含义 | 怎么选 |
| --- | --- | --- |
| `Do you want to remove legacy hymgr config file? [Y/n]:` | 是否重新生成 `/etc/hymgr.cfg` | 选 `yes` 重新生成，选 `no` 保留原文件。不确定就保留（`no`） |
| `Update vbios? [y/N]:`（K100/K100-AI 环境） | 是否更新显卡固件 | 首次安装建议选 `y` 并重启物理机；之后可选项 `N`。若环境对物理机重启有严格限制，可以不更新 |

## 卸载与升级驱动

**升级不需要先卸载**：直接装新版 `.run`，安装程序会自动卸载旧驱动。需要手工卸载时按下面的顺序做：

```bash
rpm -qa | grep rock          # 先看装了哪个包
systemctl stop hymgr         # 停驱动服务
rmmod hycu                   # 卸载驱动模块（6.2.x 及以下用 hydcu）
rpm -e rock-*                # 卸载驱动包
```

:::warning 升级固件后要重启物理机
只要这次安装动了 **HY Switch 固件或 VBIOS**，就必须重启物理机才生效。
对停机窗口有要求的现场，请把这一步排进计划。
:::

## 更新固件（VBIOS / HY Switch）

装完驱动后，宿主机上会生成固件目录 `/opt/hyhal/firmware/vbios`，里面按产品系列分子目录
（`BW3000/` 对应 BW 系列、`KM/` 对应 K100、`ZD/` 对应 K100-AI、`ZF/` 对应 Z100L、`NMZ/` 对应 BW1100），
并带有刷新工具 `hyflash_*` 与自动刷新脚本 `vbios_upgrade.sh`。

手动指定镜像刷新（`--xhcl` 表示同时开启互联）：

```bash
./hyflash --index a --update ./BW3000/BW3000-<VBIOS 版本>.bin --xhcl
```

也可以直接跑自动刷新脚本：

```bash
cd /opt/hyhal/firmware
./vbios_upgrade.sh
```

:::warning 刷固件三条禁忌
① 先确认 VBIOS 与硬件版本匹配，**刷错版本可能把卡刷废**；② 刷新过程中**不要断电**；
③ 刷新完成后**重启**才生效。生产环境刷固件请安排在维护窗口内。
:::

## 验证驱动是否加载

执行：

```bash
lsmod | grep -E "hydcu|hycu"
```

能看到驱动模块列表就说明加载成功。**模块名称随驱动版本不同**：

6.2.x 及以下驱动显示为 `hydcu`：

```text
hydcu                1435342  0
hydcu_sched            34432  1 hydcu
hyttm                  61919  1 hydcu
hykcl                  46567  3 hydcu_sched,hydcu,hyttm
hy_extra               32140  3 hydcu_sched,hydcu,hykcl
```

6.3.x 及以上驱动显示为 `hycu`：

```text
hycu                 3371008  2
hycu_sched             45056  1 hycu
hyttm                  86016  2 hycu,hydrm_ttm_helper
hykcl                  40960  5 hycu,hycu_sched,hyttm
hy_extra               65536  2 hycu,hycu_sched
```

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 安装报错提示缺少编译工具 | 依赖包没装全，或 cmake / gcc 版本过低 | 新版本驱动要求 cmake 高于 3.2、gcc 大于 7.3，先升级再装 |
| 安装报错提示找不到内核头文件 | `kernel-devel` 版本与当前内核不一致 | 用 `uname -r` 查看内核版本，安装与之完全一致的 `kernel-devel` |
| `lsmod` 里看不到驱动模块 | 驱动没装上，或装完没重启服务 | 确认安装回显成功，再执行 `systemctl restart hymgr` |
| 容器里取不到 DCU 进程信息 | 6.3.* 驱动下没有挂载调试路径 | 用 Docker 调用时把 `/sys/kernel/debug` 挂载进容器 |

:::warning 版本要配套
驱动、DTK、以及后面要装的内核头文件版本必须配套。**不要凭印象指定版本号**，
以随发布包提供的版本组合为准，否则轻则安装报错，重则装完卡不可用。
:::
