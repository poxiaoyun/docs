# DCU 驱动安装

这一步是在**每台插了 DCU 的机器上**装驱动，让宿主机自己认识这张卡。装完的标志有两个：
驱动服务 `hymgr` 正常运行，并且用 `lsmod` 能看到驱动模块。**驱动装不上，后面所有集群组件都无从谈起。**

可以把驱动理解成「显卡驱动」：没有它，操作系统只知道插了一块硬件，却不会用。

:::info 本页只管宿主机
这里不涉及 Kubernetes。集群侧的组件安装见 [Kubernetes 组件](/ecosystem/hygon/k8s-components)。
:::

## 开始之前

- 确认机器的操作系统与硬件型号，并在下面的兼容列表里找到对应的驱动版本。
- 从厂商渠道获取驱动安装包（`.run` 文件），并上传到目标机器上能访问的目录。
- 具备 **root** 权限，且能安装编译工具与内核头文件。

## 驱动兼容列表

选驱动时对照这张表，硬件型号不同，需要的驱动和开发工具包（DTK）版本也不同：

| 驱动版本 | 支持硬件 | 推荐 DTK 版本 |
| --- | --- | --- |
| rock-4.0-23-5.6.25 | Z100/Z100L | 21.04/21.10/22.04 |
| rock-4.5.2-5.11.40 | Z100/Z100L | 22.04/22.10/23.04 |

| rock-5.2.0-5.16.29 | Z100/Z100L/K100 | 23.04/23.10 |
| rock-5.7.1-6.2.26+ | Z100/Z100L/K100/K100-AI | 24.04/25.04 |
| rock-6.3.8+ | BW1000/K100-AI/K100/Z100L/Z100 | 25.04 |

## 操作步骤

### 1. 安装依赖包

根据操作系统类型执行对应命令：

CentOS：

```bash
yum install -y rpm-build gcc-c++ cmake automake elfutils-libelf-devel libdrm libdrm-devel pciutils
yum install -y kernel-devel-`uname -r` kernel-modules-extra
```

Ubuntu：

```bash
apt install -y gcc g++ cmake automake libelf-dev libdrm-amdgpu1 libtinfo5 pciutils libdrm-dev
apt install -y linux-headers-`uname -r` linux-modules-extra
```

### 2. 下载驱动并加执行权限

从厂商驱动下载地址获取对应版本的 `.run` 包，然后赋权：

```bash
chmod +x rock*.run
```

驱动下载地址：`https://cancon.hpccube.com:65024/6/main/latest驱动`

### 3. 安装驱动

```bash
./rock*.run
```

安装参数可以用下面的命令查看：

```bash
./rock*.run -h
```

安装新驱动不需要先卸载旧驱动，安装过程会自动卸载老驱动。

### 4. 重启驱动服务

```bash
systemctl restart hymgr
```

### 5. 按提示回答安装过程中的询问

安装时会遇到两类询问，按下面的原则回答：

| 询问 | 含义 | 怎么选 |
| --- | --- | --- |
| `Do you want to remove legacy hymgr config file? [Y/n]:` | 是否重新生成 `/etc/hymgr.cfg` | 选 `yes` 重新生成，选 `no` 保留原文件。不确定就保留（`no`） |
| `Update vbios? [y/N]:`（K100/K100-AI 环境） | 是否更新显卡固件 | 首次安装建议选 `y` 并重启物理机；之后可选项 `N`。若环境对物理机重启有严格限制，可以不更新 |

## 验证驱动是否加载

执行：

```bash
lsmod | grep -E "hydcu|hycu"
```

能看到驱动模块列表就说明加载成功。**模块名称随驱动版本不同**：

6.2.x 及以下驱动显示为 `hydcu`：

```text
hydcu                1435342  0
hydcu_sched            34432  1 hydcu
hyttm                  61919  1 hydcu
hykcl                  46567  3 hydcu_sched,hydcu,hyttm
hy_extra               32140  3 hydcu_sched,hydcu,hykcl
```

6.3.x 及以上驱动显示为 `hycu`：

```text
hycu                 3371008  2
hycu_sched             45056  1 hycu
hyttm                  86016  2 hycu,hydrm_ttm_helper
hykcl                  40960  5 hycu,hycu_sched,hyttm
hy_extra               65536  2 hycu,hycu_sched
```

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 安装报错提示缺少编译工具 | 依赖包没装全，或 cmake / gcc 版本过低 | 新版本驱动要求 cmake 高于 3.2、gcc 大于 7.3，先升级再装 |
| 安装报错提示找不到内核头文件 | `kernel-devel` 版本与当前内核不一致 | 用 `uname -r` 查看内核版本，安装与之完全一致的 `kernel-devel` |
| `lsmod` 里看不到驱动模块 | 驱动没装上，或装完没重启服务 | 确认安装回显成功，再执行 `systemctl restart hymgr` |
| 容器里取不到 DCU 进程信息 | 6.3.* 驱动下没有挂载调试路径 | 用 Docker 调用时把 `/sys/kernel/debug` 挂载进容器 |

:::warning 版本要配套
驱动、DTK、以及后面要装的内核头文件版本必须配套。**不要凭印象指定版本号**，
以随发布包提供的版本组合为准，否则轻则安装报错，重则装完卡不可用。
:::
