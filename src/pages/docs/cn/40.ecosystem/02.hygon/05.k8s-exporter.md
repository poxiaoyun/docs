# DCU-Exporter

DCU-Exporter 负责**定时采集每张卡的状态**——温度、功耗、显存占用、利用率、PCIe 带宽、错误计数等，
再通过 HTTP 接口暴露出来，供 Prometheus 之类的监控系统抓取。装完它，平台上才能看到卡的运行曲线并做告警。

可以把它理解成**装在每张卡上的电表**：卡不会主动汇报自己的温度和功耗，得有人定期去读表。

## 什么情况下必须装

- 需要在平台上查看 DCU 的利用率、显存、温度、功耗，或按卡的状态做告警和容量统计。
- 只做资源调度、不需要监控数据时，可以跳过本页。

## 开始之前

- 每台有卡的机器已装好驱动（`lsmod | grep -E "hydcu|hycu"` 能看到驱动模块）。
- 组件镜像已放到集群能拉取的位置。
- 准备好部署文件 `dcu-exporter-v2.yaml`。

## 部署

集群里一般以 DaemonSet 形式部署，每个有卡节点跑一个 Pod：

```bash
kubectl create -f dcu-exporter-v2.yaml
```

## 验证

### 1. 看 Pod

```bash
kubectl get pod -n kube-system -owide | grep dcu-exporter
```

每个有卡节点上各有一个 Pod，状态为 `Running`。

### 2. 直接读指标

```bash
curl localhost:16080/metrics
```

能打出内容，说明采集正常。默认端口为 `16080`，默认路径为 `/metrics`，完整访问形如 `http://<host>:16080/metrics`。

### 3. 在 Prometheus 里确认

若集群已部署 Prometheus，在 Prometheus 中查询相关指标，能看到数据就说明抓取成功。

## 端口与采集配置（可选调整）

| 想改什么 | 怎么改 |
| --- | --- |
| 指标端口 | 修改部署文件里的 `containerPort`、`prometheus.io/port` 和 Service 的 `port`（三处要一致） |
| 只采集部分指标 | 用环境变量 `ENABLE_METRICS` 指定指标名，多个用英文逗号分隔 |
| 采集间隔 | 用环境变量 `PULSE` 设置，单位为秒 |
| 日志 | 通过 `LOG*` 系列环境变量配置日志的级别与开关 |

## 在物理机上直接部署

除容器化部署外，也可以在物理机上直接安装 DCU-Exporter（需保证驱动已安装）：

### 1. 下载安装包

从社区下载 `dcu-exporter.run`。

### 2. 执行安装

```bash
bash dcu-exporter.run
```

安装目录为 `/opt/dcu-exporter`。

### 3. 查看用法

```bash
/opt/dcu-exporter/dcu-exporter -h
```

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 指标里 K8s 相关标签始终为空 | 集群里没有使用卡的工作负载 / kubelet 工作目录不对 / 环境变量与集群不一致 | 见下方「排查 K8s 标签为空」 |
| 端口 `16080` 打不开 | Pod 未就绪，或端口配置被改过 | 先确认 Pod 状态，再核对部署文件里的三处端口是否一致 |
| Pod 起不来 | 镜像拉取失败，或节点驱动异常 | `kubectl describe pod -n kube-system <dcu-exporter-pod>` 看事件，并在节点上确认驱动模块存在 |

### 排查 K8s 标签为空

1. 检查集群中是否存在使用 DCU 的工作负载：

   ```bash
   kubectl get pod -A -o wide
   ```

2. 检查节点上 `/var/lib/kubelet` 是否为 kubelet 的实际工作目录：

   ```bash
   ls -d /var/lib/kubelet
   ```

3. 检查容器里的 `KUBERNETES_SERVICE_HOST` 与 `KUBERNETES_SERVICE_PORT` 是否与集群实际配置一致：

   ```bash
   kubectl exec -n kube-system <dcu-exporter-pod> -- env | grep KUBERNETES
   ```

:::warning 升级驱动前先停 Exporter
Exporter 会周期性调用驱动接口。升级驱动前先停业务、再停 Exporter；升级完成后按相反顺序恢复，
否则会出现读到一半旧驱动、指标异常的情况。
:::
