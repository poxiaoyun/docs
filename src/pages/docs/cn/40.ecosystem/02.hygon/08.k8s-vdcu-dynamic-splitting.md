# vDCU 动态切分模式

动态切分模式下，**不用提前把卡切开**：任务提交时在资源里写明要多少算力、多少显存，
插件会自动从卡上切出对应的 vDCU 给它用，任务结束后自动回收，卡重新回到可用池。
这一能力由设备插件与 vDCU-Scheduler（或 HAMi 调度器）配合完成。

可以把它理解成**共享办公位**：不必固定给每个人留一张桌子，谁来谁用，用完即走，空出的位子别人还能坐。

## 什么情况下必须装

- 有很多中小任务、规格经常变，希望尽量提高卡的利用率。
- 需要按任务动态指定算力和显存，而不想提前手工划分实例。

只需要跑固定规格的任务时，用标准模式的预切分 vDCU 或 [MIG 模式](/ecosystem/hygon/k8s-device-plugin-mig) 即可。

## 三种切分方式怎么选

| 对比项 | 预切分 vDCU（标准模式） | MIG 模式 | vDCU 动态切分 |
| --- | --- | --- | --- |
| 什么时候切 | 提前切成固定规格 | 宿主机硬件级提前切 | 提交任务时按需切 |
| 使用前要不要人工准备 | 要，先划好 vDCU | 要，先创建 MIG 实例 | 不用 |
| 隔离性 | 一般 | 更强 | 一般 |
| 资源名 | `hygon.com/dcu-share-*` | `hygon.com/dcu-mig-*` | `hygon.com/dcunum` 等 |
| 额外组件 | 无 | 无 | 需要 vDCU-Scheduler |
| 适合场景 | 规格固定的多任务共存 | 强隔离、多任务共存 | 规格多变、追求利用率 |

**怎么选：**

- 规格固定 → 用标准模式的预切分 vDCU。
- 要求强隔离 → 用 [MIG 模式](/ecosystem/hygon/k8s-device-plugin-mig)。
- 规格多变、想尽量提高利用率 → 用本页的动态切分。

:::warning 动态切分与 MIG 不能共存
同一套环境里，动态切分和 MIG 只能选一条路线。开启 MIG 后 vDCU 虚拟化不可用。
:::

## 开始之前

- 每台有卡的机器已装好驱动，组件镜像已放到集群能拉取的位置。
- 准备好三份部署文件：`vdcu-admission-webhook.yaml`、`vdcu-scheduler.yaml`、`k8s-dcu-plugin-hami.yaml`。
- 具备对集群执行 `kubectl apply` 的权限。

## 操作步骤

### 1. 给节点打固定标签

设备插件在部署时要查询这个标签，先给有卡的节点打上：

```bash
kubectl label nodes <node-name> dcu=on
```

### 2. 依次部署三个组件

```bash
kubectl apply -f vdcu-admission-webhook.yaml
kubectl apply -f vdcu-scheduler.yaml
kubectl apply -f k8s-dcu-plugin-hami.yaml
```

## 验证

### 1. 看组件 Pod

```bash
kubectl get pod -n kube-system -owide | grep vdcu
```

`vdcu-admission-webhook`、`vdcu-scheduler` 以及设备插件对应的 Pod 都应为 `Running`。

### 2. 看节点资源

```bash
kubectl describe node <node-name>
```

在输出的 `Capacity` 字段里看到 `hygon.com/dcunum: 4`，表示这个节点有 4 个可用的 vDCU 资源。

## 怎么申请

任务通过三个资源字段告诉集群要多少 vDCU：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: vdcu-pytorch-demo
spec:
  containers:
    - name: vdcu-pytorch-demo
      image: image.sourcefind.cn:5000/dcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: ["/bin/bash", "-c", "--"]
      args: ["sleep infinity & wait"]
      resources:
        limits:
          hygon.com/dcunum: 1      # 申请 1 个 vDCU
          hygon.com/dcucores: 60   # 指定 vDCU 算力为 60%
          hygon.com/dcumem: 3000   # 指定 vDCU 显存为 3000MB
```

| 资源字段 | 含义 |
| --- | --- |
| `hygon.com/dcunum` | 申请几个 vDCU |
| `hygon.com/dcucores` | 申请的算力（按百分比） |
| `hygon.com/dcumem` | 申请的显存（单位 MB） |

## 使用限制

- 每个容器最多申请 **1 张 vDCU**。申请多于 1 张时，集群会把申请数量削减为 1 张，只有 1 张生效。

## 卸载或重新部署

若卸载动态切分组件或重新部署，除卸载上面三个组件外，还要手动清理遗留资源，否则重新部署可能失败：

```bash
kubectl delete secrets -n kube-system admission-webhook-dcu-certs
kubectl delete mutatingwebhookconfigurations mutating-webhook-dcu-cfg
```

:::warning 卸载前先停业务
清理这两项会移除 webhook 配置与证书，正在使用 vDCU 的任务可能受影响。**请先停业务再操作。**
:::
