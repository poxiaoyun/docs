# DCU-Label-Node

DCU-Label-Node 是一个常驻在每个节点上的小程序。它检查这台机器上有没有 DCU，有的话就给节点**贴标签**，
写明卡的型号、计算单元数量和显存容量。标签是后面设备插件和调度器判断「哪台机器有卡、有什么卡」的依据。

可以把它理解成**给机器挂门牌**：调度器站在走廊里，只能看门牌，看不到屋里到底装了什么卡。

## 什么情况下必须装

只要你要在集群里调度 DCU，就建议先装它，给节点补齐 DCU 标签。设备插件按标签选择要管理哪些节点；
不装的话，节点上缺少这些标签，设备插件可能管不到这台机器。

## 开始之前

- 每台有卡的机器已装好驱动（`lsmod | grep -E "hydcu|hycu"` 能看到驱动模块）。
- 组件镜像已放到集群能拉取的位置。
- 准备好部署文件 `k8s-dcu-label-node.yaml`。
- 具备对集群执行 `kubectl apply` 的权限。

## 操作步骤

### 1. 部署

以 DaemonSet 形式部署到集群（默认命名空间为 `kube-system`）：

```bash
kubectl apply -f k8s-dcu-label-node.yaml
```

### 2. 查看 Pod

```bash
kubectl get pod -n kube-system -owide | grep dcu-label-node
```

每台有卡的机器上应该各有一个 Pod，状态为 `Running`。

## 装完之后，节点上多了哪些标签

组件会在确认配置了 DCU 的节点上创建下面的标签：

| 标签 | 含义 | 示例 |
| --- | --- | --- |
| `hygon.com/dcu` | 节点是否有 DCU 设备：有则为 `true` | `hygon.com/dcu=true` |
| `hygon.com/dcu.name` | DCU 型号 | `hygon.com/dcu.name=K100_AI` |
| `hygon.com/dcu.cu-count` | DCU 的计算单元（CU）数量 | `hygon.com/dcu.cu-count=120` |
| `hygon.com/dcu.vram` | DCU 显存容量 | `hygon.com/dcu.vram=64G` |

说明：

- 节点上没有 DCU 时，以 `hygon.com/dcu` 为前缀的标签都不会生成。
- 型号、CU 数量、显存三个标签默认自动生成，也可以通过部署文件的启动参数开启或关闭。

## 验证

查看节点描述信息，确认标签已设置成功：

```bash
kubectl describe node <node-name>
```

在输出的 `Labels` 段里能看到上表中的标签，就说明贴标签成功。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 有卡节点上没有生成标签 | 组件版本偏旧，与当前驱动不兼容 | 升级到 V2.2.0 及以上版本后重新部署 |
| 只有部分节点有标签 | 这些节点上没有卡，或驱动没装好 | 在对应机器上执行 `lsmod \| grep -E "hydcu\|hycu"` 确认驱动已加载 |
| Pod 起不来 | 镜像拉取失败，或部署文件参数不对 | 执行 `kubectl describe pod -n kube-system <dcu-label-node-pod>` 看事件 |

:::warning 驱动升级后重新确认标签
升级宿主机驱动后，节点上的 DCU 信息可能变化。升级完请重新执行一次 `kubectl describe node <node-name>`，
确认标签仍与实际情况一致。
:::
