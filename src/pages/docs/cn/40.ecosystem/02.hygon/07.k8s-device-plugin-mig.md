# DCU-Device-Plugin（MIG 模式）

MIG 模式用于管控**宿主机上已经划分好的 MIG 实例**：宿主机先按硬件方式把一张卡切成若干份，
每一份都作为一个独立的可调度资源暴露给集群，任务直接申请对应规格的实例即可。

MIG 可以理解成**用隔板把一张卡硬隔成几间独立的小房间**：房间之间互不影响，隔离性比软件切分更强。

## 什么情况下必须装

- 需要比软件切分**更强的隔离性**、粒度更细的硬件级切分。
- 前提是宿主机已经开启 MIG 功能，并创建好所需的 MIG 实例（具体划分操作参考海光官方的 Multi-Instance 使用手册）。

不切卡、或采用其他切分路线时，不需要装本组件，见下方对比。

## MIG 和 vDCU 动态切分怎么选

两种方式都能让多个任务共用一张卡，区别在「什么时候切」和「隔离到什么程度」：

| 对比项 | MIG 模式 | vDCU 动态切分 |
| --- | --- | --- |
| 切分方式 | 硬件级切分 | 软件动态切分 |
| 什么时候切 | 提前在宿主机上划好实例 | 提交任务时按申请自动切 |
| 使用前要不要人工准备 | 要，先创建 MIG 实例 | 不用 |
| 隔离性 | 更强 | 一般 |
| 资源名 | `hygon.com/dcu-mig-*` | `hygon.com/dcunum` 等 |
| 适合场景 | 多任务共存、对隔离和稳定性要求高 | 任务规格经常变、想尽量提高利用率 |
| 与另一种能否共存 | 不能 | 不能 |

**怎么选：**

- 任务规格固定、要求强隔离 → 选 **MIG 模式**。
- 任务规格多变、想按需切分并自动回收 → 选 **[vDCU 动态切分模式](/ecosystem/hygon/k8s-vdcu-dynamic-splitting)**。

:::warning 开了 MIG 就没有 vDCU
开启 MIG 功能之后，vDCU 虚拟化功能不可用。同一套环境只能二选一，选之前先确认业务要的是隔离性还是灵活性。
:::

:::info 其他硬件的 MIG 怎么划
NVIDIA 的 MIG 思路相同（硬件级切分、实例间强隔离），但实例划分由 **MIG Manager** 按预设几何方案
（如 `all-1g.10gb`）自动完成，不需要手工划。对照见 [MIG 实例划分](/ecosystem/nvidia/gpu-operator/mig-manager)。
:::

## 开始之前

- 宿主机已开启 MIG 功能，并创建好所需的 MIG 实例。
- 每台有卡的机器已装好驱动，组件镜像已放到集群能拉取的位置。
- 准备好部署文件 `k8s-dcu-plugin-mig.yaml`。

## 操作步骤

### 1. 给节点打上 MIG 模式标签

```bash
kubectl label nodes <node-name> dcu-mode=mig
```

### 2. 部署

```bash
kubectl apply -f k8s-dcu-plugin-mig.yaml
```

## 验证

### 1. 看 Pod

```bash
kubectl get pod -n kube-system -owide | grep dcu-device-plugin-mig
```

每个有卡节点上各有一个 Pod，状态为 `Running`。

### 2. 看节点资源

```bash
kubectl describe node <node-name>
```

在输出的 `Capacity` 字段里看到类似 `hygon.com/dcu-mig-2g-15gb: 1`，就表示节点存在对应规格的 MIG 实例。
规格名由你实际划分的实例决定，以节点上的实际输出为准。

## 怎么申请

申请时把资源名换成节点上实际存在的规格：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: dcu-mig-pytorch-demo
spec:
  containers:
    - name: dcu-mig-pytorch-demo
      image: image.sourcefind.cn:5000/dcu/admin/base/pytorch:2.1.0-ubuntu22.04-dtk24.04.2-py3.10
      command: ["/bin/bash", "-c", "--"]
      args: ["sleep infinity & wait"]
      resources:
        limits:
          hygon.com/dcu-mig-4g-31gb: 1
```

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 节点上没有 MIG 资源 | 宿主机没开启 MIG，或没创建实例 | 在宿主机上确认 MIG 已开启并已划好实例，再重启设备插件 |
| 资源名申请不到 | 资源名与节点上实际规格不一致 | `kubectl describe node <node-name>` 看清 `Capacity` 里真实的规格名 |
| vDCU 相关功能不可用 | 已开启 MIG | 这是正常现象，MIG 与 vDCU 不能共存，二选一 |
