# DCU Kubernetes 组件用户指南

宿主机装好驱动后，机器自己能用卡了，但**集群还不知道有卡**。这一组组件跑在 Kubernetes 上，
负责把卡的信息「登记」进集群、把卡的状态「上报」给监控、把卡注册成可调度的资源。
装齐之后，业务 Pod 才能通过声明资源的方式用上 DCU。

可以把这一组组件理解成卡在集群里的**三件套**：门牌（节点标签）、电表（监控探针）、户口（资源注册）。

:::info 这一组页面怎么分
本目录按组件拆成多页。第一次接入建议从下表的「概述」开始按顺序往下做；
只想补某个组件、或在排查问题时，直接跳到对应页面。
:::

| [DCU-Device-Plugin（MIG 模式）](/ecosystem/hygon/k8s-device-plugin-mig) | 把已划分的 MIG 实例注册成资源 | 宿主机已开启 MIG 并划好实例 | 节点可分配资源里出现 `hygon.com/dcu-mig-*` |

## 为什么必须按这个顺序

1. **先装驱动** —— 后面每个组件都要读驱动接口，驱动没装它们都跑不起来。
2. **再装 DCU-Label-Node** —— 给节点打上 DCU 相关标签；设备插件按标签选择要管理哪些节点。
3. **DCU-Exporter 可先可后** —— 它只做监控采集，不参与资源注册，不影响调度。
4. **最后装 DCU-Device-Plugin** —— 把卡注册进集群。这一步做完，集群才开始「看得见」卡。
5. **需要切分再装 vDCU 相关组件** —— 动态切分要额外装 vDCU-Scheduler，并让设备插件以 HAMi 模式运行。

:::warning 切分方式三选一
标准模式（物理卡 + 预切分 vDCU）、MIG 模式、vDCU 动态切分是三条不同路线，同一套环境不要混用。
开启 MIG 后 vDCU 虚拟化不可用。选哪种见 [MIG 模式](/ecosystem/hygon/k8s-device-plugin-mig) 与
[vDCU 动态切分模式](/ecosystem/hygon/k8s-vdcu-dynamic-splitting) 里的对比。
:::

## 开始之前

- 每台有卡的机器已装好驱动，并且 `lsmod | grep -E "hydcu|hycu"` 能看到驱动模块。
- 集群 Kubernetes 版本满足[概述](/ecosystem/hygon/k8s-overview)里的系统要求。
- 各组件镜像已放到集群能拉取的位置。
- 具备对集群执行 `kubectl apply` 的权限。
