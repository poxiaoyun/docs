# 平台适配现状

平台上「认识一个加速器」要经过几处配置，每处负责一件事。下面把每一处对壁仞的实际状态列出来，省得在界面里找不到某样东西时猜是配置错了还是本来就没有。

## 逐层核对

| 层 | 位置 | 对壁仞的现状 |
| --- | --- | --- |
| 镜像加速器类型 | 镜像登记时的加速器选项 | **没有壁仞**，现有选项是 CUDA / ROCm / CANN / DKT / MACA / CoreX / Musa / Neuware / CPU |
| 模型元数据型号 | 模型卡片可选的加速卡型号 | 没有登记任何壁仞型号 |
| 模型元数据的后端枚举 | 模型元数据里的 `hardware_backends` | 没有，列表是 cpu / cuda / rocm / ascend / mlu / musa / metal |
| 规格的加速卡标签 | 规格标签上写的字样 | 走通用路径，显示 `GPU` |
| 规格的型号名 | 规格名拼接 | 前缀不会被剥掉，平台剥前缀的名单只有 nvidia / amd / intel / huawei 四家 |
| 规格的厂商图标 | 规格标签上的小图标 | 没有 |
| 集群调度组件 | 集群管理 → 运维管理 → 系统应用 | 没有，平台只内置了 NVIDIA 与昇腾两套 |

这份表里没有「配置错了」的可能，七项都是当前的产品状态。

## 现在能做什么

- **按资源名调度**：节点上报 `birentech.com/gpu` 之后，平台的配额、规格、任务申请都能按这个资源名走。
- **切分卡也能排**：先建 `birentech.com/1-2-gpu`、`birentech.com/1-4-gpu` 的规格，平台就能按对应资源名发任务。
- **多卡任务**：节点上报的是标准扩展资源，平台的多卡任务交给 Volcano 正常排队。
- **容器镜像**：壁仞的镜像按通用镜像登记，业务镜像本身带 BIRENSUPA 运行时即可，平台不参与镜像内部。

## 还不能做什么

| 缺的能力 | 影响 | 补法 |
| --- | --- | --- |
| 镜像加速器类型 | 登记镜像时选不到壁仞，筛选和检索里也没有这一类 | 目前无平台侧入口，按通用镜像登记 |
| 模型元数据型号 | 模型卡片里选不到壁砺型号 | 型号不上元数据，不影响实际调度 |
| 后端枚举 | `hardware_backends` 里没有壁仞 | 同上 |
| 规格的型号名 | 规格名不会渲染成 `106M` 这类短名，前缀会保留 | 平台剥前缀的名单不含壁仞，属展示层设计 |
| 规格的厂商图标 | 规格标签上是通用图标，不是壁仞图标 | 属展示层设计，不影响调度 |
| 专属加速卡标签 | 标签显示 `GPU`，不写壁仞 | 属展示层设计，不影响调度 |
| 一键安装集群组件 | 系统应用里没有壁仞，点不出来 | 按 [Kubernetes 组件](/ecosystem/biren/k8s-components) 手工装设备插件 |
| 平台侧监控看板 | 壁仞卡的指标不进平台监控 | 官方 exporter 未公开，暂时没法预置 |

## 手工接入的完整顺序

平台的系统应用里没有壁仞，所有步骤都在集群侧加平台的资源层完成：

1. 每台有卡的机器装驱动，`brsmi` 能列出全部卡，驱动版本 ≥ 1.2.2。
2. 装容器运行时工具链，确认容器里能看到卡；走 CDI 要求 kubelet ≥ 1.28、containerd ≥ 1.7。
3. 集群里装设备插件，给节点打上 `birentech.com=gpu`，确认出现 `birentech.com/gpu`。
4. 需要卡内切分，先在卡上配好 SVI，再确认出现 `birentech.com/1-2-gpu` 或 `birentech.com/1-4-gpu`。
5. 需要按份额切分调度，改用 `Project-HAMi/biren-device-plugin`，节点标签换成 `biren=on`。
6. 回到平台，按资源名建规格与配额，提交一个申请 1 个 `birentech.com/gpu` 的任务验一遍。

第 6 步是唯一需要动平台界面的地方，前五步全在集群侧。
