# Kubernetes 组件

集群侧的主体就是一个设备插件，外加节点标签。监控与切分调度这两块都有缺口，下面如实写清。

## 组件总览

| 组件 | 作用 | 现状 |
| --- | --- | --- |
| 设备插件 `k8s-device-plugin` | 把卡注册成 Kubernetes 资源 | 官方仓库已归档，镜像是 `ghcr.io/birentechnology/k8s-device-plugin:v0.7.1` |
| 节点标签 | 标记节点上有壁仞卡 | 官方插件用 `birentech.com=gpu`，HAMi 路线用 `biren=on` |
| 监控导出器 | 把卡指标暴露给 Prometheus | 官方 exporter 的名称与端口未确认 |
| 卡内切分 | 一张卡切成多个实例 | 用官方 SVI，必须预先在卡上配好 |

## 设备插件仓库与归档状态

仓库地址是 `https://github.com/BirenTechnology/k8s-device-plugin`。这个仓库已经归档：最后一次提交是 2024-10-17，最新的 tag 是 v0.7.3。归档意味着上游不再接收更新，遇到新内核、新容器运行时也不会再修。

现役的分发疑似转到了厂商交付包，第三方资料里出现过交付包内的 `op-adrm-device-plugin` 这个名字。这条只有第三方证据，未在官方核实，装之前先确认手上交付包的实际组件名。

:::warning 归档仓库的镜像只作对照
仓库已归档，`v0.7.1` 这个镜像是社区形态。现役集群用交付包里的哪一版，以交付清单为准。不要把社区示例的镜像和交付包里的组件混着用，两者的节点标签也不一样。
:::

## 上报的资源名

| 资源名 | 含义 |
| --- | --- |
| `birentech.com/gpu` | 整卡 |
| `birentech.com/1-2-gpu` | 切成 2 份后的一份 |
| `birentech.com/1-4-gpu` | 切成 4 份后的一份 |

申请整卡，按张数写数值：

```yaml
resources:
  limits:
    birentech.com/gpu: 1
```

申请切分卡，资源名换成对应后缀：

```yaml
resources:
  limits:
    birentech.com/1-2-gpu: 1
```

节点上还有哪些资源名可以申请，直接看节点的 Allocatable：

```bash
kubectl describe node <NODE_NAME> | grep -A 5 "Allocatable" | grep birentech.com
```

## 节点标签

```bash
kubectl label node <NODE_NAME> birentech.com=gpu
```

HAMi 路线的标签是 `biren=on`，跟官方插件不是一套。按实际装的插件选标签，打错了插件不会把节点认成壁仞节点。

## 监控现状

`brsmi` 是确认存在的命令行工具，但它不是 metrics exporter。它只在节点上提供命令行查询，不暴露 Prometheus 格式的指标。

| 项 | 现状 |
| --- | --- |
| Prometheus exporter 名称 | 官方未公开 |
| 默认端口 | 官方未公开 |
| 命令行工具 | `brsmi`，确认存在，非 exporter |
| 第三方线索 | suDCGM，第三方资料描述为 `br-dcgmd` 服务端加 `br-dcgmi` 客户端，默认端口 8182，未在官方核实 |

结论是：平台监控里暂时没有壁仞卡的指标。要接就得先确认 exporter 的真实来源，找不到就不接，不要按第三方端口去猜一个地址填进 ServiceMonitor。

## SVI 切分

官方把一卡多用叫 **SVI（Secure Virtual Instance）**，BR106 最多支持 4 个独立安全虚拟实例。切分结果对应上报的两个资源名后缀：切 2 份走 `birentech.com/1-2-gpu`，切 4 份走 `birentech.com/1-4-gpu`。

SVI 像影院包厢，得在客人进场前先在卡上隔好。实例必须预先在卡上配置，设备插件只负责按已经配好的实例上报资源，不会在调度时动态创建实例。没有预配 SVI 的节点，只会上报整卡。

第三方 HAMi 路线下的限制更紧：不能指定显存大小，只能按整卡的 2 份或 4 份来切。

## 与 Volcano 的关系

平台的多卡任务交给 Volcano 排，但壁仞没有官方的 Volcano 插件。Volcano 自带的 vGPU 能力只支持 HAMi-core（CUDA 拦截）与 NVIDIA MIG 两种模式，都覆盖不到壁仞。

实际可用的路径是 HAMi：`Project-HAMi/biren-device-plugin`（镜像 `projecthami/biren-device-plugin`）。
HAMi 从 v2.10.0 起才加入壁仞支持，装之前先确认集群里的 HAMi 版本够。这条路线装上后节点标签是 `biren=on`。
它给壁仞的能力勾选里既没有显存隔离也没有算力隔离，所以能排预划好的份额，不能指定显存大小。
资源名与其余厂商的对照见 [HAMi](/ecosystem/hami)。

不引入 HAMi 时，壁仞卡在集群里就是标准扩展资源，Volcano 按资源名和数量排。多卡任务能排，按份额排卡内切分任务不行。

## 装完怎么验证

```bash
# 节点标签打上了
kubectl get nodes -l birentech.com=gpu

# 节点上出现了可分配的资源
kubectl describe node <NODE_NAME> | grep -A 5 "Allocatable" | grep birentech.com

# 设备插件 Pod 起来了
kubectl get pods -A | grep -i biren
```

再交一个最小任务申请 1 个 `birentech.com/gpu`，容器里跑 `brsmi` 能打出卡就算通了。
