# 驱动与容器运行时

宿主机这一层的目标只有一个：让 `brsmi` 能列出全部卡。这一步不过，后面集群侧的设备插件装多少遍都没用。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 驱动版本 | ≥ 1.2.2，这是设备插件仓库给出的最低要求 |
| Kubernetes | ≥ 1.13，集群侧装设备插件时的要求 |
| CDI 方式 | kubelet ≥ 1.28 且 containerd ≥ 1.7，走 CDI 注入容器设备时同时满足 |
| 操作系统与固件 | 官方没有公开支持矩阵，以随卡交付说明为准 |

前两项来自设备插件仓库的说明，属于当前能核实到的硬要求；操作系统与固件配套没有公开清单，别按别的厂商的经验套。

## 装驱动

壁仞的驱动安装命令没有在官方公开文档里核实到，所以这里只写流程，具体命令以开发者社区当前版本的安装说明为准。

1. **确认基线**：在开发者社区查当前驱动版本支持的操作系统、卡型与固件版本，把三者对齐再动手。
2. **在每台有卡的机器上装驱动包**：驱动与固件可能分开交付，按交付包内的顺序执行，不要跳步。
3. **加载内核模块**：装完确认壁仞的设备节点出现，内核模块处于已加载状态。
4. **重启并复验**：驱动安装通常需要重启才完全生效，重启后跑一次 `brsmi`。

:::warning 命令以官方开发者社区为准
上面是流程，不是可以直接粘贴的命令。壁仞的驱动包名、安装脚本与内核模块名会随版本变化，本页不复制别处的命令。动手前打开 `https://developer.birentech.com/` 对一遍当前版本的安装说明。
集群节点还要额外注意内核版本：升级内核后驱动可能需要重编或重装，升内核和升驱动不要放在同一次变更里做。
:::

## 容器运行时工具链

设备插件支持 CDI 方式把设备注入容器，走这条路要求 kubelet ≥ 1.28 且 containerd ≥ 1.7。壁仞的容器运行时工具链名称、包名与配置路径在官方公开资料里没有直接列出，官方未公开，按随卡交付说明做。

节点上要让容器看到卡，通常是两步：先装厂商提供的容器工具链并生成设备规格，再让容器运行时引用这份规格。生成命令与规格文件路径以交付包内的说明为准，不要套用其它厂商的路径。

## 验证

```bash
brsmi
```

`brsmi`（BR-SMI）是确认存在的命令行工具，能列出卡与基本状态。具体子命令与输出字段以官方开发者社区的工具说明为准，本页不列未核实的参数。

驱动就位的判断标准有两条：`brsmi` 能列出全部卡；列出的卡数与装机数量一致。少卡通常不是驱动问题，先查固件与插槽。

## 升级与卸载

升级前先停业务，再停集群侧的设备插件，最后才动驱动。设备插件会周期性读取驱动接口，带着它升驱动容易留下一种状态：插件进程还活着，但上报的卡数不对，只能靠重启插件恢复。

驱动与固件的升级先后顺序以交付包说明为准。壁仞没有公开的卸载命令与包名，卸载按交付说明做，不要手工删内核模块或设备节点，删错了下次装载会失败。
