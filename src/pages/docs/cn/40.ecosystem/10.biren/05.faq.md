# FAQ

## 速查表

| 现象 | 先查什么 | 处置 |
| --- | --- | --- |
| `brsmi` 报找不到卡 | 驱动是否装上、设备节点在不在 | 按开发者社区文档重装驱动，重启后复验 |
| 能列出卡但数量不对 | 固件与插槽 | 按交付说明核对固件版本，少卡先查硬件 |
| 容器里看不到卡 | 容器运行时工具链与 CDI 规格 | 确认 kubelet ≥ 1.28、containerd ≥ 1.7，按交付说明生成设备规格 |
| 节点上没有 `birentech.com/gpu` | 设备插件 Pod 与节点标签 | 确认节点打了 `birentech.com=gpu`，再重启插件 |
| 设备插件 Pod 起不来 | 镜像来源 | 社区仓库已归档，确认交付包里的版本 |
| 申请 `birentech.com/1-2-gpu` 一直 Pending | 卡上是否配好 SVI | SVI 必须预先配好，插件不会动态创建 |
| 想按显存大小切分切不出来 | 走的是哪条切分路线 | 官方 SVI 只按 2 份或 4 份切，HAMi 侧也不能指定显存 |
| 多卡任务排队很久 | 有没有整卡被占住 | 没配 SVI 也没走 HAMi 时，卡按整张排 |
| 平台上看不到壁仞卡的监控指标 | 有没有 exporter | `brsmi` 不是 exporter，官方 exporter 名称与端口未公开 |
| 规格标签显示成 `GPU` 而不是壁仞 | 平台展示逻辑 | 属预期行为，不影响调度 |

## 为什么平台上找不到壁仞的选项

平台当前的加速器名单里没有壁仞：镜像登记的加速器类型、模型元数据的型号与后端枚举、规格的厂商图标，这几处都没有壁仞。这不是配置漏了，是产品当前的覆盖范围。

能用的只有资源层：节点上报什么资源名，平台就按什么资源名建规格、配额和任务。所以壁仞接入的完整工作都在集群侧，平台侧只需要按 `birentech.com/gpu` 这一类资源名建规格。逐项对照见 [平台适配现状](/ecosystem/biren/platform-support)。

## 设备插件仓库归档了还能不能用

能，但要知道后果。`https://github.com/BirenTechnology/k8s-device-plugin` 最后一次提交是 2024-10-17，最新 tag 是 v0.7.3，上游不再维护。归档的仓库不会更新，遇到新内核或新 containerd 版本时不会有修复版本。

现役分发疑似转到厂商交付包，第三方资料里出现过交付包内的 `op-adrm-device-plugin`，这条未在官方核实。现场做法是：按交付清单确认组件名与版本，不要照抄社区示例；社区镜像 `ghcr.io/birentechnology/k8s-device-plugin:v0.7.1` 只作对照。

## 一卡多用怎么切，能不能指定显存

官方的切分叫 SVI（Secure Virtual Instance），BR106 最多支持 4 个独立安全虚拟实例。切分后节点上报的资源名是 `birentech.com/1-2-gpu` 与 `birentech.com/1-4-gpu`，对应切成 2 份和 4 份。

两件事必须先说清：

- SVI 实例要在卡上预先配好，设备插件不会在调度时动态创建。没配的节点只上报整卡，申请切分资源会一直 Pending。
- 第三方 HAMi 路线不能指定显存大小，只能按整卡的 2 份或 4 份切。需要按显存比例精细切分的场景，当前的壁仞路径不支持。

## 壁仞卡在 Volcano 里怎么排

壁仞没有官方的 Volcano 插件，所以分两种情况：

- 不引入 HAMi 时，卡是标准扩展资源，Volcano 按资源名和数量排。多卡任务能正常排队，卡内切分调度没有。
- 要按份额排切分任务，走第三方 HAMi：`Project-HAMi/biren-device-plugin` 配合 HAMi 内置的 biren 设备支持。这条路线的节点标签是 `biren=on`，与官方插件的 `birentech.com=gpu` 不是一套。

Volcano 自带的 vGPU 能力只支持 HAMi-core（CUDA 拦截）与 NVIDIA MIG 两种模式，都不覆盖壁仞，这一点不要按 NVIDIA 的经验套。
