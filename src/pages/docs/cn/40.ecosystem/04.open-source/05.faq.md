# FAQ

这一页把交付和运维时最常遇到的开源组件问题整理成一张表。**先看「现象」找到你的情况，再按「怎么办」里的界面位置或命令排查。**

:::info 两个通用前提
一、平台系统组件通常安装在平台的系统命名空间里，查 Pod 状态可以先用 `kubectl get pods -n rune-system`。
二、所有「安装组件」的操作都需要**平台管理员**权限，入口是**集群管理 → 选择集群 → 运维管理**。
:::

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 系统应用页里找不到某个组件 | 该组件不在此集群的模板范围内，或账号权限不足 | 用平台管理员进入**集群管理 → 运维管理 → 系统应用**，点**创建系统应用**查看可用模板 |
| 创建系统应用后一直没有生效 | 集群缺少安装控制器，或组件正在拉取镜像 | 查 `kubectl get pods -n rune-system`，找到异常的 Pod 后看事件；确认集群已完成平台初始化 |
| 推理服务一直是「更新中」或起不来 | 镜像拉不下来、资源不足、模型文件没准备好、引擎与硬件不匹配 | 打开**推理服务**实例详情看状态；到**集群信息 → 加速卡信息**确认有卡；昇腾用 vLLM Ascend，加密模型用 ENX 版 |
| 日志管理里查不到日志 | 没装日志组件，或查询时间范围不对 | 到**运维管理 → 系统应用**确认日志组件已安装；在**运维管理 → 日志管理**的**全部日志**页签里放宽时间范围 |
| 监控图表没有数据或告警不发 | 监控组件未安装、基础指标缺失、抓取地址不通 | 到**运维管理 → 系统应用**确认监控已安装；查 `kubectl get pods -n rune-system` 中监控相关 Pod 是否就绪 |
| 创建存储卷失败 | 没有可用存储集群、没有默认存储类、容量超出上限 | 到**运维管理 → 存储集群**确认有可用集群；查 `kubectl get sc` 确认存在默认存储类；把容量改小重试 |
| 节点磁盘很快被占满 | 分布式存储的数据堆积、日志或镜像层占用 | 查 `kubectl get pv` 看各存储卷用量；清理不用的存储卷；给存储组件规划更大的磁盘 |
| 任务一直排队、Pod 停在 Pending | 资源不足、队列已满、调度组件异常 | 到**运维管理 → 调度器管理**确认调度器正常；查 `kubectl get pods -A --field-selector=status.phase=Pending` 看具体原因 |
| Pod 会自己重启或被迁移到别的节点 | VPA 应用新建议时会重建 Pod，Descheduler 会迁移热点节点上的 Pod | 到**运维管理 → 系统应用**检查 VPA 和 Descheduler 的配置；不需要时先关闭再观察 |
| 域名访问不通 | 入口网关没装、域名没解析、网关主机名列表里没有该域名 | 到**运维管理 → 系统应用**确认入口网关已安装；在入口网关里把域名加进路由主机名列表，并检查 DNS 解析 |
| 浏览器提示 HTTPS 证书无效 | 证书组件未安装，或证书还没签发完成 | 到**运维管理 → 系统应用**确认证书组件正常；查 `kubectl get certificate -A` 看签发状态 |
| 自动扩缩容没有反应 | 没装扩缩容组件，或 HPA 依赖的自定义指标没接入 | 到**运维管理 → 系统应用**安装 KEDA；需要按业务指标扩缩容时再装 Prometheus Adapter |
| 想让多个任务共用一张 GPU 但用不了 | 没有开启 GPU 虚拟化 | 在调度组件里开启 **GPU 虚拟化**；该能力仅支持 NVIDIA，配置与申请方式见 [Volcano 与 vGPU 切分](/ecosystem/nvidia/volcano-vgpu)，昇腾按整卡或设备插件方案使用 |

## 还是解决不了

- 先确认问题出在**哪个组件**：对照[开源组件总表](/ecosystem/open-source)，看这个能力由谁提供。
- 再确认组件**是否已安装、是否就绪**：入口都在**集群管理 → 运维管理**下的**系统应用**、**存储集群**、**调度器管理**、**日志管理**。
- 装好了但行为不对，回到对应分类页看该组件的「什么时候需要关注它」。
