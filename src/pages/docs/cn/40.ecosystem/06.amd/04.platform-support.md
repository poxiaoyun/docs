# 平台适配现状

平台上「认识一张卡」要经过四处代码，每处负责一件事。这一页把这四处对 AMD 的实际状态逐个列出来，
省得在界面里找不到某样东西时猜是配置错了还是本来就没有。

## 逐层核对

| 层 | 位置 | 对 AMD 的现状 |
| --- | --- | --- |
| 镜像加速器类型 | 镜像登记时的「框架 / 加速器」选项 | **已登记**：`ROCm(AMD)` |
| 模型元数据型号 | 模型卡片可选的加速卡型号 | **已登记**：MI210 / MI250 / MI250X / MI300A / MI300X / MI325X / MI350X / MI355X 共 8 个 |
| 规格里的型号名 | 由资源名与型号拼出的规格名 | **已支持**：型号名以 `amd` 开头时前缀会被去掉，`amd-mi300x` 显示成 `MI300X` |
| 规格里的厂商图标 | 规格标签上的小图标 | **已支持**：映射到 AMD 图标 |
| 规格里的加速卡标签 | 标签上写 GPU / NPU / DCU 字样 | **走通用路径**：没有 AMD 专属标签，显示成 `GPU` |
| 规格的「厂商」下拉 | 新建规格时选厂商 | **已登记**：下拉里有 `AMD` |
| 集群调度组件 | 集群管理 → 运维管理 → 系统应用 | **没有**：平台只内置了 NVIDIA 与昇腾两套 |

## 现在能做什么

- **镜像元数据**：上传或登记镜像时标注成 ROCm，检索和筛选能用上。
- **模型元数据**：模型卡片里选具体的 MI 型号，跟其他厂商的型号排在一起。
- **资源规格**：按 AMD 节点上报的资源名建规格，规格名会渲染成 `MI300X*1 . 8CPU . 64Gi` 这种形式，并带上 AMD 图标。
- **算力调度**：只要节点上装好了 AMD 的设备插件并上报 `amd.com/gpu`，平台侧的配额、规格、任务申请都能按这个资源名走。

## 还不能做什么

| 缺的能力 | 影响 | 补法 |
| --- | --- | --- |
| 一键安装集群组件 | 不能在系统应用里点一下装好 | 按 [Kubernetes 组件](/ecosystem/amd/k8s-components) 手工装官方 GPU Operator |
| 专属加速卡标签 | 规格标签显示通用 `GPU`，不写 `AMD` | 属平台展示层设计，不影响调度 |
| 分区切分模板 | 平台只有华为 NPU 的分片模板，没有 GPU 的分区模板 | 分区由 GPU Operator 的 DCM 下发，不经平台 |
| 平台侧监控看板预置 | GPU 指标要自己接 Prometheus | 建 ServiceMonitor 抓 5000 端口 |

## 手工接入的完整顺序

平台的系统应用里没有 AMD，所以四步都在集群外完成：

1. 每台有卡的机器装 `amdgpu` 驱动与 ROCm，`rocminfo` 出卡。
2. 同一批机器装 `amd-container-toolkit`，集群是 containerd 就走 CDI 生成设备规格。
3. 集群里用官方 Helm chart 装 AMD GPU Operator，确认节点出现 `amd.com/gpu`。
4. 回到平台，按该资源名建资源规格与配额，然后提交一个申请 1 张卡的任务验一遍。

第 4 步是唯一需要动平台界面的地方，前三步都在集群侧。
