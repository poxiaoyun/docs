# 驱动与容器运行时

这一页只管宿主机这一层，不涉及 Kubernetes。集群侧的组件在
[Kubernetes 组件](/ecosystem/amd/k8s-components) 里讲。

装完的标志有两个：`rocminfo` 能列出卡、`amd-smi` 能报出驱动与 ROCm 版本。
这两条不过，后面所有集群组件都白装。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 操作系统 | 与目标 ROCm 版本配套的发行版，常见是 Ubuntu 22.04 / 24.04 / 26.04、RHEL 或 CentOS 9、SLES |
| 内核驱动 | `amdgpu`。Instinct 的驱动安装与 Radeon 不是同一份文档，按 Instinct 数据中心文档做 |
| 附加库 | 部分 ROCm 工具依赖 `libatomic1`、`libquadmath0` |

```bash
sudo apt install libatomic1 libquadmath0
```

## 设备权限

默认只有 `video` 与 `render` 两个组的成员能访问 GPU 设备节点。跑业务和跑容器的账号都得加进去：

```bash
sudo usermod -a -G render,video $LOGNAME
```

不想按组管理，也可以直接用 udev 规则放开：

```bash
sudo tee /etc/udev/rules.d/70-amdgpu.rules << EOF
KERNEL=="kfd", GROUP="render", MODE="0666"
SUBSYSTEM=="drm", KERNEL=="renderD*", GROUP="render", MODE="0666"
EOF

sudo udevadm control --reload-rules
sudo udevadm trigger
```

两条路选一条。改完权限要重启才生效；**权限没配好时，症状是 `rocminfo` 能跑但报找不到设备**，
很容易被当成驱动没装上。

## 装 ROCm

以 Ubuntu 上走 apt 为例，先注册仓库再装元包：

```bash
sudo mkdir --parents --mode=0755 /etc/apt/keyrings
wget https://stable.repo.amd.com/rocm/gpg/packages.gpg -O - | \
    gpg --dearmor | sudo tee /etc/apt/keyrings/amdrocm.gpg > /dev/null

sudo tee /etc/apt/sources.list.d/amdrocm-stable.sources << EOF
X-Repo-Id: amdrocm-stable
Types: deb
URIs: https://stable.repo.amd.com/rocm/core/packages/ubuntu2604/
Suites: stable
Components: main
Architectures: amd64
Signed-By: /etc/apt/keyrings/amdrocm.gpg
Enabled: yes
EOF

sudo apt update
sudo apt install amdrocm10.0
```

仓库地址里的 `ubuntu2604` 是发行版代号，换系统要换这一段。

ROCm 按用途拆了若干元包，装哪个看你要干什么：

| 元包 | 用途 | 内容 |
| --- | --- | --- |
| `amdrocm<版本>` | 只跑应用 | 运行时、库、系统监控工具 |
| `amdrocm-core-dev<版本>` | 要自己编应用 | 上一个再加上编译器、头文件、CMake 配置 |
| `amdrocm-developer-tools<版本>` | 要做性能剖析 | 剖析器与相关工具 |
| `amdrocm-opencl<版本>` | 跑 OpenCL 应用 | OpenCL 相关组件 |
| `amdrocm-core-sdk<版本>` | 全都要 | 完整 SDK |

:::warning 命令以官方安装指南为准
ROCm 的包名带版本号（`amdrocm10.0`），换版本要换包名；仓库路径也随发行版变化。
上面这些命令用来理解流程，动手前先对着官方 Install on Linux 页面把包名和仓库地址换成当前的。
:::

## 验证驱动

```bash
rocminfo
```

看到 `ROCk module version ... is loaded` 以及 HSA Agents 里列出卡，驱动就算就位。

```bash
amd-smi version
```

这一条会同时打印 `AMDSMI Tool`、`ROCm version` 与 `amdgpu version` 三行，**排障时把这三行留着**，
报问题时对方第一句就会问驱动版本。

## 容器运行时工具链

集群里的业务都跑在容器里，宿主机认到卡还不够，得让容器也能拿到设备。AMD 这层叫
**AMD Container Toolkit**，装完会有两个东西：`amd-container-runtime`（一个 OCI 运行时）和
`amd-ctk`（配置用的命令行）。

```bash
sudo apt update && sudo apt install -y wget gnupg2
wget https://repo.radeon.com/rocm/rocm.gpg.key -O - | gpg --dearmor | sudo tee /etc/apt/keyrings/rocm.gpg > /dev/null
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/rocm.gpg] https://repo.radeon.com/amd-container-toolkit/apt/ $(. /etc/os-release && echo $VERSION_CODENAME) main" | sudo tee /etc/apt/sources.list.d/amd-container-toolkit.list
sudo apt update && sudo apt install amd-container-toolkit
```

装完有两条配置路线，**按集群用的容器运行时选，选错了容器里看不到卡**：

| 路线 | 配置方式 | 适用容器运行时 |
| --- | --- | --- |
| CDI | `amd-ctk cdi generate` 生成设备规格，运行时自己读 | Docker、Podman、containerd 都可以 |
| AMD 运行时 | `amd-ctk runtime configure` 注册 `--runtime=amd` | **仅 Docker** |

平台的集群跑的是 containerd，**走 CDI 这条**：

```bash
sudo amd-ctk cdi generate --output=/etc/cdi/amd.json
sudo amd-ctk cdi validate --path=/etc/cdi/amd.json
```

Docker 环境则是注册运行时并重启：

```bash
sudo amd-ctk runtime configure --runtime=docker --set-as-default
sudo systemctl restart docker
```

## 验证容器里能看到卡

```bash
docker run --rm --device amd.com/gpu=all rocm/rocm-terminal rocm-smi
```

容器里打出显卡列表就说明这一层通了。想按序号挑卡，先列出来再指定：

```bash
amd-ctk gpu list
docker run --rm --device amd.com/gpu=0 rocm/rocm-terminal rocm-smi
```

:::info 容器工具链的环境要求
AMD Container Toolkit 官方要求 Ubuntu 22.04 / 24.04 / 26.04 或 RHEL/CentOS 9，
Docker 25 及以上；`amd-ctk runtime configure` 需要用 root 或 sudo 执行。
Linux 上的 Docker Desktop 不在支持范围内。
:::

## 卸载与升级

```bash
sudo apt autoremove amdrocm10.0
sudo rm -f /etc/apt/sources.list.d/amdrocm-stable.sources
```

升级前先停业务，并把集群侧的设备插件一并停掉再动驱动。设备插件会周期性读驱动接口，
带着它升驱动容易留下一个「插件在跑但上报的设备数不对」的状态。
