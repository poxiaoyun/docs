# FAQ

## 速查表

| 现象 | 先查什么 | 处置 |
| --- | --- | --- |
| `ixsmi` 报找不到设备 | CoreX SDK 装完没有、内核模块加载没有 | 按官方手册重装，确认落到 `/usr/local/corex` |
| 宿主机能看到卡，容器里看不到 | ix-Container-Toolkit 装没装、runtime 注册没有 | 按官方仓库配置，确认注册名是 `iluvatar` |
| 节点上没有 `iluvatar.com/gpu` | 设备插件 Pod 状态与 `ix-config` 里的 `resourceName` | 先确认宿主机与容器工具链都好，再重启插件 |
| 老节点上报的是 `iluvatar.ai/gpu` | SDK 版本 | SDK 大于 3.4 要换成 `iluvatar.com`，规格与配额一起改 |
| 申请 vGPU 资源报资源名不存在 | 节点上实际上报的是哪个资源名 | 按节点上报的名字写，别按 `vcuda-*` 那套老口径 |
| 节点上多出一批 iluvatar.ai 资源名 | 有没有开切分或时间片 | 按实际要用的那套资源名建规格，不要混用 |
| 多卡任务在 Volcano 里排不上 | Volcano 版本与设备插件的开关 | Volcano 要 1.7.0 / 1.9.0 / 1.11.0，设备插件设 `usevolcano=true` |
| 监控里看不到卡的指标 | ix-exporter 在不在、端口对不对 | 抓 32021 的 `/metrics`，别按 9400 写 |
| 规格标签显示 `GPU` 不显示天数智芯 | 平台展示逻辑 | 属预期行为，不影响调度 |
| 模型卡片里选不到天数型号 | 平台元数据里有没有登记 | 目前没有登记，见平台适配现状 |

## 为什么资源名有两个域名

天数智芯在 Kubernetes 上用的是两套资源名，域名不一样，用途也不一样：

| 用途 | 资源名 |
| --- | --- |
| 整卡 | `iluvatar.com/gpu` |
| 切分 | `iluvatar.ai/<卡型>-vgpu`、`iluvatar.ai/<卡型>.vCore`、`iluvatar.ai/<卡型>.vMem` |

整卡那套是官方现在的口径，早期写作 `iluvatar.ai/gpu`，已废弃；
切分那套仍然用 `iluvatar.ai` 这个域名。**看到 `iluvatar.ai` 开头的资源名先分清是哪一套**，
它可能是切分份额，也可能是老集群没换过来的整卡口径。

## vGPU 的资源名到底该写哪个

切分路径下的名字有三项，都在 `iluvatar.ai` 下面：`iluvatar.ai/<卡型>-vgpu`（卡数）、
`iluvatar.ai/<卡型>.vCore`（算力，1 个单位 1%）、`iluvatar.ai/<卡型>.vMem`（显存，1 个单位 256MB）。
[HAMi 的官方文档](https://project-hami.io/docs/userguide/device-supported)给天数智芯列的就是这一套，
卡型写作 MR-V100、MR-V50、BI-V150、BI-V100；这套名字怎么申请见 [HAMi](/ecosystem/hami/device-matrix)。
厂商侧的 vGPU 文档另有一份支持的型号清单。

另外还有 `iluvatar.ai/vgpu`、`iluvatar.ai/vcuda-core`、`iluvatar.ai/vcuda-memory` 这几个名字在流传，
来自更早的口径。它们和上面那套不是一回事，混用会申请不到资源。

同一个 `iluvatar.ai` 域名下并存多套叫法，判断方法是看节点实际上报了什么：

```bash
kubectl get node <gpu-node> -o jsonpath='{.status.allocatable}' | tr ',' '\n' | grep iluvatar
```

节点上出现的那个名字才是这个集群认的名字。

## 容器里看不到卡怎么办

先确认宿主机这一层是好的，`ixsmi` 在宿主上能出卡；宿主机都不行就先修驱动，不用看容器。
宿主机没问题时，问题在容器运行时工具链上：

- **ix-Container-Toolkit 装了没有**：装完才有 `ix-ctk`。
- **runtime 注册了没有**：注册进去的名字是 `iluvatar`，配置完要重启容器运行时。
- **重启生效了没有**：改运行时配置不重启进程不生效。

集群里跑 Pod 时由设备插件注入设备，不需要在容器启动参数里手工指定设备路径，
所以 Pod 里看不到卡时，也要顺便确认这个 Pod 有没有申请 `iluvatar.com/gpu`。

## 设备插件和 Operator 装哪个

看你要不要省事。只装 ix-device-plugin 能跑起来，但要自己再装一遍 ix-exporter；
装 ix-GPU-Operator 会由它自动创建并管理这两个组件，升级和状态巡检都在一处。

选 Operator 的话注意它的 Helm chart 是否存在还没核实过，装之前先看仓库 README 确认安装方式。
两种方式上报的资源名都由 `ix-config` 的 `resourceName` 决定，这一点不变。
