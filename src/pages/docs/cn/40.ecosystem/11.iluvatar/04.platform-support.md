# 平台适配现状

平台上「认识一张卡」要经过几处代码，每处负责一件事。这一页把这几处对天数智芯的实际状态逐个列出来，
省得在界面里找不到某样东西时猜是配置错了还是本来就没有。

## 逐层核对

| 层 | 位置 | 对本厂商的现状 |
| --- | --- | --- |
| 镜像加速器类型 | 镜像登记时的加速器选项 | **已登记**：`CoreX(天数智芯)` |
| 模型元数据型号 | 模型卡片可选的加速卡型号 | **没有登记任何天数型号** |
| 模型元数据的后端枚举 | 模型元数据里的 `hardware_backends` | **没有**：列表是 cpu / cuda / rocm / ascend / mlu / musa / metal |
| 规格的加速卡标签 | 规格标签上写的字样 | **走通用路径**：显示 `GPU`，没有专属标签 |
| 规格的型号名 | 规格名拼接 | **前缀不会被剥掉**：平台剥前缀的名单只有 nvidia / amd / intel / huawei 四家 |
| 规格的厂商图标 | 规格标签上的小图标 | **没有**：天数智芯没有专属图标 |
| 集群调度组件 | 集群管理 → 运维管理 → 系统应用 | **没有**：平台只内置了 NVIDIA 与昇腾两套 |

## 现在能做什么

- **镜像元数据**：登记镜像时加速器可以选到 `CoreX(天数智芯)`，检索和筛选能用上。
- **资源规格**：按节点上报的 `iluvatar.com/gpu` 建规格与配额，平台侧的调度按这个资源名走。
- **算力调度**：节点上装好设备插件之后，多卡任务的申请与排队和别家硬件走同一套流程。

## 还不能做什么

| 缺的能力 | 影响 | 补法 |
| --- | --- | --- |
| 模型元数据里没有天数型号 | 模型卡片里选不到 BI-V100、MR-V100 这些型号 | 属平台元数据维护范围，目前只能先不填型号 |
| 没有对应后端枚举 | 模型元数据无法标出「跑在 CoreX 上」 | 暂无平台侧补法，先记在模型说明里 |
| 规格标签不显示厂商 | 标签上写通用 `GPU`，不写天数智芯 | 属展示层设计，不影响调度 |
| 规格名不剥前缀 | 型号前缀会原样留在规格名里 | 想让规格名干净只能手工命名 |
| 没有厂商图标 | 规格标签上没有小图标 | 平台资产未包含该图标 |
| 没有一键安装的集群组件 | 系统应用里只有 NVIDIA 与昇腾两套 | 按下方顺序手工装官方组件 |

## 手工接入的完整顺序

平台的系统应用里没有天数智芯，所以集群侧的步骤都在平台外完成：

1. 每台有卡的机器装 CoreX SDK，`ixsmi` 能出卡，安装目录默认在 `/usr/local/corex`。
2. 同一批机器装 ix-Container-Toolkit，把 runtime 注册成 `iluvatar`。
3. 集群里装 ix-device-plugin，或者装 ix-GPU-Operator 让它代管设备插件与监控导出器。
4. 确认节点上出现 `iluvatar.com/gpu`；需要指标就再确认 ix-exporter 在跑，端口 32021。
5. 要用卡内切分就装 vGPU 相关组件，按 `iluvatar.ai/<卡型>.vCore` 这一套建规格。
6. 回到平台，按资源名建资源规格与配额，然后提交一个申请 1 张卡的任务验一遍。

只有第 6 步在平台界面上操作，前五步都在集群侧。第 4 步的资源和第 6 步的规格名对不上，
是这一串流程里最常见的返工点。
