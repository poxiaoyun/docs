# 驱动与容器运行时

这一页只管宿主机这一层，不涉及 Kubernetes。集群侧的组件在
[Kubernetes 组件](/ecosystem/iluvatar/k8s-components) 里讲。

装完的标志是 `ixsmi` 能列出卡。这一条不过，后面所有集群组件都白装。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 操作系统 | 服务器发行版，支持列表以官方文档中心当前版本为准 |
| 硬件 | 机器上插着卡，`lspci` 能看到天数智芯的设备 |
| 权限 | root 或 sudo，装驱动要重新加载内核模块 |
| 安装介质 | CoreX SDK 安装包，按系统版本从官方文档中心取 |
| 可选依赖 | 编译型业务镜像需要与 SDK 配套的编译器工具链 |

## 装 CoreX SDK

官方把这一整套叫「天数智算软件栈」，英文写作 CoreX SDK，**默认安装到 `/usr/local/corex`**。
驱动、函数库、编译器和命令行工具都在里面，装一次就够。

流程是这四步：

1. 到官方文档中心按服务器操作系统取对应版本的安装包。
2. 停掉机器上正在用卡的业务，避免驱动更新时有进程占着设备。
3. 按官方安装说明执行安装，安装目录保持默认的 `/usr/local/corex`。
4. 让 SDK 的工具进入 PATH，或者直接用绝对路径调用。

:::warning 命令以官方当前版本为准
安装包名、安装参数、以及各工具在 `/usr/local/corex` 下的确切路径都随 SDK 版本变化。
上面几步用来理清流程，动手前对着官方文档中心当前的安装手册把命令抄准，不要照搬别处的示例。
:::

## 装容器运行时工具链

宿主机认到卡还不够，业务跑在容器里，得让容器也能拿到设备。这一层叫 **ix-Container-Toolkit**，
仓库在 `https://github.com/Deep-Spark/ix-container-toolkit`，装完会有两个东西：
配置用的命令行 `ix-ctk`，以及注册进容器运行时的 runtime。

配置步骤：

1. 按仓库 README 的说明获取并安装 ix-Container-Toolkit。
2. 用 `ix-ctk` 把 runtime 注册到节点上实际使用的容器运行时（平台的集群节点一般是 containerd）。
3. 重启容器运行时进程让配置生效。

:::info runtime 名固定是 iluvatar
不论节点上用的是 containerd 还是 Docker，注册进去的 runtime 名都是 `iluvatar`。
写 RuntimeClass 或排查配置时按这个名字找，不要按工具名去找 `ix-ctk`。
:::

重启容器运行时会连带重启节点上的所有容器，**确认节点可以停业务**，或者放到维护窗口做。

## 验证

宿主机这一层：

```bash
ixsmi
```

输出里能看到卡型号、显存容量和当前利用率，驱动就算就位。报不出设备时先回头确认 SDK 装完没有、
内核模块加载了没有，别急着怀疑卡。

随 SDK 装的命令行工具是 `ixSMI`、`ixPROF`、`ixKN`、`ixSYS`、`ixGDB`。
`ixSMI` 是日常最常用的设备查看工具，作用和 NVIDIA 那边的 `nvidia-smi` 对应；
其余几个工具的用法以官方文档中心对应手册为准。

容器这一层：

用一个带 CoreX SDK 的业务镜像起容器，容器内执行 `ixsmi`。能打出和宿主机一致的卡列表，
说明容器运行时这一层通了。在集群里跑的时候由设备插件注入设备，
不需要在容器启动参数里手工指定设备路径。

## 升级与卸载

升 SDK 之前先停业务，再停集群侧的设备插件与监控导出器。设备插件会周期性读驱动接口，
带着它升容易留下「插件在跑但上报的设备数不对」的状态，只能靠重启插件恢复。

卸载按官方手册执行，卸完确认 `/usr/local/corex` 已经清空，再装新版本，
避免新旧两版的库文件混在同一个目录里。换大版本时不要跳过确认这一步。
