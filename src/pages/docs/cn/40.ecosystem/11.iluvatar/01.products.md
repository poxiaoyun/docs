# 产品与软件栈

## 产品线

数据中心这一条分两支：训练卡叫天垓，推型号以 `BI` 开头；推理卡叫智铠，型号以 `MR` 开头。
中文产品名和型号名是两套写法，看模型规格时认型号名即可。

| 产品线 | 中文名 | 型号 | 关键规格 | 定位 |
| --- | --- | --- | --- | --- |
| 天垓 | 天垓 100 | BI-V100 | 32 GB HBM2，250 W | 训练卡 |
| 智铠 | 智铠 100 | MR-V100 | 官方一手页未取到 | 推理卡 |

官方 Kubernetes vGPU 文档另外声明支持一批型号，比上面两条产品线能覆盖的范围宽：

| 型号 | 在 vGPU 文档里的状态 |
| --- | --- |
| BI-V100 | 已声明支持 |
| BI-V150S | 已声明支持 |
| BI-V150 | 已声明支持 |
| MR-V100 | 已声明支持 |
| MR-V100-DUO | 已声明支持 |

:::warning 没核实到的型号不要按上面的规律推
MR-V50 与天垓 150 / 200 / 300 在官网一手产品页上没取到，规格与支持状态**未确认**。
选型时不要从型号编号去推代际关系和参数，以官方文档中心当前的产品页为准。
:::

## 软件栈分四层

官方把整栈统称「天数智算软件栈」，英文写作 CoreX SDK，默认装在 `/usr/local/corex`。
装的时候要分清下面四层，缺哪层后面的都跑不起来：

| 层 | 组件 | 装在哪 | 作用 |
| --- | --- | --- | --- |
| 内核驱动 | CoreX 驱动 | 宿主机 | 让操作系统认识卡，为上层提供设备节点 |
| 运行库与工具 | CoreX SDK 主体，命令行为 `ixSMI`、`ixPROF`、`ixKN`、`ixSYS`、`ixGDB` | 宿主机 | 设备管理、性能剖析、系统信息与调试 |
| 编译与算子 | 编译器与函数库 | 宿主机或业务镜像 | 业务镜像编译与运行依赖 |
| 容器与框架 | ix-Container-Toolkit，加上推理与算子库 | 宿主机 + 业务镜像 | 让容器拿到卡，让框架跑在 CoreX 上 |

算子与推理库常见的名字有 ixDNN、ixBLAS、ixCCL、ixRT、IGIE、IxFormer、ixTE。
这组名字多来自第三方整理，官方只有部分能在一手文档里对上，**引用前先在官方文档中心确认拼写与版本**，
不要直接写进交付文档。

## 资源名口径变更

这条跟产品无关，但配错就调度不到卡。设备插件上报的资源名早期写作 `iluvatar.ai/gpu`，
现在的官方口径是 `iluvatar.com/gpu`。

:::warning SDK 大于 3.4 必须换成 iluvatar.com
旧写法目前仍然有效，但官方已经把它标为废弃，并注明 SDK 版本大于 3.4 时必须改成 `iluvatar.com`。
升 SDK 时规格、配额、任务模板里的资源名要一起换，只改一处会出现「配额有、任务申请不到」的情况。
:::

注意这跟 vGPU 那套资源名不是同一个域名，两套名字的区别在
[Kubernetes 组件](/ecosystem/iluvatar/k8s-components) 里展开。

## 官方入口

| 要查什么 | 去哪 |
| --- | --- |
| 公司与产品 | `https://www.iluvatar.com/` |
| 安装手册与用户文档 | `https://support.iluvatar.com/` |
| 按问题检索的条目 | `https://ixkb.iluvatar.com.cn:9443/` |
| 开发者社区 | `https://www.deepspark.org.cn/` |
| 开源组件仓库 | `https://github.com/Deep-Spark` |

:::tip 文档中心和知识库都要搜
文档中心放的是正式发布的安装手册与用户文档，知识库适合按关键词找具体条目，
型号支持范围、资源名写法、vGPU 切分这类细节往往只出现在其中一处。两处都搜一遍再下结论。
:::
