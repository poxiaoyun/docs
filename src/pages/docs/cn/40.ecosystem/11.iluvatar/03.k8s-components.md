# Kubernetes 组件

集群侧要装的东西不多：一个设备插件加一个监控导出器，就能把卡用起来、看得见。
想省事就用官方 Operator 把这两件一起托管。

| 组件 | 形态 | 作用 | 来源 |
| --- | --- | --- | --- |
| ix-device-plugin | DaemonSet，名字叫 `iluvatar-device-plugin` | 把卡注册成 Kubernetes 扩展资源 | `https://github.com/Deep-Spark/ix-device-plugin`（Apache-2.0） |
| ix-config | ConfigMap | 设备插件的配置，上报的资源名就在里面的 `resourceName` 字段 | 随设备插件 |
| ix-exporter | 指标导出器 | 暴露卡的利用率与显存指标 | `https://github.com/Deep-Spark` |
| ix-GPU-Operator | Operator，用 kubebuilder 写的 | 自动创建并管理 ix-exporter 与 ix-device-plugin | `https://github.com/Deep-Spark/ix-GPU-Operator` |
| ix-volcano-plugin | Volcano 调度插件 | 让 Volcano 认识 vGPU 那套资源 | `https://github.com/Deep-Spark/ix-volcano-plugin` |

## 安装方式

| 方式 | 说明 |
| --- | --- |
| 设备插件自带 chart | ix-device-plugin 仓库自带 Helm chart，装完就有 DaemonSet 与 ConfigMap |
| `iluvatar-vgpu-manager-3.0.8.tgz` | vGPU 管理组件，装到 `iluvatar-vgpu` 命名空间，要求 Helm ≥ 3.2.0、Kubernetes ≥ 1.20 |
| ix-GPU-Operator | 装它就会连带把 ix-exporter 与 ix-device-plugin 创建出来 |
| Operator 自带的 chart | **未确认**：ix-gpu-operator 仓库有没有自己发布 Helm chart 没核实过，装之前先看仓库 README |

## 设备插件上报的资源名

默认上报一个整卡资源：

```
iluvatar.com/gpu
```

申请几张卡就写几：

```yaml
resources:
  limits:
    iluvatar.com/gpu: 1
```

资源名不是写死在镜像里的，由 ConfigMap `ix-config` 的 `resourceName` 字段控制。
改这个字段等于改全集群的资源名口径，规格与配额必须同步改。

:::warning 旧口径 iluvatar.ai/gpu 已废弃
`iluvatar.ai/gpu` 目前仍然有效，但官方已标为废弃，并注明 SDK 版本大于 3.4 时必须改成 `iluvatar.com`。
存量集群升 SDK 时，把规格、配额、任务模板里的资源名一起换，只改一处会出现「配额有、任务申请不到」。
:::

节点上的标签有这三个：

| 标签 | 含义 |
| --- | --- |
| `iluvatar.com/gpu.present` | 节点上有没有卡 |
| `iluvatar.com/gpu.memory` | 卡的显存容量 |
| `iluvatar.com/gpu.product` | 卡型 |

标签的取值格式以官方文档为准，**不要手工改这几个标签**，插件下一轮上报会覆盖掉。

## 监控

指标由 **ix-exporter** 提供。名字里没有 iluvatar，找镜像和 Pod 时不要搜 `iluvatar-exporter`。

| 项 | 值 |
| --- | --- |
| 监听端口 | 32021 |
| 指标路径 | `/metrics` |
| 常见指标名 | `ix_gpu_utilization`、`ix_mem_*` 前缀的一组 |

采集侧另外还有 go-ixDCGM 与 go-ixml 两个组件。

:::info 端口和别家不一样
NVIDIA 的 DCGM Exporter 用 9400，天数智芯这里是 32021。做统一监控看板时不要套同一个端口模板，
否则抓到的是空数据。
:::

## vGPU 切分与两套资源名

一卡多用官方叫 **vGPU（iluvatar VGPU）**，算力最小可以切到 1%，显存最小 256MB。
切出来的份额不是用整卡那个资源名申请的，走的是另一套：

| 用途 | 资源名 | 例子 |
| --- | --- | --- |
| 整卡 | `iluvatar.com/gpu` | 申请 1 张卡就写 `1` |
| 切分卡数 | `iluvatar.ai/<卡型>-vgpu` | `iluvatar.ai/BI-V150-vgpu: 1` |
| 切分算力 | `iluvatar.ai/<卡型>.vCore` | `iluvatar.ai/BI-V150.vCore: 50` |
| 切分显存 | `iluvatar.ai/<卡型>.vMem` | `iluvatar.ai/BI-V150.vMem: 64` |

`.vCore` 一个单位是 1% 算力，`.vMem` 一个单位是 256MB，不写显存时默认用满。卡型写作
`MR-V100`、`MR-V50`、`BI-V150`、`BI-V100`。申请多张卡时算力会按卡数自动折算。

整卡那套资源名的域名是 `iluvatar.com`，切分那套是 `iluvatar.ai`。同一家厂商两套门牌号，
背一条规则就够：**带 `iluvatar.com` 的是整卡，带 `iluvatar.ai` 的是切分**。

设备插件侧跟切分相关的配置有两个：`flags.splitboard` 与 `sharing.timeSlicing.replicas`。

:::warning iluvatar.ai 这个域名下有好几套名字，抄之前先看节点
HAMi 的[官方文档](https://project-hami.io/docs/userguide/device-supported)给天数智芯列的就是上面这套
`<卡型>-vgpu`、`<卡型>.vCore`、`<卡型>.vMem`。这套名字怎么用见 [HAMi](/ecosystem/hami/device-matrix)。
网上还流传 `iluvatar.ai/vgpu`、
`iluvatar.ai/vcuda-core`、`iluvatar.ai/vcuda-memory` 这几个名字，来自更早的口径。
同一个 `iluvatar.ai` 域名下同时存在多套叫法，**建规格前先看一眼节点上实际上报了什么**：

```bash
kubectl get node <gpu-node> -o jsonpath='{.status.allocatable}' | tr ',' '\n' | grep iluvatar
```

不要按任何一份文档直接抄进去。
:::

## 和 Volcano 的关系

天数智芯**有官方的 Volcano 插件**，仓库在 `https://github.com/Deep-Spark/ix-volcano-plugin`。
这一点和 AMD 那边不同，AMD 只能走通用扩展资源路径。

| 项 | 要求 |
| --- | --- |
| Volcano 版本 | 1.7.0 / 1.9.0 / 1.11.0 |
| 设备插件配置 | 需要设置 `usevolcano=true` |

版本对不上插件不生效。装之前先在集群里确认 Volcano 的实际版本，再把设备插件的开关打开，
顺序反了会出现插件起来了但资源不参与调度的情况。

## 装完怎么验证

```bash
# 节点上出现了可分配的天数智芯资源
kubectl describe node <gpu-node> | grep -A 5 "Allocatable" | grep iluvatar

# 设备插件 DaemonSet 起来了
kubectl get ds -A | grep iluvatar-device-plugin

# 上报的资源名到底写的是哪个
kubectl get cm ix-config -n <namespace> -o yaml | grep -i resourceName

# 开了切分才会有的那批资源名
kubectl get node <gpu-node> -o jsonpath='{.status.allocatable}' | tr ',' '\n' | grep iluvatar.ai

# 监控服务在不在
kubectl get svc -A | grep -i ix-exporter
```

再交一个最小任务，申请 1 张 `iluvatar.com/gpu`，容器里 `ixsmi` 能打出卡就算通了。
