# FAQ

## 速查表

| 现象 | 先查什么 | 处置 |
| --- | --- | --- |
| `mthreads-gmi` 提示找不到命令 | 驱动包装没装 | 装 `sgpu-dkms`，装完确认内核模块 `mtgpu` 已加载 |
| `mthreads-gmi` 跑得起来但列不出卡 | 内核模块与设备节点 | 按官方文档核对内核版本，重装驱动 |
| 宿主机能看到卡，容器里看不到 | 节点上的容器工具链 | 看 `mt-container-toolkit-daemonset` 的状态与日志 |
| 节点上没有 `mthreads.com/gpu` | `mt-device-plugin` 起没起 | 先确认驱动与容器工具链都好，再重启插件 |
| 想装集群组件但找不到下载地址 | 组件是否开源 | 组件不开源，向厂商获取 KUAE 云原生套件里的包 |
| 申请 sGPU 资源一直不满足 | 调度器与 webhook 的开关 | 启用 GPU scheduler 与 webhook，对应 `mt-gpushare-scheduler` 与 `mt-gpu-webhook` |
| 平台监控里看不到卡的指标 | 采集组件装没装 | 装 `mt-dcgm` 与 `mt-dcgm-exporter`，抓 9400 端口的 `/metrics` |
| 指标端口和 NVIDIA 的撞了 | 两家 Exporter 的监听端口 | 两边默认都是 9400，同集群改掉一个 |
| 规格名里带了一长串前缀 | 资源名里的型号串 | 平台不剥摩尔线程的前缀，属预期行为 |
| 多卡任务排队很久 | 有没有整卡被别人占住 | 平台侧没有卡内切分模板，任务按整卡数量排 |

## 为什么平台上找不到安装摩尔线程组件的地方

平台的「系统应用」里只内置了 NVIDIA 与昇腾两套硬件调度组件，摩尔线程的集群组件要拿厂商的包手工装。这不是配置问题，是当前的产品边界，逐项对照见 [平台适配现状](/ecosystem/moore-threads/platform-support)。

## 组件包为什么下载不到

MooreThreads 的 GitHub 组织下没有 device-plugin 与 operator 仓库，组件包随 KUAE 云原生套件一起发布，没有公开的 Helm repo。所以 `helm repo add` 这条路走不通，只能向厂商获取。

:::warning 别用同名 chart 顶上
第三方镜像站上出现的同名 chart 不要直接用，版本与驱动、Kubernetes 的配套关系对不上，出问题很难定位。
:::

## 一张卡分给多个任务，走哪条路

两条路给出的东西不一样：

- **sGPU**：在 Kubernetes 内切分，资源名是 `mthreads.com/sgpu-core` 与 `mthreads.com/sgpu-memory`，算力按时间片权重、显存按 512MiB 为单位。显存独占但算力分时，不是强隔离。
- **MT vGPU**：硬件路线，宿主侧走 mdev / SR-IOV，类型名 `mtgpu-1101`，S4000 与 S5000 标称支持。它给出的是设备节点，不是 Kubernetes 资源名，平台上建不了按它命名的资源规格。

HAMi 场景里的 `mthreads.com/vgpu` 又是另一回事，配套的还有 `mthreads.com/sgpu-memory` 与
`mthreads.com/sgpu-core`；HAMi 官方文档注明只在 MTT S4000 上验证过，且不支持多卡共享。
见 [HAMi](/ecosystem/hami)。

## 能不能用 Volcano 排摩尔线程的卡

先说结论：这条没确认。没有找到官方针对摩尔线程的 Volcano 插件；MT 自带的 `mt-gpu-scheduler` 与 `mt-gpushare-scheduler` 是厂商自研的调度组件，它们与 Volcano 的关系也没有官方说明。

所以别按「设备插件报标准扩展资源、Volcano 按资源名排」的通用路径直接推，先找厂商问清两者是否冲突、卡内切分归谁管。平台侧的多卡任务调度依赖 Volcano，这个前提没落实之前，先把规格与配额按整卡建好。
