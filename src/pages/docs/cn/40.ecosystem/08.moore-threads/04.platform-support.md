# 平台适配现状

平台上「认识一张卡」要经过四处代码，每处负责一件事。这一页把这四处对摩尔线程的实际状态逐个列出来，省得在界面里找不到某样东西时猜是配置错了还是本来就没有。

## 逐层核对

| 层 | 位置 | 对摩尔线程的现状 |
| --- | --- | --- |
| 镜像加速器类型 | 镜像登记时的加速器选项 | **已登记**：`Musa(摩尔线程)` |
| 模型元数据的后端枚举 | 模型元数据里的 `hardware_backends` | **已包含**：`musa` |
| 模型元数据型号 | 模型卡片可选的加速卡型号 | **没有登记**任何摩尔线程型号 |
| 规格的加速卡标签 | 规格标签上写的字样 | **走通用路径**：显示 `GPU`，没有专属标签 |
| 规格的型号名 | 规格名拼接 | **前缀不会被剥掉**。平台剥前缀的名单只有 nvidia / amd / intel / huawei 四家 |
| 规格的厂商图标 | 规格标签上的小图标 | **没有**摩尔线程的专属图标 |
| 集群调度组件 | 集群管理 → 运维管理 → 系统应用 | **没有**。平台只内置了 NVIDIA 与昇腾两套 |

## 现在能做什么

- **镜像元数据**：登记镜像时能标成 `Musa(摩尔线程)`，检索和筛选能用上。
- **模型元数据**：`hardware_backends` 里有 `musa`，按后端筛模型能筛出来；型号下拉里没有 MTT 型号，选不到具体的卡。
- **资源规格**：按节点上报的 `mthreads.com/gpu` 建规格，配额和任务申请都按这个资源名走。
- **算力调度**：节点上装好设备插件并上报资源名之后，平台侧的配额、规格、任务申请不用额外改动。

## 还不能做什么

| 缺的能力 | 影响 | 补法 |
| --- | --- | --- |
| 集群调度组件一键安装 | 系统应用里装不了，要自己拿包手工装 | 按 [Kubernetes 组件](/ecosystem/moore-threads/k8s-components) 向厂商获取组件包后安装 |
| 模型元数据里的型号 | 模型卡片上选不到 MTT S5000 这类型号 | 暂时在模型描述里写清楚，等平台补型号表 |
| 型号前缀剥离 | 资源名里带的型号串会原样出现在规格名里 | 建规格时把资源名起短一点，或做展示时人工核对 |
| 厂商图标 | 规格标签上没有摩尔线程的小图标 | 属平台展示层设计，不影响调度 |
| 专属加速卡标签 | 标签上只写通用 `GPU`，不写 MTT | 同上 |

## 手工接入的完整顺序

平台的系统应用里没有摩尔线程，所以前面几步都在集群外完成：

1. 向厂商获取 MT GPU Operator 组件包，拿到 `mt-gpu-operator-2.1.0.tgz` 和配套说明。没有公开 Helm repo，这一步绕不过去。
2. 每台有卡的机器装 MT Linux Driver（`sgpu-dkms`）与 MT Container Toolkit（`mt-container-toolkit`），`mthreads-gmi` 要能出卡。
3. 集群里装 Operator，按需要选 full 或 core 模式，确认节点上出现 `mthreads.com/gpu`。
4. 要监控就再装 `mt-dcgm` 与 `mt-dcgm-exporter`，把 9400 端口的 `/metrics` 接进 Prometheus。
5. 回到平台，按资源名建资源规格与配额，然后提交一个申请 1 张卡的任务验一遍。

第 5 步是唯一需要动平台界面的地方，前面四步都在机器和集群上。
