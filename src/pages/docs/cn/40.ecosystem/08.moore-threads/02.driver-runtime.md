# 驱动与容器运行时

这一页只管宿主机这一层，不涉及 Kubernetes。集群侧的组件在 [Kubernetes 组件](/ecosystem/moore-threads/k8s-components) 里讲。

装完的标志是 `mthreads-gmi` 能列出卡。这一条不过，后面所有集群组件都白装。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 操作系统 | 与目标驱动版本配套的发行版，以官方文档的兼容列表为准 |
| 内核驱动 | MT Linux Driver，内核模块 `mtgpu`，包名 `sgpu-dkms` |
| 硬件 | 卡已插好、供电与散热满足要求。S4000 标称 450 W、PCIe 5.0 |
| 权限 | 装驱动、装容器工具链、加载内核模块都需要 root 或 sudo |

## 装驱动

驱动与 MUSA SDK 放在同一批发布里，装的是 DKMS 包 `sgpu-dkms`，装完内核模块 `mtgpu` 跟着内核一起编译。流程是四步：

1. 到官方文档站找到与本机操作系统、内核版本配套的驱动版本。驱动与 MUSA SDK 是配套的，别单独升其中一个。
2. 按文档添加软件源或下载离线安装包，安装 `sgpu-dkms`。
3. 加载内核模块 `mtgpu`，并确认开机自动加载。
4. 跑 `mthreads-gmi`，能列出卡就说明宿主机这层通了。

:::warning 命令以官方当前版本为准
驱动与 MUSA SDK 的安装命令不写在这里，是因为包名之外的参数（源地址、版本号、内核头文件依赖）随版本和发行版变化。动手前对着 `https://docs.mthreads.com` 的安装章节把这几项换成当前的。
:::

## 容器工具链

集群里的业务都跑在容器里，宿主机认到卡还不够。摩尔线程这一层叫 **MT Container Toolkit**，包名 `mt-container-toolkit`。装完之后容器里能看到哪些卡、拿到哪些驱动能力，由两个环境变量控制：

| 变量 | 作用 |
| --- | --- |
| `MTHREADS_VISIBLE_DEVICES` | 指定容器里可见的卡 |
| `MTHREADS_DRIVER_CAPABILITIES` | 指定往容器里注入哪些驱动能力 |

设备怎么注入由工具链决定，集群节点跑 containerd 还是 Docker 会走不同配置，具体步骤看官方云原生文档里的容器工具链章节。

:::tip 业务想固定用某几张卡
不要改整机配置去迁就一个任务。先看 `MTHREADS_VISIBLE_DEVICES` 能不能把范围限住，具体怎么传给容器以官方容器章节的写法为准。
:::

## 验证

```bash
mthreads-gmi
```

输出里有卡型号、驱动版本、显存占用三样。排障时把整段留着，报问题时对方会先问驱动版本。

容器这一层的验证取决于镜像里带没带 MUSA 用户态。挑一个带工具链的镜像，按官方文档的示例跑一次，容器里能看到卡就算这一层也通了。

## 升级与卸载

- 升驱动前先停业务，再停集群侧的 `mt-device-plugin` 与监控组件。设备插件会周期性读驱动接口，带着它升驱动容易留下「插件在跑但上报的卡数不对」的状态，只能靠重启插件恢复。
- 驱动与 MUSA SDK 要一起换。业务镜像里的 MUSA 版本和宿主机驱动差得太远，运行期会直接报库缺失。
- 卸载就是移除 `sgpu-dkms` 包。装新版本之前先确认旧的内核模块没有残留，不然新模块可能加载不上。
