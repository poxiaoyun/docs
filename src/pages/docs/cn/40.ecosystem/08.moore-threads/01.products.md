# 产品与软件栈

## 产品线

数据中心这一条从 MTT S2000 走到 MTT S5000，工作站与消费这一条是 MTT S80 / S70 / S50 加 X300。

| 型号 | 定位 | 说明 |
| --- | --- | --- |
| MTT S5000 | 数据中心 | 当前旗舰 |
| MTT S4000 | 数据中心 | 48 GB GDDR6、768 GB/s、450 W、PCIe 5.0；标称支持硬件虚拟化与 SR-IOV 隔离 |
| MTT S3000 | 数据中心 | |
| MTT S2000 | 数据中心 | 上一代 |
| MTT S80 | 工作站与消费 | 桌面与图形工作站，不在数据中心选型范围内 |
| MTT S70 | 工作站与消费 | 同上 |
| MTT S50 | 工作站与消费 | 同上 |
| X300 | 工作站与消费 | 同上 |

官方不按「训练卡 / 推理卡」二分，全系统称全功能 GPU。所以选型时不要问「这张卡是训练用的还是推理用的」，问题要落到具体型号的显存、互联与虚拟化能力上。完整规格在产品页 `https://mthreads.com/product/category/gpu`。

## 软件栈分层

MUSA 是一个总名，实际装的时候要分成下面这几层，缺哪层后面的都跑不起来：

| 层 | 组件 | 装在哪 | 作用 |
| --- | --- | --- | --- |
| 内核驱动 | MT Linux Driver（内核模块 `mtgpu`，包名 `sgpu-dkms`） | 宿主机 | 让操作系统认识卡 |
| 管理库与命令行 | MTML（`libmtml.so`）、`mthreads-gmi` | 宿主机 | 查卡、查拓扑、查显存占用 |
| 容器工具链 | MT Container Toolkit（包名 `mt-container-toolkit`） | 宿主机 | 让容器拿到设备 |
| 编译与迁移 | MUSA SDK：编译器 `mcc`、迁移工具 `musify` 与 `musify-text`、`muPTI` | 宿主机或镜像 | 编译 MUSA 代码，把 CUDA 代码迁过来 |
| 算子与数学库 | muDNN、muBLAS、muFFT、muSOLVER、muSPARSE、muRAND、muPP、MUSA-X | 宿主机或镜像 | 业务镜像的算子依赖 |
| 通信库 | MCCL | 宿主机或镜像 | 多卡之间的集合通信 |
| 框架适配 | torch_musa、torchada、vllm-musa、SGLang-MUSA、TensorFlow-MUSA | 业务镜像 | 让框架跑在 MUSA 上 |
| 集群组件 | MT GPU Operator v2.1.0 及其组件，见 [Kubernetes 组件](/ecosystem/moore-threads/k8s-components) | Kubernetes 集群 | 把卡注册成可调度资源 |

命名分成两族：`mu` 开头的是算子与数学库，`mt` 开头的是管理工具与集群组件。`musify` 与 `musify-text` 负责把 CUDA 代码迁到 MUSA，业务镜像编译不过时先确认这一步做没做。

## 版本口径

本分区不锁版本。驱动、MUSA SDK、容器工具链、集群组件是配套发布的四件东西，官方文档给出了配套关系，按那个来配。用型号去反推驱动版本不靠谱，查兼容组合要去文档站。

| 要查什么 | 去哪查 |
| --- | --- |
| 产品与型号 | `https://mthreads.com/product/category/gpu` |
| 文档总入口 | `https://docs.mthreads.com` |
| 云原生与集群组件 | `https://docs.mthreads.com/cloud-native/cloud-native-doc-online/` |
| 开发者社区与 SDK | `https://developer.mthreads.com` |
| 官网 | `https://www.mthreads.com` |

:::tip 规划切分方案前先确认型号
硬件虚拟化不是全系标配。S4000 与 S5000 标称支持硬件虚拟化、GPU 弹性分区与 SR-IOV 隔离，其余型号不要按这个假设去规划 MT vGPU 方案，先找厂商要该型号的虚拟化支持清单再定。
:::
