# NPU Exporter

NPU Exporter 负责**定时采集 NPU 的运行时指标**——利用率、显存占用、温度、功耗、健康状态等，
并通过 `8082` 端口的 `/metrics` 暴露出来，供 Prometheus 之类的监控系统抓取。

可以把它理解成**装在每张卡上的电表**：卡本身不会主动汇报自己的用电和温度，得有人定期去读表。

## 什么情况下必须装

- 需要在平台上查看 NPU 的利用率、显存、温度曲线，或按算力卡利用率做弹性伸缩。
- 需要对 NPU 做告警和容量统计。

只做资源调度、不需要监控数据时，可以跳过本页。

## 开始之前

- 每台 NPU 节点已装好驱动（`npu-smi info` 能看到卡）。
- 组件镜像已放到集群能拉取的位置。
- 如果启用 ServiceMonitor 方式接入监控，集群需要已经装好 Prometheus Operator 相关的自定义资源。

## 部署方式一：容器化（DaemonSet，推荐）

### 1. 确认镜像存在

在计算节点上检查（Docker 场景）：

```bash
docker images | grep npu-exporter
```

containerd 场景：

```bash
ctr -n k8s.io c ls | grep npu-exporter
```

### 2. 把 YAML 拷到管理节点

将软件包解压目录里的 NPU Exporter YAML 拷贝到 Kubernetes 管理节点。

### 3. 按运行时类型选 YAML 并改参数

Docker 与 containerd 的差异主要在启动参数 `-containerMode` 以及运行时 socket 的挂载路径上，
选与你的节点匹配的那一份。需要调整时，改这些启动参数：

| 参数 | 作用 | 默认值 |
| --- | --- | --- |
| `-port` | 指标暴露端口 | `8082` |
| `-updateTime` | 采集周期（秒） | `5` |
| `-containerMode` | 容器运行时类型 | 按节点实际的 Docker / containerd 填 |
| `-logFile` | 日志文件路径 | 按 YAML 默认值 |
| `-logLevel` | 日志级别 | `0` |

### 4. 部署

```bash
kubectl apply -f npu-exporter-v<version>.yaml
```

### 5. 检查

```bash
kubectl get pod -n npu-exporter
```

## 部署方式二：二进制（安全要求高时）

如果集群不允许容器以特权方式运行，可以改成二进制部署：把 `npu-exporter` 放到固定目录，
用 systemd 的 service / timer 延迟启动，避免设备还没就绪就启动进程。

- 给日志目录配好属主和权限。
- 如果组件需要读取容器信息，可能要给二进制授予相应的 capability，改完重启服务。

## 结果确认

1. Pod 处于 `Running`：

   ```bash
   kubectl get pod -n npu-exporter
   ```

2. 转发端口并直接看指标，能打出内容就说明采集正常：

   ```bash
   kubectl port-forward -n npu-exporter <npu-exporter-pod> 8082:8082
   ```

   另开一个终端：

   ```bash
   curl -s http://127.0.0.1:8082/metrics | head
   ```

3. 如果启用了 ServiceMonitor，平台监控里应能看到该指标端点被成功抓取。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| Pod 反复 `CrashLoopBackOff` | 日志目录权限不对、DCMI 动态库权限不足、运行时 socket 挂载路径不对 | 先看 Pod 日志，再依次检查日志目录属主、DCMI 动态库及其父目录权限、socket 挂载路径 |
| `/metrics` 没有 NPU 相关指标 | 节点上驱动异常，或挂载路径不对 | 在节点上执行 `npu-smi info` 确认驱动正常 |
| 升级驱动后组件异常 | 组件仍在调用旧驱动接口 | 升级驱动前先停业务，再停 Exporter，升级完成后按相反顺序恢复 |

## 落地注意

- **Kubernetes 版本**：K8s 1.24 及以上版本是否需要额外准备 `cri-dockerd`，取决于集群的运行时与部署方式。
- **动态库权限**：DCMI 动态库及其父目录建议由 root 管理，不要给 group / other 写权限。
- **容器部署风险**：容器化运行需要特权模式和 socket 挂载，安全要求高时改用二进制方式。

:::warning 升级驱动前先停 Exporter
Exporter 会周期性调用驱动接口。升级驱动前先停业务，再停 Exporter；升级完成后按相反顺序恢复，
否则会出现组件读到一半旧驱动、指标异常的情况。
:::
