# Ascend Docker Runtime

这一步是在**每台 NPU 节点**上装一个容器运行时增强组件，让容器里也能看到并使用 NPU。
宿主机装好驱动只是机器自己能识别卡；业务都跑在容器里，必须再装这一层，容器才会拿到卡设备和驱动接口。

可以把它理解成**卡和容器之间的转接头**：卡在宿主机上，容器是隔离开的，转接头负责把卡「引」进容器。

## 什么情况下必须装

- 业务以**容器方式**运行（平台上的实例、推理服务都属此类）。
- 需要**整卡调度或虚拟化调度**。
- 需要**断点续训、弹性训练**。
- 需要**推理卡故障恢复 / 重调度**。

如果这台机器只做资源监测、不跑容器化业务，可以跳过本页。

:::warning 必须装在设备插件之前
Ascend Device Plugin 启动时会检查本组件是否已经存在。**先装本组件并重启容器引擎，再启动设备插件**；
顺序反了，插件常常需要重启或重装才能识别到卡。
:::

## 开始之前

- 使用 **root** 用户安装。
- 确认 `runc` 文件的用户 ID 为 `0`。
- 已装好容器引擎（Docker 或 containerd）。
- 宿主机驱动已验证通过（`npu-smi info` 能看到卡）。
- 明确运行时场景：Docker、containerd，还是 Kubernetes 集成的 containerd。

## 操作步骤

### 1. 确认运行时类型

查看节点列表：

```bash
kubectl get node
```

查看已安装的容器引擎版本：

```bash
docker --version
containerd --version
```

在 Kubernetes 节点上，也可以从节点描述里确认：

```bash
kubectl describe node <node-name> | grep -i runtime
```

根据输出判断后面该走 Docker 还是 containerd 分支。

### 2. 给安装包加执行权限

```bash
cd <安装包所在目录>
chmod u+x Ascend-docker-runtime_<version>_linux-<arch>.run
```

### 3. 先做安装前检查

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --check
```

检查不通过时先解决它提示的问题，不要直接安装。

### 4. 安装

**Docker 场景：**

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --install
```

**containerd 场景：**

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --install --install-scene=containerd
```

如需指定安装路径（必须是绝对路径）：

```bash
./Ascend-docker-runtime_<version>_linux-<arch>.run --install --install-path=<绝对路径>
```

### 5. 重启容器引擎

**Docker 场景：**

```bash
systemctl daemon-reload && systemctl restart docker
```

**containerd 场景：**

```bash
systemctl daemon-reload && systemctl restart containerd
```

### 6. 让设备插件重新识别

如果设备插件已经先装上了，这一步要重启它，否则它拿不到运行时：

```bash
kubectl rollout restart daemonset/<device-plugin-daemonset> -n kube-system
```

## 结果确认

- 第 3 步的 `--check` 通过，第 4 步安装过程没有报错。
- 第 5 步重启后容器引擎正常运行（`systemctl status docker` 或 `systemctl status containerd` 为 active）。
- 之后再启动 Ascend Device Plugin，插件能正常识别到运行时；如果插件此前已在运行，重启后不再报运行时相关错误。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 安装时找不到配置文件 | Docker / containerd 配置不在默认路径 | 安装时额外指定 `--config-file-path` |
| containerd 场景安装失败 | `config.toml` 里 runtime 配置不对，或 cgroup 版本（v1/v2）不匹配 | 检查 `config.toml` 中的 runtime 配置，并确认 runtime 路径指向正确的 `ascend-docker-runtime` |
| 装完设备插件仍识别不到卡 | 装完没有重启容器引擎，或没重启设备插件 | 重启容器引擎，再重启设备插件 |
