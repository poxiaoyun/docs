# 驱动与运行时（Ascend）

这一步是在**每台有 NPU 的机器上**装驱动和固件，让宿主机自己认识这张卡。装完的标志很简单：
执行 `npu-smi info` 能看到卡号和驱动版本。驱动装不上，后面所有集群组件都无从谈起。

可以把驱动理解成「显卡驱动」：没有它，操作系统只知道插了一块硬件，却不会用。

:::info 本页只管宿主机
这里不涉及 Kubernetes。集群侧的组件安装见 [MindCluster（集群调度组件）](/ecosystem/huawei/mindcluster)；
容器里怎么用卡由容器运行时负责，见 [Ascend Docker Runtime](/ecosystem/huawei/mindcluster/ascend-docker-runtime)。
:::

## 开始之前

- 确认节点操作系统为 **openEuler**，内核版本与目标驱动版本兼容。
- 准备好**驱动包**和**固件包**（都是 `.run` 安装包），并已上传到目标机器上能访问的目录。
- 确认本次是**首次安装**还是**覆盖安装**（已装未卸载的情况下重装）——它决定安装顺序，见下一步。
- 具备 **root** 权限。

## 操作步骤

### 1. 先看这台机器有没有装过驱动

```bash
npu-smi info
```

- 能打印出 NPU 列表和驱动版本：说明已装好，可直接跳到「验证」。
- 提示命令不存在，或列表为空：说明未安装或驱动未加载，继续往下走。

### 2. 确定安装顺序

顺序装反是最常见的坑，务必先确认场景：

| 场景 | 判断依据 | 安装顺序 |
| --- | --- | --- |
| 首次安装 | 设备出厂未装，或已卸载后重装 | **驱动 → 固件** |
| 覆盖安装 | 已装且未卸载，直接重装或升级 | **固件 → 驱动** |

### 3. 准备运行用户

驱动和固件默认用 `HwHiAiUser` 用户和同名用户组运行。如果环境中没有，先创建：

```bash
groupadd HwHiAiUser
useradd -g HwHiAiUser -d /home/HwHiAiUser -m HwHiAiUser -s /bin/bash
```

如果你要用别的运行用户，在安装驱动时显式指定（见第 6 步），并保证后续软件包的运行用户与它同组。

### 4. 装依赖

```bash
yum makecache
yum install -y make dkms gcc kernel-headers-$(uname -r) kernel-devel-$(uname -r)
```

`dkms` 负责在内核更新后自动重编驱动，缺它会导致驱动装了但加载失败。

### 5. 给安装包加执行权限

进入存放安装包的目录，替换成实际的文件名：

```bash
cd <安装包所在目录>
chmod +x Ascend-hdk-<chip_type>-npu-driver_<version>_linux-<arch>.run
chmod +x Ascend-hdk-<chip_type>-npu-firmware_<version>.run
```

### 6. 安装驱动

首次安装（默认运行用户，对所有用户生效）：

```bash
./Ascend-hdk-<chip_type>-npu-driver_<version>_linux-<arch>.run --full --install-for-all
```

覆盖安装时按第 2 步的顺序，把驱动放到固件之后执行同一条命令。

指定运行用户（不使用默认的 `HwHiAiUser` 时）：

```bash
./Ascend-hdk-<chip_type>-npu-driver_<version>_linux-<arch>.run \
  --full \
  --install-username=<username> \
  --install-usergroup=<usergroup>
```

### 7. 安装固件

```bash
./Ascend-hdk-<chip_type>-npu-firmware_<version>.run --full
```

安装路径通常是 `/usr/local/Ascend`，以安装回显为准。

### 8. 按提示重启

```bash
reboot
```

驱动安装完通常需要重启才加载完成，安装回显会明确提示，按提示执行。

## 验证

重启后执行：

```bash
npu-smi info
```

输出里通常能看到：**命令自身的版本行**、**卡的数量与型号**、每张卡的**健康状态（Health 应为 OK）**、
温度、功耗和显存占用。只要卡都列出来且健康状态正常，就说明驱动加载成功。

如果卡没出现在列表里，或者健康状态不是正常值，按下面的常见问题排查。

如果你还要装 CANN（ToolKit / Kernel / Runtime），请在驱动与固件验证通过后再按官方对应版本的安装指南继续。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| `npu-smi: command not found` | 驱动没装上，或装完没重启 | 确认安装回显显示成功，按提示重启后再试 |
| `npu-smi info` 有输出但看不到卡 | 驱动未加载完成 | 确认已完成重启；仍不行则检查 `dkms` 与内核头文件是否齐全 |
| 安装时提示缺少 Linux 工具 / dkms / 依赖 | yum 源不可用，或依赖未装全 | 先 `yum makecache`，再补 `make`、`dkms`、`gcc`、`kernel-headers`、`kernel-devel` |
| 覆盖安装后行为异常 | 安装顺序与场景不符 | 覆盖安装用 **固件 → 驱动**，首次安装用 **驱动 → 固件** |
| 提示版本不满足 | 驱动、固件、CANN 版本不配套 | 三者的版本必须以同一发布批次为准，具体提示以安装回显和官方安装指南为准 |

:::warning 版本必须配套
驱动、固件、CANN 和后续 MindCluster 组件都有版本配套要求。**不要凭印象指定版本号**，
一律使用随发布包提供的版本组合，否则轻则安装报错，重则装完卡不可用。
:::

## 版本口径与参考链接

本页不指定具体版本号：**驱动版本、固件版本、NPU 型号、操作系统内核、CANN 必须同一发布批次配套**，
以随发布包提供的组合为准。动手前把这四项记进交付单，后面排障全靠它们：

- NPU 型号
- 驱动版本 / 固件版本
- CANN 版本
- 要装的 MindCluster 版本（见 [MindCluster（集群调度组件）](/ecosystem/huawei/mindcluster) 的「版本口径」）

昇腾官方文档站的目录会随版本更新，**不要拿某个固定版本的链接去下另一个版本的包**：

- 昇腾社区（软件下载与文档总入口）：https://www.hiascend.com/developer/download
- 安装 NPU 驱动和固件（在文档站的「软件安装」目录里按版本进入）：https://www.hiascend.com/document
