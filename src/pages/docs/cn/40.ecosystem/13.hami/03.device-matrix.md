# 支持的设备与资源名

HAMi 对不同厂商的适配程度不一样，表现在三件事上：显存限制管不管得住、算力限制管不管得住、
一张卡能不能拆给多个任务的同时又让一个任务占多张卡。下表是官方在 v2.10.0 上给出的矩阵。

## 官方支持矩阵

| 厂商 | 设备类型 | 型号 | 状态 | 显存隔离 | 算力隔离 | 多卡切分 |
| --- | --- | --- | --- | --- | --- | --- |
| NVIDIA | GPU | 全部 | Stable | 有 | 有 | 有 |
| AMD | GPU | Instinct / ROCm | Stable | 有 | 有 | 无 |
| 华为昇腾 | NPU | 910B、910B3、910C、310P | Stable | 有 | 有 | 无 |
| 海光 | DCU | 全部 | Stable | 有 | 有 | 无 |
| 寒武纪 | MLU | 370、590 | Stable | 有 | 有 | 无 |
| 天数智芯 | GPU | 全部 | Stable | 有 | 有 | 无 |
| 摩尔线程 | GPU | MTT S4000 | Stable | 有 | 有 | 无 |
| 沐曦 | GPU | MXC500 | Stable | 有 | 有 | 无 |
| 昆仑芯 | XPU | P800 | Stable | 有 | **无** | 无 |
| 壁仞 | GPU | Biren166M | Stable | **无** | **无** | 无 |
| 燧原 | GCU | S60 | Stable | 有 | 有 | 无 |
| Vastai | GPU | VA16 | Stable | 无 | 无 | 无 |
| AWS | Neuron | Inf、Trn | Stable | 无 | 有 | 无 |
| 中科驭数 | DPU | 未列出 | 验证中 | 无 | 无 | 无 |

三个能力列的含义：

| 列 | 含义 |
| --- | --- |
| 显存隔离 | 容器超出申请的显存会被拒，而不是直接拿物理显存顶上 |
| 算力隔离 | 容器超出申请的算力份额会被节流 |
| 多卡切分 | 一个 Pod 能不能跨多张物理卡使用被切分出来的显存与算力 |

「多卡切分 = 无」不等于不能申请多张卡。它说的是申请多张卡时**不能再同时写显存和算力**，
写了会被当成整卡分配。这一条在下面各家的限制里会反复出现。

:::info 两份官方口径有小差异
官方中文 FAQ 里的型号写法是昇腾 `910A、910B2、910B3、310P`，寒武纪 `370、590`，
沐曦写作品牌名「魅特思 MXC500」。英文的 Device supported 页（标注对应 v2.10.0）写的是昇腾
`910B、910B3、910C、310P`。以实际装的那套设备插件上报的型号为准，别按表格里的型号名字去猜。
:::

## 各厂商资源名

申请时写的是资源名，不是型号名。同一个厂商在不同路径下可能有两套名字，别混用。

### NVIDIA

| 资源名 | 含义 |
| --- | --- |
| `nvidia.com/gpu` | 申请几个 vGPU |
| `nvidia.com/gpumem` | 申请的显存，单位 MiB |
| `nvidia.com/gpumem-percentage` | 按整卡显存百分比申请 |
| `nvidia.com/gpucores` | 申请的算力，百分比 |
| `nvidia.com/priority` | 卡内运行时抢占的优先级，`0` 高、`1` 低 |

粒度是显存 1 MiB、算力 1%。这是所有厂商里唯一支持多卡切分的一家。

### 华为昇腾

| 资源名 | 含义 |
| --- | --- |
| `huawei.com/Ascend910A`、`huawei.com/Ascend910B`、`huawei.com/Ascend310P` | 申请整卡数 |
| `huawei.com/<同上前缀>-memory` | 申请的显存 |

昇腾不是按百分比切，而是按**卡类型模板**切。模板定义在设备插件侧，比如 910A 有 `vir02`、`vir04`、
`vir08`、`vir16` 四档，910B3 有 `vir05_1c_16g`、`vir10_3c_32g`。申请落在哪两档之间会取能装下的最小档。
节点标签是 `ascend=on`。HAMi 也提供软切分模式（`hami-vnpu-core`），目前限 ARM 平台、且只能配 HAMi 调度器。

### 海光 DCU

| 资源名 | 含义 |
| --- | --- |
| `hygon.com/dcunum` | 申请几个 vDCU |
| `hygon.com/dcumem` | 每个 vDCU 的显存，单位 MiB |
| `hygon.com/dcucores` | 每个 vDCU 的算力百分比 |

粒度是显存 1M、算力 1%。一个容器只能拿一个 vDCU，要挂多张卡就别写显存和算力。
容器内要启用 vDCU 得先 `source /opt/hygondriver/env.sh`，再用 `hy-smi virtual -show-device-info` 确认。

### 寒武纪 MLU

| 资源名 | 含义 |
| --- | --- |
| `cambricon.com/vmlu` | 申请几个 vMLU |
| `cambricon.com/mlu.smlu.vmemory` | 每个 vMLU 的显存，最小分配单位 256 MB |
| `cambricon.com/mlu.smlu.vcore` | 每个 vMLU 的算力百分比 |

粒度是显存 256M、算力 1%。开启前每张卡要先执行 `cnmon set -c <id> -smlu on`，
设备插件侧要配 `mode=dynamic-smlu` 与 `min-dsmlu-unit=256`。显存与算力只有在 `vmlu` 为 `1` 时才生效，
写大于 1 就是整卡分配。这条限制与海光、摩尔线程一致。

### 天数智芯

| 资源名 | 含义 |
| --- | --- |
| `iluvatar.ai/<卡型>-vgpu` | 申请几个 vGPU |
| `iluvatar.ai/<卡型>.vCore` | 算力，1 个单位为 1% |
| `iluvatar.ai/<卡型>.vMem` | 显存，1 个单位为 256 MB |

文档里给出的卡型有 `MR-V100`、`MR-V50`、`BI-V150`、`BI-V100`。不写显存时默认用满。
申请多张卡时算力会按卡数自动折算。

:::warning 天数有两套门牌号，别抄错
按整卡走的资源名是 `iluvatar.com/gpu`，按切分走的是 `iluvatar.ai/...`，两个域名不一样。
网上还流传 `iluvatar.ai/vgpu`、`iluvatar.ai/vcuda-core`、`iluvatar.ai/vcuda-memory` 这一套名字，
和当前 HAMi 文档里的对不上。建规格前先看一眼集群里实际装的是哪个插件、上报了什么资源名。
:::

### 摩尔线程

| 资源名 | 含义 |
| --- | --- |
| `mthreads.com/vgpu` | 申请几个 vGPU，只写这一项就是整卡独占 |
| `mthreads.com/sgpu-memory` | 显存，1 个单位为 512 MB |
| `mthreads.com/sgpu-core` | 算力份额 |

限制比其他家严：不支持多卡共享，一个 Pod 里即使有多个容器也只能共享一张卡。
官方注明这些能力只在 MTT S4000 上验证过。节点侧要装 MT CloudNative Toolkits，
装完可以把 `mt-mutating-webhook` 与 `mt-gpu-scheduler` 删掉。

### 沐曦

沐曦在 HAMi 里分两条道走，资源名不同：

| 路径 | 资源名 | 说明 |
| --- | --- | --- |
| 整卡加拓扑感知 | `metax-tech.com/gpu` | 不做共享。按 MetaXLink 与 PCIe Switch 的远近关系挑卡，注解 `hami.io/node-scheduler-policy` 选 `spread` 或 `binpack` |
| sGPU 共享 | `metax-tech.com/sgpu`、`metax-tech.com/vcore`、`metax-tech.com/vmemory` | `vcore` 是百分比（`60` 即 60%），`vmemory` 单位 GiB |

两条道要的前置组件不一样：整卡拓扑要 MetaX GPU Extensions ≥ 0.8.0，sGPU 要 MetaX GPU Operator ≥ 0.10.2
与驱动 ≥ 2.32.0。不写 `vcore` 或 `vmemory` 表示该项用满。

### 昆仑芯

| 路径 | 资源名 | 说明 |
| --- | --- | --- |
| 整卡加拓扑感知 | `kunlunxin.com/xpu` | 不做共享。只允许 1、2、4、8 卡分配；1、2、4 卡不能跨 NUMA 节点；分配后尽量减少碎片 |
| vXPU 共享 | `kunlunxin.com/vxpu`、`kunlunxin.com/vxpu-memory` | 显存单位 MiB，例子里给的是 24576 |

vXPU 限 P800-OAM 卡型，前置是驱动 ≥ v5.0.21.16 与 `xpu-container-toolkit` ≥ `xpu_container_1.0.2-1`。
官方支持矩阵里昆仑芯的算力隔离是「无」，也就是说按显存切可以，按算力切不行。

### 壁仞

| 资源名 | 含义 |
| --- | --- |
| `birentech.com/gpu` | 申请设备，整卡与 SVI 分片都走这个名字 |

壁仞的显存隔离与算力隔离都不支持，**没法指定显存大小，只能申请整卡或按 SVI 预划好的分片**。
节点标签是 `biren=on`，与官方自己那套插件的 `birentech.com=gpu` 标签不是一套。

### AMD

| 资源名 | 含义 |
| --- | --- |
| `amd.com/gpu` | 申请几个 vGPU |
| `amd.com/gpumem` | 申请的显存，单位 MiB |
| `amd.com/gpucores` | 申请的算力，百分比 |

AMD 这条路径要单独装 HAMi 侧的 `amd-device-plugin`，不能拿 ROCm 上游的 `k8s-device-plugin` 顶替。
如果同时用 AMD GPU Operator 管驱动，要把它自带的设备插件关掉，否则两边抢 `amd.com/gpu`。

## 从哪个版本开始有

| 版本 | 发布日期 | 与厂商相关的变化 |
| --- | --- | --- |
| v2.6.0 | | 文档里开始出现沐曦 sGPU 章节 |
| v2.7.0 | 2025-09-26 | 昆仑芯接入：vXPU 支持与拓扑感知调度 |
| v2.8.0 | 2026-01-20 | 修复 P800 节点上 vXPU 可能不工作的问题 |
| v2.9.0 | 2026-05-13 | 新增燧原设备；修好 vLLM 0.18 以上多卡张量并行的初始化问题 |
| v2.10.0 | 2026-08-21 | 新增壁仞与 AMD vGPU 支持；主 chart 里的 DRA 组件被移出 |

昆仑芯与 vLLM 多卡这两条直接对应版本门槛：集群里跑的 HAMi 版本低于表里的版本，这些能力就是没有。
