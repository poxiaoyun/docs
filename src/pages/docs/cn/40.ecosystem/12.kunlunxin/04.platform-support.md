# 平台适配现状

平台上「认识一张卡」要经过四处代码，每处负责一件事。下面把四处对昆仑芯的实际状态逐个列出来，
省得在界面里找不到某样东西时猜是配置错了还是本来就没有。

## 逐层核对

| 层 | 位置 | 对昆仑芯的现状 |
| --- | --- | --- |
| 镜像加速器类型 | 镜像登记时的加速器选项 | **没有**。现有选项是 CUDA / ROCm / CANN / DKT / MACA / CoreX / Musa / Neuware / CPU |
| 模型元数据型号 | 模型卡片可选的加速卡型号 | **没有登记任何昆仑芯型号** |
| 模型元数据的后端枚举 | 模型元数据里的 `hardware_backends` | **没有**。列表是 cpu / cuda / rocm / ascend / mlu / musa / metal，没有 xpu |
| 规格的资源名识别 | 平台判断一条资源配置是不是加速卡 | **独有问题**：只靠资源名识别不出来，必须把规格的「类型」字段填成 GPU |
| 规格的加速卡标签 | 规格标签上写的字样 | 走通用路径，显示 `GPU` |
| 规格的型号名 | 规格名拼接 | 前缀不会被剥掉。平台剥前缀的名单只有 nvidia / amd / intel / huawei 四家 |
| 规格的厂商图标 | 规格标签上的小图标 | **没有** |
| 集群调度组件 | 集群管理 → 运维管理 → 系统应用 | **没有**。平台只内置了 NVIDIA 与昇腾两套 |

## 资源名识别这个坑

平台判断一条资源配置是不是加速卡，靠的是资源名里出现的关键词，gpu、npu、mlu、dcu、ascend 这些命中一个就算。
`kunlunxin.com/xpu` 里这几个关键词一个都不含，等于报了个不在名单上的名字，平台不会把它当成加速卡。

后果很直接：只填资源名的话，规格建出来不会被认成加速卡，配额和调度都按普通资源走。

绕法是手工指定：新建资源规格时，把「类型」字段填成 `GPU`。填完之后平台就按加速卡处理这个规格，
后面的配额与任务申请都正常。这是昆仑芯接入里唯一一个必须人工干预的地方，忘了填的症状是
规格在列表里像个普通资源，任务申请时选不到卡。

## 现在能做什么

- **资源规格**：按节点上报的资源名建规格，把「类型」字段填成 GPU 后，配额、规格、任务申请都按加速卡走。
- **两种资源名口径**：`kunlunxin.com/xpu` 与旧口径 `baidu.com/xpu` 都当普通扩展资源处理，按节点实际报的填即可。
- **算力调度**：节点上装好 `xpu-device-plugin` 并上报资源后，平台侧的多卡任务可以正常排。

## 还不能做什么

| 缺的能力 | 影响 | 补法 |
| --- | --- | --- |
| 镜像加速器类型 | 登记镜像时选不到昆仑芯，只能选一个最接近的选项 | 平台枚举缺项，不影响实际运行 |
| 模型元数据型号 | 模型卡片里没有 P800 等型号可选 | 型号信息放在模型说明或规格名里 |
| `hardware_backends` 里的 xpu | 模型元数据里标不出 XPU 后端 | 归到最接近的后端 |
| 规格的资源名关键词识别 | 忘了填「类型」就识别不出来 | 手工把「类型」字段填成 GPU |
| 规格的厂商图标 | 规格标签上没有昆仑芯图标 | 展示层缺项，不影响调度 |
| 规格名的前缀剥离 | 型号名不会被自动剥掉厂商前缀 | 平台剥前缀名单只有四家，属预期；型号填干净即可 |
| 一键安装集群组件 | 系统应用里点不到昆仑芯 | 按 [Kubernetes 组件](/ecosystem/kunlunxin/k8s-components) 手工装 |
| vXPU 切分 | 官方切分参数未生效 | 走 HAMi，见 [Kubernetes 组件](/ecosystem/kunlunxin/k8s-components) |

## 手工接入的完整顺序

平台的系统应用里没有昆仑芯，所以集群侧要自己做：

1. 每台有卡的机器装驱动包，`xpu-smi` 出卡。
2. 同一批机器配好容器运行时，容器里能看到卡。
3. 集群里装 `xpu-device-plugin` 与 `xpu-exporter`，确认节点出现 `kunlunxin.com/xpu` 或 `baidu.com/xpu`，9507 端口有指标。
4. 回到平台建资源规格，把「类型」字段填成 GPU，再建配额。
5. 提交一个申请 1 张卡的任务，容器里跑 `xpu-smi` 验一遍。

第 4 步是唯一需要动平台界面的地方，其余都在集群侧。
