# 驱动与容器运行时

宿主机这一层装完的标志只有一个：`xpu-smi` 能跑出设备。集群侧的组件在
[Kubernetes 组件](/ecosystem/kunlunxin/k8s-components) 里讲。

这一条不过，后面所有集群组件都白装。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 操作系统 | 官方未公开完整支持列表，以随卡驱动包里的发行版说明为准 |
| 内核驱动 | XRE 里的 kmd，随驱动包发布 |
| 用户态运行时 | XRE 的用户态部分，装完才有 `xpu-smi` |
| 容器运行时 | 集群节点一般跑 containerd，让容器看到卡的方式以驱动包说明为准 |
| 可编译驱动 | XDR，源码形式提供，只在需要适配特定内核版本时用 |

## 驱动与软件栈

昆仑芯把内核驱动、用户态运行时和设备管理工具打成一个包，统称 XRE。

内核里的 kmd 负责让操作系统认识卡，用户态部分提供运行时和 `xpu-smi`。再往上的算子库、通信库、
框架适配属于业务镜像里的东西，见 [产品与软件栈](/ecosystem/kunlunxin/products)。

XDR 是另一条线，源码形式给到要自己编译驱动的场景。除非有明确的内核适配需求，一般不用碰它。

:::warning 分层口径的来源性质
本页的分层口径主要来自腾讯云 TKE 的昆仑芯组件文档。那是第三方整理，引用的是官方说法。
拿它理解结构可以，拿它当安装手册不行。
:::

## 验证驱动

```bash
xpu-smi
```

能列出设备就算就位。`xpu-smi` 带哪些子命令、怎么筛选单卡，官方没有成文的公开文档，
以随驱动包发布的说明为准。报障时把这条命令的完整输出留着，对方第一句会问驱动版本。

## 容器里看到卡

宿主机认到卡还不够，容器里也要能看到。不同的容器运行时配置方式不同，配置项随驱动包发布，
这一层不展开。配完拿一个最小任务验一遍：申请 1 张卡，容器里跑 `xpu-smi` 能出卡就算通了。
申请资源的写法见 [Kubernetes 组件](/ecosystem/kunlunxin/k8s-components)。

## 升级要注意的

升级前先停业务，再把集群侧的 `xpu-device-plugin` 与 `xpu-exporter` 停掉再动驱动。
设备插件会周期性读驱动接口，带着它升驱动容易留下「插件在跑但上报的设备数不对」的状态，
只能靠重启插件恢复。

:::warning 安装命令不在网页上
昆仑芯官方没有可公开引用的开发者文档站，驱动包的包名、仓库地址、安装参数都随包发布。
动手前拿到随卡驱动包，或走官网 `https://www.kunlunxin.com` 的官方渠道索取，不要照抄第三方文档里的命令。
:::
