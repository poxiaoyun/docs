# Kubernetes 组件

集群侧要装两个组件：设备插件把卡注册成可调度资源，导出器把卡指标暴露给 Prometheus。

| 组件 | 作用 | 备注 |
| --- | --- | --- |
| `xpu-device-plugin` | 把卡注册成 Kubernetes 资源 | 官方 GitHub 仓库未确认，插件疑似随驱动包或官网账号区分发 |
| `xpu-exporter` | 暴露 Prometheus 指标 | DaemonSet，默认端口 9507 |
| `xpushare-device-plugin` | 卡内切分相关 | Docker Hub 组织 `kunlunxpu` 里有镜像，最后更新停在 2022 至 2023 年 |
| `cxpu-device-plugin` | 卡内切分相关 | 同上 |

镜像能拿到，但 `kunlunxpu` 组织下的镜像都是 2022 至 2023 年的版本，用之前先确认与当前驱动配套。

腾讯云 TKE 里这套组件的口径是：组件标识 `xpu-gpu`，DaemonSet 名 `xpu-device-plugin-daemonset`，
镜像 tag `v5.0.2-alpha.3`。自己装不一定要对齐这个版本，但对着它可以判断手里的是不是同一代。

## 设备插件上报的资源名

当前口径是整卡一个资源名：

```
kunlunxin.com/xpu
```

申请几张卡就写几：

```yaml
resources:
  limits:
    kunlunxin.com/xpu: 1
```

## 旧资源名口径

老版本设备插件的 README 里，资源名是 `baidu.com/xpu`，切分参数是 `--sriov-num-vfs`，
节点标签是 `baidu.com/sriov-num-vfs=x`。老集群里可能还在用这一套。

:::warning 建规格前先看节点实际报了哪个
两个口径都存在，谁也说不准你手里的集群是哪一个。先跑 `kubectl describe node <node> | grep -iE "kunlunxin.com|baidu.com"`，
报的是哪个就按哪个建。建错了的表现是规格建好了但任务一直申请不到卡。
:::

## 监控

指标由 `xpu-exporter` 提供，Prometheus 格式：

| 项 | 值 |
| --- | --- |
| 组件 | `xpu-exporter` |
| 形态 | DaemonSet |
| 指标格式 | Prometheus |
| 默认端口 | 9507 |
| 接入平台监控 | 建 ServiceMonitor 抓 9507 |

这个端口和 NVIDIA 的 9400、AMD 的 5000 都不一样，做统一看板时别按同一个端口写。

## vXPU 切分现状

昆仑芯官方把一卡多用叫 vXPU，基于 SR-IOV。现状分三层，一层比一层要得多：

| 路径 | 状态 | 资源名 |
| --- | --- | --- |
| 官方 vXPU（TKE chart 参数） | 参数是预留的，当前未生效 | 无 |
| HAMi 的 `vxpu-device-plugin` | 可用，限于 P800-OAM；只支持按显存切 | `kunlunxin.com/vxpu`、`kunlunxin.com/vxpu-memory` |
| 老插件的 `--sriov-num-vfs` | 老版本口径 | 配合节点标签 `baidu.com/sriov-num-vfs=x` |

:::warning 平台与云厂商侧的切分参数都还没生效
TKE chart 里的 `devicePlugin.enableSriov`、`sriovNumVfs`、`enableXpuShare` 是预留参数，
打开它们不会真的把卡切开。要在平台上按份调度，只能用 HAMi 那条路，它不在平台内置路径里。
:::

## 和 Volcano 的关系

平台的调度后端是 Volcano，而 Volcano 的设备后端只有 nvidia 与 ascend 两者，没有昆仑芯的官方插件。
所以昆仑芯走的是通用路径：设备插件把卡报成标准扩展资源，Volcano 按资源名和数量排。

- 多卡任务能排，靠的是标准的扩展资源机制。
- 卡内切分后按份调度、显存按比例分配这类能力不在 Volcano 官方支持范围内，要引入 HAMi。
  HAMi 从 v2.7.0 起支持昆仑芯，v2.8.0 修了 P800 节点上 vXPU 可能不工作的问题；它给昆仑芯的
  支持矩阵里只勾了显存隔离、没勾算力隔离，也就是按显存切可以、按算力切不行。
  这条路属于平台内置路径之外的另一条路线，前置与资源名见 [HAMi](/ecosystem/hami)。

## 装完怎么验证

```bash
# 节点上报的昆仑芯资源
kubectl describe node <node> | grep -iE "kunlunxin.com|baidu.com"

# 插件与导出器 Pod
kubectl get pods -A | grep -i xpu

# 监控端口
kubectl get svc -A | grep -i xpu-exporter
```

再交一个最小任务，申请 1 张卡，容器里跑 `xpu-smi` 能打出卡就算通了。
