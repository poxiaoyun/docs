# FAQ

## 速查表

| 现象 | 先查什么 | 处置 |
| --- | --- | --- |
| `xpu-smi` 报找不到设备 | 驱动包装没装、当前账号权限 | 按随卡驱动包说明重装 |
| 宿主机能看到卡，容器里看不到 | 容器运行时有没有配 | 按驱动包里的容器运行时说明配 |
| 节点上没有 `kunlunxin.com/xpu` | 设备插件 Pod 状态与日志 | 先确认驱动就位，再重启插件 |
| 节点上报的是 `baidu.com/xpu` | 设备插件版本 | 老口径，按实际资源名建规格，或换插件 |
| 规格建好了但不像加速卡 | 规格的「类型」字段 | 填成 GPU |
| 规格标签显示 `GPU` 而不是昆仑芯 | 平台展示逻辑 | 预期行为，不影响调度 |
| 规格名带着 `kunlunxin.com/` 前缀 | 平台剥前缀名单只有四家 | 预期行为 |
| 打开 vXPU 切分参数没效果 | 参数是不是预留的 | 当前未生效，按份调度改用 HAMi |
| 多卡任务排队久 | 有没有整卡被占住 | 平台没有内置切分，按卡数排 |
| Prometheus 抓不到卡指标 | `xpu-exporter` 端口 | 默认 9507，确认 ServiceMonitor 指对了 |

## 为什么规格建好了平台不认这是加速卡

平台判断一条资源配置是不是加速卡，靠资源名里的关键词：gpu、npu、mlu、dcu、ascend 命中一个就算。
`kunlunxin.com/xpu` 里这几个都不含，所以自动识别走不通。

改法只有一个：新建规格时把「类型」字段手工填成 `GPU`。填完之后规格按加速卡处理，
配额、规格、任务申请都正常。详细对照见 [平台适配现状](/ecosystem/kunlunxin/platform-support)。

## 节点上报的资源名到底是哪个

两个口径都存在，看节点实际报的：

```bash
kubectl describe node <node> | grep -iE "kunlunxin.com|baidu.com"
```

`kunlunxin.com/xpu` 是当前口径，`baidu.com/xpu` 出自老版本设备插件的 README。
建规格按节点实际报的填，别按文档猜。

## vXPU 参数打开为什么没效果

腾讯云 TKE 的 chart 里有 `devicePlugin.enableSriov`、`sriovNumVfs`、`enableXpuShare` 三个参数，
看着像切分开关，实际是预留参数，当前不会把卡切开。官方的 vXPU 走 SR-IOV 路线，但落到可用的配置上还没到位。

要在平台上按份调度，路径是 HAMi 的 `vxpu-device-plugin`，资源名 `kunlunxin.com/vxpu`
与 `kunlunxin.com/vxpu-memory`，目前只覆盖 P800-OAM，而且只能按显存切、不能按算力切。
HAMi 不在平台内置路径里，见 [Kubernetes 组件](/ecosystem/kunlunxin/k8s-components)。

## 为什么找不到官方的安装文档

昆仑芯没有独立的开发者文档站，`developer.kunlunxin.com` 与 `docs.kunlunxin.com` 都无法解析；
GitHub 上 `kunlunxin` 这个组织也不存在，`github.com/kunlunxin/xpu-device-plugin` 返回 404。
能公开查到的软件栈口径主要来自腾讯云 TKE 的组件文档，那是第三方整理。

所以本分区只写分层与验证方法，不给安装命令。驱动包、包名、安装参数一律以随卡驱动包为准，
或走官网 `https://www.kunlunxin.com` 的官方渠道。

:::warning 见到带版本号的第三方命令先别粘
第三方文档里的包名、仓库地址会过期，尤其是 `kunlunxpu` 组织下的镜像停在 2022 至 2023 年。
粘之前先确认它跟手里的驱动版本配套。
:::
