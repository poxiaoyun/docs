# 驱动与容器运行时

这一页只管宿主机这一层，集群侧的组件在 [Kubernetes 组件](/ecosystem/metax/k8s-components) 里讲。

装完的标志有两个：`mx-smi` 能列出卡，并且能报出驱动版本。这两条不过，后面所有集群组件都白装。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 操作系统 | 与目标 MXMACA 版本配套的发行版，具体清单见沐曦软件中心 |
| 内核驱动 | KMD / UMD，内核模块 `metax.ko`，随 `k8s-driver-image` 发布 |
| 用户态 | MXMACA® SDK，提供 `macaRT`、`mxcc` 与算子库 |
| 容器运行时 | docker ≥ 18.09.3 或 containerd ≥ 1.5.0，这是集群组件的最低要求 |
| 软件包来源 | 沐曦软件中心 `https://developer.metax-tech.com/softnova/index` |

## 装驱动

驱动分内核态 KMD 与用户态 UMD 两部分，官方以 `k8s-driver-image` 的形式发布，宿主机安装和集群下发用的是同一份包。
步骤按下面这个顺序走：

1. 在软件中心按**型号 + 操作系统 + MACA 版本**找到对应的软件包。
2. 装 KMD / UMD，装完确认 `metax.ko` 已加载。
3. 装 MXMACA 用户态，确认 `mxcc`、`macaRT` 可用。
4. 用 `mx-smi` 验证卡与驱动版本。

:::warning 命令以官方当前版本为准
沐曦的安装命令随软件包版本与发行版变化，软件中心每个包都带自己的安装说明。
上面这几步用来理解流程，动手前请打开对应包的说明页，逐条对着执行。
:::

## 容器运行时

沐曦在这一层用的是自家实现，不是 CDI，也不是标准 toolkit 那套。官方给的两个名字对应两种场景：

| 组件 | 场景 | 说明 |
| --- | --- | --- |
| `metax-container-runtime` | containerd | 沐曦的容器运行时，配置后 containerd 能按它把设备挂进容器 |
| `metax-docker` | Docker | 对应的 Docker 侧运行时 |

和标准 containerd 的关系要说清楚：**containerd 本身不动，加的是沐曦这个 runtime**。
集群节点的 containerd 照常起，业务容器通过沐曦运行时拿到设备；所以节点上要同时保证
containerd 服务正常、沐曦运行时已注册。官方基础镜像名形如 `maca-c500`、`mxc500-maca`，
业务镜像基于它构建。

安装与注册的具体命令同样以软件中心对应包的说明为准。

## 验证

```bash
mx-smi
```

宿主机上这条能列出卡与驱动版本，驱动层就算就位。

`mx-smi` 只是命令行工具，**不是监控导出器**。集群要采集指标得另外装 `mx-exporter`，
两者不是一回事，排障时别看错。

## 卸载与升级

先停业务，再停集群侧的 `gpu-device` 与 `mx-exporter`，最后动驱动。`gpu-device` 会周期性读驱动接口，
带着它升驱动容易留下「插件在跑但上报的设备数不对」的状态，只能靠重启插件恢复。

驱动与容器运行时换版本时，节点上已有的 `driver-config` 也要一起确认，SR-IOV 的 `vfNum` 就配在那里。
