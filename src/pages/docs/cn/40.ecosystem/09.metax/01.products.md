# 产品与软件栈

## 产品线

沐曦的加速卡分四条线，集群里会遇到的只有两条：训推一体的通用计算走曦云 C，纯推理走曦思 N。
图形线曦彩 G 目前只有一个型号，官网导航里的曦索 X 系列定位官方没有说明。

曦云 C 系列官方按「训推一体」定位，没有再往下拆成训练卡和推理卡：

| 型号 | 说明 |
| --- | --- |
| C500 | K8s 软件包 0.11.2 明示覆盖的型号之一 |
| C550 | K8s 软件包 0.11.2 明示覆盖的型号之一 |
| C500X | K8s 软件包 0.11.2 明示覆盖的型号之一 |
| C588 | 官网型号列表里有；K8s 覆盖情况官方未提及 |
| C600 | 新一代旗舰；K8s 支持版本未确认 |

曦思 N 系列官方按适用场景分档，不是按算力大小排的：

| 型号 | 面向的场景 |
| --- | --- |
| N100 | 传统 CV 与视频 |
| N260 | 生成式与大模型推理，K8s 软件包 0.11.2 明示覆盖 |
| N300 | 云端推理，也用于一体机与工作站；K8s 支持版本未确认 |

另外两条线目前不涉及集群接入：

| 系列 | 型号 | 定位 |
| --- | --- | --- |
| 曦彩 G | G100 | 图形 |
| 曦索 X | X206 / X301 / X302 | 官网导航里有这三个型号，产品线定位官方未作说明 |

选型时先看 **K8s 软件包覆盖到哪几档**：0.11.2 明示覆盖曦云 C500 / C500-P / C500X / C550 与曦思 N260，
C588、C600、N300 的集群侧支持情况要先向官方确认再排产。

## 软件栈分五层

MXMACA 是一个整体的名字，实际装的时候要分清下面五层，缺哪层后面都跑不起来：

| 层 | 组件 | 装在哪 | 作用 |
| --- | --- | --- | --- |
| 内核驱动 | KMD / UMD（`metax.ko`） | 宿主机 | 让操作系统认识卡，随 `k8s-driver-image` 发布 |
| 用户态运行时 | MXMACA® SDK、`macaRT` | 宿主机或业务镜像 | 提供运行时接口与设备管理 |
| 编译与算子 | `mxcc`、MCCL、mcBLAS、mcDNN、mcFFT、mcRAND、mcThrust、mcCUB、mcSPARSE、mcSOLVER | 业务镜像 | 业务编译与运行依赖，MCCL 管多卡通信 |
| 框架适配 | mcPyTorch、`vLLM-metax`、`paddle-metax-gpu` | 业务镜像 | 让 PyTorch、vLLM、PaddlePaddle 跑在沐曦卡上 |
| 容器运行时 | `metax-container-runtime`、`metax-docker` | 宿主机 | 让容器拿到设备，官方基础镜像名形如 `maca-c500`、`mxc500-maca` |

排查缺库问题时先分清报错来自哪一层：报 `mc*` 开头的库（mcBLAS、mcDNN 这些）是算子层，
报 `mxcc` 是编译器，报框架不认设备才去看框架适配层。

## 版本口径

本分区写方法，不锁版本。集群侧目前有明确口径的是 **K8s 软件包 0.11.2**，它明示覆盖曦云
C500 / C500-P / C500X / C550 与曦思 N260。C600 与 N300 的 K8s 支持版本官方未确认，
这两个型号上集群前要先跟官方对齐软件包版本。

| 要查什么 | 去哪查 |
| --- | --- |
| 产品线、型号与规格 | `https://developer.metax-tech.com/` |
| 驱动与软件包下载 | 沐曦软件中心 `https://developer.metax-tech.com/softnova/index` |
| vLLM 适配 | `https://github.com/MetaX-MACA/vLLM-metax` |
| 监控导出器 | `https://github.com/MetaX-MACA/mxExporter` |

现场一律以 **软件中心当前发布的软件包 + 随包发布的说明**为准。

:::tip mcPyTorch 不是算子库
官方算子库清单是 mcBLAS、mcDNN、mcFFT、mcRAND、mcThrust、mcCUB、mcSPARSE、mcSOLVER 这一串，
里面没有 mcPyTorch。它和 `vLLM-metax`、`paddle-metax-gpu` 一样属于框架适配层：
镜像里缺算子库要查那一串 mc 开头的包，只有框架报「不认设备」时才轮到它。
:::
