# FAQ

## 速查表

| 现象 | 先查什么 | 处置 |
| --- | --- | --- |
| `mx-smi` 列不出卡 | `metax.ko` 有没有加载 | 按软件中心对应包重装 KMD / UMD |
| 宿主机能看到卡，容器里看不到 | containerd 有没有配上沐曦运行时 | 装 `metax-container-runtime`，注册方式按官方说明 |
| 节点上没有 `metax-tech.com/gpu` | `gpu-device` 的 Pod 状态与日志 | 先确认驱动与容器运行时都好，再重启插件 |
| `helm install` 卡在拉 chart | OCI 仓库的授权与拉取凭据 | 两个 chart 都要商务授权，先拿授权 |
| 用 `metax-tech.com/vgpu` 申请不到卡 | 资源名写错了 | 沐曦没有这个资源名，整卡与 VF 都写 `metax-tech.com/gpu` |
| 配了 `vfNum` 之后配额不够用 | 规格与配额按多少张卡建的 | 可分配数量等于物理卡数 × `vfNum` |
| 想按显存比例切卡 | 有没有 HAMi 或沐曦 gpu-scheduler | sGPU 走 `metax-tech.com/sgpu`，需要 HAMi ≥ 2.6.0，见 [HAMi](/ecosystem/hami) |
| 监控里看不到沐曦指标 | `mx-exporter` 装没装、端口对不对 | 装 mx-exporter，抓 8000 端口 |
| 模型卡片里选不到 C500、N260 | 平台有没有登记沐曦型号 | 平台没登记，先选占位型号 |
| 规格名带前缀、也没有沐曦图标 | 平台展示层 | 属当前产品边界，不影响调度 |

## 为什么平台上找不到装沐曦组件的地方

平台的「系统应用」里只内置了 NVIDIA 与昇腾两套硬件调度组件，
沐曦的集群组件要按官方 chart 手工装。这不是配置问题，是当前的产品边界，
见 [平台适配现状](/ecosystem/metax/platform-support)。

## 容器里看不到卡，但宿主机正常

先分清沐曦这一层不是 CDI，也不是标准 toolkit。沐曦用的是自家容器运行时：

- **containerd 节点**：装 `metax-container-runtime`，containerd 服务本身照常跑，注册方式按官方说明做。
- **Docker 节点**：用 `metax-docker`。

判断方法很直接：看节点上有没有装这两个组件中的一个，
以及 containerd 配置里有没有指向沐曦的运行时。都没有就是没装。

## `metax-tech.com/vgpu` 能不能用

不能用。官方文档里没有出现过这个资源名，它是从别的厂商那边带过来的写法。
沐曦的设备插件只上报一个资源名：

```
metax-tech.com/gpu
```

整卡和 SR-IOV 出来的 VF 都用它。申请资源、建规格、建配额，全部按这个名字写。

## 规格名为什么带前缀、图标为什么没有

平台把规格名里的型号前缀去掉，只对 nvidia / amd / intel / huawei 四家做，
沐曦不在名单里，所以规格名会带着前缀显示。厂商图标同理，沐曦没有专属图标，
规格标签只显示通用的 `GPU`。

这两项都不影响调度，属于展示层的当前状态。要让显示变干净，需要平台侧把沐曦加进名单。
