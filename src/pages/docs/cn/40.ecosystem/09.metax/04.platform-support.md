# 平台适配现状

平台上「认识一张卡」要经过四处代码，每处负责一件事。这一页把这四处对沐曦的实际状态逐个列出来，
省得在界面里找不到某样东西时猜是配置错了还是本来就没有。

平台侧现在只给了沐曦半张身份证：加速器类型登记了，型号、图标、调度组件都还没有。

## 逐层核对

| 层 | 位置 | 对沐曦的现状 |
| --- | --- | --- |
| 镜像加速器类型 | 镜像登记时的加速器选项 | **已登记**：`MACA(沐曦)` |
| 模型元数据型号 | 模型卡片可选的加速卡型号 | **没有**：一个沐曦型号都没登记 |
| 模型元数据的后端枚举 | 模型元数据里的 `hardware_backends` | **没有** `maca`；当前枚举是 cpu / cuda / rocm / ascend / mlu / musa / metal |
| 规格的加速卡标签 | 规格标签上写的字样 | **走通用路径**：显示 `GPU`，没有沐曦专属标签 |
| 规格的型号名 | 规格名拼接 | **前缀不会被剥掉**：平台剥前缀的名单只有 nvidia / amd / intel / huawei 四家 |
| 规格的厂商图标 | 规格标签上的小图标 | **没有**：沐曦没有专属图标 |
| 集群调度组件 | 集群管理 → 运维管理 → 系统应用 | **没有**：平台只内置了 NVIDIA 与昇腾两套 |

## 现在能做什么

- **镜像元数据**：上传或登记镜像时标成 `MACA(沐曦)`，检索和筛选能用上。
- **算力调度**：节点上 `gpu-device` 报出 `metax-tech.com/gpu` 之后，平台侧按这个资源名建的配额、规格、任务申请都能走通。
- **资源规格**：可以手工按资源名建规格，功能上可用，只是显示层没有沐曦的专属信息。

## 还不能做什么

| 缺的能力 | 影响 | 补法 |
| --- | --- | --- |
| 模型元数据里的沐曦型号 | 建模型卡片时选不到 C500、N260 这些型号 | 暂时先选一个占位型号，等平台登记后改回来 |
| 模型元数据的后端枚举 | `hardware_backends` 里没有 `maca` | 该字段留空或按现有枚举挑一个最接近的，调度本身不看它 |
| 规格的加速卡标签 | 规格标签显示通用 `GPU`，不写沐曦 | 属平台展示层设计，不影响调度 |
| 规格型号名的前缀剥除 | 规格名里带着前缀，不够干净 | 等平台把 `metax` 加进剥前缀的名单 |
| 规格的厂商图标 | 规格标签上没有沐曦图标 | 同上，属展示层 |
| 一键安装集群调度组件 | 不能在系统应用里点一下装好 | 按 [Kubernetes 组件](/ecosystem/metax/k8s-components) 手工装官方 chart |

## 手工接入的完整顺序

平台的系统应用里没有沐曦，所以四步都在集群外完成：

1. 每台有卡的机器装 KMD / UMD 与 MXMACA 用户态，`mx-smi` 出卡。
2. 同一批机器装 `metax-container-runtime`（或 `metax-docker`），让容器能看到设备。
3. 集群里用 `metax-operator` 或 `metax-gpu-extensions` 装集群组件，确认节点出现 `metax-tech.com/gpu`。
4. 回到平台，按该资源名建资源规格与配额，然后提交一个申请 1 张卡的任务验一遍。

第 4 步是唯一需要动平台界面的地方，前三步都在集群侧。
