# 灵骏节点池

PPU 卡不在通用 ECS 上，它装在灵骏机器里。要让集群看见这些机器，做法是建一个**灵骏节点池**，再把机器加进去。

节点池本身遵循 ACK 标准节点池模型：创建、升降配、组件管理、升级都在控制台或 API 里做。
已有的集群不用重建，直接新增一个灵骏节点池即可，原来的 ECS 节点和 GPU 节点不受影响。
通用算力、GPU 算力、PPU 算力可以在同一个集群里共存，业务侧用 `nodeSelector` 选。

## 开始之前

| 项目 | 要求 |
| --- | --- |
| 集群 | ACK 托管集群 **Pro 版** |
| 集群组件 | 已安装 `ack-rdma-device-plugin` 和 `ack-ppu-device-plugin` |
| 节点 | 灵骏节点（PPU 节点）已在阿里云侧交付完成，处于可用状态 |
| 权限 | 能操作目标集群的节点池与组件管理 |

组件安装的细节在[设备插件 · 安装与验证](/ecosystem/aliyun/device-plugin/install)。如果先建池后装组件，
顺序不影响结果，但节点标签要等组件起来才会出现。

## 步骤

### 1. 创建灵骏节点池

在容器服务控制台进入目标集群，创建节点池时把**节点类型选为灵骏节点**。其余参数按业务需要配，
这个节点池里的机器都会成为 PPU 节点。

### 2. 添加已有灵骏节点

把已经在阿里云侧交付的灵骏节点加入这个节点池。节点加入后由 ACK 接管调度，但机器本身的驱动、固件、
硬件维护仍然在阿里云一侧，不需要也不应该手动去装驱动。

### 3. 确认节点就绪

```bash
kubectl get nodes -l aliyun.accelerator/xpu_type=ppu
```

节点状态为 `Ready` 就说明接进来了。如果这条命令什么都没返回，说明节点没有带上 PPU 标签，
先回去确认组件是否装好，而不是去查网络。

### 4. 核对节点标签

节点就绪后，会带上这几个标签：

| 标签 | 含义 | 示例值 |
| --- | --- | --- |
| `aliyun.accelerator/xpu_type` | 加速器类型 | `ppu` |
| `aliyun.accelerator/ppu_name` | PPU 型号 | `PPU-ZW810E` |
| `aliyun.accelerator/ppu_count` | 每节点 PPU 数量 | `16` |
| `aliyun.accelerator/ppu_mem` | 单卡显存 | `98304MiB` |

查看命令：

```bash
kubectl get node <NODE_NAME> -o jsonpath='{.metadata.labels}' \
  | jq 'to_entries[ ] | select(.key | startswith("aliyun.accelerator"))'
```

`ppu_count` 和 `ppu_mem` 这两个值可以直接用来核对交付：卡数对不对、显存是不是 96GB，一眼能看出来。

## 污点与容忍

灵骏节点默认带一个污点：

```yaml
key: node-role.alibabacloud.com/lingjun
effect: NoSchedule
```

**不带容忍的 Pod 不会被调度上去**，卡再多也没用。这是新人最常踩的一个坑，示例：

```yaml
tolerations:
  - key: node-role.alibabacloud.com/lingjun
    operator: Exists
    effect: NoSchedule
```

用平台的算力规格创建实例时，平台会按规格里声明的调度约束生成这段配置，不需要手工写。

## 选节点

一个集群里同时有 ECS、GPU、PPU 三类节点时，用标签挑选：

```yaml
nodeSelector:
  aliyun.accelerator/xpu_type: ppu
```

如果只要特定型号，可以再加一条 `aliyun.accelerator/ppu_name: PPU-ZW810E`。

超节点形态还有两个标签用于标识互联域，做多机任务时会用到：

| 标签 | 含义 |
| --- | --- |
| `alibabacloud.com/lingjun-hypernode-id` | 同一超节点下的子节点共享这个值 |
| `alibabacloud.com/hypernode-link.version` | 跨机互联的协议版本 |

## RDMA 与存储

- **RDMA**：`ack-rdma-device-plugin` 会把节点的 RDMA 网卡上报成 `rdma/hca`。跨机训练、
  大模型并行推理都要申请这个资源，不申请就只能走普通网络，带宽差一个量级。
- **存储**：CPFS 智算版这类高性能存储要求算力和存储实例处在**同一个高性能网络分区**。
  规划阶段就要把节点池和存储的网络分区对齐，事后调整代价很大。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 节点列表里看不到 PPU 节点 | 节点没加进灵骏节点池，或节点未就绪 | 在控制台确认节点池成员，再看节点状态与事件 |
| 节点在列表里但没有 PPU 标签 | 设备插件没装或没起来 | 检查 `ack-ppu-device-plugin` 的 Pod 状态与日志 |
| Pod 一直 Pending，提示无法容忍污点 | 没写灵骏污点的容忍 | 按上文补 `tolerations` |
| Pod 申请不到 `rdma/hca` | 没装 `ack-rdma-device-plugin` | 安装后在节点上确认 `rdma/hca` 已出现 |
