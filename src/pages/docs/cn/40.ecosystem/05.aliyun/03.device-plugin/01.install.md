# 安装与验证

组件在**阿里云容器服务控制台**安装，路径是：集群列表 → 目标集群 → 组件管理 → 搜索组件名 → 安装。

## 开始之前

- 集群是 ACK 托管集群 **Pro 版**。
- 灵骏节点池已建好，PPU 节点已加入。建池步骤见[灵骏节点池](/ecosystem/aliyun/lingjun-nodepool)。

## 1. 安装 ack-rdma-device-plugin

按控制台默认参数装即可。它负责把节点的 RDMA 网卡上报成 `rdma/hca`，跨机任务要用。

如果这一期只做单机验证，可以先不装；但多机训练和多机推理一定需要。

## 2. 安装 ack-ppu-device-plugin

安装时有一个关键选项：**勾选 `Enable PPU Topology`**。

勾上之后组件会上报 PPU 的物理拓扑信息，调度器按最优拓扑组合分配卡，支持申请 1、2、4、8、16 卡。
不勾也能用，但拿到的是随机卡组合，多卡任务的通信性能会明显差一截。

## 3. 确认组件起来了

```bash
kubectl get pods -A | grep -E "ppu|rdma"
```

设备插件是 DaemonSet，PPU 节点上有几张卡就该有几个 Pod 在跑。Pod 不是 `Running` 时先看日志：

```bash
kubectl logs -n kube-system <POD_NAME> --tail=100
```

## 4. 确认资源已上报

```bash
kubectl describe node <NODE_NAME> | grep -A 20 "Allocatable"
```

期望看到 `alibabacloud.com/ppu`，以及该卡支持的 `alibabacloud.com/ppu-*u.*g*g` 系列。
这一条能通过，说明从节点到调度器的链路是通的，后面的事都好办。

## 5. 跑一个冒烟任务

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: ppu
  name: ppu-test
  namespace: default
spec:
  selector:
    matchLabels:
      app: ppu
  template:
    metadata:
      labels:
        app: ppu
    spec:
      containers:
        - image: anolis-registry.cn-zhangjiakou.cr.aliyuncs.com/openanolis/nginx:1.14.1-8.6
          imagePullPolicy: IfNotPresent
          name: ppu
          ports:
            - containerPort: 80
              protocol: TCP
          resources:
            limits:
              alibabacloud.com/ppu: "1"
      dnsPolicy: ClusterFirst
      restartPolicy: Always
      schedulerName: default-scheduler
      tolerations:
        - key: node-role.alibabacloud.com/lingjun
          operator: Exists
          effect: NoSchedule
```

两处配置值得留意：

- `resources.limits.alibabacloud.com/ppu`：申请数量，可取 1、2、4、8、16。
- `tolerations`：灵骏节点的污点必须容忍，否则 Pod 一直 Pending。

验证：

```bash
kubectl get pod -l app=ppu -o wide
kubectl describe node <NODE_NAME> | grep -A 5 "Allocated resources"
```

Pod 状态为 `Running`、`NODE` 列是 PPU 节点，并且 `Allocated resources` 里
`alibabacloud.com/ppu` 已被占用，就算装完了。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 组件安装后节点上没有 PPU 标签 | 组件 Pod 没起来 | 看 Pod 状态与日志，确认调度到了灵骏节点 |
| `Allocatable` 里没有 `alibabacloud.com/ppu` | 设备插件没有在目标节点上运行 | 检查 DaemonSet 是否覆盖灵骏节点，节点是否带灵骏污点导致组件没调度上去 |
| Pod Pending，事件提示 taint | 漏了灵骏污点的容忍 | 按第 5 步的示例补 `tolerations` |
| 申请 `rdma/hca` 失败 | 没装 RDMA 设备插件 | 安装 `ack-rdma-device-plugin` 后重试 |
| 多卡任务通信慢 | 安装时没勾 `Enable PPU Topology` | 重新配置组件，勾上拓扑上报 |
