# PPU 基础

PPU 不是把 GPU 换个名字。平头哥自己做了并行计算架构、指令、编译器和算子库，整套软件栈叫 **PPU SDK**。
对使用者来说，多数时候看不到这层差别：镜像还是那些镜像，框架还是那些框架。但只要涉及算子缺失或者精度不匹配，
就要回到「这套栈支持到什么程度」这个问题上。

PPU 目前只在阿里云上提供，卡在灵骏机器里，通过 ACK 调度。

## 型号

| 型号 | 形态 | 公开材料里的说法 |
| --- | --- | --- |
| PPU-ZW810E | 单卡，装在灵骏节点上，一个节点常见 16 张 | 第一代公开型号，节点标签里的值是 `PPU-ZW810E` |
| ZW-M890 | 超节点实例（GP9A），以 64 卡为一个售卖单元 | 卡间互联 800GB/s，显存池 9,216GB，支持 MXFP4 |
| M890P | 与 M890 同系列 | 设备插件 1.4.0（2026-08）起全面支持 |

想知道当前节点是什么型号，不用翻订单，看标签就行：

```bash
kubectl get node <NODE_NAME> -o jsonpath='{.metadata.labels}' \
  | jq 'to_entries[ ] | select(.key | startswith("aliyun.accelerator"))'
```

`aliyun.accelerator/ppu_name` 的值就是型号。

## 关键参数（ZW810E）

| 项目 | 参数 | 说明 |
| --- | --- | --- |
| 显存 | 96GB HBM2e | 单卡容量，节点标签 `ppu_mem` 显示为 `98304MiB` |
| 片间互联 | 700GB/s | 自研 ICN 互联，多卡并行时决定通信开销 |
| 接口 | PCIe 5.0 x16 | 与宿主机之间的带宽 |
| 功耗 | 400W | 单卡 |

这组数字的用处是判断模型放不放得下、并行度开多大。96GB 单卡能直接装下 32B 级别的模型（BF16 大约 64GB 权重），
再大就要靠张量并行或量化，这一点和同显存档的 GPU 是一样的算法。

:::info 参数以控制台和交付单为准
上面是公开资料的口径，用于前期估算。真正下单和扩容时，规格、显存、卡数一律以阿里云控制台展示
和实际交付单为准；同一代芯片也可能有不同固件版本。
:::

## 软件栈

| 层次 | 内容 | 谁来管 |
| --- | --- | --- |
| 驱动与固件 | 让系统认识卡 | 阿里云维护，用户不参与 |
| PPU SDK | 编译器、算子库、`ppu-smi` 等工具 | 在业务镜像里，平台不单独安装 |
| 框架 | Megatron、DeepSpeed、vLLM、SGLang 等 | 官方口径是「支持无缝迁移」，实际要按框架版本对一遍 |

`ppu-smi` 是最常用的排查工具，位置和 `nvidia-smi` 类似：查卡、查显存、开 MIG 模式都靠它。

模型侧，公开资料提到兼容 Qwen、LLaMA 这类常见开源模型。**兼容不等于零改动**：如果业务用了冷门算子或者
自研 CUDA 扩展，迁移前先拿一个最小任务在 PPU 上跑通，再谈批量上线。

## 卡是怎么切分的

PPU 有两条路：整卡申请，或者切成实例。

| 方式 | 资源名 | 特点 |
| --- | --- | --- |
| 整卡 | `alibabacloud.com/ppu` | 一个容器独占一张卡，最简单，性能最稳 |
| MIG 切分 | `alibabacloud.com/ppu-4u.4g48gb` 这类 | 硬件级隔离，算力和显存可以分开切 |

MIG 在 PPU 上的概念和 NVIDIA 侧接近但用词不同：硬件资源先切成若干 **GPU instance**（彼此隔离），
`GPU instance profile` 描述一次切分能给出多少 CU 和显存；如果需要进一步细分，还可以把 GPU instance
切成若干 **Compute instance**，后者独占 CU、复用其他资源。开 MIG 模式的命令是：

```bash
ppu-smi -mig 1
```

具体档位和申请示例见[设备插件 · MIG 切分](/ecosystem/aliyun/device-plugin/mig)。

## 适合什么业务

- **大模型推理服务**：在线问答、RAG、Agent 这类高并发场景，vLLM 与 SGLang 都能跑，是 PPU 最主流的用法。
- **训练与微调**：预训练、后训练都在支持范围内。超节点形态的 M890 更偏向万亿参数规模的训练。
- **智驾与多模态**：阿里云在汽车行业推得比较重，数据标注、模型训练、云端仿真这条链路上有不少现成方案。
- **多租户算力池化**：接进平台后按项目、租户切分，适合内部多个团队共用一个算力池。

反过来，**单机小规模、对算子覆盖要求极窄的业务**不必急着上 PPU：迁移和调优的成本摊不开，
用现成的 GPU 池更省事。
