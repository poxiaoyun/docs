# 驱动与容器运行时（NVIDIA）

这一页要做的事都在每台有 GPU 的机器上：先把驱动装上，让宿主机自己认识这张卡；再装容器工具链
（`nvidia-container-toolkit`），让容器里也能看到卡。第一件事的判断标准很简单，执行 `nvidia-smi`
能看到卡和驱动版本就算过。

驱动是操作系统使用这张卡的基础软件，没有它，系统只知道插了一块硬件。容器工具链是卡与容器之间的转接头：
业务都跑在容器里，不装这一层，容器拿不到卡设备。

:::info 容器工具链可以交给 GPU Operator
平台的 GPU Operator 组件默认会**自动安装容器工具链**，并且默认**不安装宿主机驱动**（复用节点上已有的驱动）。
所以走平台安装时，你只需要手工做本页的「装驱动」这一段；「装容器工具链」一段留给单独部署或排障时用。
:::

## 开始之前

- 确认机器上已经有 GPU，且操作系统与目标驱动版本兼容。
- 准备好**驱动安装包**（`.run` 格式）或系统的软件包源，并已上传到目标机器能访问的目录。
- 具备 **root** 权限，且能安装编译工具与内核头文件（`gcc`、`make`、`kernel-devel` / `linux-headers`）。
- 确认这台机器上**没有**正在运行的图形界面依赖 NVIDIA 驱动：装了桌面环境的机器要先把图形界面停掉。

## 一、装宿主机驱动

### 1. 先看这台机器有没有装过驱动

```bash
nvidia-smi
```

- 能打印出 GPU 列表、驱动版本和 CUDA 版本：说明已装好，可直接跳到「验证」。
- 提示命令不存在，或报 `couldn't communicate with the NVIDIA driver`：说明未安装或驱动未加载，继续往下走。

顺便确认硬件确实在：

```bash
lspci | grep -i nvidia
```

### 2. 装依赖

CentOS / openEuler 系：

```bash
yum install -y gcc make dkms kernel-headers-$(uname -r) kernel-devel-$(uname -r)
```

Ubuntu / Debian 系：

```bash
apt install -y build-essential dkms linux-headers-$(uname -r)
```

`dkms` 负责在内核更新后自动重编驱动，缺它会出现「驱动装了、内核一升级就加载失败」的情况。

### 3. 屏蔽开源的 nouveau 驱动

Linux 发行版自带的 `nouveau` 会和 NVIDIA 官方驱动争抢设备，必须先屏蔽：

```bash
echo -e "blacklist nouveau\noptions nouveau modeset=0" > /etc/modprobe.d/blacklist-nouveau.conf
dracut --force          # Ubuntu / Debian 改用：update-initramfs -u
reboot
```

重启后确认已经屏蔽掉（没有输出即成功）：

```bash
lsmod | grep nouveau
```

### 4. 安装驱动

如果这台机器上装过旧版驱动，先用安装包自带的卸载程序清干净，再装新版：

```bash
# 卸载旧驱动（安装目录下才有这个脚本）
/usr/bin/nvidia-uninstall

# 安装
chmod +x NVIDIA-Linux-<arch>-<version>.run
./NVIDIA-Linux-<arch>-<version>.run --silent --dkms
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--silent` | 静默安装，不做交互询问，适合批量交付 |
| `--dkms` | 注册到 DKMS，内核升级后自动重编驱动 |
| `--no-opengl-files` | 只装计算相关文件，不装图形库。**纯算力机器建议加上**，避免与现有图形环境冲突 |

### 5. 按提示重启

```bash
reboot
```

## 二、装容器工具链

用平台装 GPU Operator 时不需要手工做这一段，跳过即可。

```bash
# 1) 配置仓库（以 NVIDIA 官方容器工具链仓库为准，按下发的安装说明执行）
# 2) 安装
yum install -y nvidia-container-toolkit        # Ubuntu / Debian 用 apt install

# 3) 让容器引擎使用 NVIDIA 运行时：containerd 与 Docker 二选一
nvidia-ctk runtime configure --runtime=containerd
nvidia-ctk runtime configure --runtime=docker

# 4) 重启容器引擎
systemctl daemon-reload && systemctl restart containerd
```

:::warning 重启容器引擎会影响在跑的业务
`systemctl restart containerd` 会重启节点上所有容器。**在生产节点上操作前先确认可以停机**，
或错峰执行。
:::

## 验证

### 1. 宿主机能用卡

```bash
nvidia-smi
```

输出里通常能看到：**驱动版本与 CUDA 版本**（右上角）、**显卡型号与数量**、每张卡的**显存占用**、
**利用率**和正在使用卡的进程。卡都列出来、没有报错，就说明驱动加载成功。

### 2. 容器里能用卡

```bash
docker run --rm --gpus all nvidia/cuda:12.2.0-base-ubi8 nvidia-smi
```

能打印出和宿主机一样的卡列表，说明容器工具链配置成功。用 containerd 的集群不写 `--gpus`，
而是由 GPU Operator 的设备插件在 Pod 启动时注入设备与驱动接口。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| `nvidia-smi` 提示无法与驱动通信 | 驱动没装上，或装完没重启 | 确认安装回显成功，按提示重启后再试 |
| 装驱动时报「已有驱动正在运行」 | 机器上还装着旧驱动或 nouveau | 先执行 `nvidia-uninstall`，并按第 3 步屏蔽 `nouveau` |
| 安装时提示缺少内核头文件 | `kernel-devel` / `linux-headers` 与当前内核不一致 | 用 `uname -r` 查内核版本，装与它**完全一致**的头文件包 |
| 内核升级后驱动失效 | 安装时没带 `--dkms` | 重装驱动并加上 `--dkms`，或每次内核升级后重编 |
| 容器里 `nvidia-smi` 提示找不到设备 | 容器工具链没装，或没重启容器引擎 | 检查 `nvidia-ctk runtime configure` 是否执行过并重启了引擎 |
| 有桌面环境的机器装完驱动黑屏 | 图形驱动与计算驱动冲突 | 重装时加 `--no-opengl-files`，并先停掉图形界面再装 |

:::warning 驱动和 CUDA 版本要配套
驱动版本决定它最高支持到哪个 CUDA 版本。**业务镜像里的 CUDA 版本不能高于宿主机驱动支持的上限**，
否则容器启动时会报 CUDA 初始化失败。查驱动的支持上限可以看 `nvidia-smi` 右上角的 `CUDA Version`，
或到 [NVIDIA 官方对照表](https://docs.nvidia.com/cuda/cuda-toolkit-release-notes/index.html) 核对。
:::
