# 设备插件（k8s-device-plugin）

设备插件负责**把节点上的 GPU 注册成 Kubernetes 的资源**：它发现卡、做健康检查，
然后告诉集群「这台机器有几张卡可用」。注册成功后，业务 Pod 才能通过声明资源的方式用上卡。

可以把它理解成**给卡上户口**：卡本来只是插在机器上的硬件，注册之后才有集群认可的「身份」，
调度器才知道哪台机器还有卡空着。

## 什么情况下必须装

- **整卡调度**：一个 Pod 独占一张卡。
- **共享调度**：配上 vGPU 后把一张卡切给多个 Pod（见 [Volcano 与 vGPU 切分](/ecosystem/nvidia/volcano-vgpu)）。
- **按型号调度**：用节点标签把任务钉到指定型号的机器。

它随 GPU Operator 一起部署，**不需要单独安装**。

## 平台默认参数

安装时这些参数已经设好，排障时对照它来看行为是否符合预期：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `PASS_DEVICE_SPECS` | `true` | 把设备规格（型号、显存等）传给容器，业务里可以读到 |
| `FAIL_ON_INIT_ERROR` | `true` | 初始化失败直接让 Pod 失败，而不是静默降级。**避免「Pod 起来了其实没卡」这种假成功** |
| `DEVICE_LIST_STRATEGY` | `envvar` | 用环境变量把分配到的设备传给容器，是与 vGPU 协同工作的前提 |
| `DEVICE_ID_STRATEGY` | `uuid` | 用 GPU 的 UUID 标识设备。比按序号（index）稳定，节点重启或换卡后不会串位 |
| `NVIDIA_VISIBLE_DEVICES` | `all` | 让插件能看到节点上所有卡，再由它按调度结果裁剪 |
| `NVIDIA_DRIVER_CAPABILITIES` | `all` | 容器里可用的驱动能力全开（计算、工具、视频等） |

:::info 为什么用 UUID 而不是序号
按序号分配时，「第 0 号卡」是驱动在启动时枚举出来的顺序。机器重启、换卡、插拔之后这个顺序可能变，
业务就会跑到另一张卡上。用 UUID 相当于按卡的身份证号分配，跨重启稳定。
:::

## 验证

### 1. 看插件 Pod

```bash
kubectl get pod -n gpu-operator -o wide | grep device-plugin
```

每台 GPU 节点上各有一个 Pod，状态为 `Running`。

### 2. 看节点资源

```bash
kubectl get node <gpu-node> -o jsonpath='{.status.allocatable}' | tr ',' '\n' | grep nvidia
kubectl describe node <gpu-node> | grep nvidia.com/gpu
```

`Capacity` 里出现 `nvidia.com/gpu: 8`，就表示这台机器有 8 张卡可被集群分配。

### 3. 起一个 Pod 验证端到端

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: gpu-smoke-test
spec:
  containers:
    - name: cuda
      image: nvidia/cuda:12.2.0-base-ubi8
      command: ["nvidia-smi"]
      resources:
        limits:
          nvidia.com/gpu: 1
  restartPolicy: Never
```

```bash
kubectl apply -f gpu-smoke-test.yaml
kubectl logs gpu-smoke-test
```

日志里能看到卡的信息，说明从调度到设备注入整条链路都通了。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| Pod 起来了，但节点上没有出现资源名 | 容器工具链没装好，或插件初始化失败 | `kubectl logs -n gpu-operator <device-plugin-pod>` 看报错；插件默认 `FAIL_ON_INIT_ERROR=true`，失败会直接退出 |
| 只有部分节点有资源 | 这些节点没装驱动，或标签不满足 | 在对应节点上执行 `nvidia-smi`，并核对 `nvidia.com/gpu.present` 标签 |
| 申请 `nvidia.com/gpu` 的 Pod 一直 Pending | 没有空闲卡，或资源名 / 数量写错 | `kubectl describe node <gpu-node>` 看剩余量；核对 `limits` 里的资源名拼写 |
| 卡数量比物理卡少 | 部分卡被声明给了 MIG 或 vGPU | 见 [MIG 实例划分](/ecosystem/nvidia/gpu-operator/mig-manager) 与 [Volcano 与 vGPU 切分](/ecosystem/nvidia/volcano-vgpu) |
| 容器里看不到 `nvidia-smi` | 业务镜像本身没带这个命令 | 用 `nvidia/cuda:*-base-*` 这类官方基础镜像，或自己装驱动工具 |
| 一个 Pod 申请多张卡时启动很慢 | 卡分布在多块 NUMA 上 | 调度侧配好 NUMA 亲和（平台的 Volcano 默认已启用 numa-aware 插件） |

:::warning 整卡与共享不要混用
同一张卡不要既按 `nvidia.com/gpu` 整卡申请、又按 vGPU 份额申请。**混用会导致显存超分配（OOM）。**
要共享就统一走 vGPU 的资源名。
:::
