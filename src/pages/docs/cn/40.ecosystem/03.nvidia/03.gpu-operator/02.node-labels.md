# 节点标签从哪来（NFD / GFD）

调度器站在走廊里，**只能看门牌，看不到屋里到底装了什么卡**。节点标签就是这套门牌：
它写明「这台机器上有没有 GPU、是什么型号、有多少显存」，设备插件与 MIG Manager 靠它决定自己管哪些节点，
你在创建资源池时也可以用它把任务钉到特定型号的机器上。

这套标签由 GPU Operator 里的两个组件自动生成，不需要手工打：

| 组件 | 负责写什么标签 | 数据从哪来 |
| --- | --- | --- |
| **NFD**（Node Feature Discovery，节点特征发现） | `feature.node.kubernetes.io/*`：节点上有没有 NVIDIA 设备、操作系统版本、内核特性等 | 遍历节点的 PCI 设备与系统信息 |
| **GFD**（GPU Feature Discovery，GPU 特征发现） | `nvidia.com/*`：GPU 型号、显存、驱动与 CUDA 版本、MIG 能力 | 调用驱动接口读 GPU 信息 |

可以这样理解：**NFD 判断「屋里有没有这个牌子的设备」，GFD 判断「是哪一款、多大显存」**。
GFD 依赖 NFD 已经就位，所以安装顺序上 NFD 在前。

## 常见标签

### GPU 型号与容量

| 标签 | 含义 | 示例 |
| --- | --- | --- |
| `nvidia.com/gpu.present` | 节点上是否有可用 GPU | `true` |
| `nvidia.com/gpu.product` | 显卡型号 | `NVIDIA-A100-SXM4-80GB` |
| `nvidia.com/gpu.machine` | 服务器机型 | `PowerEdge-R750` |
| `nvidia.com/gpu.count` | 卡的数量 | `8` |
| `nvidia.com/gpu.memory` | 单卡显存（MB） | `81920` |
| `nvidia.com/gpu.family` | 架构代际 | `ampere` / `hopper` |
| `nvidia.com/gpu.compute.major` / `.minor` | 计算能力（算力版本） | `8` / `0` |

### 驱动与运行时版本

| 标签 | 含义 |
| --- | --- |
| `nvidia.com/cuda.driver.major` / `.minor` | 宿主机驱动版本 |
| `nvidia.com/cuda.runtime.major` / `.minor` | 驱动支持的最高 CUDA 运行时版本 |

这两个标签在做「业务镜像 CUDA 版本与驱动是否配套」的批量核对时很好用。

### MIG 相关

| 标签 | 含义 |
| --- | --- |
| `nvidia.com/mig.capable` | 这张卡是否支持 MIG 切分 |
| `nvidia.com/mig.config` | **你声明**想要的切分方案（如 `all-1g.10gb`）；见 [MIG 实例划分](/ecosystem/nvidia/gpu-operator/mig-manager) |
| `nvidia.com/mig.config.state` | MIG Manager 执行该方案的状态，`success` 表示已按方案切好 |

### 节点通用特征

| 标签 | 含义 |
| --- | --- |
| `feature.node.kubernetes.io/pci-10de.present` | 节点上是否有 NVIDIA 的 PCI 设备（`10de` 是 NVIDIA 的厂商 ID） |
| `feature.node.kubernetes.io/system-os_release.ID` | 操作系统标识（如 `ubuntu`、`centos`） |

## 怎么用这些标签

### 1. 查看某台节点的 GPU 标签

```bash
kubectl get node <gpu-node> --show-labels | tr ',' '\n' | grep -E "nvidia|feature"
```

### 2. 把任务钉到指定型号的机器

在资源池或工作负载的节点选择里填型号标签即可，例如只要 A100：

```yaml
spec:
  nodeSelector:
    nvidia.com/gpu.product: NVIDIA-A100-SXM4-80GB
```

### 3. 确认设备插件确实认到了卡

设备插件按 `nvidia.com/gpu.present` 之类的标签筛选节点。如果标签在、资源名却不在，
问题多半出在容器工具链，而不是标签 —— 排查顺序见[设备插件](/ecosystem/nvidia/gpu-operator/device-plugin)。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 节点上一个 `nvidia.com/*` 标签都没有 | GFD 没起来，或宿主机驱动异常 | 先看 `kubectl get pod -n gpu-operator \| grep gpu-feature-discovery`，再在节点上执行 `nvidia-smi` |
| 有 `feature.node.*` 标签，没有 `nvidia.com/*` 标签 | NFD 正常、GFD 异常 | 看 GFD 的 Pod 日志，通常是驱动版本与 GFD 不兼容 |
| 标签里的型号和实际插的卡不一致 | 机器上装过不同型号的卡，或标签被手工改过 | 重启 GFD 让它重新探测；不要手工改这些标签，重启后会覆盖 |
| 改了 `nvidia.com/mig.config` 但状态不是 `success` | 显卡不支持该切分方案，或节点上还有在用卡的任务 | 核对显卡支持的 MIG 规格；先在空闲节点上试 |

:::warning 标签是探测结果，不是配置项
除 MIG 的 `nvidia.com/mig.config` 是**你写、组件读**之外，其余标签都是组件探测出来的。
手工 `kubectl label` 改它们没有意义 —— 组件下一次探测就会覆盖回去。
:::
