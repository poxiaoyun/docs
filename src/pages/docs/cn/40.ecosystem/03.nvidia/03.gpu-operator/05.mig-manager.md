# MIG 实例划分

MIG（Multi-Instance GPU）是 NVIDIA 的**硬件级切分**方式：把一张卡在硬件层面切成多个
**完全隔离**的实例，每个实例有自己的显存和计算单元，互不干扰。适合「多个小任务要共存、
又要求强隔离」的场景。

可以把它理解成**把一间大办公室用实体墙隔成几个小间**：隔断是真的，谁的噪声也传不到隔壁。

:::info 平台默认不划分 MIG
只有当你**给节点打上声明标签**时，MIG Manager 才会动手划分。默认状态下所有卡都按整卡使用。
需要切分时再按本页操作。
:::

## 与 vGPU 切分怎么选

| 对比项 | MIG（本页） | [vGPU](/ecosystem/nvidia/volcano-vgpu) |
| --- | --- | --- |
| 切分层次 | 硬件级 | 软件级（注入共享库 + 内存隔离） |
| 隔离性 | 强，实例之间硬件隔离 | 一般，靠软件限制算力与显存 |
| 规格 | 固定的几何方案（如 1g.10gb / 2g.20gb） | 提交任务时按份数或显存额度申请 |
| 使用前要不要人工准备 | 要，先声明切分方案 | 不用，插件按需切 |
| 适合场景 | 强隔离、多租户共存 | 规格多变、追求利用率 |

:::warning 同一套环境里二选一
MIG 与 vGPU 同时开启会互相冲突（可用的卡几何与显存额度都对不上）。**选定一条路线再装**。
:::

## 硬件支持情况

MIG 只对部分型号开放。平台配套的切分方案覆盖以下型号：

| 型号 | 可选几何方案（名称 → 显存 / 可切份数） |
| --- | --- |
| A30 | `1g.6gb` → 6144MB × 4；`2g.12gb` → 12288MB × 2；`4g.24gb` → 24576MB × 1 |
| A100 40GB | `1g.5gb` → 5120MB × 7；`2g.10gb` → 10240MB × 3；`3g.20gb` → 20480MB × 2；`7g.40gb` → 40960MB × 1 |
| A100 80GB | `1g.10gb` → 10240MB × 7；`2g.20gb` → 20480MB × 3；`3g.40gb` → 40960MB × 2；`7g.79gb` → 80896MB × 1 |

其他型号是否支持、支持哪些几何方案，以显卡自身的规格为准（节点上会有 `nvidia.com/mig.capable` 标签标出来）。

## 操作步骤

### 1. 确认显卡支持 MIG

```bash
kubectl get node <gpu-node> -L nvidia.com/mig.capable
```

输出为 `true` 的节点可以切分。

### 2. 声明切分方案

给节点打上声明标签，值就是想要的几何方案：

```bash
# 全部切成 1g.10gb（A100 80GB）
kubectl label node <gpu-node> nvidia.com/mig.config=all-1g.10gb --overwrite
```

常用的取值：

| 取值 | 含义 |
| --- | --- |
| `all-<几何>` | 节点上**所有**卡都按这个几何方案切（如 `all-2g.20gb`） |
| `all-balanced` | 由组件在支持的方案里挑一个均衡的 |
| `all-disabled` | 取消切分，还原成整卡 |

### 3. 等切分完成

```bash
kubectl get node <gpu-node> -L nvidia.com/mig.config,nvidia.com/mig.config.state
```

`state` 变成 `success` 就说明切好了。切分过程会**重置这些卡**，节点上正在用卡的任务会被打断，
所以要在业务空闲时做。

### 4. 确认资源已经注册

```bash
kubectl get node <gpu-node> -o jsonpath='{.status.allocatable}' | tr ',' '\n' | grep mig
```

节点上会出现 `nvidia.com/mig-1g.10gb: 7` 这类资源名。业务这样申请：

```yaml
resources:
  limits:
    nvidia.com/mig-1g.10gb: 1
```

## 还原成整卡

```bash
kubectl label node <gpu-node> nvidia.com/mig.config=all-disabled --overwrite
```

等 `state` 变回 `success` 后，节点上的 `nvidia.com/mig-*` 资源消失、`nvidia.com/gpu` 恢复。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 打了标签但 `state` 一直是 `pending` | 显卡不支持该几何方案，或节点上还有任务在用卡 | 核对方案名称；确认节点上没有正在用 GPU 的 Pod |
| 打完标签后 `nvidia.com/gpu` 消失了 | 这是预期行为：卡已被切给 MIG 实例 | 用 `nvidia.com/mig-*` 资源名申请；要整卡就还原成 `all-disabled` |
| 任务报「显存不足」但实例规格够用 | 任务申请的显存超过该几何方案 | 换更大的几何方案，或改用 [vGPU](/ecosystem/nvidia/volcano-vgpu) 按需申请 |
| 只想给部分卡切分 | 节点级标签是整节点生效 | 把要切的卡拆到独立节点上，节点粒度声明 |
| 切分后监控里卡的数量变多 | 这是预期行为：MIG 实例各自上报指标 | 按实例维度看指标即可 |

:::warning 切分会重置显卡
打标签后节点上所有卡都会被重置并按方案重切，**正在跑的任务会中断**。生产环境请先用空闲节点验证方案。
:::
