# DCGM Exporter（GPU 监控）

DCGM Exporter 负责**定时采集每张 GPU 的状态**：利用率、显存占用、温度、功耗、时钟、ECC 错误、
NVLink 带宽等，再通过 HTTP 接口暴露出来，供 Prometheus 之类的监控系统抓取。
装完它，平台上才能看到卡的运行曲线、做容量统计和告警。

可以把它理解成**装在每张卡上的电表**：卡不会主动汇报自己的温度和功耗，得有人定期去读表。

## 什么情况下必须装

- 需要在平台上查看 GPU 的利用率、显存、温度、功耗（**集群信息 → 加速卡信息**那几个面板的数据就来自这里）。
- 需要按卡的状态做告警或容量规划。

只做资源调度、不需要监控数据时可以不装，但平台上的加速卡看板会没有数据。

## 平台默认行为

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 是否启用 | 开启 | 随 GPU Operator 一起部署 |
| 创建 ServiceMonitor | 开启 | 让 Prometheus Operator 自动发现并抓取；集群没有这个 CRD 时要关掉 |
| 抓取间隔 | `30s` | 由 ServiceMonitor 指定 |
| `honorLabels` | `true` | 保留 Exporter 自己打上的标签，不被抓取侧覆盖 |
| 指标端口 | `9400` | 路径 `/metrics` |

同一个集群里的昇腾 NPU 用的是 NPU Exporter，端口是 `8082`；两套 Exporter 互不影响，可以并存。

## 验证

### 1. 看 Pod

```bash
kubectl get pod -n gpu-operator -o wide | grep dcgm
```

每台 GPU 节点上各有一个 Pod，状态为 `Running`。

### 2. 直接读指标

```bash
kubectl port-forward -n gpu-operator <dcgm-exporter-pod> 9400:9400
# 另开一个终端
curl -s localhost:9400/metrics | grep DCGM_FI_DEV_GPU_UTIL
```

能打出指标行，说明采集正常。

### 3. 在 Prometheus 里确认

若集群已部署 Prometheus，查询 `DCGM_FI_DEV_GPU_UTIL`，能看到数据就说明抓取成功。
再回到平台 **集群管理 → 选择集群 → 集群信息 → 加速卡信息**，看板里应该出现对应的曲线。

## 常用指标

| 指标含义 | 指标名称 |
| --- | --- |
| GPU 利用率（%） | `DCGM_FI_DEV_GPU_UTIL` |
| 显存已用 / 剩余（MiB） | `DCGM_FI_DEV_FB_USED` / `DCGM_FI_DEV_FB_FREE` |
| 显存占用率（%） | `DCGM_FI_DEV_FB_USED_PERCENT` |
| 温度（℃） | `DCGM_FI_DEV_GPU_TEMP` |
| 功耗（W） | `DCGM_FI_DEV_POWER_USAGE` |
| 功耗上限（W） | `DCGM_FI_DEV_POWER_MGMT_LIMIT` |
| 核心 / 显存频率（MHz） | `DCGM_FI_DEV_SM_CLOCK` / `DCGM_FI_DEV_MEM_CLOCK` |
| XID 错误数 | `DCGM_FI_DEV_XID_ERRORS` |
| ECC 可纠正 / 不可纠正错误 | `DCGM_FI_DEV_ECC_SBE_VOL_TOTAL` / `DCGM_FI_DEV_ECC_DBE_VOL_TOTAL` |
| NVLink 带宽 | `DCGM_FI_DEV_NVLINK_BANDWIDTH_TOTAL` |
| PCIe 带宽 | `DCGM_FI_PROF_PCIE_TX_BYTES` / `DCGM_FI_PROF_PCIE_RX_BYTES` |

## 指标上的标签

指标会带上这些标签，用来区分是哪张卡、哪个 Pod 在用：

| 标签 | 含义 |
| --- | --- |
| `gpu` | 节点内的 GPU 序号 |
| `UUID` | GPU 的唯一标识 |
| `modelName` | 显卡型号 |
| `Hostname` | 所在节点 |
| `namespace` / `pod` / `container` | 正在使用该卡的工作负载（没有负载时为空） |

## 常见问题

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 指标里 `pod` / `namespace` 标签始终为空 | 该卡当前没有容器在工作 | 属正常现象；跑一个用卡的 Pod 后再看 |
| 平台加速卡看板没有数据 | Exporter 未启用，或 ServiceMonitor 没建 | 检查 `kubectl get svc -n gpu-operator \| grep dcgm` 与集群里是否有 Prometheus Operator |
| `9400` 端口打不开 | Pod 未就绪，或端口被改过 | 先确认 Pod 状态与就绪探针，再核对 Service 端口 |
| 指标采集到一半中断 | DCGM 与驱动版本不配套 | 看 Exporter 日志；核对该版本 DCGM 支持的驱动范围 |
| 想自定义要采集哪些指标 | — | 通过 Exporter 的配置项指定指标分组与采集间隔，改完重启 Pod |

:::warning 升级驱动前先停 Exporter
Exporter 会周期性调用 DCGM 接口读卡。升级驱动前先停业务、再停 Exporter；
升级完成后按相反顺序恢复，否则会出现「读到一半旧驱动、指标异常」的情况。
:::
