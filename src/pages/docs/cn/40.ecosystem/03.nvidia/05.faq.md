# FAQ

NVIDIA GPU 接入时最常遇到的问题都在这张表里：先按现象找到最像的一行，再照「怎么办」里的命令排查。
表里放不下的长命令，统一放在后面的「完整命令」一节。

## 常见故障速查表

| 现象 | 可能原因 | 怎么办 |
| --- | --- | --- |
| 宿主机上 `nvidia-smi` 看不到卡 | 驱动没装、没重启，或被 `nouveau` 占用 | 见[驱动与容器运行时](/ecosystem/nvidia/driver-runtime)；重点确认 `lsmod \| grep nouveau` 无输出 |
| 设备插件 Pod 一直重启 | 容器工具链没就绪，或容器运行时类型填错 | 看 `kubectl logs -n gpu-operator <device-plugin-pod>`；确认安装时填的运行时与该节点实际一致 |
| 节点上没有 `nvidia.com/gpu` | 驱动异常，或设备插件没在跑 | 节点上执行 `nvidia-smi`；再查 `kubectl get pod -n gpu-operator \| grep device-plugin` |
| 申请卡的 Pod 一直 Pending | 没有空闲卡，或资源名 / 数量写错 | `kubectl describe node <gpu-node>` 看剩余量；核对 `limits` 里的资源名 |
| 容器启动后报 CUDA 初始化失败 | 业务镜像的 CUDA 版本高于宿主机驱动支持上限 | 看节点上 `nvidia.com/cuda.driver.major` 标签；换用更低 CUDA 版本的镜像或升级驱动 |
| 系统应用创建后一直没生效 | 镜像拉不下来、集群缺应用控制器、缺少 Prometheus Operator CRD | 查 `kubectl get pod -n gpu-operator` 与 `-n volcano-system`，找异常 Pod 看事件 |
| 平台加速卡看板空白 | DCGM Exporter 未启用，或没建 ServiceMonitor | 见 [DCGM Exporter](/ecosystem/nvidia/gpu-operator/dcgm-exporter) |
| 申请 `volcano.sh/vgpu-*` 失败 | vGPU 没开，或份额已用完 | 见 [Volcano 与 vGPU 切分](/ecosystem/nvidia/volcano-vgpu)；开启 GPU 虚拟化并确认节点资源名 |
| 打了 MIG 标签但没生效 | 显卡不支持该几何方案，或节点上还有任务在用卡 | 见 [MIG 实例划分](/ecosystem/nvidia/gpu-operator/mig-manager)；先在空闲节点验证方案 |
| 集群里同时有昇腾和 NVIDIA 卡 | 两套调度组件各自带一个 Volcano | 同一集群只保留一套调度组件；不要在已装昇腾组件的集群上重复装 NVIDIA 调度组件 |
| 节点标签里的型号和实际不符 | 标签是探测结果，可能读到了旧数据 | 重启 GPU 特征发现组件让它重新探测，不要手工改标签 |
| 升级驱动后集群看不到卡了 | 升级顺序不对，组件拿着旧驱动句柄 | 先停业务与组件再升驱动：停设备插件 → 停监控导出器 → 升驱动 → 按相反顺序恢复 |

## 完整命令

### 一键体检

按顺序执行，能定位问题大致在哪一层：

```bash
# 第 1 层：宿主机认得卡吗
nvidia-smi
lsmod | grep nouveau          # 有输出说明 nouveau 没屏蔽干净

# 第 2 层：运行时装了吗、容器引擎用的哪个运行时
nvidia-ctk --version
kubectl get node <gpu-node> -o jsonpath='{.status.nodeInfo.containerRuntimeVersion}{"\n"}'

# 第 3 层：集群认得卡吗
kubectl get node <gpu-node> -o jsonpath='{.status.allocatable}' | tr ',' '\n' | grep -E "nvidia|vgpu"
kubectl describe node <gpu-node> | grep -E "nvidia.com/gpu"
```

### 确认各组件当前版本

镜像标签即版本：

```bash
kubectl get pod -n gpu-operator \
  -o jsonpath='{range .items[*]}{.metadata.name}{"  "}{.spec.containers[*].image}{"\n"}{end}'
kubectl get pod -n volcano-system \
  -o jsonpath='{range .items[*]}{.metadata.name}{"  "}{.spec.containers[*].image}{"\n"}{end}'
```

### 看某个组件的日志

```bash
kubectl logs -n gpu-operator <pod-name> --tail=100
kubectl logs -n gpu-operator <pod-name> -c <container-name> --tail=100
```

设备插件与 vGPU 设备插件都是多容器 Pod，**日志要指定容器名**，否则默认只打第一个容器的日志。

### 定位「卡被谁占着」

```bash
kubectl get pod -A -o jsonpath='{range .items[*]}{.metadata.namespace}{"/"}{.metadata.name}{"  "}{.spec.containers[*].resources.limits}{"\n"}{end}' | grep -E "nvidia.com/gpu|vgpu"
```
