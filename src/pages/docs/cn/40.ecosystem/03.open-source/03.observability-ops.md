# 可观测与运维

这一页讲**怎么看清集群在发生什么，以及怎么让它自动变好**：指标、日志、链路追踪帮你定位问题；
扩缩容和重调度组件帮你在没人盯着的时候自动调整。
你要排查故障、看资源趋势、让服务随流量自动伸缩时，就会用到这一层的组件。

:::tip 三个词先分清
**指标（Metrics）** ≈ 体温计，定期记一个数字，看趋势。
**日志（Logs）** ≈ 病历本，把每件事按时间记下来，出事了翻记录。
**链路追踪（Tracing）** ≈ 快递单号，一次请求经过哪些环节、每段花了多久都能追。
:::

## 这个分类解决什么问题

| 问题 | 由谁负责 |
| --- | --- |
| 看 CPU、内存、显卡利用率趋势 | kube-prometheus-stack 或 VictoriaMetrics |
| 服务出问题要发告警 | Alertmanager（随监控组件安装） |
| 查某个容器的历史日志 | Loki + Logging Operator |
| 追一次请求走了哪些服务、卡在哪 | OpenTelemetry Collector + Jaeger |
| 让大模型帮忙分析故障原因 | Holmes |
| 流量涨了自动加副本、降了自动减 | KEDA |
| Pod 的 CPU、内存请求总配不准 | VPA |
| 节点忽冷忽热、资源有碎片 | Descheduler |
| 用 Prometheus 指标驱动自动扩缩容 | Prometheus Adapter |

## 包含哪些组件

| 组件 | 作用 | 关键特性 | 平台里怎么用 |
| --- | --- | --- | --- |
| kube-prometheus-stack（Prometheus 监控栈） | 采集和存储指标、触发告警 | 自带 Prometheus、Alertmanager、Grafana，以及节点和集群状态采集 | 运维管理 → 系统应用；装好后通过监控组件的看板查看 |
| metrics-server（基础指标服务，3.13.0） | 提供节点和 Pod 的基础资源用量 | 安装后资源用量类指标才完整，可选装 | 运维管理 → 系统应用（监控） |
| Loki + Logging Operator（容器日志方案） | 采集、聚合、查询容器日志 | Fluent Bit 采集、SyslogNG 聚合、Loki 存储；支持按日志量选单机/简单扩展/分布式 | 运维管理 → 系统应用；日志管理页查日志 |
| VictoriaMetrics（时序数据库与告警栈） | Prometheus 兼容的指标存储、查询和告警 | 提供采集、告警、看板一整套；支持集群模式和多副本 | 运维管理 → 系统应用 |
| VictoriaLogs（日志存储查询） | 轻量日志存储与查询 | 支持单机和集群两种模式，可设置保留时间和容量 | 运维管理 → 系统应用 |
| OpenTelemetry Collector + Jaeger（链路追踪） | 采集并存储请求链路数据 | Collector 支持多副本、可对接 Jaeger 后端 | 运维管理 → 系统应用 |
| Holmes（智能诊断服务，0.34.0） | 用大模型自动分析资源问题 | 多租户隔离，只能诊断你被授权的资源 | 系统应用里安装；平台 → AI助手设置里配置 |
| KEDA（事件驱动扩缩容，2.20.2） | 按外部事件或指标自动扩缩容 | 把消息队列、数据库、监控指标转成扩缩依据 | 运维管理 → 系统应用 |
| VPA（纵向扩缩容，1.6.0） | 自动给出并调整 Pod 的 CPU、内存请求 | 先出建议，再按策略重建 Pod 应用；不管理副本数 | 运维管理 → 系统应用 |
| Descheduler（重调度与碎片整理） | 把负载从热点节点迁到空闲节点 | 支持定时和固定间隔触发，可跳过挂载存储卷的 Pod | 运维管理 → 系统应用 |
| Prometheus Adapter（指标适配器，4.14.1） | 把 Prometheus 指标变成 Kubernetes 能用的指标 | 让自动扩缩容可以基于业务指标而不是只看 CPU | 随监控与调度组件安装 |

## 什么时候需要关注它

- **要查日志**：先确认装了 **Loki + Logging Operator**，然后到**运维管理 → 日志管理**，在**全部日志**和**节点日志**两个页签里查。
- **要看监控、配告警**：装 **kube-prometheus-stack** 或 **VictoriaMetrics**，两者能力重叠，**同一个集群按需选一套**即可，不要重复装两套采集。
- **要追跨服务调用**：装 **OpenTelemetry Collector + Jaeger**，在业务代码里接入对应的数据上报。
- **服务负载波动大**：用 **KEDA** 按事件或指标扩容；只是 CPU、内存请求配不准就用 **VPA**。
- **自动扩缩容想用业务指标**：装 **Prometheus Adapter**，把 Prometheus 指标接入。
- **节点忙闲不均**：开 **Descheduler**，按 CPU、内存水位线迁移负载。
- **想让大模型帮你排障**：装 **Holmes**，再到**平台 → AI助手设置**里填好模型和访问密钥。

:::warning 两套可观测方案不要混装
Prometheus 系（kube-prometheus-stack）和 VictoriaMetrics 系（VictoriaMetrics）功能重叠。同一个集群建议只装一套，
否则会重复采集、重复告警，还会互相抢存储和 CPU。
:::

## 开始之前

- 安装这些组件需要**平台管理员**权限，并进入**具体集群**的**运维管理 → 系统应用**。
- 存储类要提前准备好，监控和日志组件都需要持久化存储保存历史数据，否则重启后数据会丢。
